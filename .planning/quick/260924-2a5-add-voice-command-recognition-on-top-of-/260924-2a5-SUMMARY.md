## Accomplishments
- Replaced `transcribe.js`'s Web Speech API (cloud-dependent in Chrome) with a fully on-device `@huggingface/transformers` `automatic-speech-recognition` pipeline (`onnx-community/whisper-tiny.en`, q8), preserving the `startTranscription({onFinal,onInterim,onError})` interface and `{stop()}` shape exactly
- Added amplitude-threshold VAD (tunable `SILENCE_RMS_THRESHOLD`/`SILENCE_DURATION_MS` constants) to segment continuous mic input into utterances for the batch-only Whisper pipeline
- Added `commands.js`: an embedding-similarity intent classifier (`Xenova/all-MiniLM-L6-v2`) mapping transcripts to 1 of 5 fixed voice commands, with a tunable `CONFIDENCE_THRESHOLD` gating direct execution vs. a "did you mean" clarification
- Added `record.js`'s `setRecordingBaseName(name)`: a one-shot sanitized base-name override for the "save file to `<name>`" command, reverting to the timestamp default after one use
- Extracted `main.js`'s five click-listener bodies into named functions and wired voice-command dispatch through the same functions the UI buttons call

## UAT Notes (Manual Verification Pending)

The plan's manual verification steps require a real browser with microphone access and cannot be run by the executor in this environment. These remain pending human confirmation:

1. **Task 1 manual verify:** Run `npx serve hands-face-voice`, click "Start microphone," wait for the ~41MB Whisper model to download (first load only), speak a short phrase, and confirm recognizable text appears in `#transcriptFinal` within a few seconds via the local pipeline, with no console errors and no network requests to any Google/cloud speech endpoint. Reload and confirm `.onnx` files load from cache.
2. **Task 2 manual verify:** With both models loaded, verify all 5 commands: "start landmarks" starts the camera; "save file to test session" sets `#voiceCommandStatus` to report the sanitized name "test-session"; "start recording" and "stop recording" dispatch correctly and produce `test-session.webm`/`test-session.json`; an unrelated phrase (e.g. "what time is it") produces a "did you mean" clarification and executes nothing; no console errors throughout.
3. **"start microphone" is intentionally unreachable via voice.** The mic must already be running (via a manual button click) before any spoken command — including "start microphone" itself — can be heard at all. This is documented in `commands.js`'s comment above `COMMAND_EXAMPLES` and is **expected behavior, not a defect** to be filed or fixed. A UAT session that tries saying "start microphone" before ever clicking a button and finds nothing happens is confirming correct, documented behavior.
