Constants: immediately after `const POSE_COLOR = 0x34d399;` (line 29), add `JITTER_TOLERANCE = 0.004` and `SMOOTHING_FACTOR = 0.35` as two new top-level `const` declarations, with a short comment noting `JITTER_TOLERANCE` is a dead-zone radius in raw normalized `[0,1]`-ish coordinate units (measured before `normalizedTransform`/`SCENE_SCALE`), and `SMOOTHING_FACTOR` is the EMA ease-per-frame weight (0-1, higher = snappier).     2. Closure-level smoothing state: inside `createScene3D`, immediately after `let liveGroup = new THREE.Group(); scene.add(liveGroup);`, add a `smoothedPoints` `Map` (empty, module of `createScene3D`'s closure so it persists across `update()` calls but is isolated per scene instance) and a `prevSlotCounts` plain object with `hand`, `face`, `pose` keys all initialized to `0`. Then add three closure functions:
       - `resetStaleSlots(set, currentCount)`: reads `prevSlotCounts[set]` as `prevCount`. If `currentCount < prevCount` (this set's array shrank since last frame — a slot disappeared), iterate `smoothedPoints.keys()`, split each key on `":"` into `[keySet, keySlot]`, and `smoothedPoints.delete(key)` for every key where `keySet === set` and `Number(keySlot) >= currentCount` (every slot index that no longer exists this frame). Unconditionally finish by setting `prevSlotCounts[set] = currentCount`. This is what makes a reappearing slot start from "no state" instead of easing in from a stale point — it must run once per set per `update()` call, before that set's points are smoothed, so the purge happens before the new frame's (possibly reappeared) slot is processed.
       - `smoothPoint(set, slot, index, raw)`: builds `key` as the template string `` `${set}:${slot}:${index}` ``, looks up `smoothedPoints.get(key)`. If there is no existing entry, store a fresh `{x: raw.x, y: raw.y, z: raw.z}` object under `key` and return it directly (first frame after appearing — or reappearing, since `resetStaleSlots` already purged any stale entry — so it renders at the real detected position with no easing). If an entry exists, compute `dx = raw.x - prev.x`, `dy = raw.y - prev.y`, `dz = raw.z - prev.z`, and the Euclidean distance `Math.sqrt(dx*dx + dy*dy + dz*dz)`. When that distance is below `JITTER_TOLERANCE`, return `prev` unchanged (the dead-zone: sub-threshold movement is fully suppressed, not eased toward). Otherwise mutate `prev.x += dx * SMOOTHING_FACTOR`, `prev.y += dy * SMOOTHING_FACTOR`, `prev.z += dz * SMOOTHING_FACTOR` (the EMA step easing toward the raw position) and return the mutated `prev`.
       - `smoothLandmarks(set, slot, landmarks)`: returns `landmarks.map((p, index) => smoothPoint(set, slot, index, p))` — smooths every point in the full landmarks array for that slot (not just a drawn subset), since both the point-cloud indices (e.g. `FACE_TESSELLATION_INDICES`) and the connector-line indices (e.g. `FACE_LANDMARKS_CONTOURS` start/end) index into the full array, so every array position needs to be addressable and smoothed once rather than smoothing the same point redundantly from two different call sites.
