<objective>
Wire real hand-face relative position through the live hands-face-voice playground, and add
MediaPipe PoseLandmarker as a shared body-skeleton anchor for hands and face, replacing
scene3d.js's fixed-offset spacing hack.

hands-face.js already computes `handResult.landmarks` (normalized image-space, same per-frame
coordinate space as `faceResult.faceLandmarks`) but drops it before calling `onLandmarks` — only
`handResult.worldLandmarks` (per-hand metric, no shared origin) makes it through today. Thread the
normalized landmarks through too, add PoseLandmarker as a third model alongside HandLandmarker and
FaceLandmarker, and use one shared normalized-frame transform in scene3d.js so hand/face relative
position and pose-anchored placement come from real per-frame data instead of `HAND_OFFSETS_X` /
`FACE_SCALE`.

This is still the raw diagnostic playground (no gesture recognition, no command mapping) — the
offline pipeline in `.planning/spikes/MANIFEST.md`'s hands-face-voice-input section reuses this
same landmark visualization and is untouched by this change.

Non-goal: `index.html` and `main.js` need no edits. `main.js`'s `onLandmarks: (landmarks) =>
scene3D.update(landmarks)` passthrough forwards whatever shape `hands-face.js` produces, and
`index.html`'s `#metrics` div already renders whatever text `hands-face.js` writes into it — no
new DOM elements are needed for a third model's output.

Purpose: prove real body-relative position between hands and face before any gesture/pointing
logic is designed on top of it.
Output: `hands-face.js` running three MediaPipe models per frame with pose drawn in the 2D
overlay; `scene3d.js` rendering hands, face and pose from one shared coordinate frame.
</objective>

  <action>
    Rewrite the top-of-file comment (current lines 1-12, which document that hands use metric
    `worldLandmarks` with no shared origin and are spaced apart with fixed offsets purely to avoid
    overlap) to describe the new approach honestly: hands, face and pose are now all drawn from
    MediaPipe's *normalized* landmarks (x, y in [0,1] relative to the image, z relative depth)
    rather than each model's independently-reconstructed metric world landmarks — hand world
    landmarks are hand-centered and pose world landmarks are hip-centered, so mixing metric world
    landmarks across models would still have no shared origin. Normalized landmarks are computed
    in one shared per-frame coordinate system across all three models, so one shared transform
    places every point cloud in real relative position: hands appear where they actually are
    relative to the face, and the pose skeleton's wrists/shoulders/nose sit near the hand and face
    clouds they anchor, replacing the old fixed `HAND_OFFSETS_X` / `FACE_SCALE` spacing hack. State
    plainly that this is a normalized-frame visual anchor, not a metric 3D fusion — it gives
    comparable relative x/y position and z depth ordering, not physically-scaled absolute
    distances.

    Add `PoseLandmarker` to the existing `@mediapipe/tasks-vision@0.10.17` import (alongside
    `HandLandmarker`, `FaceLandmarker` — same jsdelivr URL already used in this file).

    Replace the constants block (current `HAND_SCALE`, `HAND_OFFSETS_X`, `FACE_SCALE`) with a
    single `SCENE_SCALE = 0.6` (reuses the value already proven visible for the face cloud, now
    shared by every cloud since they're all in the same normalized frame) plus a new `POSE_COLOR =
    0x34d399` alongside the existing `HAND_COLORS` and `FACE_COLOR`. `HAND_SCALE` and
    `HAND_OFFSETS_X` are no longer used by anything once hands render in the normalized frame; do
    not leave them declared unused.

    Add a module-level `normalizedTransform(p)` function returning `[(p.x - 0.5) * SCENE_SCALE,
    -(p.y - 0.5) * SCENE_SCALE, -p.z * SCENE_SCALE]` — this is the same math the face branch
    already used with `FACE_SCALE`, now factored out and reused for every cloud.

    Rewrite `update({ handsWorld, faceLandmarksList })` to `update({ handsNormalized = [],
    faceLandmarksList = [], poseLandmarksList = [] })`:

      `cloud(landmarks.map(normalizedTransform), color)` and `lines(landmarks,
      HandLandmarker.HAND_CONNECTIONS, color, normalizedTransform)` instead of building a
      per-hand `transform` closure with `HAND_SCALE`/`offsetX`.
    - Face: unchanged logic (contour-indexed cloud + `FaceLandmarker.FACE_LANDMARKS_CONTOURS`
      lines), but call `normalizedTransform` instead of the inline per-face `transform` closure

      hand/face blocks — `liveGroup.add(cloud(landmarks.map(normalizedTransform), POSE_COLOR))`

      normalizedTransform))`.

    `render()`/`onResize()` untouched — only the constants and `update()` change.
