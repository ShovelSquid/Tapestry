Lazily create and cache a single ASR pipeline instance for the module's whole lifetime — a module-level `let asrPipelinePromise` guarded by a `getAsrPipeline()` helper that calls `pipeline("automatic-speech-recognition", "onnx-community/whisper-tiny.en", { dtype: "q8" })` on first use and returns the same promise on every subsequent call.     Inside `startTranscription`, kick off `getAsrPipeline()` and `navigator.mediaDevices.getUserMedia({ audio: true })` concurrently — don't await one before starting the other — so the ~41MB first-run model download and the mic permission prompt overlap instead of serializing. Call `onInterim` with a status string while the model is loading (mention it's a one-time ~41MB local download, cached by the browser after), and clear it back to an empty string once both resolve. Route any rejection from either promise (mic access denied, pipeline load failure) to `onError`, matching the interface's existing error-handling contract — `startTranscription` itself does not throw synchronously the way the old implementation did.

    Open an independent capture stream, separate from `voice.js`'s own stream (simpler, harmless duplication, no `main.js` refactor). Construct `new (window.AudioContext || window.webkitAudioContext)({ sampleRate: 16000 })` — Whisper's feature extractor expects 16kHz mono input — and wire `audioCtx.createMediaStreamSource(stream)` into a `ScriptProcessorNode` via `audioCtx.createScriptProcessor(4096, 1, 1)` for raw PCM access. Add a comment noting `ScriptProcessorNode` is deprecated but chosen here over `AudioWorkletNode` because it needs no separate worklet module file, keeping this playground's no-build-step, single-file pattern. Connect the processor to a zero-gain `GainNode` (`audioCtx.createGain()` with `gain.value = 0`) which connects to `audioCtx.destination` — this makes `onaudioprocess` fire reliably without audibly looping the mic back to the speakers.

    In the `onaudioprocess` handler, compute the RMS amplitude of `event.inputBuffer.getChannelData(0)` each callback. Implement silence-based VAD using three named, commented constants near the top of the file — `SILENCE_RMS_THRESHOLD` (start at `0.02`), `SILENCE_HOLD_MS` (`700` — milliseconds of continuous near-silence that ends an utterance), and `MIN_UTTERANCE_MS` (`300` — shorter blips are discarded) — explicitly commented as starting points that may need tuning against a real mic/room, not fixed constants. While RMS exceeds the threshold: on the transition into speech call `onInterim("listening...")`, and copy each callback's samples (`new Float32Array(input)`, a copy — the browser reuses the underlying buffer) into an in-memory array of chunks. While RMS is below the threshold and an utterance is already in progress: keep appending chunks (to capture natural trailing breath/consonants) and start a silence timer if one isn't already running; once continuous silence exceeds `SILENCE_HOLD_MS`, finalize the utterance.

    On finalize: concatenate the buffered `Float32Array` chunks into one contiguous array, clear the chunk buffer, and compute the total duration from sample count / 16000. If duration is below `MIN_UTTERANCE_MS`, discard silently (no `onFinal` call, no error). Otherwise call `onInterim("transcribing...")`, `await` the cached ASR pipeline on the concatenated audio, call `onFinal(result.text.trim())` with the returned text, then clear the interim status back to an empty string. Wrap the inference call in try/catch and route failures to `onError` without stopping the capture stream.

    `stop()` must set a `running` flag to false (checked at the top of `onaudioprocess` and before any async finalize continuation applies its result, so no stale transcription lands after stop), disconnect the processor and gain node, stop every track on the captured `stream`, and close the `AudioContext` — mirroring `voice.js`'s existing teardown.
