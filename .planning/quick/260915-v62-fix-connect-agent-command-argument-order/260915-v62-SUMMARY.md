# Quick Task 260915-v62: Fix connect-agent command argument order Summary

`buildConnectCommand` now names the `tapestry` MCP server immediately after `add` and pushes `--`
alone just before the runtime command, so `claude mcp add`'s variadic `--env` option can no longer
swallow the server name.

## What Changed

**`app/src/main/agents/connect-command.ts`**

- `SERVER_NAME` moved into the `parts` array literal as the element directly after `'add'`, ahead
  of `--scope`, `--transport` and the env flags.
- The old `parts.push(SERVER_NAME, '--')` became `parts.push('--')`, so the separator still lands
  immediately before the runtime command in both the development and packaged branches.
- The module header gained a paragraph recording *why* the order is load-bearing: the CLI's usage
  is `claude mcp add [options] <name> <commandOrUrl> [args...]`, its env option is variadic and
  keeps eating following non-option tokens, a name placed after the env flags is read as another
  environment variable and rejected as `Invalid environment variable format: tapestry`, and `--`
  terminates that variadic list so no env value can run into the runtime command.
- Nothing else moved: the same flags, the same `shellQuote` on every interpolated value, the same
  two runtime branches, the token still appearing exactly once.

**`app/src/main/agents/connect-command.test.ts`**

- Both full-command expectations corrected to the new order (server name after `add`, `--`
  directly before the runtime command), keeping the existing multi-line concatenation style.
- New third test, `puts the server name before --env, which is variadic and would swallow it`,
  loops over `isPackaged` false and true, splits on spaces and asserts on token indices: the
  `tapestry` index is > -1 and less than the first `--env`/`-e` index; exactly one token equals
  `--`; every env-flag index is below the `--` index; the token after `--` is `node` when not
  packaged and `shellQuote(BASE.execPath)` when packaged. It carries a comment recording that the
  old order reached a real terminal as `Invalid environment variable format: tapestry` — the
  evidence the test exists to protect.
- The two existing property tests (token appears once, spaced userData path stays one argument)
  are untouched and still pass, so T-02.2-23 quoting is unaffected.
