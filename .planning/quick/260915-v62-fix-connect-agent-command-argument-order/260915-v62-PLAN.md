<objective>
Fix the argument order of the connect-agent command so `claude mcp add` can parse it.

`buildConnectCommand` currently emits the server name AFTER the env flags
(`parts.push(SERVER_NAME, '--')`, connect-command.ts:78). `claude mcp add` declares its env option
as variadic (`-e, --env <env...>`), and a variadic option keeps consuming following non-option
tokens — so `tapestry` is swallowed as a third environment variable, never becomes the server name,
and the CLI aborts with:

    Invalid environment variable format: tapestry, environment variables should be added as: -e KEY1=value1 -e KEY2=value2

Purpose: Kaelen cannot connect an agent at all right now — the Agents panel hands out a command that
fails in the terminal every time. The diagnosis is confirmed against the real CLI (see the task's
read_first); this plan is the surgical reorder plus the tests that pin the CLI's grammar.

Output: `connect-command.ts` emitting the name first and the `--` separator directly before the
runtime command; `connect-command.test.ts` with the two full-command expectations corrected and one
new test asserting the CLI's argument grammar as an invariant.

Scope check (single source: the quick-task description and its diagnosis):

- NOT in scope: anything in app/src/main/commands/, app/src/renderer/ or tapestry/kernel/ (other

  options only and is unaffected by the internal ordering).
