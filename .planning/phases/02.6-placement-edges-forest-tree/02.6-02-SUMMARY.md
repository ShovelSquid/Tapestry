# Phase 2.6 Plan 02: Forest and Tapestry Tree Summary

**On first launch, the settings.json arrangement is imported into a readable `Forest.tree`. The import is one `system tapestry` commit that writes `placement` edges carrying real `origin.x`/`origin.y`. A `Tapestry.tree` then references the forest by digest and path hint, and the settings pointer is written last. A drop is one forest commit signed by the person, and a relaunch restores every frame from the forest alone. Both journals are held outside `TreeRegistry`.**

## Accomplishments

- **`space/shapes.ts`.** Every approved name is spelled here and nowhere else. It holds the node types, edge labels, keys, kinds, titles, world and file names, `HOME_LOCATION = 'space-dir'`, `SETTINGS_POINTER_KEY = 'tapestry'` and `SETTINGS_VERSION = 2`. It also holds three builders for the approved messages: `importMessage`, `createHomeMessage` and `moveFrameMessage`. The doc comment covers the approval, the v1 legality, the origin-only frames with the 3D-FRAMES defaults, the neighbouring `tapestry.forest/remote@1`, and the note "placement" that belongs to 2.5.
- **Settings pointer.**
  - `getTapestryPointer()` returns only a safe absolute `.tree` path.
  - `setTapestryPointer()` validates the path, then writes the raw object with `version` set to max(file, 2). `trees` and every unknown key stay raw.
  - The last-opened checks moved into the exported `readLastOpenedTree()`, which both `migrateLastOpened` and the import use.
- **`ForestStore` and `TapestryHome`.** Each holds its own bridge and is never adopted by the registry.
  - Creation is exclusive and makes one first commit with predicted ids. The ids are checked, and the file is removed if anything fails.
  - Opening classifies the file as missing, locked, damaged or foreign, and writes nothing.
  - Origins are always written with an explicit `real` type.
  - `assertWritable()` refuses a rewound bridge. Nothing in `space/` calls undo or redo.
- **`migrate.ts`.**
  - `classifySpace` is pure.
  - Case A imports in the approved order. Malformed entries are counted (case J). When `trees` is empty, last-opened.json is folded in at (0, 0).
  - Cases D-H reopen, with the digest check that catches case H.
  - `problemMessage` carries the approved wording 4.2-4.8. `SPACE_NOT_OPEN` is 4.9.
- **`SpaceService`.**
  - `start()` classifies, then imports or reopens.
  - It restores native members through `registry.tryOpen`. Vault members go only through the `restoreVault` hook, and without the hook they stay in the forest.
  - `list()` joins registry entries to members by identity.
  - `moveFrames()` validates the whole batch before writing and commits only the entries that changed, as one commit.
  - `close()` never rewinds.

## Decisions Made

- The checkpoint values are listed above. They were chosen autonomously and are pending Kaelen's review.
- A caught failure during the import removes only files the same call created: the forest if the Tapestry tree could not be made, and both if the pointer write fails. The next launch then starts cleanly from case A instead of landing in case C, which in this plan would only report `not-set-up`. A crash still leaves case B or C, as approved in 2.4.
- When a Tapestry tree's forest hint is not a safe absolute `.tree` path, it is reported as `forest-missing` at that hint (4.3). Calling it `home-foreign` (4.7) would say the Tapestry tree isn't a Tapestry file, which is not true.
- If the file holds several placement edges to one member, the lowest edge id wins. An unwritten or non-numeric origin reads as 0, which is the default in the reader's guide.
