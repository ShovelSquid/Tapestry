# Phase 02.6 Plan 05: Frame Undo and System Fit Summary

**Ctrl+Z after a frame drag writes a new signed forest commit that puts every moved frame back. The before-values are read from the forest, and the forest is never rewound. Automatic frame fitting is now a `system tapestry` commit, made at most once per member per session and never over the person's own move. `trees:setFrame` is gone.**

`FRAME_UNDO_REACH` in effect: **`'run'`**. Consecutive drags are undone one per press, and Ctrl+Shift+Z redoes them.

## Accomplishments

- **Main: compensating frame undo (D-09).** `moveFrames` saves each changed placement's stored origin as `before`, then pushes one step per drop and clears redo. `undoFrames` and `redoFrames` pop a step and apply only entries whose placement is still live and still at the step's `after`. They write every applied entry in one `setOrigins` call, signed by the person, with `undo move frame "(name)"` or `redo move frame "(name)"`. Then they push the inverse step. Both stacks are capped at `FRAME_HISTORY_LIMIT = 100`, which can be overridden with `frameHistoryLimit`. `close()` clears them.
- **Main: system fit (D-12, T-2.6-01).** `fitFrame(treeId, x, y)` validates the call, resolves the tree through the registry and `memberFor`, and checks it against `fitEligible`. That set holds every member restored at `start()` or created by `addMember`, and `moveFrames` removes every frame it moves or pushes aside. A fit spends the member's eligibility and writes only if the origin actually changes, as `system tapestry` with `fit frame "(name)" beside its neighbours`. The residual risk is documented in the doc comment.
- **IPC.** `trees:undoFrames` and `trees:redoFrames` resolve `getHumanActor()` and return `{ ok, committed, undoable, redoable }`. `trees:fitFrame` needs no name. None of the three emits `trees-changed`, and the renderer sends no actor or before-values. `trees:setFrame` has been removed from main, the preload and the types. `index.ts` has no `setTreeFrame` call left.
- **Renderer.**
  - `App.tsx` routes Ctrl+Z and Ctrl+Shift+Z through `chooseUndoTarget` using `frameRunRef`. The old precedence comments were moved into the keydown handler.
  - A wrapped `submitChange` records `'tree-edited'` on every note commit. Separate effects record `'editing-started'` and `'selection-changed'` for the note selection and the frame selection.
  - `handleFrameStep` clamps the run to main's returned stack sizes and refreshes the frames when something was committed.
  - `handleFramesMoved` arms the run after a commit. On failure it shows "Could not move the frame: [reason]" (4.12) and calls `refreshTreeList()`.
  - `Canvas` reports every drop result through `onFramesMoved`. Its placement correction now calls `fitFrame`, and the `placedRef` guard carries the D-12 and Pitfall 7 comment.
