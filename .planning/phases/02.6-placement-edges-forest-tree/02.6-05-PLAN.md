**As** Kaelen, **I want to** arrange my trees and have that arrangement kept in a readable forest tree referenced from one always-open Tapestry tree, **so that** arranging trees gets an actor, undo, history and branches like any other edit.

*(User story derived from the ROADMAP Phase 2.6 Goal line; its "so that" clause is quoted verbatim.)*

The arrangement now has history (Plans 02-04). This plan gives it **undo** and makes automatic layout honest about who moved what:

1. **Tracer — Ctrl+Z after a drag puts the frame back (D-08, D-09).** One path through every layer: keydown → routing decision → IPC → main writes a compensating commit read from the forest → renderer refreshes the frames. Redo mirrors it.
2. **Automatic fit is the system's, and only when something moved (D-12).** The renderer's placement correction stops writing settings and becomes a system commit that happens at most once per member per session, and never over the person's own move. `trees:setFrame` disappears.

Ctrl+Z reach is Part 3 of the Plan 02 checkpoint. Every value in brackets is the Recommended value; use `02.6-02-SUMMARY.md` § Checkpoint decisions where it differs. The approved wording for a failed drop is 4.12. This plan adds one visible change, the 4.12 banner, which was approved at that checkpoint. The one-way doors were confirmed at Plan 02 Task 1, and this plan adds no record name.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → `trees:fitFrame` | The renderer asks main to sign a move as the system |
| renderer → `trees:undoFrames` / `redoFrames` | The renderer asks main to write positions it does not supply |
| keyboard → undo routing | A keystroke chooses between the forest and a member tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
