# Phase 2.6 Plan 06: Launch recovery, space-problem notices, reader's guide, and the end of the settings tree writers Summary

**If the space can't open, the window now says why, in the approved wording, in the app-error banner. An upgrade whose pointer went missing now finishes as approved: case B reuses the Tapestry tree and case C reuses the forest, and neither imports `trees` a second time. Refusals to add a tree (no space open, or Tapestry's own file) are shown word for word. `tapestry/docs/tree/forest.md` explains both files so they can be read without the app. Nothing in the app can write the settings `trees` list any more.**

## Accomplishments

- `recoverHome` (case B, answer B(i)). It reopens the Tapestry tree at the default path and checks its forest exactly as a reopen does (the shared `openReferencedForest`). Then it writes the pointer last and imports nothing. A foreign file is reported as `home-foreign` (4.7). Its bytes and settings.json stay unchanged, and no forest is created.
- `recoverForest` (case C, answer C(i)). It opens the forest read-only and creates a Tapestry tree naming the forest's digest, signed `system tapestry` with message `create Tapestry tree referencing Forest.tree`. Then it writes the pointer last. The forest's bytes are unchanged. A foreign file is reported as `forest-foreign` and is never written.
- `SpaceService` routes both cases, keeps the last problem for `problemNotice()`, and marks the 4.9 refusal with the `SpaceRefusal` type. `noticeFor()` recognises 4.9 and every 4.10 sentence the registry was given.
- `trees:spaceProblem` IPC. `trees:open`, `trees:create`, `trees:close` and `vault:add` failures carry `notice` when the refusal is an approved one. The startup log now uses `problemNotice()`.
- App.tsx asks for the space problem on mount and after every trees-changed, and shows each distinct message once through `showAppError` (4.1). `addTreeToSpace` and `handleAddVault` show a `notice` verbatim and otherwise keep their old copy.
- `migrate.test.ts` (26 tests, real addon, temp paths only) covers `classifySpace` (6 rows), cases A, B (recovered and foreign), C (recovered and foreign), F (damaged, never repaired), I and J, `problemMessage` for all 10 kinds, and `noticeFor`.
- `settings.ts` follows answer 2.2 (delete). The four legacy writers and the `treesReplaced` branch are gone. `write` always carries the raw `trees` value through unchanged, and a file without `trees` keeps none.
- `tapestry/docs/tree/forest.md` (340 lines) has eight sections plus a fenced example copied from a real test-run forest.

## Deviations from Plan

### Auto-fixed Issues

**1. [Plan conflict, resolved toward D-10] A settings file with no `trees` key now keeps none**
- **Found during:** Task 2
- **Issue:** The plan's action says "a file with no `trees` key keeps none", and also says "every Plan 01 and Plan 02 settings test still passes". The Plan 01 test `writes the full known shape when there is no file yet` expected `trees: []` to be written into a new file, so both statements could not hold.
- **Fix:** Followed the explicit rule and the prohibition "No code path writes the settings `trees` list". The test is now `writes the known shape without a trees key when there is no file yet`, and a companion test `does not add a trees key when a mutator returns one for a file without it` was added. `read().trees` still returns `[]` for such a file, so no reader changes.
- **Files modified:** app/src/main/settings.ts, app/src/main/settings.test.ts
- **Commit:** 6247076

**2. [Rule 2 - Correctness] `openIntoSpace` and `trees:close` throw `SpaceRefusal` instead of returning a bare 4.9 error**
- **Found during:** Task 1
- **Issue:** Both handlers checked `space.ready` and returned `{ ok: false, error: SPACE_NOT_OPEN }` directly, so the new `notice` field would never be set for the most common 4.9 case: an add while the space is closed.
- **Fix:** They now throw `SpaceRefusal` inside their `try`, and the shared `spaceFailure` helper maps it to `notice`. The `error` text is unchanged.
- **Files modified:** app/src/main/index.ts
- **Commit:** 9b9ff29

**3. [Scope note] The phase-wide "kernel and note code unchanged" gate reports a non-2.6 diff.** See the Phase gate table. The diff comes from quick task 260924-glr (canvas roll) in `NoteCard.tsx`, which merged onto this branch during the phase. It is not 2.6 work, and no 2.6 commit touches those paths.
