<objective>
Close verification gap 1 (review finding CR-01). It breaks SC-1: "the migration is non-destructive".

Today `SettingsStore.readRaw()` returns `null` both for a missing settings.json and for one that exists but will not parse. `setTapestryPointer()` then treats the file as empty and writes `{version: 2, tapestry: {...}}` over it. That write now runs at launch with no action from the person (case A import, case B `recoverHome`, case C `recoverForest`). A hand-edited file with one trailing comma therefore loses its `trees` backup, its `userName` and every unknown key, and the forest is imported empty. Once the pointer exists, the import never runs again.

This plan makes settings.json tell "missing" apart from "present but unreadable". Nothing is ever written over an unreadable file, and all three launch paths stop with the approved `setup-failed` problem before they create or open anything. A later launch then imports normally once the person fixes the file.

1. **Tracer (Task 1):** the whole first-launch path. The three-state read, the pointer write's refusal and the early `setup-failed` in `importFromSettings` are proven end to end through `SpaceService.start()` against the real addon. An unparseable file stays byte-identical, no space file is created, and fixing the file lets the next launch import.
2. **Task 2:** cases B and C get the same early stop, every other writer (`write()`, so `setUserName` and the agents switch) refuses too, and settings.test.ts covers each state.

Purpose: SC-1 promises that the previous app state can be recovered, and #18 is a one-way door. The verifier recommends closing this gap before Kaelen's end-of-phase check on copied userData, because otherwise a bad copy would be destroyed without anyone seeing it.

Output: a hardened `settings.ts`, early guards in `migrate.ts`, and regression tests.

Requirements: the phase owns none (ROADMAP). This plan exercises TREE and PROV through integration only, so `requirements` is empty.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| settings.json (user-editable file) → launch | Hand-edited content that may not parse; it holds the only copy of the `trees` backup and the user name |
| settings writers → disk | Every write replaces the whole file (tmp + rename) |
| main → window banner | The setup-failed sentence now carries the settings path and the parse error |
