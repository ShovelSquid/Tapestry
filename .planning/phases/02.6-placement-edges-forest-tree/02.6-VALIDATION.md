# Phase 2.6 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Seeded from `02.6-RESEARCH.md` § Validation Architecture.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | vitest 2.1.9 (`environment: 'node'`, `pool: 'forks'`), and ctest for the kernel |
| **Config file** | `app/vitest.config.ts` |
| **Quick run command** | `npm --prefix app run test -- src/main/space src/renderer/layout/frame-moves.test.ts src/renderer/state/undo-target.test.ts src/main/settings.test.ts` |
| **Full suite command** | `npm --prefix app run test && npm --prefix app run typecheck && npm --prefix app run build:js && ctest --test-dir tapestry/build-kernel` |
| **Estimated runtime** | ~60 seconds (app suite) plus ~2 seconds (kernel) |

Only pure renderer modules can be unit-tested, because there is no DOM. Main-process handler logic lives in `app/src/main/space/`, and its integration tests use the real native addon and temp worlds (`app/test/helpers/temp-tree.ts`). Forest and home paths are always injected; tests never use `app.getPath`.

---

## Sampling Rate

- **After every task commit:** the quick run command, limited to the touched files, plus `npm --prefix app run typecheck`.
- **After every plan wave:** the full suite command.
- **Before `/gsd-verify-work`:** the full suite is green, and the kernel test count equals the post-merge baseline Plan 01 Task 1 records (the kernel is untouched in 2.6; 59/59 on main before the merge).
- **Max feedback latency:** 90 seconds.
