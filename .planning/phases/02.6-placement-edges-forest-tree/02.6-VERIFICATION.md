- a forest file holds `placement` edges;

### Gaps Summary

The gaps come from two root causes.

**A. settings.json cannot tell "missing" from "unreadable" (gap 1, CR-01).** The pointer write now runs automatically at launch, so a hand-edited file with one syntax error loses the `trees` backup and the user name permanently. The forest is also imported empty and never re-imported. This breaks SC-1's promise of a non-destructive, recoverable migration at the #18 one-way door. The fix is small and local: `settings.ts` plus an early `setup-failed` in `migrate.ts`.

**B. The join between registry entries and stand-ins assumes one-to-one, but unavailable records are keyed by path only (gaps 2 and 3: CR-02 and WR-01).**
- In gap 2, `create` at a missing member's path leaves a stale `path:` record. Two frames then share one placement edge, and closing the stale one removes the live world from the forest.
- In gap 3, opening a path that now holds a different world leaves the old member's stand-in hidden and unremovable, which contradicts SC-5 and the 04-SUMMARY claim.

One fix plan can cover both:
- `adopt()` clears the path's unavailable record;
- `removeMember` refuses to delete a stand-in that another live entry still joins to;
- `addMember` treats a same-path stand-in with a different digest as replaced;
- regression tests for all three reproduced flows.

WR-02 through WR-05 should go into the same gap-closure round as warnings. They do not block any success criterion on their own.
