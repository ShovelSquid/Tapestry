<objective>
Close three renderer warnings from the 02.6 code review. None breaks a roadmap success criterion on its own, and the verifier asked for all of them in this gap-closure round:

- **WR-04:** a frame pushed aside by a note landing or resizing is reported to App as a frame drop. That arms frame undo, so the next Ctrl+Z undoes the neighbour push instead of the note change the person just made. D-08's rule is that a tree edit ends the frame run.
- **WR-05:** the fit effect moves a frame on screen before main answers, and ignores main's refusal. In a new renderer session (a window re-created on macOS `activate`, or a reload), main refuses the fit, so the screen shows a position the forest never recorded.
- **WR-03:** Close tree needs a name and an open space now, and it returns a 4.9 notice. But both renderer callers discard the result, so a refusal does nothing visible.

1. **Tracer (Task 1, WR-04):** the whole path from Canvas's batch recorder, through App's result handler, to the pure run rule, with a unit test on the rule.
2. **Task 2 (WR-05):** a pure `originAfterFit` rule, and a fit effect that applies the fitted origin only when main committed it.
3. **Task 3 (WR-03):** Close tree routed through an App handler that shows the notice or the error.

**Deliberately left for Kaelen.** WR-04's other half is the forest commit message. A growth push is still recorded as `move frame "<first pushed frame>" and push N aside`, signed by the person. Better wording, such as naming the frame that grew, would be a new sentence in the approved commit-message set (shapes.ts, answer 1.12). An unattended run must not invent it. The executor records this in the SUMMARY as an open REVIEW question.

This plan touches only renderer files, and none that plans 07, 08 or 10 touch, so it runs in wave 1.

Requirements: the phase owns none, so `requirements` is empty.
