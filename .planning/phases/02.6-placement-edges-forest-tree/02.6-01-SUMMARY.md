## Accomplishments

- **Settings passthrough (D-10, RESEARCH Pitfall 1, cases I and J).**
  - `readRaw()` parses the file once.
  - `read()` reports the file's own `version`, or 1 when it is not a positive safe integer.
  - `write()` merges the validated known fields over the file as it is on disk. Unknown keys keep their values and their order.
  - `trees` is written back raw unless a legacy writer (`addTree`, `setTreeFrame`, `removeTree` or `migrateLastOpened`) replaced the array.
  - `version` is never lowered.
  - `readLegacyTrees()` returns the valid entries plus a `skipped` count.
- **`buildFrameMoveBatch`.** It extracts `settleFrames`' delta arithmetic into a pure function. The dragged frame comes first and displaced frames follow, sorted by id. Unknown ids are skipped.
- **`undo-target.ts`.**
  - `chooseUndoTarget` keeps App's precedence when no frame run is active: editing note, then selected note, then selected frame, then the last changed tree, then the first tree.
  - The `nextFrameRun` reducer handles both reach values.
  - `FRAME_UNDO_REACH = 'run'` is declared exactly once.
- **Registry seams.**
  - `classifyOpenFailure` and `closeQuietly` are now exported.
  - `TreeIdentityClash` keeps the identical message.
  - `tryOpen` accepts `expect: { id, reason }`. On a mismatch it closes the bridge and records the tree as `missing` with the caller's reason. `reopen` passes `expect` again, and `summary()` never exposes it.
  - `setReserved()` refuses the resolved path, the real path (so symlinks too) and reserved identities (so copies too). The refusal words are passed in.
  - The `summary()` doc comment is rewritten for placement edges.

## Decisions Made

- A settings write never lowers a valid version already in the file, even when a mutator returns a lower one. This is case I and threat T-2.6-08.
- The frame-run counts never go negative. An undo with nothing undoable, or a redo with nothing redoable, leaves the run unchanged.
- Reserved paths are also compared through the real path of their folder. This matters when the file does not exist yet, as with the forest before it is created.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `single`-reach frames-undone from an empty run**
- **Found during:** Task 2
- **Issue:** The plan says literally that frames-undone under `single` "sets undoable 0 and redoable 1". Applied to an empty run, that makes a frame redo reachable when no frame move ever happened, which contradicts the "counts never go negative" behaviour.
- **Fix:** frames-undone and frames-redone are no-ops when the source count is 0. This applies to both reach values.
- **Files modified:** `app/src/renderer/state/undo-target.ts`
- **Verification:** `counts never go negative (reach single|run)` tests
- **Committed in:** `fb76ba1`

**2. [Rule 2 - Missing critical] Symlinked-folder match for a reserved file that does not exist yet**
- **Found during:** Task 3
- **Issue:** The plan asks for `realpathSync.native` only "when the file exists". Plan 04 is likely to reserve `Forest.tree` or `Tapestry.tree` before they exist. On macOS the temp and home folders can sit behind a symlink (for example `/var` resolves to `/private/var`), so the resolved form of the reserved path would not equal the real path of a symlink to the file created later. That is exactly threat T-2.6-09.
- **Fix:** When the file is absent, `realPath()` resolves its folder and joins the basename. This applies both when reserving and when checking.
- **Files modified:** `app/src/main/trees/registry.ts` and `registry.test.ts` (new test: "refuses a path reached through a symlinked folder, even when reserved before the file exists")
- **Committed in:** `639cd51`

**3. [Project rule] TDD tests and implementation committed together**
- **Found during:** Tasks 2 and 3 (both `tdd="true"`)
- **Issue:** The TDD reference calls for a separate RED `test(...)` commit. The project rule for this run is that the suite must be green before every commit that touches `app/`.
- **Fix:** RED was observed locally before implementing. Task 2 failed with "Failed to load url ./frame-moves" and "Failed to load url ./undo-target". Task 3 had 7 of 9 new tests failing. The tests and the implementation then went into one `feat` commit per task.
