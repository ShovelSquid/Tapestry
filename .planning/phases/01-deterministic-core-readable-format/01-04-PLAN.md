## Phase Goal

> The world's content, relationships, changes, and history live in a durable `.tree` journal a person can read without Tapestry — and unknown plugin data stays readable and safe

**Mode:** mvp — expansion slice 2 on the tracer: crash-safety (TREE-03) proven by exhaustive failure injection, plus explicit repair and byte-identical save-as.

<objective>
Prove and complete the durability story: an injectable sink records write/sync order and can fail or truncate mid-record; exhaustive prefix-truncation and single-byte-corruption sweeps show open() never accepts a partial or damaged record and never loses a complete one; torn journals refuse appends until an explicit `repair()` preserves the tail in a sidecar and truncates; a second opener is locked out; `saveAs` copies the verified prefix byte-identically.

Purpose: TREE-03 is the promise that a crash mid-save costs at most the unacknowledged commit and never silently rewrites history. These tests run in milliseconds and need no kernel-level crash simulation (RESEARCH "Validation Architecture").
Output: `kernel_tests/journal_test.cpp`; `Journal::repair`, `Journal::saveAs`, `Sink::truncate`; `Kernel::repair`, `Kernel::saveAs`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Kernel → OS filesystem | Reordered/partial writes, non-durable fsync, torn sectors |
| Two processes → one journal | Concurrent writers |
| journal path → sidecar path | Sidecar naming must not be influenced by file content |
