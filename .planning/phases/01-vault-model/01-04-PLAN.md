<objective>
Make `Store` the one serialized writer for every vault change this milestone needs, safe against symlinks, path tricks, permission loss and concurrent outside edits, and record every note, link and card event in the journal. Add content-hash classification so the watcher (plan 05) can tell the app's own writes from outside edits.

Decisions honored: D-04 (layout is written only when a caller issues `SetLayout`; the Store never writes on its own or per frame, so Phase 3 writes on drag/resize release), D-05 (`SetFolderWorld` stores a moved folder's `world-x`, `world-y`, `world-scale` in `Folder/Folder.md`, creating it if missing), D-06 (`AddLink` writes `[[Note#^id|description]]` across folders with the `^id` anchor on the target block), D-07 (`AddLink` requires the user's description and writes nothing at all when it is empty or invalid), D-08 (anchoring is its own explicit command, `InsertAnchor`/`AddLink`, so Phase 4 can add the prompting line's `^id` only on keep or idle; the Store never edits a note without a command), D-10 (`created:` plus a journal entry for every create, link and card event, and `note_estimated` for pre-existing notes, feed the growth replay).

Purpose: VAULT-05 and the writer half of VAULT-06; LINK-02 and LINK-03 end to end on disk.
Output: complete `store.rs` and `journal.rs`, store integration tests.
</objective>
