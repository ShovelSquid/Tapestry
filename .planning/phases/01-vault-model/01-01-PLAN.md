  <behavior>
    All inputs are Rust string literals in tests/frontmatter.rs (never fixture files: editors and git can normalise CRLF and BOM). Every successful splice is also checked by a helper that re-parses the output with yaml_serde and asserts the patched keys hold the patched values and every non-app key's Value equals the original.
    - CRLF + comment + block list + existing x: in `---\r\ntitle: A # keep\r\ntags:\r\n  - a\r\nx: 10\r\n---\r\nBody\r\n`, set x 12.5 and y 40, out `---\r\ntitle: A # keep\r\ntags:\r\n  - a\r\nx: 12.5\r\ny: 40\r\n---\r\nBody\r\n`
    - No frontmatter (world/notes style): `# Heading\nI think about a note\n` with x 0, y 0, w 230, h 150 gives `---\nx: 0\ny: 0\nw: 230\nh: 150\n---\n# Heading\nI think about a note\n`
    - BOM with frontmatter: `\u{FEFF}---\nx: 1\n---\nb` set x 2 gives `\u{FEFF}---\nx: 2\n---\nb`; BOM without frontmatter: `\u{FEFF}# T\n` set x 0, y 0 gives `\u{FEFF}---\nx: 0\ny: 0\n---\n# T\n`
    - Empty frontmatter `---\n---\nbody` set x 5 gives `---\nx: 5\n---\nbody`; comment-only frontmatter `---\n# c\n---\n` set x 5 gives `---\n# c\nx: 5\n---\n`
    - No trailing newline: `---\nx: 1\n---\nbody` set x 3 gives `---\nx: 3\n---\nbody`
    - A `---` horizontal rule in a body with no frontmatter (`Intro\n\n---\n\nmore\n`) is not frontmatter: set x 1 prepends a block and the body is byte-identical
    - Trailing comment kept: `---\nx: 10 # left edge\n---\n` set x 12 gives `---\nx: 12 # left edge\n---\n`; null value `---\nx:\n---\n` set x 5 gives `---\nx: 5\n---\n`
    - Unknown keys, their order, lists, quoted strings and a nested block scalar whose indented line reads `  x: 5` stay identical; missing keys are inserted before the closing line in the order x, y, w, h, world-x, world-y, world-scale; world keys splice the same way (`world-x: 10` parses)
    - No-op: `---\nx: 10.0\ny: 20\n---\n` set x 10, y 20 returns `Ok(None)`
    - format_num: 12.345 gives `12.3`; 120.0 gives `120`; -12.5 gives `-12.5`; -0.04 gives `0`; 1e21 gives digits only (no exponent); NaN or infinity in a patch gives `Err(NonFinite(key))`
