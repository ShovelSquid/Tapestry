<assumption_delta_decision>
Detector fired (pluralization: "fallback"): the watcher and the fallback rescan are two sources of "a note may have changed".
- Primary noun: the content hash of a vault-relative note path, held by `Store` (`known` and `own_writes` tables, `Store::classify`).
- Decision: promote. Hash classification is the single identity of change; FSEvents events and the stat-diff rescan are both demoted to producers of candidate rel paths that feed `Store::classify`. Neither event kinds nor mtimes decide anything (macOS replays history and coalesces kinds, research probe 2).
- Consequence: a third source later (git hook, Obsidian plugin) only has to produce rel paths; no new identity model is needed.
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS file events to watcher | FSEvents paths and kinds are untrusted (replayed history, coalesced kinds, canonical vs symlinked paths) |
| any folder to vault-check | vault-check may be pointed at any directory, including real user vaults |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-23 | Tampering (integrity) | watch.rs + Store::classify | medium | mitigate | Own writes recognised by content hash set before rename, so an echo never triggers a reload that could clobber an editor buffer; tested live (Task 1) |
| T-1-24 | Elevation of privilege / DoS | watch.rs debouncer cache | medium | mitigate | `NoCache` instead of the default file-id cache, which walks the tree following symlinks at watch time |
