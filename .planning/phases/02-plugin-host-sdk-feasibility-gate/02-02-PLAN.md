  <action>
Wire the Electron app on top of Plan 01's native addon and kernel bridge so a user can double-click the canvas, type into a ProseMirror note, and see it persisted.

MAIN PROCESS (app/src/main/index.ts): Create BrowserWindow with nodeIntegration false, contextIsolation true, preload pointing to the preload script. On app ready, load the renderer. Store the window reference. Handle app activate (macOS) and window-all-closed. Register IPC handlers by calling KernelBridge.registerHandlers(ipcMain) and PluginHost.registerHandlers(ipcMain).

PLUGIN HOST (app/src/main/plugin-host.ts): On startup, scan the plugins/ directory for subdirectories containing tapestry.plugin.json. Parse each manifest. For each plugin, load its main entry (the "main" field from the manifest) using require or dynamic import. Call the plugin's activate function, passing a PluginContext that includes a reference to the kernel API (submit, getNodes, etc.) and a registerNodeView callback. Store active plugins in a Map keyed by plugin name. Expose IPC handler plugin:list returning the loaded plugin names and their contributions. For this tracer, the note plugin's registerNodeView callback stores a mapping from node type to the React component name that renders it; the renderer queries this mapping.

PRELOAD (app/src/preload/index.ts): Use contextBridge.exposeInMainWorld to expose a tapestry object with kernel (create, open, submit, getNodes, getNode, getEdges, status — each wrapping ipcRenderer.invoke) and plugins (list — wrapping ipcRenderer.invoke for plugin:list). Declare the window.tapestry type in a global.d.ts or ambient declaration.

TSCONFIG WEB (app/tsconfig.web.json): TypeScript config for the renderer targeting DOM + ESNext, with JSX support for React.

NOTE PLUGIN (plugins/tapestry-notes/): tapestry.plugin.json manifest with name "tapestry-notes", version "1", displayName "Notes", main "index.ts", api "1", contributions.nodeTypes ["tapestry.notes/note@1"]. The index.ts file exports a TapestryPlugin that in activate() registers the note schema and a nodeView for tapestry.notes/note@1. The plugin does not import Electron or Node APIs — only the SDK types.

RENDERER (app/src/renderer/): index.html with a root div. main.tsx rendering the React App into the root. App.tsx renders a full-window canvas (per D-05 layout from the brief). It calls window.tapestry.kernel.getNodes() on mount to load existing nodes and renders each as a NoteCard positioned absolutely at the node's position.x and position.y properties. The canvas background uses the dominant color #F7F5F0 from the UI-SPEC. Double-clicking empty canvas space (per D-04) calls kernel.submit to create a tapestry.notes/note@1 node with position.x and position.y set to the click coordinates, then immediately enters editing mode on the new card. Escape or clicking outside the card ends editing without discarding text (per D-04).

NOTE CARD (app/src/renderer/components/NoteCard.tsx): A React component that renders a white card (secondary color #FFFFFF, border #E0DDD7, shadow per UI-SPEC) at the note's position. Inside the card, mount a ProseMirror EditorView with prosemirror-schema-basic schema (doc, paragraph, text, bold, italic, heading marks). The editor is initialized with content from the node's body text property. On every ProseMirror transaction that changes the doc, serialize the doc to plain text and call kernel.submit with a SetProperty op setting the body property. Also update the title property from the first line or heading. The card shows the note title in the heading style (22px/600 from UI-SPEC) above the editor.

Per D-04: Enter inserts a newline (ProseMirror default). The card receives focus immediately after creation. Clicking text moves the caret. The note is keyboard-first with minimal chrome.

AUTOSAVE (D-02): In kernel-bridge.ts, after every successful submit, the .tree file is already written by the kernel (Journal::append writes and syncs). Saving is inherent in the kernel's submit path — every SetProperty, CreateNode, etc. is already durable after submit returns. In the renderer, add a save-state indicator component beside the file/project name in the top-left corner. The indicator shows three states: "Saved" (neutral color, 13px/400 label), "Saving..." (neutral, 13px/400), "Not saved" (destructive #E5484D, 13px/400). The renderer tracks whether a submit is in-flight (Saving) and whether the last submit succeeded (Saved) or failed (Not saved). Never imply unsaved text was saved — if a submit call rejects or the IPC fails, show "Not saved" immediately. Add debounce logic in the NoteCard component: buffer ProseMirror transactions and submit a SetProperty op after 300ms of inactivity (not on every keystroke). While the debounce timer is active, the indicator shows "Saving..." so the user knows text is pending.

SAVE INDICATOR COMPONENT (SaveIndicator.tsx): A small React component positioned in the top-left corner beside the file name. It receives the current file path and save state as props. The file name is displayed with truncation at 200px max width and an ellipsis, with the full name in a title tooltip (backstop from UI-SPEC). The save state text sits immediately after the file name.

REOPEN LAST FILE (D-03): In the main process, on app ready, check electron.app.getPath("userData") for a last-opened.json file containing the path of the last .tree file. If it exists and the file is accessible, open it via kernel:open. On every successful kernel:create or kernel:open, write the path to last-opened.json. If the last file is missing or unreadable on launch, show the empty canvas with the empty-state hint text: heading "Double-click anywhere to start", body "Create notes, connect ideas, and build your world of thought." (from UI-SPEC copywriting contract). In the preload, expose a kernel:getFilePath handler returning the current file path for the save indicator.

EMPTY STATE: When no file is open (first launch or last file unavailable), the canvas shows the centered empty-state text using the UI-SPEC typography (heading 22px/600, body 16px/400). Double-clicking still creates a new .tree file (prompt the user for a save location using Electron dialog.showSaveDialog with a .tree filter, then call kernel:create).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer to Main | IPC messages cross the contextBridge; renderer has no direct Node.js access |
| Plugin to Host | Plugin JS/TS code executes and calls the SDK API |
| Filesystem to App | .tree files and plugin manifests are read from disk |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-02 | Tampering | Plugin direct file access | high | mitigate | Plugins receive only the KernelAPI (submit/getNodes); no file handles or journal access exposed. All mutations go through Kernel::submit which validates and records (D-31, PLUG-06). |
| T-02-03 | Elevation of Privilege | Renderer Node.js access | critical | mitigate | nodeIntegration: false, contextIsolation: true, sandbox: true in BrowserWindow webPreferences. All kernel access goes through the contextBridge preload. |
| T-02-04 | Spoofing | Plugin identity | low | accept | Plugin identity derived from its directory name and manifest; user's trust decision per D-31. |
| T-02-05 | Information Disclosure | Cross-plugin data | medium | accept | Single-process Electron model; user trusts installed plugins per D-31. Plugin isolation is not a Phase 2 requirement. |
</threat_model>
