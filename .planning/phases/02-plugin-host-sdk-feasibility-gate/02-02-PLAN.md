  <action>
CANVAS COMPONENT (Canvas.tsx): Extract the canvas rendering from App.tsx into a dedicated Canvas component. The canvas manages a view transform with panX, panY, and zoom state. Implement pan by tracking mousedown on empty canvas space (not on a note) and mousemove to update panX/panY. Implement zoom via wheel event, scaling around the pointer position. Apply the view transform using a CSS transform: translate(panX, panY) scale(zoom) on a container div inside the canvas viewport. Notes are positioned inside the transformed container at their world-space coordinates using absolute positioning with left/top set to position.x and position.y.

World-to-screen and screen-to-world coordinate conversion functions: screenToWorld(screenX, screenY, panX, panY, zoom) returns {x, y} in world space. worldToScreen(worldX, worldY, panX, panY, zoom) returns screen coordinates. These are used for placing new notes from double-click (converting screen click to world position) and for rendering connections.

DRAG TO REPOSITION (D-01): In NoteCard, add mousedown handler on the card header/border area that starts a drag. During drag (mousemove on the document), compute the world-space delta from the mouse movement divided by the current zoom level, and update the note's position.x and position.y. On mouseup, submit a SetProperty op through the kernel bridge to persist the new position. During drag, update the card's position locally for immediate visual feedback before the kernel confirms. Position values use real type in the kernel (position.x real 12.5 format in the .tree file).

The drag must not interfere with text editing: mousedown on the note body text area starts text selection, not dragging. Only mousedown on the card border, header area, or a non-editable area initiates drag.

CONNECTION DISPLAY (ConnectionLine.tsx): Render edges as SVG lines in a layer above the canvas but below the notes. For each edge returned by kernel.getEdges(), draw a line from the center of the source note to the center of the target note. Lines use the warm gray color #B0ADA6 for default state (UI-SPEC thread line default). The SVG overlay sits in the transformed container alongside the notes so connections pan and zoom with the canvas.

Update App.tsx to use the Canvas component, passing notes and edges as props. The Canvas component renders NoteCards and ConnectionLines. Add a kernel:getEdges IPC handler in kernel-bridge.ts if not already present, and expose it through the preload.

NOTE CONTROLS (NoteControls.tsx per D-06): Create a component that renders small bubbly round controls around a note's edges. Two mandatory controls: (1) a connection handle — circular, 28px diameter, filled with accent color #4A7CFF, containing a link/connection icon glyph, scales to 32px on hover. (2) a red delete bubble — circular, 28px diameter, filled with destructive #E5484D, containing an X or trash icon glyph, scales to 32px on hover. Position the controls just outside the note's border. Use CSS transitions for the scale animation.

Controls appear when the note is hovered OR selected, and remain hidden when the note is neither hovered nor selected. The controls must remain reachable while moving the pointer from the note body to the controls (D-06): do not use a tight hover boundary that collapses when the pointer leaves the card body. Instead, extend the hover detection zone around the note to encompass the control positions, or use a short delay before hiding. The note card and its controls form one logical hover group.

HOVER FOCUS VS TEXT FOCUS (D-07): Hovering a note reveals controls without moving the caret or losing the existing text selection in any note. Clicking text moves the caret (ProseMirror handles this). Clicking a control executes its action and preserves the text selection if relevant. Implement this by separating hover state (which note the pointer is over) from focus state (which note has the ProseMirror editor focused). The Canvas component tracks hoveredNoteId and focusedNoteId as separate state values.

BORDER SELECT (D-08): Clicking a note's border (not its text content) selects the whole note. A selected note shows an accent #4A7CFF border (2px) and an elevated shadow (0 2px 8px rgba(0,0,0,0.10)) per UI-SPEC. The selected state is distinct from the editing state. Selecting a note does not enter edit mode — double-clicking or clicking inside the text content enters edit mode.

RESIZE (D-08): Dragging the edges or corners of a selected note resizes it. Text reflows within the new dimensions. Implement using resize handles (small squares at corners and midpoints of edges) that appear on selection. Track the note's width as a property. The minimum note width is 120px. On resize completion, submit a SetProperty for the width (height is determined by content reflow).

CONNECTION CREATION: When the user clicks the connection handle on a note, the canvas enters "connecting" mode. A temporary line follows the pointer from the source note's center. When the pointer is released over another note, submit a CreateEdge op through the kernel bridge with the source and target node ids and the label "link". If released over empty space, cancel the connection. Provide visual feedback during connecting mode: the temporary line uses the accent color #4A7CFF and the target note highlights on hover. The connection handle's click handler must not interfere with text selection (D-07).

DELETE BUBBLE: Clicking the red delete bubble will eventually delete the note (Plan 04 implements deletion/undo per D-20/D-21/D-22). For this plan, clicking the delete bubble shows a console warning that deletion is not yet implemented. The bubble is visually present to prove the control system works.
