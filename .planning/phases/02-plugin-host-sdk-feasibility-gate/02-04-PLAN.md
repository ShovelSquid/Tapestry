CONTENT VS STRUCTURE DELETION (D-20): Implement the universal rule: clearing content preserves the container and its connections; deleting the container removes it and cuts attached connections.

For notes: clearing all text from the ProseMirror editor (selecting all and pressing Delete) results in an empty note card that remains on the canvas with its position and any attached connection edges intact. The note still has its node in the kernel world with an empty body property. This is just a SetProperty with an empty text value — the kernel already handles it.

Deleting the note structure means submitting a DeleteNode op through the kernel. The kernel's World::apply for DeleteNode cascades to all edges touching the node (from Plan 01-03: delete-node cascades to touching edges). After the delete, the note card and all its connection lines disappear from the canvas. Notes at the other end of those connections remain.

DELETE BUBBLE AND KEYBOARD (D-21): The red delete bubble (from Plan 02) now submits a DeleteNode op for the note it belongs to. When the user clicks the delete bubble, submit a Proposal with a DeleteNode op and refresh the canvas to remove the card and its connections.

For keyboard deletion: maintain a selectedNoteId state in the Canvas. When a note is selected (border-clicked, not text-editing) and the user presses Delete or Backspace, submit a DeleteNode for that note. When the ProseMirror editor has focus (the user is editing text with a caret or selection), Delete and Backspace keys are handled by ProseMirror for text editing — they do not delete the note structure. This distinction comes from checking whether the ProseMirror editor has focus: if it does, keydown events go to ProseMirror; if the note is selected but the editor is not focused, keydown events go to the canvas handler.

To avoid accidental deletion while typing: only handle Delete/Backspace at the canvas level when the canvas or a note border has focus, not when a ProseMirror editor has focus.

UNDO/REDO (D-22): Implement undo/redo as navigation through the kernel's commit history. Each user action (create note, set property, delete node, create edge) is a separate commit in the .tree journal. Undo means reverting the world to the state before the last commit; redo means re-applying it.

In the kernel bridge, add kernel:undo and kernel:redo IPC handlers. The undo implementation: read the journal's commits, replay from the beginning up to (lastSeq - 1), and update the in-memory world accordingly. Store the "undone" commits so redo can replay them.

Implementation approach: maintain an undoStack (list of CommitSeq values that have been undone) in the kernel bridge. Undo: save the current lastSeq to the undo stack, call a method on the native addon that rebuilds the world from the journal up to (lastSeq - 1). Redo: pop from the undo stack and rebuild up to that seq. The addon needs a replayUpTo(seq) method that opens the same journal bytes and replays commits up to the given seq.

The undo stack is cleared whenever a new commit is made (a new edit after undoing forks from that point — full branching is Phase 3, so for now a new edit after undo discards the redo stack).

Undo must coexist with autosave (D-22): the .tree journal is append-only, so undone commits are still in the file. Undo only changes the in-memory world state, not the file. A new commit after undo appends as the next seq in the journal. This means the file grows monotonically and the undo history is embedded in the commit sequence — no evidence is erased.

Register Cmd/Ctrl+Z for undo and Cmd/Ctrl+Shift+Z for redo at the window level. These shortcuts take precedence over ProseMirror's built-in undo (which operates on text-level changes within a single note). For the feasibility gate, world-level undo (reverting entire commits) is the primary undo; ProseMirror's text-level undo is secondary and works within a single editing session before a submit. The interaction: ProseMirror's undo handles intra-note text changes that haven't been submitted yet; world-level undo handles committed changes.

Expose kernel:undo and kernel:redo through the preload contextBridge.
