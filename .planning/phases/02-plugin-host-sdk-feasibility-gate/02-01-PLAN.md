  <action>
Wire ONE path: the C++ kernel compiles as a Node native addon, the TypeScript bridge loads it and can create a world, submit an op, and read back the result.

ROOT WORKSPACE SETUP: Create package.json at the workspace root with "private": true and "workspaces" listing app, sdk, and plugins/*. This enables npm workspace linking so plugins can import the SDK.

NATIVE ADDON (app/native/): Create CMakeLists.txt that finds node-addon-api include dirs (via cmake-js), adds the tapestry kernel source directory as a subdirectory (the existing tapestry/CMakeLists.txt with TAPESTRY_BUILD_RENDER=OFF, TAPESTRY_BUILD_APP=OFF, TAPESTRY_BUILD_TESTS=OFF), and builds a shared library tapestry_addon linking tapestry_kernel and node-addon-api. The addon.cpp file wraps tapestry::kernel::Kernel in a Napi::ObjectWrap with these methods: static create(path, worldName) returning a new wrapper, static open(path) returning a wrapper, submit(actorKind, actorId, message, ops) where ops is a JS array of operation objects that the binding converts to std::vector of tapestry::kernel::Op, getNodes() returning an array of {id, type, props} objects, getNode(id) returning a single node object, getEdges() returning an array of {id, from, to, label, props}, status() returning the journal status. Each Op object from JS has a field "op" naming the verb (createNode, setProperty, etc.) and the verb-specific fields. The binding constructs the C++ Op variant from these. Actor comes from separate actorKind/actorId string arguments. Submit returns {seq, digest, nodeIds, edgeIds}. Value conversion: JS string to Value::ofText, JS number to Value::ofInt (if integer) or Value::ofReal, JS boolean to Value::ofBool. Property maps returned as plain JS objects with typed values.

ELECTRON BUILD CONFIG (app/): Configure electron-vite with three entries: main (app/src/main/index.ts), preload (app/src/preload/index.ts), renderer (app/src/renderer/). app/package.json lists electron, electron-vite, vite, react, react-dom, the six prosemirror packages, cmake-js, and node-addon-api as dependencies or devDependencies. Add scripts: "build:native" running cmake-js build --directory native with the appropriate cmake flags to disable render/app/tests on the kernel, "dev" running electron-vite dev, "build" running npm run build:native then electron-vite build, "typecheck" running tsc --noEmit. Add a postinstall script that runs npm run build:native so the addon is compiled after npm install.

TypeScript configs: app/tsconfig.json as the base, app/tsconfig.node.json for main/preload (targeting Node.js), both configured for the electron-vite project structure. The web tsconfig is deferred to Plan 02.

KERNEL BRIDGE (app/src/main/kernel-bridge.ts): Load the native addon via require with the built .node file path. Export a KernelBridge class that holds the addon wrapper instance and exposes IPC handler registration: kernel:create (path, worldName), kernel:open (path), kernel:submit (actorKind, actorId, message, ops), kernel:getNodes, kernel:getNode (id), kernel:getEdges, kernel:status. Each handler delegates to the corresponding addon method. The bridge holds a single kernel instance (one world open at a time). Export a static registerHandlers(ipcMain) method that Plan 02 will call from the main process.

SDK (sdk/src/index.ts): Export TypeScript interfaces: TapestryPlugin with name, version, activate(context: PluginContext), deactivate(). PluginContext with kernel: KernelAPI and registerNodeView(nodeType: string, component: string). KernelAPI with submit, getNodes, getNode, getEdges, status methods matching the IPC surface. NodeSchema with type (string in dotted-path/name@version format), displayName, defaultProperties (Record of string to ValueType). PluginManifest with name, version, displayName, main, api, contributions (nodeTypes string array, commands string array). ValueType enum matching the kernel's text, int, real, bool, ref, time.

Verify the kernel tests still pass after the native addon build to confirm no kernel regression.
