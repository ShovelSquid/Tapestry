# Phase 2.3: Time Threads - Context

**Gathered:** 2026-09-15
**Status:** Ready for planning

<domain>
## Phase Boundary

A **thread** is a new node type: one central, growing document (a full Tapestry note) together with its complete writing history. While someone writes in the note typer, the thread is drawn live along the z-axis: dots stream at 60 per second and each letter sits at the moment it was typed. Afterwards the thread is read back in a left-to-right side view, where session notes, dashes for time-out and time-in, and letters (including deleted ones) show how the document came to be. A user can share a thread with an agent, with each author's letters kept visibly distinct.

This phase also renames Phase 2.1's connection-with-a-centre-note from `thread-center` / `thread-arm` to `knot` / `knot-tie` (D-26), because the name "thread" now belongs to time threads (02.2 D-02).

**Proposed success criteria** (the ROADMAP entry reads "TBD in discuss"; the planner should adopt or refine these):
1. User can create a thread, write in the note typer, and watch the live z-axis line gain dots and letters at display rate, with the pause slowdown and a time-out dash (D-09..D-14)
2. Closing and reopening the world redraws the same line from saved keystrokes and sessions alone, with no stored dots, and a person can read the typed text, deletions and timings in the `.tree` file (D-06)
3. In the side view, user can zoom from the whole thread down to single dots, fly to session notes, scrub by date, and click any point to see the document as it was then (D-15..D-19)
4. An agent writing into a shared thread appears as its own coloured strand, cannot delete the user's letters, and its text can be pulled apart for display (D-20..D-23)
5. No `thread-center` / `thread-arm` names remain in code; 2.1's feature works as `knot` / `knot-tie` (D-26)

**Not in this phase:** writing from an earlier stage, which branches the thread (Phase 3); detaching an agent's strand into its own note; deleting or pruning history to shrink files; navigation gravity on the 2D canvas (Phase 4).

</domain>

<decisions>
## Implementation Decisions

### What a thread is and what it saves
- **D-01:** A thread is **one central growing document**. The line shows when each letter arrived. Session notes (D-07) are stages of this same document, not separate documents. Kaelen's words: "It's a central one growing document, with the line showing when each letter arrived."
- **D-02:** The thread's document is a **full note**, with the same editor, schema, formatting toolbar, passage links and connections as every note (Phase 2 D-26 universal editing). Making a link or applying formatting drops a small marker on the line at that moment. This is how the thread "drops its links/updates" onto the line.
- **D-03:** **Nothing on the line is erased.** A deleted letter stays at the moment it was typed, drawn faded or struck through, and a small mark shows the moment it was deleted.
- **D-04:** **Undo is an ordinary edit.** Cmd+Z removes text from the document as usual. On the line it looks like a deletion (letters stay faded) with an undo mark at that moment.
- **D-05:** **Paste lands at one moment:** a tight cluster at the paste time with a paste marker. It is never spread out to look typed.
- **D-06:** **In `.tree`, small commits as you type.** Like today's autosave (about ⅓ s of typing, Phase 2 D-02), each commit lists the letters typed and deleted, each with its time offset, readable in a text editor. Persistent data is keystrokes and sessions, never dots (spike 001). Dots, dashes and positions are redrawn from time × speed, consistent with Phase 3's rule that continuous values regenerate from recorded inputs. A crash loses at most a moment. — **Reversibility:** one-way — the keystroke record shape is written into append-only journals, so every saved thread keeps the first format forever. `tapestry/docs/tree/FORMAT.md` and its golden `example.tree` must change in the same commit.
- **D-07:** **A session runs from a time-in to a time-out** (D-10). Each return after a time-out drops a new session note on the line. On the 2D canvas, a thread looks like **a bridge of session notes** joined by the drawn line. Kaelen called it "a session log so that you can easily revert and head back to previous document stages".
- **D-08:** **Viewing past stages is in 2.3; branching is in Phase 3.** Clicking a session note or letter shows the document as it was at that moment, read-only, and text can be copied from it. Writing from an earlier stage, which branches the thread and keeps the original, arrives with Phase 3's world branching, so threads and worlds branch the same way.

### Live writing view
- **D-09:** **Typer on top, line into depth.** Clicking a thread opens the note typer as a text window at the top. Below it the line streams away from the viewer into the distance. The canvas dims behind.
- **D-10:** **Time-out is adjustable per thread and defaults to 2.5 minutes**, matching Apple Messages' timestamp spacing.
- **D-11:** **Pause slowdown.** While the typer is open and typing stops, dots keep streaming at 60/s, then slow: about 30/s after roughly 10 s, about 10/s at roughly 30 s, and 1/s after a minute. The rate holds at 1/s until the time-out, which draws a dash, and the line stops until typing resumes (time-in dash). The numbers are Kaelen's rough defaults.
- **D-12:** **The line travels at constant speed during pauses; only the dots get sparser.** Distance along the line always equals elapsed writing time.
- **D-13:** **The slowdown curve is adjustable per thread**, like the time-out, with D-11's values as defaults. Dot rates follow real seconds, not the display's refresh rate, so a 120 Hz display draws the same line.
- **D-14:** **The live view fades by distance only.** Nothing is hidden on purpose; older writing gets smaller and dimmer with depth.

### Side view read-back
- **D-15:** **The line follows writing time.** Letters and session notes sit where they were written, matching the live line exactly. A session's "when it happened" date, if given, shows as a label on its session note. The line is never reshuffled.
- **D-16:** **Gaps between sessions keep their true length, drawn dim.** The line stays honest about time, even across weeks.
- **D-17:** **Navigation.** Zoom from the whole thread to single dots, pan, click a session note to fly to it, and drag through any day on a thin date scrubber bar along the bottom. The timeline itself never changes. **Gravity** pulls the view toward a note only when hovering near it, more strongly for bigger notes; there is no pull while moving freely. Kaelen: "It's like space, huge gaps broken up with small planets, but the gravity is enough to easily be able to navigate between them."
- **D-18:** **Clicking any point shows the document at that moment** in the text window above: read-only, with that letter highlighted. Scrubbing along the line shows the document changing (see D-08).
- **D-19:** **Letters stay sharp at any zoom.** Before building, run a small spike: SDF or MSDF glyphs inside the same instanced-quad, single-draw-call design as spike 002b. Canvas-atlas letters blur above about 48 px.

### Agents writing in a thread
- **D-20:** **Agent text lands when it arrived.** A whole write is one tight cluster, like a paste; streamed text spreads out as it streams. It is never replayed as fake typing.
- **D-21:** **Two strands twisted together.** Each author has their own coloured strand; they run side by side and twist into one where both write in the same stretch. In the document, each letter carries its author's colour at least as an underlay beneath the font colour, and hovering shows the actor id (for example `agent.claude`). — **Reversibility:** costly — per-letter actor attribution becomes part of the keystroke record shape (D-06).
- **D-22:** **Agents add anywhere but delete or rewrite only their own letters.** This extends 02.2 D-05 (agents edit only what they wrote) down to single letters.
- **D-23:** **Dragging a strand apart is for display in 2.3.** Dragging the agent's strand out shows each author's text on its own and leaves the document unchanged; letting go twists it back. Detaching agent text into its own note is deferred.
- **D-24:** **Agents can start threads**, but each must grow from an existing note and be connected to it (02.2 D-04). Agent threads are never loose.

### Threads in an Obsidian vault
- **D-25:** **A vault thread's `.md` holds only the current text**, so Obsidian sees a normal note. Keystroke timings, sessions, deleted letters and author strands are stored as Tapestry's additions in the vault tree (02.2 D-14). An edit made in Obsidian arrives on the line as one observed cluster, like a paste, attributed per 02.2 D-21.

### 2.1 rename
- **D-26:** **Rename 2.1's `thread-center` to `knot` and `thread-arm` to `knot-tie`.** The centre note is the knot, and its two lines are ties. The rename covers node and edge type names, `ThreadCenterNode` and its CSS classes, `Canvas.tsx`'s `isThreadCenter` and `'thread-arm'` label checks, and editor comments. — **Reversibility:** reversible now — no saved world contains these types (`~/Documents/we.tree` has none, and nothing in the app creates them yet). It becomes costly once worlds are written with the new names.

### Thread orientation (added 2026-09-15, after the main discussion)
- **D-27:** **A thread stores its own frame; the cursor that sets it ships later.** Each thread records `origin.x/y/z`, `direction.x/y/z` (a unit vector) and `roll` (degrees) as ordinary readable properties, defaulting to the ThreadCard's canvas position at z 0, `0 0 -1` (today's fixed axis) and `0`. The live view's camera sits at the now-head aimed along `direction`; the side view aims perpendicular to it — both **derived from the stored frame, never hardcoded**. With every thread at the default, 2.3 renders exactly as the UI-SPEC describes, so this carries no visual risk. Forward-vector-plus-roll is required over a quaternion because `0 0 -1` is readable in the `.tree` file and four quaternion reals are not (project readability constraint). Kaelen's decision: ship 2.3 on the default axis, but store the field now so the later phase builds only the cursor, not a renderer, side-view and scrubber rewrite. — **Reversibility:** reversible now (no saved world has threads); costly once threads exist.

### Claude's Discretion
- The exact `.tree` syntax for keystroke, session and marker records within D-06, which must stay readable without Tapestry and keep FORMAT.md in step. The same applies to the commit interval, as long as it stays close to the existing autosave.
- How times are encoded (hour blocks plus offsets, as spike 001 requires), and the floating render origin.
- Visual design of markers (link, format, paste, undo, deletion), author colours, and session-note geometry on the 2D canvas.
- The dynamic glyph atlas for emoji and non-Latin scripts, grapheme-aware keystroke records, and the SDF/MSDF generator choice for D-19.
- The gravity strength curve and hover radius within D-17.

### Open for research and planning to propose (not discussed; bring back to Kaelen if users would see the choice)
- What happens when a person and an agent type into the same thread at the same moment: ordering, cursor collisions, and how the two strands twist.
- How a thread is started: a new-thread gesture, turning an existing note into a thread, or both.
- How the 02.2 MCP tools address a thread (append, insert at position, stream), within D-20 and D-22.
- Where per-thread settings live (D-10, D-13), and whether they are recorded in history.

</decisions>

### Reusable Assets
- `app/src/renderer/editor/schema.ts` and `editor/use-prosemirror.ts`: the shared ProseMirror schema and hook used by NoteCard and the centre node. The thread typer should reuse them (D-02). ProseMirror transactions are a natural source of per-keystroke steps with times.
- `app/src/renderer/components/NoteCard.tsx`: the 300 ms debounced autosave through `window.tapestry.kernel.submit` (App.tsx save callbacks). This is the pattern D-06's small commits extend.
- `app/src/renderer/components/FloatingToolbar.tsx`: formatting controls whose actions become line markers (D-02).
- `.planning/spikes/001-thread-stream-load/thread.js` and `002b-glyphs-canvas-atlas/glyphs.js`: working procedural ribbon and instanced glyph code to port. three.js is not yet an app dependency (only in `.planning/spikes/package.json`).

### Established Patterns
- All durable writes go through `Kernel::submit` with an actor; commits are append-only with a SHA-256 chain (Phase 1). Deleted letters and undo (D-03, D-04) fit naturally.
- Unknown plugin node types and properties stay readable with fallbacks. A thread opened without the thread plugin must still show its document text.
- Save indicator: "Saving…" while a debounce timer or IPC call is pending, and never "Saved" early (App.tsx header comment).

### Integration Points
- Rename (D-26): `components/ThreadCenterNode.tsx`, `components/TreeFrame.tsx` (`isThreadCenter`, `threadCenterAuto`, `'thread-arm'` edge labels; ~L32, ~L298–329, ~L387–436 @8c4e219; 2.2 moved these out of `components/Canvas.tsx`), `App.css` `.thread-center-*` classes, and comments in `editor/schema.ts`, `editor/use-prosemirror.ts` and `FloatingToolbar.tsx`. <specifics>
## Specific Ideas

- Kaelen's original description: "every input is registered on that tapestry thread z axis, storing each letter in space and updating it when you write. it looks like a different way to write, and will affect your reading and writing performance."
- The time-out default follows the Apple Messages timestamp spacing (2.5 minutes).
- Side-view navigation as space: "huge gaps broken up with small planets, but the gravity is enough to easily be able to navigate between them."
- A thread on the canvas is "a bridge of notes for different context sessions … it should be those notes on the timeline, with the line drawing it and connecting them."
- Author colour is "at least underneath the color of the actual font", so provenance stays visible even when text is formatted.

</specifics>

<deferred>
## Deferred Ideas

- **Branching a thread from an earlier stage** (write from a past session and keep the original): Phase 3 Branching History, together with world branching.
- **Detaching an agent's strand into its own note**, removing that text from the shared document as a recorded edit: a later phase.
- **Truly deleting notes and folders, or pruning history, so `.tree` files don't grow with things that don't matter** (Kaelen, this discussion). This conflicts with the append-only journal (Phase 1; Phase 2 D-31), so it needs its own design, probably alongside Phase 3 snapshots and history.
- **Navigation gravity on the 2D canvas** (beyond the side view): Phase 4 Spatial Notebook.
- **The anchor cursor, and agent bodies made of threads** (Kaelen, 2026-09-15): a 3D cursor — place by snapping to a line, note or view plane, aim at a second point, roll on one ring, then an explicit key to fly the view into that frame — which is how a thread's D-27 orientation gets set by hand. Kaelen chose to give this its own phase after 2.3, together with agents moving as clusters of notes. Background: `~/Tapestry Tales/Connections/Concept - Anchor Cursor.md` and `Concept - Embodied Agents.md`. 2.3 stores the field (D-27) but ships every thread on the default axis and builds no cursor.

</deferred>
