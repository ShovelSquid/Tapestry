# Phase 2.3: Time Threads - Research

**Researched:** 2026-09-15
**Domain:** Readable keystroke history (`.tree` plugin data), ProseMirror step capture and collaborative sequencing, three.js/WebGL overlays in Electron, time-axis navigation
**Confidence:** MEDIUM overall. The kernel/format fit and ProseMirror capture are HIGH, verified against source and probes. WebGL integration is HIGH, carried by spikes 001/002b. The D-19 glyph choice is LOW until spike 003 reports. Agent/concurrency UX is MEDIUM.

## Summary

A time thread needs **no kernel change and no new `.tree` verb**. The kernel's vocabulary is closed at seven verbs and six value types. FORMAT.md states "plugins compose their data from them and never add a verb of their own". `Proposal` has no field for extension lines, so `x-` lines cannot be submitted without a kernel change either. The fit is a **per-commit `set <thread> thread.log text <<TEXT` block** in a small, line-oriented, versioned grammar: one line per recorded ProseMirror step, each with a millisecond offset, the letters inserted, and the text deleted. FORMAT.md already documents the reading rule this relies on: "the history of the value is the sequence of `set` lines". Per-letter authorship (D-21) comes free and cannot be forged. Every commit is stamped with its actor by the main process (02.2 Plan 01), and each commit holds one writer's steps, so a letter's author is the actor of the commit that inserted it. No self-declared actor field appears inside the log.

The capture model to use is **prosemirror-collab's central-authority model**. It is the standard ProseMirror answer, with no hand-rolled sequencing. The renderer typer runs the `collab` plugin and pushes `sendableSteps` with their keystroke times to a main-process `ThreadService`. That service is the authority: it holds the document, its version and a letter index. It sequences human steps and agent writes, enforces D-22 (agents delete only their own letters), and commits batched `thread.log` values on a cadence close to autosave. The cadence is a 300 ms idle flush plus a **max-wait of about 1 s**. Today's debounce never fires during continuous typing. The body (ProseMirror JSON) is written as a **checkpoint**: at session time-out, on typer close, and at most about every 60 s. The fallback view and the Obsidian `.md` therefore stay readable, and the file does not grow by a whole document every third of a second. "Document at time T" is the last checkpoint at or before T plus the replayed steps up to T. Replay order is commit order, and position on the line is recorded time. Those two orders differ, and that is intended.

Rendering ports spike 001's procedural ribbon (sessions and gaps as 4-vertex chunks, dots in the fragment shader, hour-block times, floating origin) and spike 002b's instanced glyph quads into a single lazily-created `three@0.186.0` WebGLRenderer. That renderer is owned by a full-window thread overlay whose DOM typer sits on top. **D-19 is unresolved:** spike 003a (tiny-sdf SDF) and 003b (msdfgen-wasm MSDF) exist in `.planning/spikes/` but are still `PENDING` in MANIFEST.md. The side-view sharpness task must gate on that verdict, and spike 004 (typer over live thread) is also pending.

**Primary recommendation:** Lock the `thread.log` grammar (D-06, one-way) in a tracer plan that ends with Kaelen reading a real `.tree`. Build capture on prosemirror-collab with a main-process authority. Port the spike renderers unchanged in structure. Gate glyph shading on spike 003 and input latency on spike 004.

## User Constraints (from CONTEXT.md)

### Locked Decisions

#### What a thread is and what it saves
- **D-01:** A thread is **one central growing document**. The line shows when each letter arrived. Session notes (D-07) are stages of this same document, not separate documents. Kaelen's words: "It's a central one growing document, with the line showing when each letter arrived."
- **D-02:** The thread's document is a **full note**, with the same editor, schema, formatting toolbar, passage links and connections as every note (Phase 2 D-26 universal editing). Making a link or applying formatting drops a small marker on the line at that moment. This is how the thread "drops its links/updates" onto the line.
- **D-03:** **Nothing on the line is erased.** A deleted letter stays at the moment it was typed, drawn faded or struck through, and a small mark shows the moment it was deleted.
- **D-04:** **Undo is an ordinary edit.** Cmd+Z removes text from the document as usual. On the line it looks like a deletion (letters stay faded) with an undo mark at that moment.
- **D-05:** **Paste lands at one moment:** a tight cluster at the paste time with a paste marker. It is never spread out to look typed.
- **D-06:** **In `.tree`, small commits as you type.** Like today's autosave (about ⅓ s of typing, Phase 2 D-02), each commit lists the letters typed and deleted, each with its time offset, readable in a text editor. Persistent data is keystrokes and sessions, never dots (spike 001). Dots, dashes and positions are redrawn from time × speed, consistent with Phase 3's rule that continuous values regenerate from recorded inputs. A crash loses at most a moment. — **Reversibility:** one-way — the keystroke record shape is written into append-only journals, so every saved thread keeps the first format forever. `tapestry/docs/tree/FORMAT.md` and its golden `example.tree` must change in the same commit.
- **D-07:** **A session runs from a time-in to a time-out** (D-10). Each return after a time-out drops a new session note on the line. On the 2D canvas, a thread looks like **a bridge of session notes** joined by the drawn line. Kaelen called it "a session log so that you can easily revert and head back to previous document stages".
- **D-08:** **Viewing past stages is in 2.3; branching is in Phase 3.** Clicking a session note or letter shows the document as it was at that moment, read-only, and text can be copied from it. Writing from an earlier stage, which branches the thread and keeps the original, arrives with Phase 3's world branching, so threads and worlds branch the same way.

#### Live writing view
- **D-09:** **Typer on top, line into depth.** Clicking a thread opens the note typer as a text window at the top. Below it the line streams away from the viewer into the distance. The canvas dims behind.
- **D-10:** **Time-out is adjustable per thread and defaults to 2.5 minutes**, matching Apple Messages' timestamp spacing.
- **D-11:** **Pause slowdown.** While the typer is open and typing stops, dots keep streaming at 60/s, then slow: about 30/s after roughly 10 s, about 10/s at roughly 30 s, and 1/s after a minute. The rate holds at 1/s until the time-out, which draws a dash, and the line stops until typing resumes (time-in dash). The numbers are Kaelen's rough defaults.
- **D-12:** **The line travels at constant speed during pauses; only the dots get sparser.** Distance along the line always equals elapsed writing time.
- **D-13:** **The slowdown curve is adjustable per thread**, like the time-out, with D-11's values as defaults. Dot rates follow real seconds, not the display's refresh rate, so a 120 Hz display draws the same line.
- **D-14:** **The live view fades by distance only.** Nothing is hidden on purpose; older writing gets smaller and dimmer with depth.

#### Side view read-back
- **D-15:** **The line follows writing time.** Letters and session notes sit where they were written, matching the live line exactly. A session's "when it happened" date, if given, shows as a label on its session note. The line is never reshuffled.
- **D-16:** **Gaps between sessions keep their true length, drawn dim.** The line stays honest about time, even across weeks.
- **D-17:** **Navigation.** Zoom from the whole thread to single dots, pan, click a session note to fly to it, and drag through any day on a thin date scrubber bar along the bottom. The timeline itself never changes. **Gravity** pulls the view toward a note only when hovering near it, more strongly for bigger notes; there is no pull while moving freely. Kaelen: "It's like space, huge gaps broken up with small planets, but the gravity is enough to easily be able to navigate between them."
- **D-18:** **Clicking any point shows the document at that moment** in the text window above: read-only, with that letter highlighted. Scrubbing along the line shows the document changing (see D-08).
- **D-19:** **Letters stay sharp at any zoom.** Before building, run a small spike: SDF or MSDF glyphs inside the same instanced-quad, single-draw-call design as spike 002b. Canvas-atlas letters blur above about 48 px.

#### Agents writing in a thread
- **D-20:** **Agent text lands when it arrived.** A whole write is one tight cluster, like a paste; streamed text spreads out as it streams. It is never replayed as fake typing.
- **D-21:** **Two strands twisted together.** Each author has their own coloured strand; they run side by side and twist into one where both write in the same stretch. In the document, each letter carries its author's colour at least as an underlay beneath the font colour, and hovering shows the actor id (for example `agent.claude`). — **Reversibility:** costly — per-letter actor attribution becomes part of the keystroke record shape (D-06).
- **D-22:** **Agents add anywhere but delete or rewrite only their own letters.** This extends 02.2 D-05 (agents edit only what they wrote) down to single letters.
- **D-23:** **Dragging a strand apart is for display in 2.3.** Dragging the agent's strand out shows each author's text on its own and leaves the document unchanged; letting go twists it back. Detaching agent text into its own note is deferred.
- **D-24:** **Agents can start threads**, but each must grow from an existing note and be connected to it (02.2 D-04). Agent threads are never loose.

#### Threads in an Obsidian vault
- **D-25:** **A vault thread's `.md` holds only the current text**, so Obsidian sees a normal note. Keystroke timings, sessions, deleted letters and author strands are stored as Tapestry's additions in the vault tree (02.2 D-14). An edit made in Obsidian arrives on the line as one observed cluster, like a paste, attributed per 02.2 D-21.

#### 2.1 rename
- **D-26:** **Rename 2.1's `thread-center` to `knot` and `thread-arm` to `knot-tie`.** The centre note is the knot, and its two lines are ties. The rename covers node and edge type names, `ThreadCenterNode` and its CSS classes, `Canvas.tsx`'s `isThreadCenter` and `'thread-arm'` label checks, and editor comments. — **Reversibility:** reversible now — no saved world contains these types (`~/Documents/we.tree` has none, and nothing in the app creates them yet). It becomes costly once worlds are written with the new names.

## Project Constraints (from CLAUDE.md)

- **Readability:** content, relationships, changes and provenance must be inspectable without the app. The `thread.log` grammar must read in a text editor, and letters typed and deleted must be legible as text, not as binary or base64.
- **Control / History:** editing the past preserves the original future (branching is Phase 3, D-08). Replay must use **recorded outcomes**: record time-outs as they happened and never re-derive them from a later setting.
- **Simple core:** storage, graph state and rule execution stay small and separate from live AI and adapters. **No kernel verb or value type added for threads.**
- **Plugins from the beginning:** features extend the versioned public API, and first-party plugins use the same API. The thread type is registered through a plugin manifest, like `tapestry-notes` and 02.2's `obsidian-vault`.
- **Developer accessibility:** plugin authors should not need to build native code. The thread grammar parser and replayer should be pure TypeScript with no Electron or native imports.
- **Usable UI:** actual editing, spatial interaction and timeline navigation, not backend demos.
- **Development scope:** work in `/Users/kaelencook/Tapestry` on branch `phase-2-implementation-v1`; do not rename it.
- **GSD workflow enforcement:** file changes go through GSD commands (`$gsd-execute-phase` for this phase).
- **Vite transpiles TS without checking it:** keep a separate `npm --prefix app run typecheck`.

### Pattern 1: `thread.log` as a set-line text block (D-06 record shape)

**What:** each thread commit carries one `set <node> thread.log text <<TEXT` op whose value is a block in a versioned, line-oriented grammar. Letters typed and deleted appear as quoted text with millisecond offsets. The commit's `actor` line is the author of every step in it.

**Fit with the kernel (verified):**
- The op vocabulary is closed. FORMAT.md:239-247 lists `create-node`, `set`, `unset`, `create-edge`, `delete-node`, `delete-edge` and `advance`, then says "Everything about the world's meaning is expressed with these seven verbs and the six value types below; plugins compose their data from them and never add a verb of their own." [VERIFIED: tapestry/docs/tree/FORMAT.md:237-249]
- Value types: `enum class ValueType { Text, Int, Real, Bool, Ref, Time };` [VERIFIED: tapestry/kernel/Value.hpp:14]
- `struct Proposal { Actor actor; std::string message; std::vector<Op> ops; };` carries no extension lines [VERIFIED: tapestry/kernel/Kernel.hpp:21-25], so the `x-` route needs a kernel change.
- Block text is automatic: "the text contains a newline or is longer than 80 bytes" [VERIFIED: tapestry/kernel/Value.hpp:65-67]. The delimiter becomes `TEXT1`, `TEXT2`, … if a line equals `TEXT` [VERIFIED: FORMAT.md:296-300].
- Limits: `kMaxRecordBytes = 64u << 20`, `kMaxLineBytes = 1u << 20` [VERIFIED: tapestry/kernel/tree/Codec.hpp:19-20]. World refuses text with a longer line: `": a line of the text exceeds "` [VERIFIED: tapestry/kernel/World.cpp:118-119]. A paste larger than about 1 MiB on one record line must be split across lines (`cont`).
- `set` on an existing key replaces the value with no same-value refusal. `SetProperty` prepare checks only live target, key and value [VERIFIED: tapestry/kernel/World.cpp:188-195]. The value history is the sequence of `set` lines [VERIFIED: FORMAT.md:160-162].
- The key grammar `[A-Za-z_][A-Za-z0-9_.:-]*` allows `thread.log` and `thread.session.3.event` [VERIFIED: tapestry/kernel/Ops.hpp:125-143].
- `recorded` has whole seconds only: "Fractional seconds, offsets other than Z, and a lowercase z are rejected." [VERIFIED: tapestry/kernel/Time.hpp:21-23]. Millisecond times must therefore live inside the block, not in `time` values.

Rules for the planner to lock:
1. **Line 1** `thread <grammar-version> v<collab version before the first step>`, which lets the replayer verify that no step is missing between commits. **Line 2** `at <RFC 3339 UTC with exactly 3 fraction digits>` is the anchor. Every later line starts `+<seconds>.<3 digits>`, parsed as **integer milliseconds** with no float.
2. **One step = one line.** An optional cause token (`paste`, `drop`, `cut`, `undo`, `redo`, `ime`, `format`, `link`, `enter`, `observed`) precedes the verb. No cause means typed.
3. Verbs:
   - `ins <pos> "<text>" [attr-less marks…]`: exact only when the step is a flat single-text-node `ReplaceStep` with `from == to`.
   - `del <from> <to> "<deleted text>"`: always quotes what was removed, taken from the doc before the step, with block boundaries as `\n` (D-03 readable).
   - `mark+`/`mark- <mark> <from> <to>`: attr-less marks only.
   - `step <exact Step JSON> "<readable text of the slice>"`: everything else (structure, attr marks like `textColor`/`link`, `ReplaceAroundStep`).
   - `marker link e<k>`: D-02 link marker.
   - `in <session#>`, `out`: time-in/time-out, D-07/D-10.
   - `cont "<text>"`: continuation for more than 1 MiB.
   Strings use the FORMAT inline escapes (`\"`, `\\`, `\n`, `\t`, `\r`, `\u00XX`) so no raw line feed ever appears inside a record.
4. **Letters (D-06 grapheme awareness):** each inserted string is segmented context-free with `Intl.Segmenter('und', {granularity: 'grapheme'})`. Letter ids are implicit: the k-th grapheme inserted in thread record order is letter k. The id is deterministic on replay and never written. A combining mark typed separately is its own letter on the line.
5. **Author (D-21):** the `actor` line of the enclosing commit. A commit never mixes actors, and ThreadService flushes on actor switch.
6. **Replay order = commit order, then line order. Line position = record time.** After a rebase, a user's steps can land in a commit after an agent commit while carrying earlier times. That is correct and must be tested.
7. **Recorded outcomes:** `out` is written when the time-out was detected (last activity + timeout in force). A later change to `thread.timeout` never moves past dashes. If `out` is missing (crash), the reader derives it and ThreadService writes it on the next write.

**Body checkpoint:** `set n7 body text <<TEXT {ProseMirror JSON}` goes in the same commit at `out`, on typer close, and at most every 60 s of writing [ASSUMED cadence; planner-tunable, not a format change]. The body key and JSON format match `tapestry.notes/note@1`, whose `defaultProperties` are `'position.x': 'real'`, `'position.y': 'real'`, `body: 'text'`, `title: 'text'` [VERIFIED: plugins/tapestry-notes/index.js]. Without a checkpoint policy, 1 h of typing at about 1 commit/s × a 10 KB body is about 36 MB/h of repeated bodies [ASSUMED arithmetic]. Log-only commits are about 0.3–0.6 KB each.

**Per-thread settings (open question 4, recommendation):** node properties written at thread creation, so defaults are frozen per thread and recorded like any edit: `set n7 thread.timeout real 150`, `set n7 thread.slowdown text "10:30 30:10 60:1"`, `set n7 thread.format int 1`. Changing a setting is an ordinary recorded `set`. Because `out` records are outcomes, only future dashes and dot density change. Settings UI is **Kaelen-visible**: a small "Thread settings" popover; confirm placement.

**Recorder algorithm:**
1. In `dispatchTransaction`, for each `tr.docChanged`, set `t = anchorMs + performance.now()`, where the anchor is `performance.timeOrigin` rounded, captured per session.
2. Cause: `uiEvent`, else `isHistoryTransaction ? (undo|redo)`, else `composition != null ? ime`, else a mark or link command meta set by `toolbar-commands.ts`/`passage-plugin.ts` (add `tr.setMeta('threadCause', 'format'|'link')`).
3. While `view.composing`, apply locally but **do not emit glyphs**. At composition end, emit the committed graphemes at the composition-end time as one cluster [ASSUMED UX: Kaelen-visible for IME users].
4. For each step, compute the readable line from `stateBefore.doc`: deleted text via `doc.textBetween(from, to, "\n")`, inserted text via `slice.content.textBetween(0, size, "\n")`.
5. Push to ThreadService through collab (Pattern 3).

**LetterIndex (D-03, D-21, D-22):** a run table in document order, `{firstLetterId, graphemeCount, utf16Length, actor, insertedAtMs}`, updated with `step.getMap().forEach((oldStart, oldEnd, newStart, newEnd) => …)`. Test it with randomized edit sequences against a naive per-UTF-16-unit array oracle.

**Document at time T (D-18):** find the last `body` checkpoint commit whose records end ≤ T, then replay the record lines with time ≤ T. Records are grouped by commit order, not sorted by time (rule 6). Cache docs at each checkpoint. Scrubbing replays at most one checkpoint interval (60 s ≈ hundreds of steps), throttled to rAF. Show the result in a read-only `EditorView` (`editable: () => false`) with a decoration on the letter at T; copying works (D-08).

### Pattern 3: prosemirror-collab authority in main (open question 1)

- Renderer: `collab({ version })` plus `history()`. On each dispatch, when `sendableSteps(state)` is non-null, send `{version, steps: steps.map(s => s.toJSON()), clientID, times, causes}`.

- Agent write (MCP): main builds steps against the authoritative doc (for example insert at the end, or after a quoted anchor), checks D-22 on any delete, applies them, broadcasts, and flushes as its own commit (`actor plugin agent.<name>`).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---|---|---|---|
| Two writers into one document | Custom operational transform or queueing | prosemirror-collab | Rebasing, step mapping and selection mapping are subtle; the library is maintained with the editor |
| Grapheme boundaries | Regex or code-point loops | `Intl.Segmenter` | ZWJ sequences, flags and combining marks (probe) |
| Position mapping through edits | Manual offset arithmetic | `Step.getMap()` / `Mapping` | Structure steps shift positions (Enter mapped 10→12) |
| Paste/cut/drop/undo detection | Key listeners | `uiEvent`, `paste`, `composition` meta and `isHistoryTransaction` | Covers menu, context-menu and drag paths |
| SDF/MSDF generation | Distance transforms | tiny-sdf or msdfgen-wasm per spike 003 | Edge cases in font metrics and fallback |
| Smooth zoom-pan flight | Ad-hoc easing | d3-interpolate `interpolateZoom` | Perceptually uniform path |
| Block text escaping in `.tree` | Our own delimiter logic | The kernel's `textNeedsBlock` and delimiter selection | Already guarantees reopen |

**Key insight:** the thread feature's hard parts are sequencing and identity (who wrote which letter, and when). ProseMirror's collab model and the kernel's host-stamped actor already solve both. The only genuinely new code is the readable grammar and the LetterIndex, and both are pure and testable.

## Common Pitfalls

### Pitfall 1: Autosave never fires while typing continuously
**What goes wrong:** `debounceRef.current = setTimeout(…, 300)` resets on every change [VERIFIED: use-prosemirror.ts:277-286], so a fast typist gets no commit until they pause. That breaks "a crash loses at most a moment".
**How to avoid:** ThreadService flush = idle 300 ms OR max-wait 1 s OR `out` OR close OR actor switch.
**Warning signs:** a vitest with a fake clock pushing a step every 100 ms for 5 s sees zero commits.

### Pitfall 2: Commits refused while the world is rewound
**What goes wrong:** KernelBridge throws `'Cannot commit while history is rewound; redo to the latest change or discard the undo first'` [VERIFIED: app/src/main/kernel-bridge.ts:158-162]. A thread typing session after a canvas-level undo would fail every flush.
**How to avoid:** opening the typer reconciles to latest, reusing the 02.2 Plan 04 UA-14 approach [VERIFIED: 02.2-04-PLAN.md:47]. Never mark steps confirmed-durable until submit returns. Keep "Saving…" while ThreadService has an unflushed batch (App.tsx rule: never "Saved" early).

### Pitfall 3: Sorting records by time for replay
**What goes wrong:** rebased user steps carry earlier times than an agent commit that precedes them, so replay by time applies steps to the wrong positions.
**How to avoid:** replay by commit order, then line order. Position glyphs by time. Test this exact interleaving.

### Pitfall 4: UTF-16 positions vs letters
**What goes wrong:** one emoji spans 8 positions (probe). Counting positions as letters misplaces glyphs and deletions. Backspace in some scripts removes a code point, not a grapheme [ASSUMED], leaving a partial grapheme.
**How to avoid:** LetterIndex keeps `utf16Length` and `graphemeCount` per run. A deletion that splits a grapheme marks the whole old letter deleted and inserts the remainder as a new letter at the same time.

### Pitfall 5: IME intermediate text recorded as typing
**What goes wrong:** composition dispatches many replace transactions with `composition` meta [VERIFIED: prosemirror-view dist:5124], so kana preview churn floods the line.
**How to avoid:** record committed text only when composition ends. Test with a synthetic composition sequence in vitest (EditorState-level) and manually with the macOS Japanese IME.

### Pitfall 6: three.js upload-range trap and culling
**What goes wrong:** history silently never reaches the GPU, or the ribbon is culled (spike 001 trail items 3 and 5).
**How to avoid:** port `pendingFullUpload`, `DoubleSide` and the manual bounding sphere verbatim. Every visual plan includes a `--shots`-style screenshot check, because frame rate alone proved nothing in spike 001.

### Pitfall 7: `gl.finish()` timing
**What goes wrong:** work time reads 0.1 ms at 100 ms frames.
**How to avoid:** measure rAF frame intervals only (CONVENTIONS.md).

### Pitfall 8: File growth from body snapshots
**What goes wrong:** a full ProseMirror JSON on every batch grows `.tree` by megabytes per hour, and pruning is deferred.
**How to avoid:** use the checkpoint cadence (Pattern 1) and measure bytes/hour in a vitest with synthetic 1 h typing.

### Pitfall 9: Clock sources
**What goes wrong:** `recorded` comes from the kernel clock in whole seconds; keystroke times come from renderer `performance.now()`. The laptop sleeping mid-session or the wall clock jumping can produce negative or huge offsets.
**How to avoid:** anchor `at` per batch from `Date.now()` at batch start, with monotonic offsets inside the batch. Clamp offsets to ≥ 0. Treat a gap above the timeout as `out` + `in`.

### Pitfall 10: Agent streaming floods commits
**What goes wrong:** an agent calling append 50×/s creates 50 fsync'd commits per second.
**How to avoid:** ThreadService coalesces per actor within the flush cadence while each call keeps its own arrival time (D-20). Rate-limit per agent token.

### Pitfall 11: Author colours conflict with 02.2 UI-SPEC
**What goes wrong:** 02.2 UA-02 says "Provenance is neutral grey with glyph + literal actor id, no per-agent colors" [VERIFIED: 02.2-UI-SPEC.md:634]. D-21 requires coloured strands and an underlay.
**How to avoid:** the 2.3 UI-SPEC must reconcile this. Thread strands use colour *plus* the actor id on hover and in a legend, never colour alone (DRAW-04), and 2.2 provenance badges stay grey.

export function causeOf(tr: Transaction): string | null {
  const ui = tr.getMeta('uiEvent') as 'paste' | 'cut' | 'drop' | undefined
  if (ui) return ui
  if (isHistoryTransaction(tr)) return 'undo' // distinguish redo via the command that dispatched it
  if (tr.getMeta('composition') != null) return 'ime'
  return (tr.getMeta('threadCause') as string | undefined) ?? null   // set by toolbar/passage commands
}

export function linesFor(tr: Transaction, before: EditorState, tMs: number) {
  let doc = before.doc
  return tr.steps.map((step) => {
    const json = step.toJSON()
    let line
    if (step instanceof ReplaceStep && step.slice.openStart === 0 && step.slice.openEnd === 0
        && (step.slice.content.childCount <= 1 && (step.slice.content.firstChild?.isText ?? true))) {
      const from = (step as any).from as number, to = (step as any).to as number
      const deleted = from < to ? doc.textBetween(from, to, '\n') : ''
      const inserted = step.slice.content.firstChild?.text ?? ''
      line = { tMs, kind: from < to ? (inserted ? 'repl' : 'del') : 'ins', from, to, inserted, deleted,
               marks: step.slice.content.firstChild?.marks.map((m) => m.type.name) ?? [] }
    } else {
      line = { tMs, kind: 'step', json, text: stepText(step, doc) }
    }
    doc = step.apply(doc).doc!   // keep "before" doc in step with the transaction
    return line
  })
}

import { Step } from 'prosemirror-transform'
export class ThreadAuthority {
  version = 0; steps: Step[] = []; clientIDs: (string|number)[] = []
  constructor(public doc: import('prosemirror-model').Node) {}
  receive(version: number, stepsJson: unknown[], clientID: string|number, actor: string) {
    if (version !== this.version) return { ok: false as const, missing: this.stepsSince(version) }
    for (const j of stepsJson) {
      const step = Step.fromJSON(schema, j)
      // D-22: if actor is an agent and step deletes, every letter in range must be authored by actor
      const res = step.apply(this.doc); if (res.failed) return { ok: false as const, error: res.failed }
      this.doc = res.doc!; this.steps.push(step); this.clientIDs.push(clientID)
    }
    this.version += stepsJson.length
    return { ok: true as const, version: this.version }
  }
  stepsSince(v: number) { return { steps: this.steps.slice(v), clientIDs: this.clientIDs.slice(v) } }
}
