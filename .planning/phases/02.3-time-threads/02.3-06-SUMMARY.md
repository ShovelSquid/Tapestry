# Phase 02.3 Plan 06: Sessions, the canvas bridge, and per-thread settings Summary

**Sessions are now recorded outcomes a settings change can never rewrite -- a per-thread time-out timer in `ThreadService` writes the `out`/`in` boundary the moment a pause is actually detected, session data flows into a canvas bridge of session pills and an accessible `SessionList`/`MarkerList`, and every per-thread setting (time-out, slowdown curve, gravity, author colours) is an ordinary recorded edit through a new `ThreadSettingsPopover`.**

## Accomplishments

- `sessions.ts`: `DEFAULT_TIMEOUT_SECONDS`, `detectTimeout`, `deriveSessions` -- session boundaries, letter counts, authors and markers reconstructed from `in`/`out`/`ins`/`del`/marker records alone, with a module-load assertion pinning its default against `settings.ts`'s own constant.
- `ThreadService`: a per-thread time-out timer (read from the node's own `thread.timeout` at open) is now a fifth flush trigger alongside idle/max-wait/close/actor-switch. Reopening within the still-live window resumes the same session; reopening after it treats a missing `out` as a crash and repairs it as its own honestly-timestamped commit on the very next write.

- `ThreadSettingsPopover.tsx`: the time-out field (validated 10s-60min), the slowdown table with add/remove-step controls and a live 240px preview strip driven by the identical `dotRateAt` the CPU tests and GPU shader already share, the gravity and author-colour toggles, and the always-visible recorded-outcome note. Every change commits as an ordinary `set` on the thread node.
- `TreeFrame.tsx`: mounts the bridge below every ThreadCard (live-updating on `thread:confirmed`), the D-24 agent-started footer (dormant until a later plan creates the data it reads), and the ThreadCard menu (`Open thread` / `Thread settings` / `Delete thread`).
