<objective>
**As a** person sharing a thread with an agent, **I want to** see exactly which letters it wrote and know it cannot touch mine, **so that** working alongside it never costs me the certainty that my own words are my own.

This plan opens the thread to a second writer: MCP tools an agent can call, the rule that it may add anywhere but change only what it wrote, two coloured strands that twist where both authors worked, and a per-letter underlay that names who wrote what.

Purpose: D-22 is a security boundary, not a UX preference. It is enforced in the main process from authorship the journal already proves, never from anything the caller supplies. D-21's attribution is `costly` to change once written, because per-letter authorship is read out of the record shape locked in Plan 02.

Output: the thread tool surface with its refusal path, strands and underlays, and the authors legend.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP agent call → thread authority | An untrusted agent requests writes into a document a person also owns |
| agent token → actor identity | The agent's name must come from the host, never from the call |
| `LetterIndex` authorship → D-22 decision | The access-control decision reads authorship derived from journal commits |
| strand display transform → document | A display-only interaction sits over real document data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.3-08-01 | Elevation of privilege | agent editing a user's letters | critical | mitigate | Every letter in a delete or replace range is resolved through `LetterIndex.authorOf`, built from host-stamped journal commit actors, and the whole call is refused if any letter has a different author. | T-02.3-08-02 | Elevation of privilege | bypass via `update_note` on a thread | critical | mitigate | `update_note` is routed or refused for thread node types, closing the whole-body rewrite that would otherwise defeat the per-letter rule entirely |
| T-02.3-08-03 | Spoofing | forged agent identity | high | mitigate | No thread tool reads an actor or author argument; the actor is stamped by main from the agent's token via `agentActor`. A negative grep asserts no `args.actor` or `args.author` read exists |
| T-02.3-08-04 | Spoofing | forged authorship colour | medium | mitigate | Colour is a display mapping derived from the commit actor and is never written to `.tree`; a negative grep asserts no author token appears in the shared or main layers, so no colour can reach the file |
| T-02.3-08-05 | Denial of Service | agent streaming floods commits | high | mitigate | Per-agent-token rate limiting plus per-actor coalescing within the flush cadence, each write keeping its own arrival time, so 50 calls a second cannot produce 50 fsync'd commits |
