# Phase 02.3 — UI Design Contract

> Visual and interaction contract for time threads: the live z-axis writing view, the side-view read-back, the thread on the 2D canvas, markers on the line, author strands, thread settings, and the no-plugin fallback. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Inherits the approved Phase 02.1 and 02.2 UI-SPECs. No palette, type scale or spacing token from 02.1 is changed.

Generated unattended. **No questions could be asked** (subagent, non-interactive). Every choice that CONTEXT.md, RESEARCH.md, the 02.1/02.2 UI-SPECs, Kaelen's own concept note and the renderer source did not settle is marked **proposed default** with an id (`TA-nn`) and a one-line rationale, and every one is listed in **Questions for Kaelen** at the end.

Four answers Kaelen gave in this session are **locked** and are not proposed defaults:

| # | Locked answer | Where it binds |
|---|---------------|----------------|
| L-1 | Both creation routes: a "New thread" action on the canvas **and** "Make this note a thread"; a converted note's history begins at conversion | Interaction Contracts § Starting a thread; Copywriting |
| L-2 | Agent text lands **after** Kaelen's caret; the caret never jumps. Strands twist where both authors wrote within ~2 s | Interaction Contracts § Agents writing live |
| L-3 | Session notes are **views derived from the thread's history**, not separate nodes: not draggable, not connectable. Clicking one shows the document as it was then | Session notes (line + canvas bridge); resolves RESEARCH A3 |
| L-4 | **Author colours everywhere** — D-21 supersedes 02.2 UA-02 | Color § Author identity; see § Supersedes 02.2 UA-02 |

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (custom React + plain CSS; ProseMirror for note text; three.js 0.186.0 for the thread stage) |
| Icon library | Inline SVG glyphs (established Phase 2 pattern; no external icon library) |
| Font (chrome and typer) | System stack: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif`. Serif and Mono stacks from the 02.1 font palette remain available as user marks. |
| Font (stage glyph atlas) | One face for the whole stage: the System stack rasterized into the glyph atlas. Letters on the line do **not** carry the user's font mark (TA-09) |

Toolkit continues unchanged: Electron + React + ProseMirror + plain CSS in `app/src/renderer/App.css`, classes prefixed `tapestry-`. This phase adds one non-DOM surface — the WebGL **stage** — whose visual values are declared here in the same tokens, converted to screen pixels. New CSS uses the tokens below.

Three facts about the stage that bind every visual choice in this document:

1. Letters are **instanced quads from one glyph atlas, one draw call** (spike 002b). There is no per-letter DOM, so no per-letter CSS, no text selection and no focus ring on the stage. Reading, selecting and copying always happen in the DOM typer above.
2. Dots are drawn **procedurally in a fragment shader** from time × speed (spike 001). Nothing about a dot is stored, so nothing about a dot can be styled per instance.
3. Position on the line is **recorded time**, always. No visual rule may reorder, compress or re-space the line (D-12, D-15, D-16).

## Spacing Scale

Declared values (multiples of 4, identical to 02.1 and 02.2):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Author swatch-to-id gap, marker-to-label gap, scrubber tick inset, legend row gap |
| sm | 8px | Header item gap, popover item gap, settings row gap, chip padding |
| md | 16px | Typer inner padding (sides), scrubber margin from window edges, session pill label offset |
| lg | 24px | Typer padding block, popover padding, gap between the typer and the stage |
| xl | 32px | Gap between header rows and the typer body; stage side inset |
| 2xl | 48px | Typer offset from the top of the window; gravity hover radius (D-17) |
| 3xl | 64px | Minimum stage height reserved below the typer before the view switches to list-only |

Exceptions, each with its reason:

- **Typer max width 688px.** 688 − 2 × 24px padding = 640px of text, about 75 characters at Body 16px — the upper end of comfortable measure, and the same reading width for live writing and for a past stage.
- **Typer height: min 160px, max 44% of the window height, then scrolls.** 160px holds the header row plus three Body lines (3 × 24px) and the 24px padding block; 44% keeps more than half the window for the line, which is the point of the live view (D-09).
- **Scrubber bar 32px tall.** Inherits the 02.1 toolbar hit target (32px), so the only draggable chrome in the view is as tall as every other control.
- **Session pill diameter 12px to 32px**, on a log scale from ≤100 to ≥5,000 letters. 12px is the smallest disc that still reads as a disc rather than a dot at 100% zoom; 32px matches the 02.1 hovered connection-handle bubble, so the largest "planet" never out-sizes an existing canvas control.
- **Session pill pointer target: `max(pill radius, 12px)`** — a 24px minimum target, so the smallest pill is as clickable as the largest (DRAW-04).
- **Marker glyphs 6–8px, drawn in screen space, with a 20px pick radius.** 8px is the smallest ring whose hole survives one device pixel of anti-aliasing at DPR 2; screen-space sizing keeps a marker the same size at every zoom, because a marker means "a thing happened here", not "a thing this big happened here".
- **Strand lateral separation 6px** (clamped 4–12px as zoom changes). 6px is two strand widths (1.5px each) plus a 3px gap, the narrowest separation where two strands still read as two at 100% zoom.
- **Strand drag-apart travel: 120px maximum.** Equals the 02.2 agents command block max height and about one third of the typer width, so pulling a strand out never covers the document above it.
- **Glyph LOD floor: 7px em.** Below 7px the atlas glyph is noise (spike 002b read cleanly at 8px); under the floor the stage draws the ribbon and dots only, and the DOM typer carries the reading (DRAW-03).
- **Glyph LOD ceiling: 48px em, gated on spike 003** (TA-09). 002b is soft at 48px and blurred at 120px.
- **Live-view dot diameter 3px at the head**, collapsing to a solid line when spacing falls under 1.5px (spike 001's `fwidth` rule). 3px is the smallest filled disc that survives perspective minification without shimmering.
- **Time-out / time-in dash: 2px × 16px cross bar.** 2px matches the 02.1 passage bracket thickness (the established "this is a structural mark" weight); 16px is the md token, long enough to read against a 1.5px line.
- Carried from 02.1/02.2 unchanged: 32px control/hit targets, 28/32px control bubbles, 8px note radius, 16px knot radius, 300ms submenu grace, 440px dialog width, 6s transient notice duration.

## Typography

Same four roles and two weights as 02.1 and 02.2. **No new size and no new weight.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Note Title | 18px | 600 (semibold) | 1.25 |
| Label | 13px | 400 (regular) | 1.4 |
| Heading | 22px | 600 (semibold) | 1.25 |

Phase 2.3 role assignments:

- **Thread document text** (live and read-only): Body. Identical to every other note (D-02 universal editing).
- **Thread title** in the overlay header and on the ThreadCard: Note Title.
- **Save state, session dates, gap durations, actor ids, marker labels, scrubber tick labels, settings rows, legend rows, notices**: Label.
- **Session pill number** (drawn inside a pill ≥24px): Label at 600 weight — the one place the semibold weight appears at Label size, because it sits on a filled disc and must survive the colour behind it.
- **Dialog title**: Heading. **Dialog body**: Body. **Dialog buttons and helper text**: Label.
- **Stage letters**: not DOM type. They render at their projected size between the 7px floor and the 48px ceiling (gated, TA-09). They are the document's own characters at the document's own size in world units — they are not a type role and must never be re-sized for emphasis.

### Author identity (D-21, L-4)

Author colours are a **provenance palette**, reused verbatim from the 02.1 user text-colour palette so this phase adds no new hues. Blue is excluded (accent), Charcoal belongs to the person, Gray means "author unknown".

| Actor | Colour | Contrast on #F7F5F0 | Assigned |
|-------|--------|--------------------|----------|
| `human user.<name>` (Kaelen) | Charcoal #2C2C2C | 12.82:1 | Always. The person's own writing reads as ordinary ink |
| agent, 1st connected | Magenta #CD2B74 | 4.60:1 | In palette order at connect time (02.2 Agents panel) |
| agent, 2nd | Green #18794E | 4.96:1 | " |
| agent, 3rd | Orange #AD5700 | 4.66:1 | " |
| agent, 4th | Purple #6E56CF | 4.95:1 | " |
| agent, 5th | Red #D13415 | 4.57:1 | " |
| `plugin obsidian.bridge`, observed edits, unknown | Gray #6B6B6B | 4.89:1 | Never claims a colour — it is the "author unknown" of 02.2 |

Ratios computed against `#F7F5F0` (not `#FFFFFF`, which is what 02.1 lists) with the WCAG 2.x relative-luminance formula, 2026-09-15. Every author colour clears AA (4.5:1) for normal text on the stage, with Red the tightest at 4.57:1 — so darkening the paper is the one change that would break this table, which is why TA-01 keeps the stage on paper rather than a dark backdrop.

Rules:

1. **Colour is a display mapping, never data.** No colour is written to `.tree`. The file's provenance is the host-stamped actor id, and the UI derives the colour from it.
2. **Beyond five agents the palette cycles**, and the pattern cue below carries the difference.
3. **Colour is never the only cue** (DRAW-04). Every surface that colours an author also carries at least one of: the literal actor id in text, a per-author underline pattern, or the letter's position on its own strand.

| Author | Underline pattern (typer) | Strand pattern (stage) |
|--------|---------------------------|------------------------|
| Person | none (default reading) | solid, always the **near** strand |
| Agent 1 | 1px dotted (2px on, 2px off) | dotted |
| Agent 2 | 1px dashed (4px on, 2px off) | dashed |
| Agent 3 | 1px long dash (8px on, 2px off) | long dash |
| Agent 4 | 1px dash-dot | dash-dot |
| Agent 5 | 1px double rule | double |
| Unknown | 1px wavy | wavy |

**Per-letter underlay in the typer (D-21):** an agent's letters carry a background wash of their colour at 18% opacity behind the glyph, under whatever font colour the user applied. The person's letters carry **no** wash (TA-03) — otherwise every document is striped and the 60/30/10 split is lost. Ink on an 18% wash stays above 11:1.

| State | Fill | Border | Label |

### Where opacity is and is not used

The live view fades **by distance only** (D-14). To keep that promise honest and auditable, this is the complete list of opacity reductions in the phase; there is no age-based fading anywhere:

1. Perspective distance in the live view (letters and dots), reaching 0 at the far plane — this is the projection, not a rule.
2. Gaps at 30% — a line, no text.
3. The silent strand inside a shared stretch at 25% — a line, no text.
4. The overlay surface at 97% over the canvas.

No text is ever drawn below full strength. Deleted letters are struck through, not dimmed (TA-08).

### Dark mode

Tapestry ships **one light theme**. `app/src/renderer/App.css` contains no `prefers-color-scheme` rule today (checked 2026-09-15), and this phase adds none — a second theme for the stage would need its own contrast audit of the seven author colours and is out of scope. The stage therefore uses the same paper palette as the canvas. If a dark theme is added later, the seven author colours and the four opacity uses above are the values that must be re-derived first.

### Screen-reader announcements for visual-only cues

Marker shapes, pills, dashes and strands are drawn on a canvas and carry no accessible tree of their own. Meaning is carried as follows; the stage `<canvas>` itself is `aria-hidden` and is mirrored by the SessionList.

| Cue | Announcement |
|-----|--------------|
| Stage canvas | `aria-hidden="true"`; the accessible equivalent is the Sessions list and the caret authorship readout |
| Moving focus to a session (`[` / `]`) | LiveAnnouncer (polite): "Session [n], [date] [time], [n] letters, by [authors]" |
| Opening a past stage | LiveAnnouncer (polite): "Showing the document as it was on [date] at [time]. Read-only." |
| Returning to now | LiveAnnouncer (polite): "Back to now. You can write again." |
| Zoom change | LiveAnnouncer (polite), throttled to one per 500ms: "Showing [duration] across the view" |
| Agent text landing (L-2) | LiveAnnouncer (polite): "agent.[name] added [n] letters. Your cursor hasn't moved." |
| Refused agent change (D-22) | LiveAnnouncer (polite), once: "agent.[name] tried to change letters it didn't write. Nothing was saved." |
| Save failures / unreadable history | `aria-live="assertive"` region, once when it appears |
| Author of the text at the caret | The caret authorship readout is a live region updated on selection change, throttled to 300ms |

## Interaction Contracts

### Starting a thread (L-1)

| Trigger | Behaviour |
|---------|-----------|
| Right-click (or Ctrl-click) empty space inside a frame | Small menu on the PassageChooser surface: "New note", "Start a thread" (TA-04). Double-click keeps creating a plain note exactly as today — no existing gesture changes |
| Frame menu (keyboard route) | The same two items appear in the frame's options menu, so neither route is pointer-only (DRAW-04) |
| "Start a thread" | A ThreadCard appears at the click point, the thread overlay opens, the typer takes focus, and the first keystroke starts session 1 |
| Right-click a note → "Make this note a thread" | The note becomes a ThreadCard in place with no position jump. Its existing text is recorded as **one cluster at the conversion moment**, marked "written before the thread started" (TA-05), and the explain chip appears. History before that moment is honestly unknown |
| Agent starts a thread (D-24) | The new ThreadCard appears next to its origin note, joined by a `grew-from` line, with the footer naming the origin and the agent. An agent thread is never loose |

### Live writing view (D-09 … D-14)

| Property | Value |
|----------|-------|
| Layout | Full-window overlay. Typer at 48px from the top, horizontally centred, max 688px wide. The stage fills everything below it, with 24px between them |
| Vanishing point | Horizontal centre of the stage area, 38% down it, so the near line has depth to travel through |
| Canvas behind | Dimmed by the 97% overlay surface; it is never interactive while the overlay is open |
| Line direction | Away from the viewer into depth; the newest moment is nearest, at the now-head cap |
| Dot rate | 60/s while typing; 30/s after 10s idle; 10/s after 30s; 1/s after 1 minute; holds at 1/s until the time-out (default 2.5 minutes), which draws the time-out dash and stops the line. The next keystroke draws the time-in dash and the line resumes (D-11, D-13, all per-thread adjustable) |
| Line speed | **Constant, always.** Only dot density changes during a pause (D-12) |
| Rate source | Real seconds, never frames — a 120Hz display draws the same line (D-13) |
| Fading | Distance only (D-14). Opacity and size follow the projection; nothing is hidden by age or by rule |
| Input priority | **A keystroke is never deferred for the animation.** If a frame budget is missed, the stage drops the frame; the typer never drops or delays a character (spike 004 acceptance) |
| Letters | Land above their strand at the moment they were typed, one atlas quad each |
| Paste (D-05) | One tight cluster at the paste moment with a paste marker. Never spread out to look typed |
| IME | Nothing is drawn while composing; the committed graphemes land as one cluster at composition end (RESEARCH A4) |
| Deleting / Cmd+Z (D-03, D-04) | The letters stay where they were typed, struck through and offset below the strand; a deletion or undo marker lands at the moment of the change |
| Formatting / linking (D-02) | The full FloatingToolbar is available (universal editing). Each action drops its marker on the line at that moment |
| Escape | Closes the thread view and returns to the canvas. It never discards text |

### Side view read-back (D-15 … D-19)

| Trigger | Behaviour |
|---------|-----------|
| "Read the thread back" | The stage turns to the side view: the whole thread left (oldest) to right (newest), the typer staying above. The line is never reshuffled (D-15) |
| Wheel / pinch | Zoom, continuous, from about 1.1 × the thread's duration across the view down to 0.5s across the view (single dots) |
| `+` / `-` | Zoom one step (×2 per press), around the focused point |
| Drag / arrow keys | Pan. Arrow keys move by 10% of the view width, Shift+arrow by 100% |
| Click a session pill | Flies to it (`interpolateZoom`, 300–900ms scaled to path length) |
| `[` / `]` | Previous / next session — the keyboard equal of fly-to, and the path a screen-reader user takes |
| Hover near a session pill | **Gravity:** only within 48px, only below 120px/s pointer speed, and only when no wheel or drag happened in the last 150ms. A critically damped spring on the view centre, strength `k0 · clamp(log2(1 + letters)/10, 0.2, 1)` — bigger sessions pull harder. Any movement above 240px/s, any key, or the settings toggle cancels it. Gravity never moves the view while the pointer is travelling freely (D-17) |
| Drag the date scrubber | Moves the view window through true time. The timeline itself never rescales (D-16, D-17) |
| Scrubber keyboard | Focusable; arrows move one day, Shift+arrows one week, Home/End the first/last day |
| Click any point on the line | Opens the document as it was at that moment in the typer above, read-only, with the clicked letter highlighted (D-18) |
| Scrub along the line while a past stage is open | The document above changes as the point moves, throttled to one redraw per frame |
| `Enter` on a focused point or session | The same as clicking it |
| "Return to now" / Escape | Leaves the past stage, returns the typer to the live document and puts the caret back where it was |

**Past stage (read-only) treatment:** the typer keeps its surface and Body type; its border becomes 1px solid Line #B0ADA6, the caret is hidden, and the header reads "Reading [date], [time] — read-only". Text stays selectable and copyable (D-08). Writing from a past stage is **not** in this phase — it branches the thread, which is Phase 3 — so keystrokes there do nothing except show the notice: "Writing from an earlier moment will branch the thread. That's coming with branching history. Choose Return to now to keep writing."

**Gap and scrubber honesty (D-16):** a two-week gap occupies two weeks of line. The scrubber is linear in true time, with a 1px `#E0DDD7` tick per day and, on days with writing, an Ink bar whose height is that day's letters relative to the busiest day. The current view is a 2px accent bracket.

### The thread on the 2D canvas (D-07)

| Element | Behaviour |
|---------|-----------|
| ThreadCard | An ordinary NoteCard showing the document's title and current text, draggable, connectable and deletable like any note |
| Session bridge | Below the card: a 1.5px Line `#B0ADA6` horizontal line carrying one session pill per session, joined end to end — "a bridge of session notes joined by the line" |
| Spacing on the canvas | **Evenly spaced by session order, not by true time** (TA-02). The canvas has no time axis; true-time spacing lives in the side view, and every pill carries its date |
| Overflow | Above 9 sessions the bridge shows the first 4, a "+[n]" pill, and the last 4. Clicking "+[n]" opens the Sessions list |
| Click a pill | Opens the thread overlay in the side view, flown to that session, showing the document as it was then |
| Pill affordances | None beyond clicking (L-3): no drag, no connect handle, no delete bubble, no context menu |
| Card menu | "Open thread", "Thread settings", "Delete thread" |

### Agents writing live (D-20 … D-23, L-2)

| Trigger | Behaviour |
|---------|-----------|
| Agent writes into a shared thread | The text lands at the moment it arrived — a whole write is one cluster, streamed text spreads as it streams. It is never replayed as fake typing (D-20) |
| Agent text at or after the caret (L-2) | It lands **after** the caret. The caret does not move, and unsent keystrokes are rebased and never lost |
| Agent text off screen | Transient chip, 6s: "agent.[name] added [n] letters above." **Show the change** scrolls there without moving the caret |
| Two authors in the same stretch | Two strands run side by side, 6px apart, and twist — one smooth crossing per 1.0s of thread time — through any stretch where both authors wrote within a 2s window (TA-11). Outside shared stretches they run parallel and the silent strand drops to 25% |
| Hover a letter or a strand | A chip shows the literal actor id (`agent.claude`) on the PassageChooser surface (D-21) |
| Drag a strand perpendicular to the line (D-23) | The strands separate, up to 120px, each author's letters on their own line, with the chip "Showing agent.[name] on its own. The document hasn't changed." Release springs them back over 240ms. **The document is not modified** |
| `A`, or "Show each author on its own line" | The keyboard equal of the drag: a latched separated view, released by pressing `A` again (DRAW-04 — the drag is never the only route) |
| Agent tries to delete or rewrite a letter it didn't write (D-22) | Refused; nothing is committed. No modal and no interruption to writing. The Authors legend row gains "· [n] changes refused" with the explaining tooltip, and the refusal is announced once (TA-07) |

### Thread settings (D-10, D-13)

Opened from the gear in the overlay header, and from the ThreadCard menu (TA-13). A popover on the PassageChooser surface, min width 320px, 24px padding, dismissed by clicking outside or Escape. Every change is an ordinary recorded edit and takes effect from now on; the recorded-outcome note is always visible, because past dashes must never move when a setting changes.

The slowdown table edits the D-11 curve directly as "after [n] seconds · [n] a second" rows, with a live 240px preview strip showing the dot spacing the current curve produces over a two-minute pause.

### No-stage fallback (no WebGL, or graphics lost)

The thread must stay usable without the stage — the project's readability constraint applies to the feature itself, not only to its files.

| Situation | What is shown |
|-----------|---------------|
| WebGL unavailable | The typer stays, full width of the overlay. Where the stage would be, `StageFallbackPanel` shows the SessionList: one row per session with date, duration, letter count and authors; Enter opens that stage read-only. Writing works normally and history is recorded normally |
| Context lost mid-session | The error notice with **Redraw thread**; buffers rebuild from the records, never from the screen |
| Threads plugin disabled | FallbackNodeView with the checkpoint text and its notice (see Copywriting) |

### Keyboard map (DRAW-04 — every navigation action has a key)

| Key | Action |
|-----|--------|
| `Esc` | Return to now, then close the thread view |
| `Tab` / `Shift+Tab` | Typer → Authors → Sessions → Settings → scrubber → stage focus point |
| `[` / `]` | Previous / next session |
| `+` / `-` | Zoom out / in |
| Arrows | Pan (stage) or move one day (scrubber), by focus |
| `Home` / `End` | First / last moment of the thread |
| `Enter` | Open the document at the focused point |
| `A` | Separate / twist the authors |
| `Cmd+Z` | Ordinary editor undo in the typer (never kernel undo — D-04) |

Focus order inside the overlay is trapped. `:focus-visible` rings are 2px accent at 2px offset on every new control. No action in this phase is reachable by hover alone.

### Motion and `prefers-reduced-motion`

No reduced-motion rule exists in the renderer today (checked 2026-09-15); this phase introduces the first one, and it must be honoured by the stage as well as by CSS.

| Under `prefers-reduced-motion: reduce` | Behaviour (TA-12) |
|---|---|
| Live streaming | **Off.** The stage stops animating per frame. The line still grows: it is redrawn when a letter lands, and at most 4 times a second while idle, so the geometry, dots, dashes and slowdown are all still visible and still correct |
| Fly-to | Instant jump, with the polite announcement, instead of the interpolated flight |
| Gravity | Off, and the settings toggle shows as off |
| Strand twist | Drawn as static crossings; no animated weave |
| Strand drag-apart release | Snaps instead of springing |
| Transient chips | Appear and disappear without fade |

Nothing is removed by reduced motion — only the movement between states.

### Gated on pending spikes

Spikes 003a/003b (sharp glyphs) and 004 (typer over a live thread) were still `PENDING` in `.planning/spikes/MANIFEST.md` when this contract was written. Two clauses above are therefore conditional and must not be read as settled:

| Clause | Until the verdict | If the spike validates | If it does not |
|--------|-------------------|------------------------|----------------|
| Glyph sharpness above 48px (D-19, TA-09) | The side view **clamps glyph em to 48px on screen**: letters stop growing while the ribbon, markers and pills keep zooming, and the DOM typer carries the reading | The clamp is removed; letters stay sharp to 240px through the winning SDF/MSDF atlas, with no other visual change (same quads, same instance data, same draw call) | The clamp stays and is a declared limit of the side view, not a defect |
| Live typing latency (004) | "Input priority" above already binds: a missed frame is dropped, a keystroke never is | Nothing changes | The live view falls back to landing letters at flush time rather than per keystroke, keeping the same geometry |

Any plan task that depends on either clause carries a `depends_on` for the spike verdict.

## Supersedes 02.2 UA-02

02.2's UI-SPEC assumption **UA-02** reads: "Provenance is neutral grey with glyph + literal actor id, no per-agent colors."

**D-21 and Kaelen's locked answer L-4 supersede it.** Each agent has one colour, used consistently on:

1. thread strands,
2. per-letter underlays in the typer,
3. **provenance badges** — the badge's glyph takes the author's colour; its text keeps Ink/Muted so contrast is unchanged, and the literal actor id is still always shown,
4. the **Agents panel** — each row gains a 12px colour swatch before its existing glyph and id.

Colour is added *beside* 02.2's cues, never instead of them: the glyph shape, the literal actor id and the per-author pattern all remain, so nothing in 02.2 that worked without colour stops working.

**02.2's UI-SPEC needs a follow-up amendment to UA-02 and to its provenance-badge table.** That file is owned by another session and is **not edited here**. This section is the authority for the conflict until that amendment lands.
