# Phase 02.3 — UI Design Contract

> Visual and interaction contract for time threads: the live z-axis writing view, the side-view read-back, the thread on the 2D canvas, markers on the line, author strands, thread settings, and the no-plugin fallback. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Inherits the approved Phase 02.1 and 02.2 UI-SPECs. No palette, type scale or spacing token from 02.1 is changed; this revision **adds** two neutral tokens (§ Theming) and names every existing value so a theme can rebind it.

Revision 2 (2026-09-15) changed four things and nothing else:

1. **Four more of Kaelen's answers are locked** (L-5 … L-8) and replace the proposed defaults that stood in for them.
2. **Spikes 003a, 003b and 004 have verdicts**, so the glyph clause is no longer conditional: MSDF wins, the 48px clamp is gone, and its real costs are carried forward as constraints (§ Spike verdicts).
3. **Loading and catch-up states are declared** for every wait this phase can produce (§ Copywriting → Loading and catch-up).
4. **Four checker recommendations are addressed:** a focal-point table, a marker-stepping key, a destructive text colour with a computed ratio, and a darker thread line that clears WCAG 1.4.11.

Everything still marked **proposed default** (`TA-nn`) is a choice Kaelen has not seen yet; each is listed in **Questions for Kaelen** at the end, and each ships as written if there is no answer.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (custom React + plain CSS; ProseMirror for note text; three.js 0.186.0 for the thread stage) |
| Icon library | Inline SVG glyphs (established Phase 2 pattern; no external icon library) |
| Font (app chrome) | System stack, unchanged from 02.1: `-apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif` |
| Font (thread document — typer **and** stage) | **One bundled single-file face, used by both surfaces** (TA-25). Spike 003b: MSDF cells are generated from font **files**, and macOS `.ttc` collections are not supported, so the stage cannot use the system stack. If the typer and the line do not read the same file, "the same word looks like two different typefaces" (003b §9) |
| Glyph path (stage) | **MSDF from font files** (spike 003b, WINNER) in 002b's instanced-quad design, with the **browser-SDF cell (003a) drawn immediately** while the MSDF cell generates and as the permanent fallback for shaped clusters and scripts the bundled file lacks; **colour emoji are bitmap cells** in the same atlas. One atlas, one draw call, per-instance `kind` flag (0 = SDF, 1 = MSDF, 2 = colour bitmap) |

Toolkit continues unchanged: Electron + React + ProseMirror + plain CSS in `app/src/renderer/App.css`, classes prefixed `tapestry-`. This phase adds one non-DOM surface — the WebGL **stage** — whose visual values are declared here in the same tokens, converted to screen pixels. New CSS uses the tokens in § Theming and **no raw hex at any use site**.

Three facts about the stage that bind every visual choice in this document:

1. Letters are **instanced quads from one glyph atlas, one draw call** (spikes 002b, 003b). There is no per-letter DOM, so no per-letter CSS, no text selection and no focus ring on the stage. Reading, selecting and copying always happen in the DOM typer above.
2. Dots are drawn **procedurally in a fragment shader** from time × speed (spike 001). Nothing about a dot is stored, so nothing about a dot can be styled per instance.
3. Position on the line is **recorded time**, always. No visual rule may reorder or re-space the **line** (D-12, D-15, D-16). The **canvas bridge** is not the line: it is a map of the thread, and it compresses empty stretches (L-6, § Bridge time scale).

## Spacing Scale

Declared values (multiples of 4, identical to 02.1 and 02.2):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Author swatch-to-id gap, marker-to-label gap, scrubber tick inset, legend row gap, ghost offset below the strand |
| sm | 8px | Header item gap, popover item gap, settings row gap, chip padding, minimum pill-to-pill clearance on the bridge |
| md | 16px | Typer inner padding (sides), scrubber margin from window edges, session pill label offset |
| lg | 24px | Typer padding block, popover padding, gap between the typer and the stage |
| xl | 32px | Gap between header rows and the typer body; stage side inset |
| 2xl | 48px | Typer offset from the top of the window; gravity hover radius (D-17); **squashed-gap dash run on the bridge** (L-6) |
| 3xl | 64px | Minimum stage height reserved below the typer before the view switches to list-only |

Exceptions, each with its reason:

- **Typer max width 688px.** 688 − 2 × 24px padding = 640px of text, about 75 characters at Body 16px — the upper end of comfortable measure, and the same reading width for live writing and for a past stage.
- **Typer height: min 160px, max 44% of the window height, then scrolls.** 160px holds the header row plus three Body lines (3 × 24px) and the 24px padding block; 44% keeps more than half the window for the line, which is the point of the live view (D-09).
- **Scrubber bar 32px tall.** Inherits the 02.1 toolbar hit target (32px), so the only draggable chrome in the view is as tall as every other control.
- **Session pill diameter 12px to 32px**, on a log scale from ≤100 to ≥5,000 letters. 12px is the smallest disc that still reads as a disc rather than a dot at 100% zoom; 32px matches the 02.1 hovered connection-handle bubble, so the largest "planet" never out-sizes an existing canvas control.
- **Session pill pointer target: `max(pill radius, 12px)`** — a 24px minimum target, so the smallest pill is as clickable as the largest (DRAW-04).
- **Bridge time scale: 2px per minute of thread time** at 100% canvas zoom, with gaps over 30 minutes squashed to a 48px dash run (§ Bridge time scale, TA-02).
- **Minimum pill centre-to-centre on the bridge: `r₁ + r₂ + 8px`.** Two sessions minutes apart must still read as two pills.
- **Marker glyphs 6–8px, drawn in screen space, with a 20px pick radius.** 8px is the smallest ring whose hole survives one device pixel of anti-aliasing at DPR 2; screen-space sizing keeps a marker the same size at every zoom, because a marker means "a thing happened here", not "a thing this big happened here".
- **Strand lateral separation 6px** (clamped 4–12px as zoom changes). 6px is two strand widths (1.5px each) plus a 3px gap, the narrowest separation where two strands still read as two at 100% zoom.
- **Strand drag-apart travel: 120px maximum.** Equals the 02.2 agents command block max height and about one third of the typer width, so pulling a strand out never covers the document above it.
- **Glyph LOD floor: 7px em.** Below 7px the atlas glyph is noise (spike 002b read cleanly at 8px); under the floor the stage draws the ribbon and dots only, and the DOM typer carries the reading (DRAW-03).
- **Glyph LOD ceiling: 240px em** — the largest size spike 003b validated as razor-sharp ("straight edges and true corners at 240 px"). Above 240px the letter stops growing; nothing else stops zooming. This replaces the 48px clamp of revision 1, which was a placeholder for the 003 verdict.
- **Author-underlay reveal threshold on the stage: 24px glyph em** (TA-03). Below it, authorship is carried by strand position, dash pattern and the legend; at or above it, "examining closely" is literal and the underlay band draws.
- **Live-view dot diameter 3px at the head**, collapsing to a solid line when spacing falls under 1.5px (spike 001's `fwidth` rule). 3px is the smallest filled disc that survives perspective minification without shimmering.
- **Time-out / time-in dash: 2px × 16px cross bar** on the stage; **2px × 12px** on the canvas bridge, where it also marks a squashed gap. 2px matches the 02.1 passage bracket thickness (the established "this is a structural mark" weight).
- Carried from 02.1/02.2 unchanged: 32px control/hit targets, 28/32px control bubbles, 8px note radius, 16px knot radius, 300ms submenu grace, 440px dialog width, 6s transient notice duration.

## Typography

Same four roles and two weights as 02.1 and 02.2. **No new size and no new weight.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Note Title | 18px | 600 (semibold) | 1.25 |
| Label | 13px | 400 (regular) | 1.4 |
| Heading | 22px | 600 (semibold) | 1.25 |

Phase 2.3 role assignments:

- **Thread document text** (live and read-only): Body. Identical to every other note (D-02 universal editing) except for its font **file** (§ Design System, TA-25): the thread document renders in the bundled face so the typer and the line agree.
- **Thread title** in the overlay header and on the ThreadCard: Note Title.
- **Save state, loading and catch-up status, session dates, gap durations, actor ids, marker labels, scrubber tick labels, settings rows, legend rows, notices**: Label.
- **Session pill number** (drawn inside a pill ≥24px): Label at 600 weight — the one place the semibold weight appears at Label size, because it sits on a filled disc and must survive the colour behind it.
- **Dialog title**: Heading. **Dialog body**: Body. **Dialog buttons and helper text**: Label.
- **Stage letters**: not DOM type. They render at their projected size between the 7px floor and the 240px ceiling. They are the document's own characters at the document's own size in world units — they are not a type role and must never be re-sized for emphasis. Font **marks** (serif, mono, size) do not apply on the line; the display **colour** does (§ Two colour channels, TA-09).

### Two colour channels (L-7, D-21)

There are **two independent colour channels on every letter**, and they must never be confused:

| Channel | What it means | Who sets it | Where it is drawn |
|---------|---------------|-------------|-------------------|
| **Display colour** | How the text is styled | Whoever wrote it — **a human or an agent** — through the 02.1 `textColor` mark in the FloatingToolbar or through an MCP call. Default: `--tap-ink` | The **glyph itself**, in the typer and on the line |
| **Author underlay** | Who wrote it | Nobody. The host derives it from the commit's actor id; it is never written to `.tree` | **Beneath** the glyph: a wash in the typer, the strand and an underlay band on the stage |

Rules that keep the channels apart:

1. **An agent may set the display colour only on letters it wrote** (D-22). A display-colour change is an ordinary recorded edit and drops a formatting marker on the line like any other (D-02).
2. **The author underlay exists for every author, including Kaelen** (L-7). There is no author without an underlay colour.
3. **The underlay is always beneath, never instead of.** D-21's words: "at least as an underlay beneath the font colour."
4. **A letter's display colour can never be mistaken for authorship**, because the underlay is a *band behind the text* and the display colour is *the text*, and because hovering any letter shows the literal actor id.

**Revealing the underlay without striping the typer (TA-03).** The underlay is always in the data; it is drawn on close examination, by three routes:

| Route | Behaviour | Default |
|-------|-----------|---------|
| Hold `Opt` (`Alt`) | Every letter in the typer shows its author wash while the key is held; releasing it returns the plain reading surface | **On** — momentary, so ordinary writing is never striped |
| Hover a run of text | Only the hovered run shows its wash, plus the actor-id chip (D-21) | On |
| "Always show author colours" in Thread settings | Latches every wash on permanently, for anyone who cannot hold a key or who wants it always | Off |

On the **stage**, "examining closely" is literal: the underlay band draws under a letter once its glyph em reaches **24px** (zoomed in), and below that authorship is carried by strand position, dash pattern and the legend. The **caret authorship readout** under the typer names the author of the text at the caret at all times, in words, with no key held.

Wash strength: **18% of the author colour**. Ink on an 18% wash stays above 9.8:1 for every author colour, computed 2026-09-15 (magenta 10.63, green 10.86, orange 10.90, purple 10.93, red 10.60, unknown 10.98, Kaelen's charcoal 9.89).

3. **Colour is never the only cue** (DRAW-04). Every surface that colours an author also carries at least one of: the literal actor id in text, a per-author underline pattern, or the letter's position on its own strand.

| Agent 2 | 1px dashed (4px on, 2px off) | dashed |
| Agent 3 | 1px long dash (8px on, 2px off) | long dash |
| Agent 4 | 1px dash-dot | dash-dot |
| Agent 5 | 1px double rule | double |
| Unknown | 1px wavy | wavy |

The person's underline is **solid** rather than absent, because under L-7 the person is an author like any other; it is only ever visible while the underlay is revealed, so the ordinary reading surface is still plain.

### Ghost letters (L-8, TA-08)

Kaelen's words: "faded with a line through them, like ghosts." So a deleted letter is **both** faded **and** struck through — revision 1 had struck-through only.

| Property | Value | Why |
|----------|-------|-----|
| Fade | **70%** of the display colour when it is `--tap-ink`; **80%** for any other display colour | Ink at 70% composites to #696867, **5.10:1** on paper (AA). Every other palette colour at 70% falls to 2.8–3.0:1, so those ghosts fade only to 80% (3.31–3.54:1), which clears the 3:1 graphics floor. No ghost is ever drawn below 3:1 |
| Strike | 1px through the glyph, in `--tap-thread-line` at **full strength** | The "deleted" cue itself never depends on the faded glyph, so a ghost is identifiable even where the fade is hardest to see |
| Offset | 4px below the strand | Ghosts sit in their own band, so live text never reads as crossed out and a dense stretch of deletions never obscures what survived |
| Deletion marker | A cross-tick at the moment of the **deletion** | The ghost says *what*, the marker says *when it went* |

A ghost written in a light display colour is the one text in this phase that can sit under AA. Its readable equivalent is one click away and is stated in the UI: **click the line just before the deletion and the typer shows those letters at full strength** in the past stage (D-18). That is the "different presentation conveys the same information" route, not an exemption claimed by assertion.

### Non-text contrast audit (WCAG 1.4.11, checker recommendation 4)

The 02.2 exemption that let `Line #B0ADA6` (2.06:1) run as a connection stroke does not transfer, so the thread line is darkened. ### Where opacity is and is not used

The live view fades **by distance only** (D-14). To keep that promise honest and auditable, this is the complete list of opacity reductions in the phase; there is **no age-based fading anywhere** — a ghost is faded because it was *deleted*, never because it is old:

1. Perspective distance in the live view (letters and dots), reaching 0 at the far plane — this is the projection, not a rule.
2. Gaps at 30% — a line, no text.
3. The silent strand inside a shared stretch at 25% — a line, no text.
4. The overlay surface at 97% over the canvas.
5. Dots at 55% of ink.
6. Author underlay washes at 18%, and only while revealed.
7. **Ghost letters at 70% / 80%** (L-8), floored at 3:1, with a full-strength strike.

Live text is never drawn below full strength.

## Theming (L-5)

Kaelen: "paper like everything else, but we should have different themes to get a space theme." Two consequences, both binding on this phase:

1. **The stage stays on paper now.** Nothing in 2.3 is drawn on a dark backdrop, and the contrast table above is computed on `#F7F5F0`.
2. **Every colour is a named token, so a theme can rebind it.** This is the work 2.3 must do so that a later theme is a values change, not a rewrite.

| Rule | Detail |
|------|--------|
| No hex at a use site | CSS uses `var(--tap-*)`; React components take token names, never literals; the stage's shader uniforms are loaded from the same token values |
| One source | Tokens are declared once, in `:root` in `app/src/renderer/App.css`. The WebGL stage reads the computed values at start-up (`getComputedStyle`) and converts them to linear floats |
| Theme change is a uniform re-upload | Changing a token re-uploads stage uniforms; it must never rebuild geometry, re-parse history or regenerate the glyph atlas |
| Token names in this phase | `--tap-paper`, `--tap-surface`, `--tap-surface-sunk`, `--tap-ink`, `--tap-muted`, `--tap-line`, `--tap-border`, `--tap-accent`, `--tap-destructive`, `--tap-destructive-text`, `--tap-thread-line`, `--tap-author-self`, `--tap-author-1` … `--tap-author-5`, `--tap-author-unknown`, `--tap-overlay` |
| New in this phase | `--tap-thread-line` #8E8A80 (TA-19) and `--tap-destructive-text` #B4232A (TA-20). Both are neutral/red ramp additions, not new hues |

**The dark "space" theme is a later phase, not 2.3.** When it is built it must, before anything else: re-derive all seven author colours against the new surface (five of them are between 4.57:1 and 4.96:1 on paper and will not survive a dark backdrop unchanged), re-derive `--tap-thread-line`, `--tap-ink` at 55% for dots, `--tap-destructive-text` and `--tap-accent`, re-check the seven opacity uses above, and re-run this contract's non-text audit. Recorded in § Deferred Ideas.

Tapestry ships **one theme today.** `app/src/renderer/App.css` contains no `prefers-color-scheme` rule (checked 2026-09-15) and this phase adds none; the token layer is what makes adding one cheap later.

### Loading and catch-up

Opening a thread is a replay: fetch every `thread.log` value, parse it, replay to a LetterIndex, then rebuild the stage buffers (RESEARCH Pattern 1). At this phase's reference load — **8 h, 78k keystrokes, 62k drawn letters** (spikes 001/003/004) — that is a real wait, and it is the wait revision 1 declared nothing for. `SaveIndicator`'s three states describe **writing**; these describe **reading back**. The counted form is 02.2's, verbatim in shape.

| State | Where | Copy | Style |
|-------|-------|------|-------|
| Replaying history on open | Header status slot | "Catching up ([n] of [total] changes)" | Label, `--tap-muted` |
| Replaying history on open | Under the typer, one line | "This is the last saved text. Writing starts when the history has finished loading." | Label, `--tap-muted` |
| Building the stage after replay | Centred under the line, in the stage area | "Drawing the line ([n] of [total] letters)" | Label, `--tap-muted` |
| Ready | Header status slot | The status line is replaced by the ordinary save state ("Saved") | Label, `--tap-muted` |
| Finding a past stage (doc-at-T, slow case) | Header, in place of the read-only line | "Finding the document at [time]…" | Label, `--tap-muted` |
| Past stage ready | Header | "Reading [date], [time] — read-only" with **Return to now** | Label |
| Catch-up failed | Header, then the notice | "Couldn't finish reading this thread's history — [reason]. The last saved text is below and is read-only. Choose Show tree file in Finder to look at it." Actions: **Show tree file in Finder** / **Close thread view** | `--tap-destructive-text` |

Rules that make those states honest:

1. **Nothing blank, ever.** The typer opens immediately with the node's last **checkpoint** text — the same text the no-plugin fallback shows — so a reader can read and copy within one frame of opening. The stage area shows paper with the ribbon drawn as soon as session times are parsed (the ribbon needs no glyphs); letters fill in behind it. There is no spinner and no empty rectangle anywhere in this phase.
2. **Read first, write a moment later.** While catching up, the typer is read-only, because the collab authority has not rebuilt the document yet and a step pushed against a stale version would rebase wrongly. Focus stays in the typer; the caret appears and writing unlocks when the status clears. A keystroke during catch-up is not swallowed silently — it shows the under-typer line above.
3. **400ms threshold.** No loading status appears for a wait under 400ms; a short thread opens with no status at all, and nothing flashes.
4. **Counts always advance.** Both counted statuses take their total up front: `[total] changes` is the number of `thread.log` values the addon returned, and `[total] letters` is known once replay finishes. Neither is an estimate.
5. **Scrubbing does not get a loading state in the normal case.** Doc-at-T replays at most one checkpoint interval (~60s of steps) and is throttled to one redraw per frame, so it is expected to land inside a frame; the previously shown stage stays on screen until the new one is ready, and the text never blanks or flickers. "Finding the document at [time]…" appears only if a single doc-at-T exceeds 400ms. That expectation is **spike 008's** to confirm; the 400ms copy above is what the UI shows if it does not hold, so no clause here depends on the verdict.
6. **Glyph sharpening is never a loading state.** A letter is drawn immediately from its browser-SDF cell (~0.5ms) and is replaced by its MSDF cell when that finishes (§ Spike verdicts). A letter is never absent, and no status is ever shown, because its sharp cell is not ready.

Announcements for these states are in § Screen-reader announcements.

Destructive actions in this phase, in full:

| Action | Confirmation | Why |
|--------|--------------|-----|
| Delete thread | Dialog above (TA-06) | A thread carries far more than a note's text; the dialog says plainly what survives |
| Delete a letter, delete a word, Cmd+Z | **None, ever** | Nothing is erased (D-03, D-04). The letters stay on the line as ghosts |
| Make this note a thread | **None** — an explain chip instead (below) | Recorded, undoable, adds nothing the note didn't have |
| Change the time-out or the slowdown | **None** | An ordinary recorded edit; past dashes never move |
| Change a letter's display colour | **None** | An ordinary formatting edit, and it cannot touch authorship (§ Two colour channels) |

**Button labelling rule (carried from 02.2):** every button names its action with a verb and a noun. Dismiss buttons say what stays the same. No button in this phase reads "Cancel", "OK", "Continue", "Done", "Open", "Dismiss" or "Try again".

| `Enter` on a focused point or session | The same as clicking it |
| "Return to now" / Escape | Leaves the past stage, returns the typer to the live document and puts the caret back where it was |

**Past stage (read-only) treatment:** the typer keeps its surface and Body type; its border becomes 1px solid `--tap-thread-line`, the caret is hidden, and the header reads "Reading [date], [time] — read-only". Text stays selectable and copyable (D-08). Writing from a past stage is **not** in this phase — it branches the thread, which is Phase 3 — so keystrokes there do nothing except show the notice: "Writing from an earlier moment will branch the thread. That's coming with branching history. Choose Return to now to keep writing."

**Gap and scrubber honesty (D-16):** in the side view a two-week gap occupies two weeks of line — **always, with no compression**. The scrubber is linear in true time, with a 1px `--tap-line` tick per day and, on days with writing, an Ink bar whose height is that day's letters relative to the busiest day. The current view is a 2px accent bracket.

### Marker meaning without the stage

Markers are stage-only graphics, so their meaning is carried twice over, and neither route is a hover:

1. **`,` / `.` step between markers** when the stage has focus, announcing each marker's label (the same text the hover chip shows).
2. **The SessionList mirrors them.** Every session row expands to a `MarkerList`: one row per marker in time order, reading "[marker label] · [time]", focusable and `Enter`-activatable to open that moment. This is the list the no-stage fallback shows, so a machine with no WebGL loses no meaning at all.

### The thread on the 2D canvas (D-07)

| Element | Behaviour |
|---------|-----------|
| ThreadCard | An ordinary NoteCard showing the document's title and current text, draggable, connectable and deletable like any note |
| Session bridge | Below the card: a 1.5px `--tap-thread-line` horizontal line carrying one session pill per session, joined end to end — "a bridge of session notes joined by the line" |
| Spacing on the canvas | **By real elapsed time, with long empty stretches squashed** (L-6) — see Bridge time scale below |
| Overflow | Above 9 sessions the bridge shows the first 4, a "+[n]" pill, and the last 4. Clicking "+[n]" opens the Sessions list |
| Click a pill | Opens the thread overlay in the side view, flown to that session, showing the document as it was then |
| Pill affordances | None beyond clicking (L-3): no drag, no connect handle, no delete bubble, no context menu |
| Card menu | "Open thread", "Thread settings", "Delete thread" |

#### Bridge time scale (L-6, TA-02)

Kaelen: "by real time, and maybe squashing with the dashes and eliminating empty space."

| Rule | Value | Why |
|------|-------|-----|
| Scale | **2px per minute** of thread time at 100% canvas zoom | An hour of writing is 120px — about half a note card, so a normal evening's thread reads as one object |
| Squash threshold | A stretch with **no writing for more than 30 minutes** (60px at scale) is squashed | Below the threshold, real time is cheap enough to draw honestly |
| Squashed run | Drawn as **time-out dash · 48px of the gap's dotted stroke · time-in dash**, total 52px, whatever the true duration | The dashes are the existing vocabulary for "time passed here" (D-11), so the compression announces itself in the language the line already speaks |
| Label | "Away [duration] — shortened here", Label, `--tap-muted`, centred under the run | The true duration is always in words, so nothing is lost by shortening the drawing |
| Date readability | **Every pill keeps its own date label** under it, at every scale | A reader never has to measure the bridge to know when something happened |
| Crowding | Minimum centre-to-centre `r₁ + r₂ + 8px`. If real time puts two pills closer, they are pushed to the minimum and that segment is drawn **solid** (no dashes) | Two sessions minutes apart still read as two pills, and the absence of dashes marks "these are close together", the mirror of the squash |
| Total width | Max 960px at 100% zoom. Past that the existing first-4 / "+[n]" / last-4 overflow applies | A thread is a note on a canvas, not a ruler across it |

**Reconciling with D-16 — the two must be stated together, because they differ on purpose:**

| Surface | Gaps | Why |
|---------|------|-----|
| **Side view** (the line itself) | **True length, always.** A two-week gap occupies two weeks | D-16. The side view *is* the timeline; its honesty about time is the point of the feature, and the scrubber is linear in true time to match |
| **Canvas bridge** | **Real time, with stretches over 30 minutes squashed to a 52px dash run** | The canvas has no time axis — it is a spatial map where a thread sits beside unrelated notes. At true scale one two-week gap would push the newest session 40,000px away from its own card, off every screen. The squash is marked by dashes and stated in words, so it is never mistaken for true time |

### Agents writing live (D-20 … D-23, L-2)

| Trigger | Behaviour |
|---------|-----------|
| Agent writes into a shared thread | The text lands at the moment it arrived — a whole write is one cluster, streamed text spreads as it streams. It is never replayed as fake typing (D-20) |
| Agent text at or after the caret (L-2) | It lands **after** the caret. The caret does not move, and unsent keystrokes are rebased and never lost |
| Agent text off screen | Transient chip, 6s: "agent.[name] added [n] letters above." **Show the change** scrolls there without moving the caret |
| Agent sets a display colour (L-7) | Allowed **only on letters that agent wrote** (D-22). It is an ordinary recorded formatting edit with its own marker; it cannot change any author underlay |
| Two authors in the same stretch | Two strands run side by side, 6px apart, and twist — one smooth crossing per 1.0s of thread time — through any stretch where both authors wrote within a 2s window (TA-11). Outside shared stretches they run parallel and the silent strand drops to 25% |
| Hover a letter or a strand | A chip shows the literal actor id (`agent.claude`) on the PassageChooser surface (D-21), and that run's underlay wash appears |
| Drag a strand perpendicular to the line (D-23) | The strands separate, up to 120px, each author's letters on their own line, with the chip "Showing agent.[name] on its own. The document hasn't changed." Release springs them back over 240ms. **The document is not modified** |
| `A`, or "Show each author on its own line" | The keyboard equal of the drag: a latched separated view, released by pressing `A` again (DRAW-04 — the drag is never the only route) |
| Agent tries to delete or rewrite a letter it didn't write (D-22) | Refused; nothing is committed. No modal and no interruption to writing. The Authors legend row gains "· [n] changes refused" with the explaining tooltip, and the refusal is announced once (TA-07) |

### Thread settings (D-10, D-13)

Opened from the gear in the overlay header, and from the ThreadCard menu (TA-13). A popover on the PassageChooser surface, min width 320px, 24px padding, dismissed by clicking outside or Escape. Every change is an ordinary recorded edit and takes effect from now on; the recorded-outcome note is always visible, because past dashes must never move when a setting changes.

The slowdown table edits the D-11 curve directly as "after [n] seconds · [n] a second" rows, with a live 240px preview strip showing the dot spacing the current curve produces over a two-minute pause.

### No-stage fallback (no WebGL, or graphics lost)

The thread must stay usable without the stage — the project's readability constraint applies to the feature itself, not only to its files.

| Situation | What is shown |
|-----------|---------------|
| WebGL unavailable | The typer stays, full width of the overlay. Where the stage would be, `StageFallbackPanel` shows the SessionList: one row per session with date, duration, letter count and authors, each expanding to its `MarkerList`; Enter opens that stage read-only. Writing works normally and history is recorded normally |
| Context lost mid-session | The error notice with **Redraw thread**; buffers rebuild from the records, never from the screen. The rebuild shows "Drawing the line ([n] of [total] letters)" |
| Threads plugin disabled | FallbackNodeView with the checkpoint text and its notice (see Copywriting) |

### Keyboard map (DRAW-04 — every navigation action has a key)

| Key | Action |
|-----|--------|
| `Esc` | Return to now, then close the thread view |
| `Tab` / `Shift+Tab` | Typer → Authors → Sessions → Settings → scrubber → stage focus point |
| `[` / `]` | Previous / next session |
| `,` / `.` | Previous / next marker on the line |
| `+` / `-` | Zoom out / in |
| Arrows | Pan (stage) or move one day (scrubber), by focus |

Focus order inside the overlay is trapped. `:focus-visible` rings are 2px accent at 2px offset on every new control. No action in this phase is reachable by hover alone.

### Motion and `prefers-reduced-motion`

No reduced-motion rule exists in the renderer today (checked 2026-09-15); this phase introduces the first one, and it must be honoured by the stage as well as by CSS.

| Under `prefers-reduced-motion: reduce` | Behaviour (TA-12) |
|---|---|
| Live streaming | **Off.** The stage stops animating per frame. The line still grows: it is redrawn when a letter lands, and at most 4 times a second while idle, so the geometry, dots, dashes and slowdown are all still visible and still correct |
| Fly-to | Instant jump, with the polite announcement, instead of the interpolated flight |
| Gravity | Off, and the settings toggle shows as off |
| Strand twist | Drawn as static crossings; no animated weave |
| Strand drag-apart release | Snaps instead of springing |
| Transient chips | Appear and disappear without fade |
| Loading and catch-up statuses | Text only; no animated ellipsis, no pulsing, no skeleton shimmer |

Nothing is removed by reduced motion — only the movement between states.

### Costs carried forward as constraints (the planner must respect these)

| Constraint | Evidence | Consequence for plans |
|------------|----------|----------------------|
| **MSDF generation runs off the main thread** | 7.7–8.1ms typical per glyph, **22.6ms worst case** (003b) — too close to a 16.7ms frame. The atlas copy itself is 0.03–0.22ms on main | `msdfgen-wasm` runs in a web worker. The main thread only copies finished cells |
| **Atlas warm-up is visible on a cold cache** | A cold 8h build ≈ 679 glyphs × 8ms ≈ **5.4s** (003b); a warm atlas made the same 8h build cost 1.63s | Letters draw from their **browser-SDF cell in ~0.5ms** and are replaced by MSDF cells as they arrive, so warm-up is never a wait (§ Loading and catch-up rule 6) |
| **A glyph cache belongs to the app, not to a thread open** | 003b: "The 8 h build cost almost nothing here because the 1 h atlas was still warm" | One cache shared across threads and across opens, persisted for the session; never rebuilt per overlay |
| **Memory ceiling** | 122–127MB private at 1h and 8h with MSDF, against 71–79MB with SDF only (003a/003b). Instances cost 56 bytes each: 3.4MB of GPU buffers at 8h | Budget **≤150MB private** at the 8h / 78k-letter reference load. Exceeding it is a defect, not a tuning note |
| **Atlas paging** | A 2048px atlas holds **1024 cells** (`003-shared/glyph-layer.js`) | A thread with more than 1024 distinct graphemes (CJK) needs a second page or LRU eviction. Untested by 003; **spike 007 is queued for it** |
| **Font files only, no `.ttc`** | msdfgen takes font files; macOS ships Hiragino and PingFang as `.ttc` collections (003b) | The thread document ships and uses a **bundled single-file face** for both the typer and the line (TA-25) |
| **Emoji and non-Latin fallback path** | Colour emoji cannot be distance fields — both variants draw them as **colour bitmap cells** with a per-instance kind flag. msdfgen has **no cluster shaping**: "स्ते" renders as "स" only, where 003a shapes the whole grapheme through the browser | Three cell kinds in one atlas, chosen per instance: **0 = browser SDF** (shaped clusters, scripts the bundled face lacks, and the immediate cell), **1 = MSDF** (the default for anything the bundled face covers), **2 = colour bitmap** (emoji). The SDF↔MSDF swap is **untested** by 003b; **spike 007 is queued for it**, including whether a cell swap is visible as a pop |
| **Joining scripts can't be read along the line** | Arabic shows isolated forms in both variants, because each letter sits at its own keystroke time (003a §4, 003b §7) | Declared limit, not a defect. The DOM typer carries readable text for those scripts, and the past stage is the route to reading them |
| **A large paste on a cold atlas can drop one frame** | 33.4ms, 1.1% of frames, empty thread, cold atlas; with a warm atlas it dropped nothing (004 §5) | Acceptable, and further reduced by off-main-thread generation. It must never delay the keystroke path |
| **IME composition is unverified** | 004: "Input-method composition still needs a human check" | The plan carries spike 004's `checkpoint:human-verify`; no UI value here depends on its outcome |
