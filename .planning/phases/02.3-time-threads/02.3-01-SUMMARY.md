# Phase 02.3 Plan 01: Free the name "thread" — rename 2.1's centre note to the knot Summary

**Phase 2.1's centre-note connection is now the knot with knot-ties: `KnotNode.tsx` owns `KNOT_TYPE`/`KNOT_TIE_LABEL`, the substring node-type test became an exact `===` match, and the CSS renamed selectors without touching a single declaration value.**

## Accomplishments

- `ThreadCenterNode.tsx` renamed to `KnotNode.tsx` via `git mv`, so history follows the file (recorded as R100 in the commit).
- `KnotNode.tsx` now exports `KNOT_TYPE = 'tapestry.notes/knot@1'` and `KNOT_TIE_LABEL = 'knot-tie'` alongside `KNOT_WIDTH` / `KNOT_MIN_HEIGHT`, so one module owns every spelling and no second copy can drift.
- The substring predicate `node.type.includes('thread-center')` became `isKnot(n) => n.type === KNOT_TYPE`, closing threat T-02.3-01-01: a world file can no longer supply a type such as `evil/knotwork@1` and have it accepted into the knot render path.
- All **four** `'thread-arm'` edge-label comparisons now test `KNOT_TIE_LABEL` (the plan predicted three).
- `App.css` selectors became `.knot-node` / `.knot-editor`; a diff filter proves **zero declaration lines changed**, so every 02.1 visual value is carried through byte for byte.
- The grep gate over `app/src`, `plugins` and `sdk` for all four old spellings returns no matches.

## Issues Encountered

- **The knot feature has no way to be exercised in the current build.** Nothing in the app creates a `thread-center`/knot node or a `thread-arm`/tie edge: the only node type ever constructed is `tapestry.notes/note@1` (`app/src/main/commands/notes.ts:37`, `plugins/tapestry-notes/index.js:26`, `App.tsx:225`). The old substring predicate and the new exact predicate therefore both match zero live nodes, which makes this rename behaviour-preserving in practice — and makes the outstanding visual check (D4) impossible to perform until a later plan can create knots. This matches CONTEXT D-26's reversibility note that "no saved world contains these types and nothing in the app creates them yet". Flagged so it is not mistaken for a regression introduced here.
- **`KNOT_TYPE`'s value is new, not migrated.** The old predicate matched any type *containing* `thread-center`; no such literal was produced anywhere, so `'tapestry.notes/knot@1'` is a fresh canonical value with no existing data to migrate (consistent with the plan's `reversibility` rating).
- **First commit initially captured only the file rename.** The `git add` listed the now-deleted `ThreadCenterNode.tsx` path, which aborted the whole `git add` invocation, so the commit picked up just the staged `git mv`. Caught immediately by the mandatory post-commit `git show --stat` check, and corrected with `git commit --amend` (unpushed, own branch, no other session's work in the index). Both commits verified to contain only this plan's paths.
