<objective>
**As a** person who may one day not have Tapestry, **I want to** open a thread's `.tree` file in a text editor and understand how the document was written, **so that** the meaning of my history does not depend on the application that made it.

This plan makes the tracer's grammar official: a reader's spec in `threads.md`, a worked section in `FORMAT.md`, real thread commits in the golden `example.tree`, and a cross-layer test proving the committed fixture replays to its own checkpoint. It also delivers the other half of readability — a thread stays usable when the threads plugin is switched off.

Purpose: D-06 requires FORMAT.md and `example.tree` to change together. The project constraint requires the feature to degrade to something readable, not to nothing.

Output: the grammar documentation, extended golden commits, the replay module, and the no-plugin fallback.
</objective>

  <action>
    Write `app/src/shared/threads/replay.ts` as pure TypeScript, exporting `replayTo(checkpointDoc, records, untilMs)` and `docAt(commits, tMs)`.

    `docAt` finds the last `body` checkpoint commit whose records end at or before `tMs`, then replays the record lines with time at or before `tMs` on top of it. Records are grouped by **commit order, then line order** — never sorted by time. Sorting by time is the failure mode to avoid: after a rebase a user's steps can land in a commit following an agent's while carrying earlier times, and replaying them in time order applies them at the wrong positions. Cache the document at each checkpoint so a scrub replays at most one checkpoint interval.

    Track deleted letters rather than removing them: a deletion records a `deletedAtMs` against the letters it removed, so the caller can draw them as ghosts (D-03) and mark the moment they went. `replayTo` returns both the document and the letter table.

    Write `replay.test.ts` covering: `docAt` at a checkpoint equals the stored checkpoint body exactly; `docAt` between checkpoints equals the state after replaying the prefix; and the interleaving case — records committed after another author's commit but carrying earlier times replay to the correct document, which a time-sorted implementation gets wrong.

    Write `app/src/shared/threads/fixture.test.ts` as the cross-layer golden. It reads the committed `tapestry/docs/tree/example.tree` from disk, extracts the `thread.log` block values by scanning for the `set … thread.log text` op and its block delimiter, parses them with `parseBlock`, replays them with `replayTo`, and asserts the result equals the `body` checkpoint stored in the same fixture. This is the test that catches the C++ writer and the TypeScript reader drifting apart, so it must read the real committed file and never an inline copy of it.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.tree` file → `parseBlock` on open | A hand-edited, corrupt or hostile log is parsed into documents |
| checkpoint body → fallback renderer | Stored document text is rendered outside the editor |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.3-03-01 | Denial of Service | `parseBlock` on a malformed log | high | mitigate | The parser is strict and returns a rejection; the thread enters the read-only unreadable-history state with its checkpoint text shown, so a half-read history can never be the base for a new commit. `fallback.test.ts` pins the corrupted-value case |
| T-02.3-03-02 | Tampering | replay ordering | high | mitigate | Replay is by commit order then line order, never by time; `replay.test.ts` includes the interleaving case a time-sorted implementation fails |
| T-02.3-03-03 | Information disclosure | fallback body rendering | low | accept | The body shown is the same document text the owner already has in their own file, rendered in their own app; no new audience gains access |
| T-02.3-03-04 | Tampering | writer/reader drift between C++ and TS | medium | mitigate | `fixture.test.ts` reads the real committed `example.tree` rather than an inline copy, so a change on either side fails the cross-layer golden |

No package-manager install occurs in this plan, so no package-legitimacy gate applies.
</threat_model>
