# Phase 02.3 Plan 03: Publish the grammar, replay any moment, and stay readable Summary

**The `thread.log` grammar is now a published reader's spec with a 10-commit golden fixture proving it, a pure-TS `replayTo`/`docAt` reconstructs any thread's document at any past moment from that fixture alone, and a thread degrades to its readable checkpoint text — never a crash — whether its plugin is disabled or its own history fails to parse.**

## Accomplishments

- `tapestry/docs/tree/threads.md`: the complete `thread.log` reader's spec — every verb (`in`/`out`/`ins`/`del`/`mark+`/`mark-`/`step`/`marker`/`cont`), the escape set, and the two rules a reader needs most: author is the enclosing commit's `actor` line (never a field inside the block), and replay order is commit order then line order, which genuinely differs from time order after a rebase.
- `FORMAT.md`'s new "Plugin data with its own readable grammar" section (after § Extension lines), plus a commit-by-commit walkthrough of the four new golden commits and why `x-` extension lines are the wrong tool for this content.
- `example.tree` grows from 6 to 10 commits, byte-identical through commit 6: a `tapestry.threads/thread@1` node with its D-27 frame and D-10/D-13 settings, two `thread.log` batches exercising `in`, a plain `ins`, a `paste`-caused `ins`, an `undo`-caused `del`, a plain `del`, and `out`, and a `body` checkpoint (`"Hi Sam"`) that is exactly what those batches replay to.
- `readability_test.cpp`'s `buildGoldenWorld` extended with the four new commits; every pinned line-count assertion and the reopened-world node/edge checks updated to match — the regenerated fixture is byte-identical to what is committed, and the full 63-test kernel suite is green.
- `app/src/shared/threads/replay.ts`: pure TypeScript `replayTo`/`docAt` (D-08, D-18). Applies `ins`/`del` records in exactly the order given — never resorted by time — and tracks every letter ever inserted with `insertedAtMs`/`deletedAtMs` rather than dropping deleted ones (D-03). `docAt` finds the last `body` checkpoint at or before a moment and replays only what came after it, so a scrub never replays more than one checkpoint interval.
- `replay.test.ts` (9 tests) proves the interleaving case explicitly: two records where the second-committed one carries an earlier time replay correctly in commit order (`'YX'`), and are shown to differ from what sorting the same two records by time would produce (`'XY'`).
- `fixture.test.ts` (2 tests): the cross-layer golden. Reads the real committed `example.tree` from disk, extracts both `thread.log` blocks for the thread node, replays them, and asserts the result equals the fixture's own `body` checkpoint.
- `ThreadService.open()` no longer throws on a malformed `thread.log` value (T-02.3-03-01): it falls back to the last `body` checkpoint, reports `{unreadable: true, unreadableReason}`, and registers no write handle, so a `push` against it refuses rather than building a new commit on a half-read history.
- `FallbackNodeView.tsx`: a disabled thread's `body` checkpoint now renders as the card's primary content — Body role, `pre-wrap`, selectable, never truncated, never an input — above its other typed properties (the last `thread.log` value stays visible there too). The notice reads the UI-SPEC copy verbatim, including the checkpoint's own saved date/time.
- `ThreadNotice.tsx`: the history-unreadable and graphics-lost notices, with their exact copy, named action buttons, `--tap-destructive-text` token throughout, and none of the seven banned generic button labels.
- `fallback.test.ts` (3 tests): a thread's checkpoint is retrievable through the ordinary `getNodes` path with zero thread-specific code running; a corrupted `thread.log` value yields `{unreadable: true}` rather than a throw; the resulting handle refuses a `push`.

**1. [Rule 3 - Blocking] `tsconfig.node.json` needed the `ES2022.Intl` lib for `replay.ts`'s `Intl.Segmenter` use**
- **Found during:** Task 2, running `npm run typecheck`

**2. [Rule 1 - Bug] `ThreadService.open()` threw on a malformed `thread.log` value instead of degrading gracefully**
- **Found during:** Task 3, writing `fallback.test.ts`'s corrupted-value case
- **Issue:** `open()` called `docFromFlatText(replayFlatText(blocks))` and `parseBlockHeader`/`parseBlock` with no error handling. A malformed `thread.log` value (a real possibility this plan's own threat register names, T-02.3-03-01) would propagate an uncaught exception out through `thread:open`'s IPC handler rather than the documented "becomes read-only" behavior the plan's acceptance criteria requires.
- **Fix:** Wrapped the parse/replay path in `open()` in try/catch. On failure, returns `{version: 0, doc: <last body checkpoint>, totalChanges, unreadable: true, unreadableReason}` and registers no write handle, so a subsequent `push` refuses (`Thread not open`) rather than building on a half-read history.
- **Files modified:** `app/src/main/threads/thread-service.ts`, `app/src/renderer/global.d.ts` (type addition)
- **Verification:** `fallback.test.ts`'s two `ThreadService.open` tests pass; existing `thread-service.test.ts` (3 tests) still passes unchanged.
- **Committed in:** `af9e40a`

**3. [Rule 3 - Blocking] `FallbackNodeView` had no path to a checkpoint commit's own `recorded` stamp**
- **Found during:** Task 3, writing the notice's "from [date], [time]" text
- **Issue:** The plan's action text requires the notice to name when the checkpoint was saved, taken from the commit that wrote it — but `node.props` (from the generic `getNodes` path) carries only each property's *current* value, with no per-property history. `getPropertyValues` already existed on `KernelBridge` (02.3-02) but was never exposed over IPC to the renderer, and `kernel-bridge.ts`/`preload/index.ts`/`global.d.ts` were not in Task 3's file list.
- **Fix:** Registered `kernel:getPropertyValues` in `KernelBridge.registerHandlers` as a generic, ungated read (the same treatment `kernel:getHistoryIndex` already gets — independent of any plugin's enabled state), added the matching `preload` method and `global.d.ts` types, and had `FallbackNodeView` call it for the thread's `body` key.
- **Files modified:** `app/src/main/kernel-bridge.ts`, `app/src/preload/index.ts`, `app/src/renderer/global.d.ts`
- **Verification:** `npm run typecheck && npm run build:js` both exit 0; `FallbackNodeView`'s date/time only depends on this call resolving, degrading to the shorter notice sentence if it does not.
- **Committed in:** `af9e40a`
