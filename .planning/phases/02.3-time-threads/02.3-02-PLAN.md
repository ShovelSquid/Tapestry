<objective>
**As a** person writing into Tapestry, **I want to** open a thread, type into it, close the world and open it again and find every letter still there with the moment it was typed, **so that** the history of how a document came to be is mine to read — in the app, and in the `.tree` file without the app.

This is the phase's tracer: one letter travels the whole stack — ProseMirror transaction → recorder → collab push → ThreadService authority → `Kernel::submit` → `.tree` journal → addon read → parse → replay → back on screen. Every later plan expands outward from this proven path.

Purpose: D-06 is a **one-way door**. The keystroke record shape goes into append-only journals, so every thread ever saved keeps the first format forever. Proving the whole path on one letter, and locking the grammar with Kaelen before the first commit, is what makes the door safe to walk through.

Output: the `thread.log` grammar, the thread node type and its plugin, the main-process authority, the read path through the addon, and a thread card you can type into.
</objective>

  <options>
    <option id="proposed">
      <name>The proposed grammar, as RESEARCH.md Pattern 1 describes it</name>
      <pros>Every letter typed and deleted is quoted as plain readable text next to its millisecond offset. One step per line. Times are integer milliseconds off a per-commit RFC 3339 anchor, so no float ever decides where a letter sits. Author comes free and cannot be forged, because it is the commit's own host-stamped `actor` line and never a field inside the block. Node type `tapestry.threads/thread@1` matches the existing `tapestry.notes/note@1` convention.</pros>
      <cons>Verb tokens (`ins`, `del`, `mark+`, `step`, `marker`, `in`, `out`, `cont`) are terse; a reader meets them first in `threads.md` rather than guessing them. Anything the flat verbs cannot express falls back to an exact ProseMirror Step JSON on a `step` line, which is readable but noisy.</cons>
    </option>
    <option id="verbose">
      <name>Spelled-out verbs — `insert` / `delete` / `format` instead of `ins` / `del` / `mark+`</name>
      <pros>A first-time reader needs no legend at all.</pros>
      <cons>Roughly 30-40% more bytes per record on the commonest line in the whole format; at about one commit per second of typing this is the line that repeats most.</cons>
    </option>

      <name>Absolute RFC 3339 timestamps on every line instead of `+seconds.millis` offsets</name>
      <pros>Each line is self-dating with no need to read the block's `at` anchor.</pros>
      <cons>About 24 extra bytes on every keystroke line, and the millisecond precision the line needs is not expressible in the kernel's `time` value type, which is whole seconds — so it would still be text either way.</cons>
    </option>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (`thread:push`) | Untrusted step JSON, times and causes cross into the single write authority |
| pasted/typed text → `thread.log` record line | Arbitrary user text is encoded into a line-oriented grammar inside a block |
| `.tree` file → parser on reopen | A hand-edited or corrupt log is parsed back into documents |
| addon argument → kernel | JS values cross into C++ before any kernel call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.3-02-01 | Tampering | `grammar.ts` record encoding | high | mitigate | Every string is written with the FORMAT.md inline escape set, so a newline or a line equal to `TEXT` in pasted text cannot forge a record line or close the block early; the round-trip test pins exactly those inputs |
