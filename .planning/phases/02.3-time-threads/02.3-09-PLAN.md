<objective>
**As a** person who keeps notes in an Obsidian vault, **I want to** turn one of those notes into a thread without Obsidian ever seeing anything strange in the file, **so that** Tapestry's history is an addition to my vault rather than a takeover of it.

This plan lets a vault note be a thread: the `.md` file keeps only the current text, every timing and deleted letter lives in the vault's Tapestry tree, and an edit made in Obsidian arrives on the line as one honest observed cluster.

Purpose: D-25 is where this phase meets 02.2's bridge. The storage rule 02.2 established already makes room for it — `thread.log` is not an `md.` key, so it is Tapestry's own addition and belongs in the tree rather than the file.

Output: the vault thread path and its observed-edit attribution.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| vault `.md` file → thread records | File content written by any process on the machine becomes thread history |
| external author → attribution | The true author of a file edit is generally unknowable |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.3-09-01 | Spoofing | attribution of an external edit | high | mitigate | An observed edit is attributed `obsidian.bridge` unless 02.2's sign-in log proves a specific agent wrote that exact content. The user is never guessed as the author, so an edit by another process cannot be recorded as the person's own writing |
| T-02.3-09-02 | Tampering | record-line injection via file content | high | mitigate | File text is encoded through `grammar.ts`'s escape set like any other string, so a `.md` file containing a newline, a quote or a literal `TEXT` line cannot forge a record line or close the block early |
| T-02.3-09-03 | Denial of Service | a very large external edit | medium | mitigate | The observed cluster is diffed against the authority's document so only the change is recorded, and the over-1 MiB line split applies as it does to any other record |
| T-02.3-09-04 | Information disclosure | timings leaking into the vault file | medium | mitigate | The `md.` storage rule keeps every Tapestry addition in the tree; the test asserts the `.md` equals the current text byte for byte with no offsets, actor ids or front-matter block, and a negative grep asserts no direct filesystem write exists in this module |
</threat_model>
