  <action>
    Create app/src/renderer/editor/passage-plugin.ts. Define a PluginKey named passagePluginKey. The plugin state tracks: hoverPos (number or null representing the document position under the pointer), and allPassages (array of objects with anchorId, from, to extracted from all passage marks in the document).

    In the plugin's state.init, scan the initial doc using doc.descendants to find all passage marks and their positions. In state.apply, if the transaction changed the document, rescan all passage marks from the new doc. Map hoverPos through the transaction mapping (tr.mapping.map). Accept a setHoverPos meta key on the PluginKey to update hoverPos from mouse events.

    In the plugin's props.handleDOMEvents, register a mousemove handler. On mousemove, use view.posAtCoords with the mouse clientX/clientY to get the document position. Dispatch a transaction with setMeta on the passagePluginKey setting hoverPos to the resolved position. On mouseleave of the editor, set hoverPos to null.

    In the plugin's props.decorations callback, compute gradient decorations from the plugin state. For all passages: create an inline Decoration from each passage's from to to with class tapestry-passage-idle (the 8% accent background). If hoverPos is not null: filter passages whose from to to range contains hoverPos. Sort containing passages by span length ascending (shortest first). For index 0 (the smallest/innermost passage), apply class tapestry-passage-active. For index 1, apply tapestry-passage-level1. For index 2+, apply tapestry-passage-level2. These decoration classes REPLACE the idle class on the containing passages (do not double up). For passages not containing hoverPos, keep the idle decoration. Return a DecorationSet created from the doc and the decorations array.

    Equal-length tiebreaker (UI-SPEC backstop): if two passages have equal span length, the one appearing earlier in document order (lower from position) gets the stronger highlight.

    Export passagePluginKey and a createPassagePlugin factory function.

    In use-prosemirror.ts: import createPassagePlugin and add it to the plugins array when creating the EditorState. The passage plugin should be included for both NoteCard and ThreadCenterNode editors.

    Also export a getHoveredPassageAnchorId function from the plugin that reads the plugin state from an EditorView and returns the anchorId of the active (innermost) passage at hoverPos, or null. The useProseMirror hook should accept an onPassageHover callback prop. When the passage plugin detects that the active passage changed (different anchorId at hoverPos), call onPassageHover(anchorId) or onPassageHover(null). This lets Canvas know which passage is being hovered so it can highlight the corresponding thread and remote endpoint.

    Add CSS to App.css for the gradient classes per UI-SPEC Color section. tapestry-passage-idle: background rgba(74, 124, 255, 0.08). tapestry-passage-active: background rgba(74, 124, 255, 0.25), add a 2px left border (via box-shadow inset or border-left) in accent at 80% opacity. tapestry-passage-level1: background rgba(74, 124, 255, 0.15), 2px left border at 50% opacity. tapestry-passage-level2: background rgba(74, 124, 255, 0.10), 2px left border at 30% opacity. The left border renders as a passage bracket per UI-SPEC: a 2px-wide vertical bar on the left edge of the span. Use the CSS approach that works within ProseMirror's inline decoration rendering (border-left or box-shadow inset 2px 0 0 0).

    Thread endpoint highlighting (D-13): in Canvas.tsx (deferred to this plan's scope or wired by the consumer), when onPassageHover fires with an anchorId, look up the thread center node whose thread.sourceAnchorId matches, then highlight the source passage, the thread line, and the destination note. The Canvas tracks hoveredAnchorId state. ConnectionLine components whose from/to path passes through a thread center matching the hovered anchorId render with accent color and 2px stroke. The destination note gets a subtle accent border.
