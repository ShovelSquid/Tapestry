## Fixed Issues

### CR-01: Dragging a thread center never pins it and submits a kernel command on every pointer move

**Files modified:** `app/src/renderer/components/ThreadCenterNode.tsx`, `app/src/renderer/components/Canvas.tsx`, `app/src/renderer/App.tsx`
**Commit:** `edb13f0`
**Status:** fixed: requires human verification
**Applied fix:** Drag now updates a local `localPos` state on `pointermove`; `pointerup` calls a new `onPinnedPositionChange(nodeId, x, y)` exactly once. Canvas threads the new required prop through; App adds `handlePinnedPositionChange`, which submits `position.x`, `position.y` and `pinned: {type:'bool', value:true}` in a single "Pin thread center" commit. `localPos` clears when `x`/`y`/`isPinned` props converge (NoteCard pattern). A click without movement does not pin.

### CR-02: Empty ("ghost") thread centers can never be revealed

**Files modified:** `app/src/renderer/components/Canvas.tsx`
**Commit:** `80f7822`
**Status:** fixed: requires human verification
**Applied fix:** `isHovered` for a thread center is now `hoveredNoteId === node.id || endpointIds.includes(hoveredNoteId)` where `endpointIds` are the `thread-arm` source/destination notes. NoteCard's existing 300 ms hover-out delay gives the pointer time to reach the revealed center, after which the center's own `onMouseEnter` takes over. Not done: a hit-path on `ConnectionLine` (thread-line hover) and auto-entering edit mode after creation -- no code creates centers yet, so there is no creation point to hook.

### CR-03: FloatingToolbar and PassageChooser are never rendered; passage-connection props are never wired

**Files modified:** `app/src/renderer/components/NoteCard.tsx`, `app/src/renderer/components/ThreadCenterNode.tsx`
**Commit:** `5bcb14a`
**Status:** fixed (partial): requires human verification
**Applied fix:** Both editor hosts now render `<FloatingToolbar view={editorView} containerRef={cardRef} zoom={zoom} />` while editing. Because the hook creates the `EditorView` inside an effect, each host mirrors `viewRef.current` into `editorView` state (effect keyed on the node id) so the toolbar receives a real view. ThreadCenterNode's drag guard now also ignores pointer-downs inside `.floating-toolbar`, otherwise clicking a toolbar button would start dragging the center.
**Open remainder (not fixed, by design):** `PassageChooser` is still unmounted and `onSelectionChange`/`hasTextSelection`/`applyPassageMark` still have no caller. Wiring them requires the passage-connection gesture end-to-end: a kernel representation for anchors, creation of `thread-center` nodes and `thread-arm` edges (App's `handleEdgeCreate` still emits `label: 'link'`), and the D-15 disambiguation flow. That is a product/design decision, not a code fix, and should be tracked as unfinished D-15/D-24 work rather than treated as complete.

### CR-06: A title edit is silently lost if the card unmounts within the 300 ms debounce

**Files modified:** `app/src/renderer/components/NoteCard.tsx`
**Commit:** `8ab0eec`
**Status:** fixed: requires human verification
**Applied fix:** A cleanup effect keyed on `node.id` flushes a pending title debounce: clears the timer, calls `onMarkClean`, serializes the body from `viewRef.current ?? lastViewRef.current` (a destroyed `EditorView` still exposes `state.doc`; the hook nulls `viewRef` in its own cleanup, so `lastViewRef` makes this independent of cleanup order), falling back to the latest `body` prop, then calls `onSave` with the current title. Note: if both a title and a body debounce are pending at unmount, two saves are submitted (the hook's and this one); both carry the correct title and body, so this is redundant rather than wrong.
