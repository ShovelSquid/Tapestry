# Phase 02.2 Plan 01: Host-Stamped Actors and the First-Run Name Prompt Summary

**The Electron main process now signs every durable change — renderer commits read `actor human user.<name>`, plugin commits are bound to `plugin <pluginId>` and cannot claim `human`, and vitest runs against the real addon in guarded temp dirs.**

## Accomplishments

- Closed the actor-spoofing hole end to end: `kernel:submit` takes `(message, ops)` only, and the actor comes from `getHumanActor()` in main. A call in the old four-argument shape now throws before reaching the kernel.
- Bound plugins to their own identity: `makePluginKernelFacade` ignores the actor pair a plugin passes and records `plugin <pluginId>`, while `assertPluginSubmitKind` throws for `human`/`system` rather than silently correcting it.
- Reserved the `agent.`, `user.` and `obsidian.` prefixes and the bare `tapestry` id, so a plugin directory cannot impersonate a connected agent or the bridge.
- Added `SettingsStore` with per-field validation, so a hand-edited `settings.json` cannot splice a space or line break into an `actor` line.
- Built the first-run name prompt on a reusable `Dialog` shell whose Escape contract falls out of whether a dismiss action exists.
- Installed the Wave 0 harness every later plan in this phase depends on: vitest 2.1.9, `createTempTree`, and the `assertNotRealData` guard.

## Decisions Made

- **The facade stays synchronous.** The SDK types `KernelAPI.submit` as promise-returning, but the facade returns the `CommitResult` directly — the same runtime shape the previous untyped context literal had. Keeping it synchronous is what lets a refused submit throw before anything is written, which is exactly what the D-06 behaviour asserts.
- **`ACTOR_NAME_RE` is stricter than the kernel's token rule.** The kernel accepts any non-space, non-control bytes including all of UTF-8; actor ids are the part of a commit a person scans by eye, so they stay lowercase ASCII.
- **Throw, do not re-stamp.** A plugin passing `human` could have been quietly corrected to `plugin <id>`. Throwing makes a plugin that believes it can write as you visible the first time it tries.
- **The renderer duplicates `USER_NAME_RE`.** The renderer cannot import main-process modules; the copy decides only what the dialog lets you press, and main validates again before any write.

- **Found during:** Task 2 (plugin facade)
- **Issue:** `tsc` reported `CommitResult` is not assignable to `Promise<CommitResult>` at the `plugin:executeCommand` context.
