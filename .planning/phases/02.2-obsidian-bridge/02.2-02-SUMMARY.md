# Phase 02.2 Plan 02: Authorship from the Journal and Provenance Footers Summary

**Who made a note is now computed from the actor lines of the commits that touched it — never from a property a writer could set — and shown on the card as a neutral glyph plus the literal actor id, with tree identity and next-id prediction exposed for the plans that follow.**

## Accomplishments

- **Made authorship underivable from anything a writer controls.** `buildHistoryIndex` walks `CommitRecord`s and reports, per node, the actor on the commit that created it and the actor on the most recent commit that wrote a property to it. There is no `created-by` property anywhere in the file, which is precisely what makes the D-05 check in Plan 04 rest on facts on disk rather than on a field an agent could fill in about itself.
- **Kept the rewound view honest.** Every history read is parameterised by a `maxSeq`, and `KernelBridge` passes its replay position rather than the journal head. Undo a change and the note stops claiming the agent touched it, because from where the reader now stands, it has not.
- **Reproduced the delete cascade the file does not spell out.** The kernel removes every edge touching a deleted node but records only the `delete-node` line, so the index re-derives the cascade; otherwise an edge would read as live forever in the history view.
- **Gave each tree an identity that costs no new field.** `Journal::headerDigest()` exposes the digest that was already the parent of commit 1, and it survives close and reopen — what the tree registry and cross-tree links (D-16) need to name a tree without naming its path.
- **Made a note and its connection possible in one commit.** `getNextIds()` predicts the ids the next creations will receive, and refuses while history is rewound, where those ids are stale.
- **Shipped provenance that is readable without color.** `ProvenanceBadge` pairs a 16px `aria-hidden` glyph with the literal actor id; actors differ by glyph shape and by text, never by hue, and the accent is never used.

## Decisions Made

- **`changedBy` starts equal to `createdBy`.** A node nobody has edited reports its creator as its last changer, so the footer never renders a blank half and callers need no "never changed" special case.
- **`getNextIds()` refuses while rewound.** It could have returned the rewound world's next ids, but a commit is always appended at the journal head, where those ids are already taken. Refusing makes the mistake impossible instead of merely unlikely.
- **The footer fades rather than unmounting.** `opacity` keeps the card's height fixed, so notes do not jump as the pointer crosses them. It also means the footer stays in the accessibility tree, which is what the UI-SPEC's screen-reader row wants.
- **Only `obsidian.bridge` is annotated.** Every other badge is the bare actor id. `obsidian.bridge` gains "author unknown" because that id names the watcher that saw a file change, not whoever typed it (D-21) — showing it unannotated would be the one case where the literal id misleads.
- **Edge history carries no `changedBy`.** Edge properties are not shown as authorship anywhere and endpoints never change, so tracking it would add a field with no reader.
