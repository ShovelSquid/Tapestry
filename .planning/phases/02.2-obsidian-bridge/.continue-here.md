## Critical Anti-Patterns

| # | Anti-pattern | severity |
|---|---|---|
| 1 | An executor committed another session's uncommitted files | blocking |

**1. Sweeping a peer session's files into a phase commit.** Wave 4's commit `7030918` contains four `.planning/phases/02.3-time-threads/` files that a different Claude session had edited but not yet committed. The executor's own staging guard reported clean, so it either inspected the index at the wrong moment or staged a directory rather than named files. Nothing was lost and history was deliberately NOT rewritten (five sessions were committing into this one tree; a rebase would have been worse than a wrong commit message), but the record is mis-attributed.

Structural prevention — every executor dispatch must carry these as hard rules, not advice:
- Never `git add` a directory, a glob, `-A`, `.`, or `-u`; never `git commit -a`. Staging ONE named file (`git add path/to/file`) is allowed and is the only way to commit a new file — the ban is on anything that can sweep in a path you did not name.
- Commit only via `git commit -- <explicit file paths>`. Note this form cannot commit an untracked file: stage that one file by name first, then commit it by name.
- Immediately BEFORE each commit, run `git status --porcelain` and read it.
- Immediately AFTER each commit, run `git show --name-only --format= HEAD` and verify every path is one you edited. If a foreign path appears: stop, report, do not continue, do not rewrite.
- Never-yours paths: `.planning/phases/02.3-time-threads/**`, `.planning/spikes/**`, `.gsd/**`, `tapestry/kernel/**`, `tapestry/tests/**`, `app/src/main/agents/connect-command.*`.

## Known issues later waves must handle

- **Tree id collisions (plans 05, 15):** a tree's id is its header digest, derived from world name + creation time rounded to the second. Same name in the same second collides and `TreeRegistry` refuses the second as "already open".
- **Journal reopen is quadratic in commit count** (~176 ms at 2.3k commits, ~22.7 s at 27k) because the world is copied per commit during replay. Plans 07/09/10 must not reopen a journal per file event or per tool call. A peer session was fixing this in `tapestry/kernel/` at handoff time — re-measure before assuming it still applies.

A peer session fixed the `--env` case in `app/src/main/agents/connect-command.*`; wave 4's SUMMARY still claims the original worked and should be corrected.
