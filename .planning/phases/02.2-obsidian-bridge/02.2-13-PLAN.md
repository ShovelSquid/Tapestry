<objective>
Agents write to the source itself (D-08), whether Tapestry is open or closed (D-09).
- **App open:** agent tools on vault trees go through the shared VaultNoteCommands and the writer, signed `agent.<name>`.
- **App closed:** the shim writes the vault file itself and appends a readable sign-in log line. The catch-up from Plan 10 attributes the write to that agent by content hash.
- **Rules everywhere:** the grew-from rule (D-04) and the own-notes rule (D-05) hold in both modes.
- **Tapestry worlds:** writes made while Tapestry is closed are queued in a readable outbox beside the world file and applied as the agent when Tapestry opens (research recommendation, scheduled last).

Purpose: this completes the agent half of D-08 and D-09 on the same command set (D-01). An agent's note in House Party is a real file with honest attribution.
Output: OfflineCaller, the shim fallback, online vault routing, appendSigninLine, the world outbox, and docs/tree/agents.md.

ChatGPT and other HTTP MCP clients are served by Plan 14, which adds the Streamable HTTP transport on this same tool set, bound to loopback and disabled by default. Nothing about ChatGPT is deferred out of this phase.

Recorded choices:
- The world outbox uses one line per entry, with a JSON object for arguments. Research had suggested blocks; one line per entry keeps the log line-oriented and readable.
- Offline agent deletes move the file into the vault's .trash folder, Obsidian's own trash convention, because the shim cannot reach the system Trash.
- Offline reads of Tapestry worlds are not available: the tools return "Tapestry is closed; open it to read <world>". D-09 concerns only source writes.
