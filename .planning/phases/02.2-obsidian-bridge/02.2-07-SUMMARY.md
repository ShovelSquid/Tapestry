# Phase 02.2 Plan 07: The Vault Becomes a Tree Summary

**An Obsidian vault folder becomes its own tree inside that folder (D-13), holding one note per `.md` file whose `md.text` is byte-for-byte what the file contains (D-12, D-30), with folders as group nodes and everything that changed while Tapestry was closed recorded as `actor plugin obsidian.bridge` observations (D-20, D-21).**

## Accomplishments

- **The mirror is byte-exact, and proved so through a close and reopen.** `crlf.md` keeps its CR bytes, `no-trailing-newline.md` gains no final newline, and `text-line.md` keeps the bare `TEXT` line that forces the encoder onto a fresh block delimiter. The assertion is a `Buffer.equals` against `readFileSync`, not a string comparison — a mirror that is only correct in memory has proved nothing about the file.
- **One rule decides where every key belongs.** `shapes.ts` states it once: every key starting `md.` is what the file says or is derived from it; every other key is Tapestry's. That is what lets a person reading the `.tree` file tell the record from the opinion without a legend, and it is the shape every later source plugin inherits (D-10, D-14).
- **The read path refuses rather than repairs.** `decodeMarkdown` rejects invalid UTF-8, a NUL byte and a line over 1 MiB — each one a limit the kernel itself enforces, so a file that decodes is a file that will commit. Nothing is ever transcoded to fit: bytes repaired to fit would then be recorded as what the file "says", which is exactly the claim D-10 forbids.
- **Reading a vault changes nothing in it.** Asserted directly: every fixture file's sha256 is compared before and after the import. `walkVault` uses `lstat` only, so a symlink is recorded and never followed (T-02.2-33); `readVaultBytes` checks the size before allocating (T-02.2-34); `vault:add` accepts only a root the user picked in the folder dialog (T-02.2-37).
- **A catch-up over an unchanged vault writes nothing.** Without that, every launch would append a commit saying the same thing as the one before it, and Tapestry's own future writes would echo back as observations (research Pitfall 3). One changed file produces exactly one commit reading `observed change to Characters/Rune.md`.
- **A registered component name now selects a component.** Until this plan, *any* node type a plugin registered rendered as a `NoteCard`. A vault note would therefore have been drawn through a ProseMirror editor, where a single keystroke could have committed editor JSON into `md.text`. `NODE_VIEW_COMPONENTS` maps the name to a component the host already trusts, and an unmapped name falls through to the readable fallback (D-33/D-35).
- **The fixture is synthetic, and its bytes are pinned.** Ten files authored here reproduce every shape the tests assert. `.gitattributes` marks the folder `-text`, so a checkout with `core.autocrlf` enabled cannot rewrite the very bytes under test.
