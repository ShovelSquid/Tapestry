## Which file is the real one

### When a note exists both in Tapestry and as a .md file in the vault, which one is the real one?

| Option | Selected |
|--------|----------|
| .tree is real, .md is a live copy (Recommended) |  |
| Vault is real, .tree adds the rest |  |
| Both equal | ✓ |

**User's choice:** Both equal
**Recorded as:** Both equal: either side can be edited at any time and the bridge keeps them matched. Neither .tree nor the vault is subordinate. REFINED by the next answers: the source is the truth for its own data; Tapestry and Obsidian are both places to edit it.

**Notes:** Refined by the next answer into the source-mirror model.

### If the same note changed in both Tapestry and Obsidian before the bridge caught up, what happens?

| Option | Selected |
|--------|----------|
| Merge, ask on overlap (Recommended) |  |
| Keep both as two notes |  |
| Latest edit wins |  |

**User's choice:** Source-mirror model (confirmed by Kaelen): each outside source (the Obsidian vault now; other apps/devices via plugins later) is its own tree, an append-only, never-rewritten record of what the source actually contains. Tapestry never holds a diverging version: an edit is output to the source (e.g. writes the .md), and the tree records what the source then says. No merging; the file wins. Kaelen verbatim: "there should be immutable representations of that data. tapestry can output to change that data, but it should always only represent what that actual data is ... These inputs should be displayed in different trees perhaps, which makes up the forest."

**Notes:** Claude reflected this back as the source-mirror model and Kaelen confirmed.
