# Phase 02.2 Plan 03: The Agent Bridge over MCP Summary

**Claude Code can now grow a note from an existing note in a Tapestry world over MCP — the shim relays a tool call across a 0600 Unix socket, main turns the caller's token into `agent.claude` before anything runs, and the note plus its `grew-from` edge land in a single commit the agent could not have signed any other way.**

## Accomplishments

- **Closed the identity question at the protocol edge.** No MCP schema has an actor field, and every schema is `.strict()`, so `{"actor": "human"}` is a validation *error* rather than a field to ignore. The id is derived in main from `sha256(token)` compared with `timingSafeEqual`, and an unknown token is refused before `dispatch` is ever called — asserted with a spy, so "refused" means the command layer never ran.
- **Made the loose note impossible rather than discouraged.** `createFrom` resolves the tree, validates the title and text, and requires `grewFrom` to be a *live* node in that same tree. Each of the six refusal paths is asserted twice: that it returns `{ok:false}`, and that the file's size and the world's node and edge counts are unchanged. A refusal that still appended a commit is exactly the failure D-04 exists to prevent.
- **Put the note and its connection in one commit.** `getNextIds()` from Plan 02 predicts the id the new node will receive, so the `create-edge` line can name it before it exists. History therefore never contains a moment where an agent's note sits unattached.
- **Opened no TCP port.** The transport is a stdio shim plus a Unix domain socket at mode 0600 inside a 0700 directory. A browser page cannot address a Unix socket, so DNS rebinding is off the table by construction rather than by validation. The socket server replaces a stale socket but refuses to delete a regular file sitting at that path.
- **Kept the shim free of the app.** `out/main/mcp.js` bundles the MCP server and zod but contains **zero** occurrences of `require("electron")`; the one type it shares with the command layer is imported with `import type`, so nothing drags in the kernel bridge or the native addon. Tapestry remains the only writer of `.tree` files, which is what the journal's exclusive flock already guaranteed.
- **Proved it through the real shim.** `shim.test.ts` spawns the built `out/main/mcp.js` as an actual child process and speaks newline-delimited JSON-RPC to it — initialize, initialized, tools/list, two tools/call. Nothing is mocked: a real socket, a real token, a real `.tree` file on disk.
- **Made an agent's note appear without a refresh.** Every landed commit reports through `onCommitted`; main forwards it as `tree-changed` and the canvas calls `refreshAll`. A refused command never fires the hook.

## Decisions Made

- **The shim is a relay, and is not trusted.** Arguments are re-validated in main against the same zod schemas the shim advertises. The shim is an ordinary local process that any program running as this user could replace, so main checking again is the only thing that makes the schema a guarantee rather than a suggestion.
- **`ToolCaller`'s result type is imported `import type`.** A value import of `CommandResult` from the command layer would have pulled `kernel-bridge` — and therefore the native addon and electron — into the shim bundle. The type-only form is erased at build, which is what keeps `require("electron")` at zero.
- **A non-socket file at the socket path is never deleted.** A stale *socket* is replaced, but anything else causes `listen()` to reject. Deleting an unexpected regular file there could destroy data with nothing to do with Tapestry.
- **The socket's mode is set by umask at bind time, not chmod afterwards.** `chmod` after `listen` would leave a window in which the socket was world-writable.
- **A refusal does not notify the renderer.** Firing `onCommitted` on refusals would be simpler, but the canvas would flicker on every rejected agent request.
- **Control characters in a title are refused, not stripped.** The title is written into a `.tree` text block and becomes a file name later (D-28); silently changing what the caller asked for would make the stored title disagree with the title the agent believes it set.

Every commit staged its declared paths by explicit path, behind a guard that aborts and resets the index if any `.planning/`, `.gsd/`, spike or `02.3` path appears staged; none ever was. New 02.3 plan edits and spike directories 006 through 011 appeared in `git status` during the run and were left untouched.
- **TDD RED was genuine for the new behaviour and absent for the rest, and neither was faked.** `notes.test.ts` failed 4/14 with `commands.readNote is not a function` / `commands.listTrees is not a function`, and `shim.test.ts` failed 2/5 with `Tool read_note not found` and a missing `list_trees` — a real red-green cycle. `registry.test.ts` (9/9) and `socket-server.test.ts` (11/11) passed on first run, because `TreeRegistry`, `AgentRegistry` and `AgentSocketServer` were all shipped by Task 1, which the plan's own decomposition requires (the tracer must cross every layer). Those two files are therefore **characterisation tests over already-shipped behaviour**, not a red-green cycle, and are reported as such rather than presented as RED.
- **Tree identity collides for same-name worlds created in the same second.** A tree's id is the digest of its header record, and the header is `world <name>` plus `created <whole second>` (FORMAT.md). Two worlds created with the same name inside the same second therefore produce the same id, and `TreeRegistry` would refuse the second as "already open from ...". This did not block anything — the tests give each world a distinct name and override the display name separately — but Plans 05 and 15 lean on this id for multi-tree and cross-tree links, so it is recorded here rather than discovered there. A copied `.tree` file has the same identity by the same mechanism, which is deliberate and is covered by a test.
- **`REQUIREMENTS.md` was legitimately left untouched.** This plan's `requirements` frontmatter names `D-01`, `D-03`, `D-04` and `D-06`, which are **CONTEXT.md decision ids**, not `REQUIREMENTS.md` requirement ids — that file tracks `TREE-`, `HIST-`, `PROV-` and `PLUG-` ids. `requirements.mark-complete D-01` therefore matched nothing and wrote nothing (`write_set_complete: false`), and the file is correctly unmodified. `requirements.ready-ids` separately reported `D-03`, `D-04` and `D-06` as blocked, since plans 04, 13 and 14 also declare them and have no SUMMARY yet — so even on a matching id they would not have been marked here. `requirements-completed` in this summary's frontmatter copies the plan's array verbatim, as the template requires.
- **No safety-relevant surprises.** Nothing read or wrote `~/House Party`, `~/Documents/we.tree` or `~/Tapestry Tales`; every temp world went through `makeTempDir`, which asserts `assertNotRealData` first. No TCP port was bound anywhere in this plan.
