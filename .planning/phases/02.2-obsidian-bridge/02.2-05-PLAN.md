<objective>
Several trees live in one space, each in its own named frame that moves as a whole and never overlaps another frame (D-15). The set of open trees and their frame positions persist in app settings and reopen on launch (D-18). Main already holds a TreeRegistry. This plan makes every kernel channel tree-scoped and gives the renderer per-tree state, frames, frame headers with each tree's save status, and drag with push-apart.

Purpose: a vault is its own tree (D-10), so it can appear only once the space holds more than one tree. This is also the forest Kaelen described ("these inputs should be displayed in different trees, which makes up the forest").
Output: tree-scoped IPC, settings persistence and migration, useForest hook, TreeFrame and FrameHeader, pure frame geometry with tests.

Recorded choices:
- Node positions stay frame-local, so no stored coordinate changes.
- A migrated single tree is placed at frame (0, 0), which renders identically to today.
- Plugins keep a single kernel facade bound to the primary tree, meaning the most recently opened native tree; its SDK API is unchanged.
- The rule that double-clicking outside every frame while trees are open creates nothing (UA-06) is implemented here, because a note must belong to a tree.
</objective>

    pushApart(rects: Array<{ id: string; x: number; y: number; width: number; height: number }>, movedId: string, gap = FRAME_GAP): Map<string, { x: number; y: number }>.
    - Start a work queue with movedId.
    - Pop a frame A. For each other frame B, in ascending id order and never the moved frame, check whether A's rect expanded by gap intersects B.
    - If it does, compute the horizontal push: when B's center x >= A's center x, dx = A.right + gap - B.x; otherwise dx = A.x - gap - (B.x + B.width). Compute dy the same way on the vertical axis.

    - Stop after 200 steps.
