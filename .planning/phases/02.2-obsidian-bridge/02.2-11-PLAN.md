<objective>
Tapestry becomes a place to edit a vault, not just to view one (D-10). Edits made in Tapestry go out to the file about a second after typing pauses (D-22). Retitling renames the file (D-28), deleting moves the file to the Trash (D-25), and undo writes files back as a group (D-23). A file that changed outside Tapestry first always wins, while Tapestry's losing edit stays in history (D-11).

Purpose: this completes the two-way bridge for note text and names while keeping the mirror honest. The tree always ends up recording what the files actually say.
Output: VaultWriter, the path write rules, VaultNoteCommands (the shared vault command layer, D-01, reused by agent tools in Plan 13), editable VaultNoteCard, FrameNotice, write status and Retry write, retitle with link updates, delete to Trash, compensating undo/redo, and closure of the native title debug note.

Recorded choices:
- A file whose line endings are uniformly CRLF is edited as LF and saved back as CRLF, because a textarea normalizes line breaks. A file with mixed line endings is shown read-only with the note "This file mixes line endings; edit it in Obsidian." so its bytes are never silently changed.
- A retitle rewrites links in other vault notes that resolved to the renamed note, as Obsidian does for renames.
- Deleted files go to the system Trash through shell.trashItem.
- Undo is session-scoped, like native undo (Phase 2 D-22).

    Write algorithm, per path:
    1. Emit 'writing'.
    2. Resolve the target with resolveWritableVaultPath.
    3. Read the current bytes if the file exists and hash them (null when absent).

    5. Otherwise open `.<basename>.tapestry-tmp` in the same folder with flags wx and the existing file's mode (else 0o644). Write the UTF-8 text, fsync, close, then renameSync over the target.
    6. Record expected[rel] = sha256(text) with a timestamp, and emit 'written'.
    Any error unlinks the tmp file if present and emits 'failed' with err.message.
