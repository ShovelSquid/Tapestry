<objective>
D-03 asks that any agent — "Claude, ChatGPT or any other agent" — can connect. Plans 03, 04 and 13 deliver that for clients that speak stdio, which covers Claude Code and other local MCP clients. ChatGPT speaks the MCP Streamable HTTP transport instead. This plan builds that transport on the same tool set and the same command layer, so the any-agent goal is delivered rather than reduced.

The transport ships switched off. `agentHttp.enabled` defaults to false, so a default install listens on nothing. When Kaelen turns it on, it binds loopback only, demands a per-agent bearer token, and validates Host and Origin. Tapestry never opens a tunnel and never binds a public address; if Kaelen wants ChatGPT's servers to reach it, running and trusting a tunnel is his own act, documented here and in the agents guide.

Purpose: shipping the transport disabled is full delivery of "any agent can connect" while keeping an unattended run safe. The capability exists, is tested, and is inert until a person chooses otherwise.
Output: the loopback listener (`startAgentHttp` / `stopAgentHttp` over the `LOOPBACK` constant, handed back as an `AgentHttpHandle`), the opt-in setting and Agents panel control, and the HTTP section of docs/tree/agents.md.

Recorded choices:
- Transport selection is Claude's discretion under 02.2-CONTEXT.md ("MCP transport, and how the server reaches the kernel"). Adding a second transport does not change D-06 stamping or the D-04/D-05 rules, because both transports share one command layer.
- `@modelcontextprotocol/node@2.0.0` supplies the Streamable HTTP transport plus `localhostHostValidation()` and `localhostOriginValidation()`. RESEARCH's Package Legitimacy Audit records it as OK / Approved (7 weeks old, 1.33M weekly downloads, github.com/modelcontextprotocol/typescript-sdk, no postinstall), so no human checkpoint gates this install.
- The listener runs in the Electron main process, not in the shim, because it needs the command layer and the journal writer. The stdio shim is unchanged.
- No read-only mode is added here. D-05 already limits an agent to its own notes, and the same limit applies over HTTP.

    **app/src/main/mcp/http.ts** exports `const LOOPBACK = '127.0.0.1'`, `interface AgentHttpHandle { port: number; close(): Promise<void> }`, `startAgentHttp(options): Promise<AgentHttpHandle>` and `stopAgentHttp(handle): Promise<void>`.

    startAgentHttp takes `{ commands, agents: AgentRegistry, port, onLog? }`.
    1. Build the Streamable HTTP transport from '@modelcontextprotocol/node', wrapping an McpServer built by buildMcpServer with a caller that dispatches through runAgentTool.
    2. Apply `localhostHostValidation()` and `localhostOriginValidation()` from the same package as the outermost request handling, so a rejected Host or Origin never reaches authentication or a tool.
    3. Authenticate every request: read the `Authorization: Bearer <token>` header, call agents.verify(token), and on null respond 401 with a JSON body `{ error: 'Unknown agent token' }`. Never log the token.
    4. On success derive the actor with agentActor(name). The actor comes only from the token; any actor-shaped field in the request body is ignored, because runAgentTool takes the actor as its own parameter and the zod schemas admit no actor field.
    5. Listen with `server.listen(port, LOOPBACK)`. Pass the literal LOOPBACK constant; never pass undefined, '0.0.0.0' or '::', which would bind every interface.
    6. Resolve with the actual bound port from `server.address()`, so a caller may pass 0 for an ephemeral port.
    7. Surface listen errors (EADDRINUSE in particular) as a rejected promise with a readable message naming the port.

    stopAgentHttp closes the HTTP server and awaits its 'close' event, and is idempotent.

    **index.ts lifecycle.** After the commands bundle and AgentRegistry exist, read settings.agentHttp. Start the listener only when `enabled` is true, inside try/catch with the log prefix '[AgentHttp]' so a failure never blocks launch. Keep the handle in a module variable. Call stopAgentHttp on 'before-quit' and whenever the setting is turned off. Starting is never implicit: no code path may start the listener because an agent asked for it.
