<objective>
Tapestry knows who made each note and who last changed it, derived from the actor line on the commits in the journal, and shows it on the note. This is the authorship source that D-05 (agents may edit only their own notes) enforces in Plan 04. It is also the visible side of D-06 and D-07 attribution. The same native pass adds each tree's identity (its header digest), which the tree registry and cross-tree links (D-16) use, and prediction of the next node and edge ids. With id prediction, a note and the connection pointing at it can be created in one commit (D-04, Plan 03).

Purpose: attribution must be inspectable in the app, not only in the .tree file. The D-05 check must rest on facts on disk, not on a property an agent could set.
Output: kernel History module + doctests, three addon methods, KernelBridge wrappers, provenance footer with ProvenanceBadge.
</objective>

    Create tapestry/kernel/History.hpp and History.cpp in namespace tapestry::kernel.

    Types:
    - struct NodeHistory { NodeId id; CommitSeq createdSeq; Actor createdBy; CommitSeq changedSeq; Actor changedBy; std::optional<CommitSeq> deletedSeq; std::optional<Actor> deletedBy; }
    - struct EdgeHistory { EdgeId id; NodeId from; NodeId to; CommitSeq createdSeq; Actor createdBy; std::optional<CommitSeq> deletedSeq; std::optional<Actor> deletedBy; }
    - struct HistoryIndex { std::vector<NodeHistory> nodes; std::vector<EdgeHistory> edges; }, each vector in ascending id order.

    Function: HistoryIndex buildHistoryIndex(const std::vector<CommitRecord>& commits, CommitSeq maxSeq). It walks commits in order, stops after seq maxSeq, and applies these rules:
    - CreateNode sets createdSeq, createdBy, changedSeq and changedBy.
    - SetProperty or UnsetProperty whose target holds a NodeId updates that node's changedSeq and changedBy.
    - CreateEdge records an edge with its from/to.
    - DeleteEdge sets deletedSeq and deletedBy on the edge.
    - DeleteNode sets them on the node, and also on every not-yet-deleted edge whose from or to is that node. The kernel cascades these deletes but records only the delete-node line.
    - Advance and edge-targeted property ops do not change node history.
