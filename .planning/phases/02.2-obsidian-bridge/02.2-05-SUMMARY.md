# Phase 02.2 Plan 05: Several Trees in One Space Summary

Tapestry now shows several trees at once, each in its own named frame that moves as a whole and never ends closer than 64px to another (D-15), with the open set and frame positions living in app settings rather than a forest file (D-18).

## Accomplishments

- **Every kernel channel is tree-scoped.** `kernel:submit` and the seven read/undo channels take a `treeId` first. `resolveTree` requires `sha256:` plus 64 hex digits *and* an open registry entry, so an unknown id is refused rather than quietly resolving to the primary tree.
- **Two worlds stay genuinely separate.** Opening a tree no longer closes another; each holds its own journal lock, and a commit made through one bridge appears in that `.tree` file and not the other. This is asserted on disk, by reading both files.
- **The space persists.** `trees` in `settings.json` records each open world and its frame. A Phase 2 `last-opened.json` is adopted once, at frame (0, 0), so a world opened before the space existed survives the upgrade.
- **Frame geometry is pure and test-first.** `computeFrameBounds` pads content by 48px under a 64px header band; `pushApart` settles the space from the dropped frame outward; `placeNewFrame` measures from the rightmost *edge* so a new frame cannot land on a wide one.
- **Each frame carries its own status.** `FrameHeader` fills the 64px band with the tree's name, its kind label and its own Saved / Saving... / Not saved state. The single window-corner `SaveIndicator` is deleted — with several trees open it would have had to average them, and "Saved" while another tree is still writing is exactly the false reassurance D-02 forbids.

- **No automated test exercises the React layer.** `vitest.config.ts` runs in the `node` environment with no jsdom, so frame dragging, push-apart-on-drop, header status during typing and double-click hit-testing have **no test in this repo**. The geometry beneath them is unit-tested; the wiring from pointer to geometry to `trees:setFrame` is unverified until UAT. Recorded as `human_judgment: true` on D7/D8/D9 above.
- **Frame header right slot is intentionally empty** — Plan 06 puts the Tree options button there.
- **Vault status states are not implemented.** `FrameHeader` renders the three native states; the vault vocabulary ("Up to date", "Writing [file]...") belongs to the vault plans.
- **Cross-tree connection drags do nothing.** A connect drag ending on another tree's note is ignored by design; D-16 links are Plan 15. `handleEdgeCreate` guards this a second time in App.
