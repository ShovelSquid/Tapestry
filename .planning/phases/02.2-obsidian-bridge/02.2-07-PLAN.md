<objective>
An Obsidian vault becomes its own tree (D-10). That tree is an append-only record of what the vault's files actually contain. Adding House Party creates `House Party.tree` inside the vault (D-13) with:
- one note per `.md` file, with exact text (D-12, D-30);
- folders, file notes (D-29) and placeholders (D-34);
- wikilink edges labeled with their literal line (D-31);
- tags and frontmatter as properties (D-33).
Reopening Tapestry catches up on changes made while it was closed (D-20). House Party is the first vault (D-19); tests use a snapshot copy only.

Purpose: this is the Obsidian half's tracer. It proves the source-mirror model (D-10, one-way) and the record shapes on real data before live sync and writes are layered on.
Output: the obsidian/ modules (shapes, vault-fs, scan, resolve, reconcile, vault-service), the fixture and helpers, the first-party obsidian-vault node-view plugin, AddVaultDialog, a minimal verbatim VaultNoteCard, and docs/tree/obsidian-vault.md.

Recorded choices:
- Bridge services run as host services in main, because they need fs and the reserved `obsidian.bridge` actor that plugins may not use (Plan 01).
- Vault node views ship as the first-party plugin `obsidian-vault`, so a disabled plugin shows readable fallback cards (Phase 2 D-33/D-35).
- The first import is committed as `plugin obsidian.bridge`.
- Placeholders are keyed by lowercased link text, one per distinct missing target.
- No `.tree` format change: FORMAT.md and example.tree are unchanged.
</objective>
