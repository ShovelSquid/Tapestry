## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Scope and sequence
- **D-01:** Phase 2.2 covers both the agent bridge and the Obsidian bridge. Build one shared note/connection command set, expose it to agents over MCP first, then build Obsidian sync on the same commands.
- **D-02:** Time threads are out of 2.2 and become their own Phase 2.3, directly after 2.2. The 2.2 agent tools must not rule out writing into threads later. Time threads keep the name "thread". Phase 2.1's connection-with-a-centre-note (`thread-center` / `thread-arm`) gets renamed, and the new name is chosen in the 2.3 discussion. — **Reversibility:** costly — the rename touches 2.1's renderer components, node/edge type names and any worlds already written with them.

#### Agent bridge
- **D-03:** An MCP server gives any agent (Claude, ChatGPT, others) a small, clear set of tools for reading, creating notes, connecting notes and writing to the source. The SDK's namespaced `CommandContribution` is the natural base for those tools.
- **D-04:** Every note an agent creates must name an existing note it grows from, written by a human or an agent, and is created already connected to it. Agents can never create loose notes. The bridge enforces this, not the agent.
- **D-05:** Agents may read any note and draw connections to any note, but may edit or delete only notes they wrote. Authorship comes from the actor on the commit that created the note.
- **D-06:** Agent commits read `actor plugin agent.<name>` (for example `agent.claude`, `agent.chatgpt`). Agents must be distinguishable from each other, because Kaelen says agents and avatars are a core part of the roadmap. There is no `.tree` format change. The bridge stamps the agent id itself: an agent cannot choose it and can never write as a human. — **Reversibility:** costly — actor ids are written into append-only history and cannot be rewritten later, so a different scheme would leave old commits in the old form.
- **D-07:** Human commits read `actor human user.<name>`, for Kaelen `actor human user.kaelen`. This replaces today's `actor human local` (all 390 commits in `~/Documents/we.tree`). Existing `local` lines remain valid history. — **Reversibility:** costly — same reason as D-06.
- **D-08:** Agents get tools that write to the source itself (the vault's `.md` files), and the vault tree records the result. D-04 and D-05 still apply.
- **D-09:** Agents may write to the source while Tapestry is closed. The bridge appends each write to a small, readable sign-in log (who changed what, when). When Tapestry catches up, it reads the log and attributes those edits to the right `agent.<name>`. Changes not in the log are treated as observed, author unknown (D-21).

#### Source of truth and trees
- **D-10:** **Source-mirror model.** Each outside source is its own tree: the Obsidian vault now, and later other apps and devices through plugins. That tree is an append-only record of what the source actually contains, and Tapestry never keeps a diverging version. Both Tapestry and Obsidian are places to edit: a Tapestry edit is sent out to the source, and the tree then records what the source says. In Kaelen's words: "there should be immutable representations of that data. tapestry can output to change that data, but it should always only represent what that actual data is. this is because plugins will be used for all manner of different apps and devices, and needs to be able to reflect accurate informaion. These inputs should be displayed in different trees perhaps, which makes up the forest." — **Reversibility:** one-way — every later source plugin, the vault tree's record shapes, and D-11/D-14/D-16 all depend on this model.
- **D-11:** No merging. If a note changed in both Tapestry and the file before the bridge caught up, the file wins. The losing Tapestry edit stays in history and can be accessed later; no separate "attempt" object or re-send is needed.
- **D-12:** Notes written inside Tapestry keep today's editor JSON in `.tree`. A vault tree stores each `.md` file's text exactly as it is in the file. JSON is converted to Markdown only when a Tapestry-native note is written out to the vault (for example, by copying it into the vault frame, D-17). Kaelen chose this over storing Markdown everywhere, which Claude had recommended.
- **D-13:** The vault's tree file lives inside the vault folder, for example `~/House Party/House Party.tree`, so the vault and its history travel together.
- **D-14:** What Tapestry adds about vault notes (positions, Kaelen's own short connection labels, authorship) is stored in the vault tree, clearly marked as Tapestry's and kept apart from the mirrored file content. These additions never touch the `.md` files. Exception: connections drawn between vault notes are source data and go to the file (D-32).
- **D-15:** Tapestry shows several trees in one space. Each tree sits in its own named frame, like an island. A frame moves as a whole, notes stay inside their tree's frame, and trees never overlap.
- **D-16:** A connection between notes in different trees is recorded in both trees. Each tree records its own end, naming the other tree and note, so either tree opened alone shows that the link leads elsewhere. More generally, a change one tree makes to another is recorded within the trees it touches. — **Reversibility:** costly — the cross-tree reference shape is written into every affected journal.
- **D-17:** Dragging a note into another tree's frame creates a copy there, connected back to the original. Nothing disappears from its source tree.
- **D-18:** Tapestry remembers which trees were open in the space, and where their frames sat, and reopens them on the next launch. This lives in app settings; there is no forest file. Kaelen chose this over a readable forest file.

#### Syncing
- **D-19:** The first vault to build and test against is House Party (`~/House Party/`): 13 character notes plus lore notes, plain `[[links]]` and `#tags`, in active use. Other Claude sessions currently edit its `.md` files directly, which makes it a real test of the unknown-author path (D-21).
- **D-20:** While Tapestry is open it watches the vault live and records changes within moments. On opening, it catches up on everything that changed while it was closed.
- **D-21:** A file change with no known author is recorded as `actor plugin obsidian.bridge` with a message like `observed change to Rody.md`. Tapestry never guesses the author. Edits that go through the bridge's agent tools carry `agent.<name>` because the bridge knows who made them (D-09).
- **D-22:** Tapestry writes edits to vault notes about a second after typing pauses, so Obsidian sees words and sentences, not every keystroke.
- **D-23:** Changes Tapestry notices within the same moment are grouped into one history entry listing every changed file, and they undo together. Kaelen chose this over one entry per file.
- **D-24:** A file renamed in Obsidian stays the same note under a new name: its position, connections and history remain, and the rename is recorded. The link rewrites Obsidian makes in other files are recorded as observed changes, grouped per D-23.
- **D-25:** A file deleted from the vault removes its note from the frame and cuts its connections, including cross-tree ones. The other trees record the cut too. Everything stays in history and can be restored. This is consistent with Phase 2 D-20: deleting a container removes its connections.
- **D-26:** Vault folders (such as `Characters/`) appear as labeled groups inside the vault's frame, and notes can be arranged within a group. Moving a note to another group moves its file to that folder, which is a write to the source.
- **D-27:** A new note created inside the vault frame becomes `Title.md` in the folder of the group it was placed in (for example `Characters/Luna.md`). An untitled note is `Untitled.md` until it gets a title.
- **D-28:** A vault note's title and file name are always the same, as in Obsidian, so retitling a note in Tapestry renames its file.
- **D-29:** Non-Markdown files in the vault (images, PDFs, `.canvas`) appear as file notes showing the name, the type and a link to open the file. The file's bytes are not copied into the tree. Embeds like `![[map.png]]` become connections to the file note.

#### Markdown ↔ notes mapping
- **D-30:** One `.md` file is one note.
- **D-31:** A `[[link]]` becomes a connection labeled with the actual line it sits in, for example `Best friends with [[Max]]` in `Rody.md`. Tapestry never extracts or guesses a shorter label. Kaelen may add a short label in Tapestry, stored as Tapestry's (D-14).
- **D-32:** A connection drawn in Tapestry between two vault notes adds a `[[link]]` line to the source note: `[[Max]]`, or `best friends with [[Max]]` when a label was given. Obsidian sees the link. This refines D-14.
- **D-33:** `#tags` and frontmatter become readable, filterable properties on the note (for example `tags: Guy`). The file text is unchanged.
- **D-34:** A link to a note that doesn't exist yet (such as `[[create a link]]` in `Welcome.md`) shows as a faint, empty placeholder note connected to the link. Typing in the placeholder creates the `.md` file.

## Project Constraints (from CLAUDE.md)

- Work only in `/Users/kaelencook/Tapestry` on branch `phase-2-implementation-v1`; do not rename the branch.
- **Readability:** content, relationships, changes and provenance must be inspectable without the app. This applies to the sign-in log, and it rules out any binary sidecar or database as the only copy of meaning.
- **Control / History:** editing never erases the earlier value; the original origin stays available.
- **Simple core:** storage, graph state and rule execution stay separable from AI and integration adapters. The bridges belong in the app/plugin layer, not the C++ kernel. No new `.tree` verb (FORMAT.md: "plugins compose their data from them and never add a verb of their own").

- **Developer accessibility:** plugin authors must not need a native build to try an extension.
- Do not add a web server dependency for packaged operation (Electron row of the stack table). A loopback HTTP endpoint for ChatGPT is therefore an opt-in, deferred slice.
- SQLite or a search index may only ever be a rebuildable cache.
- GSD workflow: file changes only through GSD commands.
- Real data is read-only in tests: never mutate `~/House Party/` or `~/Documents/we.tree` (additional context).

## Summary

The kernel already supports everything this phase needs without a format change. Actor ids are one token, and dots are legal. Namespaced node types and dotted property keys give room to separate "what the file says" from "what Tapestry adds". Block text stores Markdown byte-for-byte, including CR bytes, a missing trailing newline, and lines that read `TEXT`. The phase is therefore almost entirely app-layer work in three parts:

1. **A host-owned command layer** that stamps actors. Today the renderer hard-codes `'local'` in 9 places, and plugins pass any actor straight through.
2. **Several `KernelBridge` instances** (one journal and one flock per tree) behind a tree registry, with frames in the renderer.
3. **A reconciler** that turns filesystem state into grouped, attributed commits.

**Architecture: Tapestry is the only writer of `.tree` files.** Agents connect over **stdio** to a thin `tapestry-mcp` process that Claude Code or Claude Desktop launches. When the app is running, the shim forwards each tool call over a **Unix domain socket** (mode 0600) to the Electron main process. There, a per-agent token maps to `agent.<name>`, and the shared command layer validates D-04/D-05 and submits. When the app is closed, the shim writes vault `.md` files directly and appends a readable line (path, resulting sha256) to the vault's sign-in log. The reconciler attributes a later observed change to that agent only if the file's hash matches a logged hash. Anything else is `plugin obsidian.bridge`. This one hash-matching rule also answers D-22's "was this our own write?".

ChatGPT cannot reach localhost or stdio. It needs a public HTTPS endpoint or OpenAI's Secure MCP Tunnel in developer mode. It belongs in a late, opt-in slice behind a human checkpoint.

**The file watcher is only a hint; the scanner decides what changed.** chokidar 4 events only mark paths dirty. After a quiet window (recommended 750 ms, which is "the same moment" for D-23), the reconciler hashes those paths and compares them with the tree. It detects renames by matching content hashes (and inodes while the app runs), then submits one commit per group. Catch-up on open (D-20) is the same reconciler run over the whole vault.

**Primary recommendation:** Build tracer-first in this order:
1. Actor stamping plus the shared command layer, including `user.<name>`.
2. The `tapestry-mcp` stdio shim reaching one native tree through the socket, with `create_note` grown from a note.
3. A read-only House Party mirror tree with catch-up.
4. The live watcher with observed commits and the sign-in log.
5. Tapestry → file writes (edit, connect, rename, new note).
6. Multi-tree frames and cross-tree links.
7. ProseMirror → Markdown copy with an explicit loss prompt.

Pin `@modelcontextprotocol/server@2.0.0`, `zod@4.5.4` and `chokidar@4.0.3`. Chokidar 5 cannot load in Electron 32's Node 20.18.1.

### Pattern 1: Host-stamped actor (closes the spoofing hole)
**What:** No caller outside main supplies an actor. The renderer calls `kernel:submit(treeId, message, ops)`, and main adds `human user.<name>`. A plugin's `context.kernel.submit` is bound to `plugin <pluginId>`. Agent calls are bound to `plugin agent.<name>` from the token. The reconciler uses `plugin obsidian.bridge` or the attributed actor.
**Evidence of the hole:** `plugin-host.ts:331-332` `submit: (actorKind: string, actorId: string, message: string, ops: any[]) => this.kernelBridge.submit(actorKind, actorId, message, ops),`. The same code is at `plugin-host.ts:785-786`. The renderer sends `'human', 'local'` at `App.tsx` lines 203–204, 246–247, 293–294, 346–347, 385–386, 424–425, 485–486, 553–554 and 633–634. [VERIFIED: files read this session]
**Token rules:** `Ops.hpp:104-106` `return kind == "human" || kind == "plugin" || kind == "system";` and `Ops.hpp:118` `if (c < 0x20 || c == 0x7F || c == ' ') { return false; }`. Dots are therefore legal, and `agent.claude`, `user.kaelen` and `obsidian.bridge` are each one valid token. FORMAT.md:271-272 agrees: "The **actor kind** is exactly `human`, `plugin` or `system`; the actor id is one token." [VERIFIED: tapestry/kernel/Ops.hpp:104-123, tapestry/docs/tree/FORMAT.md:263-272]
**Recommended host rule (stricter than the kernel, for readability):** names match `^[a-z0-9][a-z0-9_-]{0,31}$`. Plugin ids must not start with `agent.`, `user.` or `obsidian.`, and must not equal `tapestry`. Reject kind `human`/`system` from any plugin facade.
**SDK compatibility:** keep `KernelAPI.submit(actorKind, actorId, message, ops)` at API "1", but have the host **ignore the supplied pair and stamp its own**. If the supplied kind is `human`/`system`, throw instead of silently re-stamping, so misbehaving plugins surface. Add `CommandContext.actor` (read-only) so shared commands know who invoked them.

### Pattern 2: Tapestry is the single `.tree` writer; the stdio shim forwards
**What:** Claude Code runs `claude mcp add tapestry --env TAPESTRY_AGENT_TOKEN=… -- <runtime> out/main/mcp.js`. The shim (a) connects to `<userData>/agents.sock`. If that succeeds, it (b) sends `{token, tool, args}` JSON lines and relays results. If the socket is absent, it runs offline handlers: vault notes only, plus the sign-in log.
**Why:** journals take `flock(fd, LOCK_EX | LOCK_NB)` for the life of the open session (`Sink.cpp:125`), and a second writer gets `IoError{EWOULDBLOCK, "locked"}` (`Sink.cpp:126-129`). Two writers are impossible by design, and "read-only opens never take the lock" (FORMAT.md:478-479). [VERIFIED: tapestry/kernel/journal/Sink.cpp:118-131]
**Identity:** tokens are generated by the app ("Connect an agent" → name → token shown once plus the ready-made `claude mcp add` command). `userData/agents.json` stores `{name, tokenSha256}`. The model never sees an actor field in any tool schema. MCP `clientInfo` (available through `getClientVersion()` in the SDK d.ts) may be logged as a cross-check, but it is never the identity.
**Runtime for the shim:** run it under the Tapestry Electron binary with `ELECTRON_RUN_AS_NODE=1`. That gives Node 20.18.1 (MCP server needs `>=20`) and the same N-API module ABI (`modules 128`) if the shim ever loads the addon read-only. `forge.config.ts` sets no fuses, so `runAsNode` stays at its default (enabled) [ASSUMED default]. In development, system `node` v20.20.2 also works.

### Pattern 3: Watcher as hint, reconciler as truth
**What:** chokidar 4 (`ignoreInitial: true`, `atomic: true`, ignoring `.obsidian/`, `.trash/`, dotfiles, `*.tree`, `*.tree.torn-*`, the sign-in log and `.*.tapestry-tmp`) only adds paths (and their parent folders) to a dirty set. After **750 ms with no new events** (the D-23 window; also force-flush after 5 s of continuous activity), the reconciler:
1. `lstat` + read + sha256 each dirty path. Unreadable or vanished paths are treated as deleted.
2. Compares against the tree's current `md.sha256` per `md.path`.
3. Pairs deleted paths with created paths of equal hash, or equal inode while the app runs, as **renames** (D-24).
4. Attributes each change:
   - hash ∈ own-write map → the actor who made the Tapestry edit, and usually no commit because the tree already holds the text;
   - (path, hash) in an unconsumed sign-in log line → `plugin agent.<name>`;
   - otherwise `plugin obsidian.bridge`.
5. Submits **one commit per actor per group**. The message lists every file, e.g. `observed change to Characters/Rody.md, Characters/Max.md`.

The actor is per commit, so a group with mixed authors is split by actor. This is the only honest encoding without a format change; note it for Kaelen.

**Catch-up on open (D-20)** is `reconcile(allPaths)`. Catch-up cannot use inodes (not stored in the tree, since they are machine-specific), so a rename while closed is detected by equal hash only. A rename plus an edit while closed becomes delete + create, which is honest rather than guessed.

### Pattern 4: Tapestry → file writes that satisfy D-11 and D-22
Order on a Tapestry edit of a vault note:
1. Commit the edit to the vault tree immediately with the human actor, so a losing edit remains in history (D-11).
2. Debounce **1 s** after typing pauses (D-22).
3. Re-hash the file on disk. If it differs from the hash the tree held *before* this edit, **do not write**: the file wins, and the reconciler records the file's text as observed.
4. Otherwise write atomically: `.<name>.tapestry-tmp` in the same directory, `fsync`, `rename`. Record `expected[path] = sha256(text)`, so the watcher echo is recognized as our own write.

The same path handles D-32 (append a `[[Target]]` / `label [[Target]]` line), D-26 (move the file between folders), D-27/D-28 (create or rename `Title.md`) and D-34 (typing into a placeholder creates the file).

### Pattern 5: Several trees in one space
- `TreeRegistry` holds `Map<treeId, KernelBridge>`. Every `kernel:*` IPC channel gains a `treeId` as its first argument. The undo stack is already per `KernelBridge` instance.
- **treeId** = the header record digest (the `@end sha256:` of `@tree`). It is stable for the file's life and machine-independent. Read it from the file's first four lines in TS, or add an addon getter (`Journal::header()` exists).
- **Frames:** the renderer draws each tree in `<div class="tree-frame" style="transform: translate(fx, fy)">`. Node positions stay frame-local (existing `position.x/y`), so no stored world coordinates change. Frame rectangles are computed from content bounds plus padding. On frame drag end, push overlapping frames apart (D-15).
- **Settings (D-18):** replace `userData/last-opened.json` (`index.ts:54-81`) with `userData/settings.json` `{ version: 1, userName, trees: [{path, kind: "native"|"vault", vaultRoot?, frame:{x,y}}] }`. Migrate `last-opened.json` on first run.
- **Vault undo is not `replayUpTo`.** `KernelBridge.submit` refuses commits while rewound (`kernel-bridge.ts:158-161`), and rewinding a mirror tree would show text the file no longer has (violates D-10). Undo on a vault tree is a new Tapestry edit that writes the previous text back through Pattern 4. A D-23 group undoes as one compensating write set.

**Byte-exact Markdown storage.**

### Markdown scanning (D-31, D-33, D-34)
Hand-written, line-based and pure:
- Skip frontmatter only if line 1 is exactly `---` and a closing `---` exists.
- Track fenced code (```` ``` ```` / `~~~`) and ignore links and tags inside fences and inline code spans. Cast.md writes tags as `` `#Guy` ``. [VERIFIED: Cast.md] Whether Obsidian counts backtick tags is [ASSUMED no]. Follow Obsidian: inline code is not a tag.
- Links: `!?\[\[([^\]\|#\^]+)(#[^\]\|]*)?(\|[^\]]*)?\]\]`. The target is group 1 trimmed. Heading, block and alias parts do not change the target.
- Tags: `(^|\s)#([\p{L}\p{N}_/-]*[\p{L}_/-][\p{L}\p{N}_/-]*)`, which rejects pure-number tags [ASSUMED Obsidian rule].
- Resolution:
  1. If the target contains `/`, match the vault-relative path with or without `.md`.
  2. Otherwise match basenames case-insensitively, `.md` first, then attachments with an explicit extension.
  3. One match → resolved; zero → placeholder; **several → unresolved-ambiguous**, never guessed (D-31 spirit).

  Obsidian's own tie-break is undocumented officially. Community sources say case-insensitive with a shortest-path tie-break. [CITED: obsidian.md/help/links for syntax and the disallowed characters "`# | ^ : %% [[ ]]`"; tie-break ASSUMED]
- House Party links: 18 distinct targets. `[[create a link]]` (Welcome.md) is the only unresolved one. [VERIFIED: grep]

### Sign-in log format (D-09)
Location: `<vault>/<vault name>.signin.log`, next to `<vault name>.tree` (D-13 keeps vault and history together). Plain UTF-8, one append-only line per write, written with `O_APPEND` plus `flock` for the duration of the line:
```
2026-09-15T18:02:11Z agent.claude create Characters/Luna.md sha256:9f2c… grew-from "Characters/Rody.md"
2026-09-15T18:04:40Z agent.claude write Characters/Luna.md sha256:1ab0…
2026-09-15T18:05:02Z agent.chatgpt rename Characters/Luna.md -> Characters/Lunara.md sha256:1ab0…
```
- The app never rewrites the log. Consumption is derived: a line is "applied" when a commit exists whose actor is that agent and whose ops set `md.sha256` to that hash for that path.
- The commit message cites the log line, e.g. `message "from sign-in log 2026-09-15T18:02:11Z: write Characters/Luna.md"`.
- A logged hash that no longer matches the file (someone edited after the agent) attributes the current content to `obsidian.bridge`. The agent's line stays in the log as evidence.

**Native trees while the app is closed:** recommend the *same* line format in `<tree>.signin.log` next to the `.tree`, carrying the intended command (`create-note grew-from n12 title "…" text <<TEXT … TEXT`). On open, the app validates each pending line through the command layer and commits it as that agent. A line that fails validation is recorded as an empty `system tapestry` commit with message `refused sign-in entry <stamp>: <reason>`. **MVP option:** native-tree writes return a clear tool error ("Tapestry is closed; open it to write to we.tree") and the outbox ships as the last slice. The planner should schedule it last.

### Anti-Patterns to Avoid
- **Passing actor through IPC or the plugin API.** Always stamp in main.
- **MCP server that opens `.tree` files itself while the app runs.** It gets `locked` or, worse, forks history.
- **Trusting watcher event types** (rename, change) as truth. Always re-hash.
- **Rewinding a vault tree with `replayUpTo` for undo.** Write a compensating edit.
- **Storing an extracted "relationship" label** ("best friends") from the line. D-31 forbids it.
- **Using the sentence as the edge label.** Labels are one token.
- **Guessing between duplicate basenames.** Mark ambiguous instead.
- **Writing a cross-tree link into `.md`.** Obsidian would show a broken `[[…]]` and then a D-34 placeholder loop. Recommend **not** writing it (open question for Kaelen).
- **Copying v1 MCP examples** (`@modelcontextprotocol/sdk/server/mcp.js`, `server.tool`). Use v2 `@modelcontextprotocol/server`.
- **Logging to stdout in the shim.** It corrupts the stdio protocol. The official serving guide says "stdout must not be used for logging".

## Common Pitfalls

### Pitfall 1: World name with a space
**What goes wrong:** creating `House Party.tree` with world name `House Party` fails. The header grammar is `world <token>` (FORMAT.md:212).
**How to avoid:** reuse the existing sanitizer (`App.tsx` `fileName.replace(/[^A-Za-z0-9_-]/g, '_')` → `House_Party`). Display the frame name from the vault folder name, not the world token.

### Pitfall 2: Chokidar 5 or other ESM-only packages in the Electron main bundle
**What goes wrong:** `out/main/index.js` is CJS (`"use strict"; const electron = require("electron");`) and `externalizeDepsPlugin()` leaves dependencies as runtime `require`. Node 20.18.1 cannot `require()` ESM without a flag [ASSUMED for 20.18], and chokidar 5 declares `node >= 20.19.0`.
**How to avoid:** chokidar 4.0.3. `@modelcontextprotocol/server` 2.0.0 ships a `require` export, so it is fine in main as well as in the shim. [VERIFIED: out/main/index.js head; package.json exports]

### Pitfall 3: Feedback loop between writer and watcher
**What goes wrong:** Tapestry writes `Rody.md`, the watcher sees it, the reconciler commits "observed change" as `obsidian.bridge`, and the edit loses its human attribution. With D-32 link lines this can re-trigger forever.
**How to avoid:** the expected-hash map is checked before attribution. Idempotence: if the file hash equals the tree's current `md.sha256`, emit no commit.

### Pitfall 4: Cross-tree changes are two separate commits
**What goes wrong:** D-16/D-25 write to two journals. Commits cannot be atomic across files, so a crash between them leaves one side recorded.
**How to avoid:** write the target tree's stub first and the source edge second. On open, the registry scans `tapestry.forest/remote@1` stubs whose counterpart edge is missing in an open tree, and completes or cuts them with a `system tapestry` commit whose message says why. Test it with injected failure.

### Pitfall 5: Mixed authors in one D-23 group
**What goes wrong:** one commit has one actor line, so an agent write and an Obsidian edit in the same 750 ms cannot share a commit honestly.
**How to avoid:** split per actor inside a group (a message like `observed changes (group 2026-09-15T18:05:02Z, 1 of 2)`). Undo treats commits sharing the same group stamp as one unit. Tell Kaelen, since it refines D-23.

### Pitfall 6: Grouped commit exceeds record limits
**What goes wrong:** catch-up on a large vault puts every file's full text in one record, over `kMaxRecordBytes` (64 MiB).
**How to avoid:** cap each commit at about 32 MiB of `md.text` and continue in the next commit of the same group.

### Pitfall 7: Journal growth from full-text sets
**What goes wrong:** every observed edit stores the whole file again (no deltas in v1). we.tree already has 86 `body` sets for 12 notes. A 5 KB `Cast.md` edited 200 times adds 1 MB.
**How to avoid:** accept it for House Party (D-22's 1 s debounce already coalesces keystrokes). Record growth in verification and flag large-vault behaviour as a later concern. No format change in this phase.

### Pitfall 8: Obsidian Sync is enabled in House Party
**What goes wrong:** `.obsidian/core-plugins.json` has `"sync": true`. If Obsidian Sync is active, `House Party.tree` and the sign-in log sync to other devices where another Tapestry could append, forking the chain. [VERIFIED: core-plugins.json; whether Sync is actually signed in is unknown]
**How to avoid:** ask Kaelen. Consider excluding `*.tree` / `*.signin.log` in Sync settings. Tapestry must refuse to open a vault tree whose journal is not `Ok`, rather than repair it.

### Pitfall 9: A plugin can still bypass stamping
**What goes wrong:** plugins are `require()`d into the main process (`plugin-host.ts:306`) with full Node access, so a malicious plugin could load the addon directly.
**How to avoid:** stamping is policy, not a sandbox. Document it (FORMAT.md:499-502 already says the actor line is "what the writing process claimed"). Real isolation is a later phase.

### Pitfall 10: Undo while rewound blocks bridge commits
**What goes wrong:** `KernelBridge.submit` throws `'Cannot commit while history is rewound…'` (`kernel-bridge.ts:158-161`). If Kaelen undoes in a vault tree and the watcher then fires, every observed commit fails.
**How to avoid:** vault trees never rewind (Pattern 5). For native trees, reconciler-style incoming agent writes must either wait for redo or discard the redo stack explicitly, surfaced in the UI.

### 4. Reconciler core (pure, testable)
```typescript
type Snapshot = Map<string /*vault-relative path*/, { sha256: string; ino?: number }>
type Change =
  | { kind: 'create'; path: string; sha256: string }
  | { kind: 'modify'; path: string; sha256: string }
  | { kind: 'delete'; path: string }
  | { kind: 'rename'; from: string; to: string; sha256: string }

export function diff(tree: Snapshot, disk: Snapshot): Change[] {
  const created = [...disk].filter(([p]) => !tree.has(p))
  const deleted = [...tree].filter(([p]) => !disk.has(p))
  const changes: Change[] = []
  for (const [from, old] of deleted) {
    const i = created.findIndex(([, now]) => now.sha256 === old.sha256 || (old.ino !== undefined && now.ino === old.ino))
    if (i >= 0) { const [to, now] = created.splice(i, 1)[0]; changes.push({ kind: 'rename', from, to, sha256: now.sha256 }) }
    else changes.push({ kind: 'delete', path: from })
  }
  for (const [path, now] of created) changes.push({ kind: 'create', path, sha256: now.sha256 })
  for (const [path, now] of disk) { const old = tree.get(path); if (old && old.sha256 !== now.sha256) changes.push({ kind: 'modify', path, sha256: now.sha256 }) }
  return changes
}
// attribute(change): ownWrites.get(path)===sha → that actor (usually no-op) ;
//                    signinLog.match(path, sha) → agent.<name> ; else OBSIDIAN_BRIDGE
```

## Security Domain

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes (agent → app) | Per-agent random 256-bit token (`crypto.randomBytes(32)`), stored hashed (sha256) in `agents.json`, compared with `crypto.timingSafeEqual` |
| V3 Session Management | minimal | Stateless per request over the socket. Token on each call |
| V4 Access Control | yes | D-04/D-05 enforced in the command layer. Actor stamping. Plugins cannot claim `human`/`system`/reserved ids |
| V5 Input Validation | yes | zod schemas at the MCP boundary. Re-validate in main (never trust the shim). Vault path canonicalization |
| V6 Cryptography | limited | `node:crypto` only (sha256, randomBytes). No hand-rolled crypto |
| V12 Files and Resources | yes | Path containment, symlink refusal, atomic writes |

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Plugin or renderer claims `actor human` | Spoofing | Host stamping (Pattern 1). Throw on `human`/`system` from plugins |
| Agent path traversal (`../../.ssh/x`, absolute paths, `Characters/../../`) | Tampering / Elevation | Resolve with `path.resolve(vaultRoot, rel)`, then `fs.realpath` of the parent dir, then require the result to start with `realpath(vaultRoot) + sep`. Reject `..` segments, NUL, absolute input, and names starting with `.`. Only `.md` for agent writes. Refuse writes into `.obsidian/`, `.trash/`, `*.tree`, `*.signin.log`. Open with `O_NOFOLLOW` (as `Sink.cpp` does) and refuse if the target is a symlink |
| Local process connects to the socket and impersonates an agent | Spoofing | Socket in `userData` with dir 0700 and socket 0600; token required. Residual: any process running as the user can read client configs (documented local-trust limit; FORMAT.md: actor is "a claim, not proof") |
| DNS rebinding / browser hitting a localhost MCP HTTP port | Spoofing | No TCP listener in core slices. Deferred HTTP slice: bind `127.0.0.1`, `localhostHostValidation()` + `localhostOriginValidation()` + bearer token (`@modelcontextprotocol/node`) |
| Exposing the world to the internet via a ChatGPT tunnel | Information disclosure | Opt-in only, human checkpoint, per-agent token, read-only mode option. Never enabled by default |
| Prompt-injected agent deletes Kaelen's notes | Tampering | D-05 (own notes only). Deletes are recorded and restorable (D-25). `destructiveHint` annotation lets clients confirm |
| Huge or malicious `.md` (NUL, invalid UTF-8, 2 MB line) | DoS | Kernel refuses (`World.cpp:115-119`). Bridge maps to `obsidian.vault/file@1` with `md.unreadable`. Cap per-file read size (e.g. 16 MiB) before hashing into text |
| Style injection via exported HTML color/font | Tampering | Reuse `isValidTextColor` / `isValidFontFamily` allow-lists (`schema.ts:89-95`) |
| Sign-in log forgery (a writer claims `agent.claude`) | Repudiation | Attribution requires hash match plus a line format written only by the shim holding a valid token (shim verifies against `agents.json`). Residual local-trust limit documented |
