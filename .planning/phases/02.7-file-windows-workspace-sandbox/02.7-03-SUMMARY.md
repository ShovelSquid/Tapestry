# Phase 2.7 Plan 03: Folders as subspaces Summary

**A workspace's folders are now nested frames in the tree-frame design, with the same FrameHeader, border and content area. Each folder's files sit in folder-local coordinates, so a folder drags as one unit, and every folder collapses to its header and expands again. Siblings are pushed apart with the existing pushApart, up to the workspace frame and then among tree frames. Every folder starts collapsed, so the ~740-file repository opens as its root files plus a compact column of folder headers. Older workspace trees are re-laid out once, on open, in one `system tapestry` commit. None of this touches a file on disk or any `file.*` key.**

## What Kaelen should know

- **Your existing workspace trees are re-laid out once.** When 02.7-01's flat-layout tree first opens under this plan, `WorkspaceService.arrangeSubspaces` runs after `remember` and before catch-up. This happens in both `addWorkspace` and `openWorkspace`. It commits `planSubspaceMigration(...)` once as `system tapestry` (`SYSTEM_ACTOR`, kind `system`, id `tapestry`) with the message `arrange workspace <name> into folder subspaces`.
  - The commit is a fresh layout from `layoutSubspaces` over the paths the tree records, not a conversion of the old numbers. Converting them would leave nested frames overlapping their parents' siblings.
  - It writes only `position.x` and `position.y` (for nodes whose position changes) and `subspace true` plus `collapsed true` on every folder. It never writes a `file.*` key.
  - It is idempotent. Once every folder carries `subspace`, the plan is empty and a second open writes nothing. The test checks the actor line, the message, that only layout keys appear, that there is no `file.` key, and that a second open adds no commit.
  - Any hand arrangement from your first dogfood try is replaced. The earlier positions stay in the tree's history.
  - The app was not launched in this session. Your first launch of the windows workspace writes this commit (checkpoint step B1).
- **Every folder starts collapsed.** New folders get `collapsed true` in three cases: on first import (`createOp` adds `subspace` and `collapsed` when `layout.subspaces` is on), in the migration, and when a folder arrives later through catch-up or an agent write. A collapsed folder is a 320-wide header band. Expanding one is a person's commit, `Expand folder <path>`, and it pushes its neighbours aside. Collapsing is `Collapse folder <path>` and moves nothing. The state is stored in the tree, so it survives a relaunch.
- **What a folder frame shows.** Its header uses the tree-frame header's two rows and styles:
  - Row 1: the folder's name, with a **Collapse folder** / **Expand folder** button.
  - Row 2: `Folder · <n> files`.
  - It has no Tree options and no Chat with Claude button. Right-click and the card chat buttons still work on the files inside.
- **Dragging a folder** by its header moves the frame and its contents live. On drop, one commit by you, `Move folder <path>`, writes that folder's position plus the positions of whatever had to yield. None of its files is named, because their positions are local to it.
- **Connections** between workspace notes are drawn between absolute centres. A connection with an end inside a collapsed folder is hidden, not rerouted.
- **The vault and native trees are unchanged.** `MirrorLayout.subspaces` defaults to false, and `computeFrameBounds`' new options default to today's constants. frames.test.ts and spatial.test.ts pass unchanged.

## Deviations from Plan

### Auto-fixed Issues and judgement calls

**1. [Rule 1 - Bug] The card estimate is 280 x 280, and rows are 304 apart**
- **Found during:** Task 1, Stages A and B
- **Issue:** The plan's default card size of 280 x 200, with rows based on 224, is shorter than a real card. A collapsed text card has a title, up to 128px of preview, the Open file button and the provenance footer, and measures about 270px. Main never measures cards, so with the plan's numbers the estimated rects would overlap once drawn.
- **Fix:** `CARD_ESTIMATE = { width: 280, height: 280 }` in subspaces.ts. `WORKSPACE_LAYOUT.rowStep` and `columnStep` are 304.
- **Files modified:** app/src/renderer/layout/subspaces.ts, app/src/main/workspace/shapes.ts
- **Commits:** b9b0a4a, 440ddb5

**2. [Rule 1 - Bug] A folder's cards yield as one block**
- **Found during:** Task 1, Stage A
- **Issue:** Cards in a grid sit closer together than FRAME_GAP. If each card went into pushApart on its own, a settle would first push the cards away from each other and scatter the grid.
- **Fix:** settleSubspace treats a parent's cards as one block (`CARD_BLOCK_ID`) that moves as a unit, so the grid keeps its shape.
- **Files modified:** app/src/renderer/layout/subspaces.ts
- **Commit:** b9b0a4a

**3. [Judgement] Collapsed headers don't move**
- Collapsing a folder submits only `collapsed true`. It does not call settleSubspace, so nothing moves back to fill the space. The plan's action already called for "collapsing submits `setProperty collapsed true`". This records that nothing is pulled back.
- **Files modified:** app/src/renderer/App.tsx
- **Commit:** 3422ec0

**4. [Rule 3 - Blocking] subspaces.ts takes its node type from placement.ts**
- The plan said subspaces.ts imports only types from kernel-bridge. It uses `PlacementNode` from `./placement` (`import type`). That is the node shape main already passes to placement.ts, so look and place can hand the same nodes to both modules. The import is type-only and pure, with no React and no DOM.
- **Files modified:** app/src/renderer/layout/subspaces.ts
- **Commit:** b9b0a4a

**5. [Rule 3 - Blocking] The append test watches the disk instead of using editFile**
- **Issue:** The plan's test creates a file in `src/nested` by editFile. `editFile` edits existing files only and refuses a path that doesn't exist ("<path> does not exist in <name>"). Creating files belongs to 02.7-05's write_file.
- **Fix:** The test writes the file with `writeFileSync`, then calls `service.observePath(...)`, the path catch-up and the watcher take. A second test covers a new folder the same way.
- **Files modified:** app/src/main/workspace/subspaces.test.ts
- **Commit:** 440ddb5

**6. [Rule 3 - Blocking] The folder drag lives in Canvas (Task 2)**
- The plan put the header drag in FolderFrame and App's drag state. Canvas already owns pointer capture, zoom and the live drag state for frames and cards, so the folder drag uses that machinery. FolderFrame's header starts the drag, and Canvas calls `onFolderDrop(treeId, folderId, local, dimsOf)` on release. Task 2's commit touches Canvas.tsx, App.tsx and spatial.ts. FolderFrame.tsx was unchanged in Task 2.
- **Files modified:** app/src/renderer/components/Canvas.tsx, app/src/renderer/App.tsx
- **Commit:** 6a79054

**7. [Rule 1 - Bug] Settling waits for the tree to refresh**
- **Issue:** Calling `settleFrames(treeId)` right after a toggle or a drop would measure the workspace frame against the nodes from before the commit, which are stale.
- **Fix:** Canvas keeps `pendingSettleRef` and a `settleTick`. After an expand, collapse or folder drop lands and the tree refreshes, the frame is settled among tree frames on the next render, from the refreshed nodes.
- **Files modified:** app/src/renderer/components/Canvas.tsx
- **Commits:** 3422ec0, 6a79054

**8. [Judgement] The migration writes positions only where they change**
- `planSubspaceMigration` emits a position op only for a node whose stored position differs from the new layout. It adds `subspace` and `collapsed` on every folder. The plan said "for every workspace node". The result is the same, with fewer lines in the tree file.
