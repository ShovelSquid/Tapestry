- **Note tools refuse workspace trees.** They would create `title`/`body` keys, or free notes, that no file contains (D-03). connect_notes, look, place and read_note still work.
- **Nothing in production writes `lock.*`.** Tests write lock properties as a person through `submitAs(humanActor(...))`, as the 2.4 suites do.

**file-tools.ts.**

`listFiles({ workspace?, path?, limit? })`:
1. Resolve the folder.
2. List the files: git mode uses listGitFiles; otherwise walkFolder(realRoot, isIgnoredWorkspacePath). Keep rels under the prefix, then lstat each, skipping missing ones.
3. Each entry is `{ path, bytes, kind, note }`:
   - kind is 'text' or 'file' from the recorded note's type, or null when the tree has not recorded it yet;
   - note is the id or null.
4. Sort by path. limit defaults to 1000.
5. Return `{ workspace: name, root, folder: prefix, files, total, truncated }`.

Reading never commits.

`writeFile(actor, { workspace?, path, text })`:
1. Resolve in write mode and validate the text with the shared validator. Export the validator as `validateWorkspaceText` from file-tools.ts, and point Plan 01's editFile and saveFile at it if they used a private copy.
2. Read readPathState without committing. A `file` or `folder` state is refused with `<path> is not a text file (<reason>); write_file replaces only text files`.
3. Text equal to the disk (same sha256) returns `{ ..., unchanged: true }` with no write and no commit.
4. Call observePath, which is observe-first.
5. Create missing parent folders one segment at a time with mkdirSync(abs, { mode: 0o755 }), never recursive. Before each mkdir, lstat must show the segment absent; a segment that appeared as a symlink since resolution is refused with the symlink message.
6. Call commitWrite(actor, target, text, exists ? `write <rel>` : `create <rel>`).
7. Return `{ workspace, path, note, seq, sha256, created }`.
