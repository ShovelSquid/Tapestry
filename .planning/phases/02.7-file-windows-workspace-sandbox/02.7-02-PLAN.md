Task 1 re-checks every spelling against the installed CLI before code depends on it.

Recorded choices:
- **One long-lived process per chat.** With `--input-format stream-json` the CLI reads one JSON user message per line and keeps its session across turns. It is spawned lazily on the first message. After Stop, a crash or a relaunch, the next message respawns it with `--resume <session-id>`. New sessions pass `--session-id <crypto.randomUUID()>`, so the id is known before the first reply.
- **Stop kills rather than interrupts.** Stop sends SIGTERM to the process group, then SIGKILL after 3 s. The session stays resumable, so this always works, even without relying on an undocumented control message.
- **`--setting-sources user`.** `-p` skips Claude Code's workspace-trust dialog. Without this flag, an untrusted repository opened as a workspace could run its project `.claude/settings.json` hooks, or add permissions, as soon as the chat starts. The person's own user settings still apply. The workspace's CLAUDE.md still loads, since it is memory, not settings.
- **The panel's own agent is `agent.claude-chat`.** The Agents panel's `claude` token is stored only as a hash and cannot be reused. The chat therefore gets its own registry entry, visible in the Agents panel. Its token is re-issued with `AgentRegistry.issueToken` on every launch, so a leftover config file from an earlier run grants nothing.
- **The MCP server runs on Electron's own Node.** It uses `process.execPath` with `ELECTRON_RUN_AS_NODE=1` (the packaged-app form of the 02.2 connect command), so a Finder-launched Tapestry does not need `node` on its PATH.
- **The system prompt stays constant for the life of a chat.** `--system-prompt-snapshot` defaults to recording the prompt once and reusing it on every resume, so the text already covers the shell toggle 02.7-03 adds ("unless shell access is turned on for this chat...").
- **One chat per workspace, one engine for now.** The model picker, cost display and concurrent chats are deferred (CONTEXT Deferred Ideas). `ChatStartOptions` holds only what every engine shares, and engine-specific settings go in each engine's constructor.
- **Transcripts live in memory.** A relaunched chat resumes its Claude Code session but shows the notice "Continuing your earlier conversation; earlier messages aren't shown here." Claude Code keeps the session itself, under the person's ~/.claude.
</objective>

- `ChatEvent`, a discriminated union on `type`:

  - `user { text }`;
  - `text-delta { text }`;
  - `text { text }`, a complete assistant text block that replaces the deltas streamed for it;
  - `tool-call { id, name, input }`;
  - `tool-result { id, isError, text }`;
  - `notice { text }`;
  - `error { kind, message }`;

- `CHAT_MCP_SERVER = 'tapestry'` and `BUILTIN_TOOL_NAMES = ['Bash','Read','Edit','Write','Glob','Grep','NotebookEdit','WebFetch','WebSearch','Task','TodoWrite','LS','MultiEdit']`.
- `buildClaudeArgs({ sessionId, resume, mcpConfigPath, systemPrompt }): string[]` returns exactly, in this order:
  `-p`, `--input-format`, `stream-json`, `--output-format`, `stream-json`, `--verbose`, `--include-partial-messages`, `--mcp-config`, mcpConfigPath, `--strict-mcp-config`, `--tools`, `''` (an empty string element), `--allowedTools`, `mcp__tapestry`, `--permission-mode`, `dontAsk`, `--permission-prompts`, `none`, `--setting-sources`, `user`, `--append-system-prompt`, systemPrompt, then `--resume` sessionId when resume is true, otherwise `--session-id` sessionId.

  - Every variadic option is followed by another option, and there is no positional argument, so a variadic list cannot swallow anything.

- `parseStreamJsonLine(line): ChatEvent[]`, which never throws:
  - empty or non-JSON lines give `[]`;
  - `{type:'system', subtype:'init'}` gives `session` from `session_id`. If its `mcp_servers` lists `tapestry` with a status other than `connected`, it also gives `error tools-unavailable`: `Claude couldn't start Tapestry's workspace tools (<status>).`;

  - `{type:'assistant', message.content[]}` gives `text` for each text block and `tool-call` for each tool_use block;
  - `{type:'user', message.content[]}` gives `tool-result` for each tool_result block. The text joins string content or text parts, is truncated to 4000 chars, and isError comes from `is_error`;
  - `{type:'result'}` gives `done { ok: !is_error, reason: subtype }`, preceded by an `error` from classifyExit when is_error is true;

**app/src/main/chat/claude-cli-engine.ts** (new). `class ClaudeCliEngine implements ChatEngine`, kind 'claude-cli'. Constructor: `({ command: { path, prefixArgs? }, mcpConfigPath, systemPrompt, env, turnTimeoutMs = 30 * 60_000 })`.

- `start({ cwd, resumeSessionId })` stores cwd and the session id (a new crypto.randomUUID() when none is given) and returns `{ sessionId, resumed }`. It spawns nothing.
- `send(text)`:
  - throws `Claude is still answering; stop it or wait` while busy;
  - spawns when there is no live process: `spawn(path, [...prefixArgs, ...buildClaudeArgs({ sessionId, resume: hasHistory, mcpConfigPath, systemPrompt })], { cwd, env, stdio: 'pipe', shell: false, detached: true })`. hasHistory is true after the first successful spawn or when started with resumeSessionId;
  - writes userMessageLine(text) to stdin and marks busy.
- stdout: read by line with a cap of 8 MiB per line. An oversize line gives `error protocol` and kills the process. Each line goes through parseStreamJsonLine and is emitted; `done` clears busy, and `session` adopts the reported id.
- stderr: kept in an 8 KiB ring buffer and never logged whole.
- 'error' with code ENOENT emits `error not-installed`.
- 'exit' while busy emits classifyExit's error and then `done { ok: false }`. The process is marked dead, so the next send respawns with `--resume`.
- The turn timer emits `error timeout` ("The turn ran longer than 30 minutes and was stopped.") and runs the stop logic.
- `stop()` sends `process.kill(-pid, 'SIGTERM')`, then SIGKILL to the group after 3 s if it is still alive. When busy it emits `done { ok: false, reason: 'stopped' }`.
- `dispose()` ends stdin, stops, and removes listeners.

**app/src/main/chat/chat-service.ts** (new). `CHAT_AGENT_NAME = 'claude-chat'` and `class ChatService`. Constructor:
- `{ userDataDir, agents: AgentRegistry, workspaces: WorkspaceService, launch: { isPackaged, appPath, execPath, resourcesPath }, isBridgeEnabled: () => boolean, emit: (treeId, event) => void }`;
- plus test seams `createEngine?` and `claudeBinary?`.

Per open workspace tree it keeps `{ engine, transcript: ChatEvent[] (capped at 2000, oldest dropped), sessionId }`.

- `open(treeId)` returns `{ workspace: name, sessionId | null, transcript, busy, resumed }`. The tree must be an open workspace, otherwise NO_WORKSPACE_MESSAGE.
- `send(treeId, text)`:
  1. Validate the text: a non-empty string of at most 100000 chars.
  2. `isBridgeEnabled()` false means emit `error bridge-off` ("Agents are turned off in the Agents panel, so Claude can't reach the workspace tools. Turn agents on, then send again.") and spawn nothing.
  3. Resolve the binary; if it isn't found, emit `error not-installed`.
  4. Ensure the engine:
     - on the first need per app launch, issue the panel token once: `agents.issueToken(CHAT_AGENT_NAME)`;
     - write `<userDataDir>/chat/<first 16 hex of the tree id>.mcp.json` with mode 0600 in a 0700 folder, holding `{ mcpServers: { tapestry: { type: 'stdio', ...chatShimLaunch(...) } } }`;
     - construct the engine with `childEnv(process.env)` and `chatSystemPrompt(name)`, then `start({ cwd: ws.realRoot, resumeSessionId })`.
  5. Record a `user` event and call `engine.send(text)`.
- Every engine event is appended to the transcript and passed to emit.
- `stop(treeId)`.
- `newChat(treeId)` disposes the engine, clears sessionId and transcript, and persists.
- `closeWorkspace(treeId)` disposes the engine and deletes its MCP config file.
- `disposeAll()` does the same for every chat.
- Persistence: `<userDataDir>/chat/chats.json` (0600) is `{ version: 1, chats: { [realRoot]: { sessionId } } }`, written when a `session` event arrives and read on first open. A resumed chat emits the notice "Continuing your earlier conversation; earlier messages aren't shown here."
- On `error session-lost`, emit the notice "The earlier conversation couldn't be resumed, so this is a new one.", clear the session, and resend the same text once on a fresh session.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (chat:*) | The window can send any text and tree id |
| main → spawned `claude` process | Arguments, environment and working directory cross into a powerful local program |
| `claude` → Tapestry MCP shim → agent socket | The model's tool calls, authenticated only by the panel agent's token |
| workspace contents → Claude Code | An untrusted repository's settings, hooks and files are read by the CLI |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
