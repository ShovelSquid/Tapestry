Recorded choices:
- **One long-lived process per chat.** With `--input-format stream-json` the CLI reads one JSON user message per line and keeps its session across turns. It is spawned lazily on the first message. After Stop, a crash or a relaunch, the next message respawns it with `--resume <session-id>`. New sessions pass `--session-id <crypto.randomUUID()>`, so the id is known before the first reply.
- **Stop kills rather than interrupts.** Stop sends SIGTERM to the process group, then SIGKILL after 3 s. The session stays resumable, so this always works, even without relying on an undocumented control message.
- **`--setting-sources user`.** `-p` skips Claude Code's workspace-trust dialog. Without this flag, an untrusted repository opened as a workspace could run its project `.claude/settings.json` hooks, or add permissions, as soon as the chat starts. The person's own user settings still apply. The workspace's CLAUDE.md still loads, since it is memory, not settings.
- **The panel's own agent is `agent.claude-chat`.** The Agents panel's `claude` token is stored only as a hash and cannot be reused. The chat therefore gets its own registry entry, visible in the Agents panel. Its token is re-issued with `AgentRegistry.issueToken` on every launch, so a leftover config file from an earlier run grants nothing.
- **The MCP server runs on Electron's own Node.** It uses `process.execPath` with `ELECTRON_RUN_AS_NODE=1` (the packaged-app form of the 02.2 connect command), so a Finder-launched Tapestry does not need `node` on its PATH.
- **The system prompt stays constant for the life of a chat.** `--system-prompt-snapshot` defaults to recording the prompt once and reusing it on every resume, so the text already covers the shell toggle 02.7-04 adds ("unless shell access is turned on for this chat...").
- **One chat per workspace, one engine for now.** The model picker, cost display and concurrent chats are deferred (CONTEXT Deferred Ideas). `ChatStartOptions` holds only what every engine shares, and engine-specific settings go in each engine's constructor.
- **Transcripts live in memory.** A relaunched chat resumes its Claude Code session but shows the notice "Continuing your earlier conversation; earlier messages aren't shown here." Claude Code keeps the session itself, under the person's ~/.claude.
- **D-20 hello is its own request type.** The shape is `{ id, token, type: 'hello' }`. The socket server handles it before the tool-request checks, so a hello can never dispatch a tool. A known token calls `noteSeen` and `markConnected`, the same bookkeeping a tool call does.
  - The shim sends one hello at startup, then one every `HELLO_INTERVAL_MS = 60_000`, inside the 120 s CONNECTED_WINDOW_MS. The timer is unref'd, so it never keeps the shim alive after its client leaves.
  - A hello that fails because Tapestry isn't running is silent, and the next keep-alive retries. Starting Tapestry after Claude Code therefore still shows the agent as connected within a minute.
  - `TAPESTRY_HELLO_INTERVAL_MS` overrides the interval for tests only, clamped to at least 100 ms.
- **D-19 menu.** The renderer has no context menu today, so this adds one small app-wide component (ContextMenu.tsx). It holds one provider and a hook, with **Ask Claude…** as its only item for now; later items can join it.
  - Right-clicks are handled per card, because cards carry no data attributes a canvas-level handler could read, plus one handler for the canvas background.
- **D-19 attachments.** An attachment is text only, and goes over stdin like any message:
  - `Context: the file <path> in the workspace <name>.`
  - `Context: the note <id> "<title>" in the tree <tree name> (<tree id>). Read it with read_note.`

  It shows as a removable chip in the composer and is prefixed to the first message sent after it was attached. Notes live in trees rather than workspaces, and the panel's Claude reaches them through the Tapestry MCP tools it already has (read_note, search_notes), under the same lock rules.

- `send(text)`:
  - throws `Claude is still answering; stop it or wait` while busy;
  - spawns when there is no live process: `spawn(path, [...prefixArgs, ...buildClaudeArgs({ sessionId, resume: hasHistory, mcpConfigPath, systemPrompt })], { cwd, env, stdio: 'pipe', shell: false, detached: true })`. hasHistory is true after the first successful spawn or when started with resumeSessionId;

- The turn timer emits `error timeout` ("The turn ran longer than 30 minutes and was stopped.") and runs the stop logic.
- `stop()` sends `process.kill(-pid, 'SIGTERM')`, then SIGKILL to the group after 3 s if it is still alive. When busy it emits `done { ok: false, reason: 'stopped' }`.
- `dispose()` ends stdin, stops, and removes listeners.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (chat:*) | The window can send any text and tree id |
| main → spawned `claude` process | Arguments, environment and working directory cross into a powerful local program |
| `claude` → Tapestry MCP shim → agent socket | The model's tool calls, authenticated only by the panel agent's token |
| workspace contents → Claude Code | An untrusted repository's settings, hooks and files are read by the CLI |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.7-27 | Tampering | argv injection into the spawned CLI | high | mitigate | spawn with an argument array, `shell: false`. Message text goes only over stdin as stream-json. Every value is a single argv element; no positional argument exists, and every variadic option is followed by another option. claude-cli.test.ts proves hostile values stay single elements |
| T-02.7-28 | Elevation of Privilege | the panel's Claude reaching outside the workspace with the shell off | high | mitigate | `--tools ""` removes every built-in and `--strict-mcp-config` loads only Tapestry's server. `--allowedTools mcp__tapestry` with `--permission-mode dontAsk --permission-prompts none` means nothing else runs or prompts. | T-02.7-29 | Elevation of Privilege | an untrusted workspace's .claude/settings.json hooks or permissions running without the trust dialog (-p skips it) | high | mitigate | `--setting-sources user` loads only the person's own settings. The workspace's settings, hooks and MCP servers are ignored |
