# Phase 2.7 Plan 05: Full file tools, the refusal matrix, file locks and guards Summary

**Agents can now list, create, replace, edit, read and open workspace files. Every way out of the workspace is refused through the real dispatch, and a byte fingerprint proves nothing was written. File notes obey explicit text and layout locks. A workspace tree can no longer drift from its files through the note tools, window submits or undo.**

## What Kaelen should know

- **New tools.** `list_files` lists what the workspace window shows (git's view), with size, text/other and note id. `write_file` creates a file, and any missing folders, or replaces a text file's whole text. A new file gets 0644 under the umask; a replaced file keeps its mode (a 0755 script stays executable). Writing the text a file already has changes nothing and commits nothing. `open_file` pans the canvas to the file's card and opens its window. Collapsed folders above it open for this view only, and nothing is committed. Collapsing one of them ends the reveal.
- **Locks on files (D-09).** A file is open to every agent unless someone set an explicit `lock.text` or `lock.layout` on its note. A locked file refuses `write_file`/`edit_file` with `<path>: <note> text is locked by <owner>`, and a locked layout refuses `place`. Both refusals come before anything is written or committed. Nothing in the app writes `lock.*` yet (Decision Register #19 is still open), so for now only tests set locks.
- **What the window refuses on workspace trees.** Main refuses creating or deleting notes, setting or unsetting any `file.*` key, and undo/redo. Double-clicking inside a workspace frame shows "Workspace windows hold files. Create a file with an agent's write_file or in your editor." Cmd+Z / Cmd+Shift+Z while a workspace frame is the undo target shows "Undo isn't available in a workspace window; the files are the record. Use git to undo a file change." Moving, resizing and collapsing cards, and connecting notes, still commit.
- **Note tools and workspace trees.** An agent that calls create/update/rename/delete_note on a workspace tree is told `<name> is a workspace; its notes are files. Use write_file or edit_file`.

## Accomplishments

- **Task 1 (tracer): list_files and write_file.** Strict schemas and dispatch cases. The sandbox gains a `folder` mode: '' or '.' means the root, the target must be an existing directory, and the ignore rule does not apply to a folder prefix. writeFile resolves the path, validates the text and refuses non-text targets. It returns `unchanged` on equal text. Otherwise it observes first, creates missing folders one lstat-checked `mkdir` at a time, and commits `create <path>` or `write <path>` as the agent in one commit that also carries the new folder notes. The tracer gate re-ran end to end over the real shim and passed.
- **Task 2: matrix, case, locks, note tools.** `sandbox-matrix.test.ts` runs 86 escape and tool combinations plus the no-workspace case. Each one checks the refusal reason and a fingerprint of every file (sha256), link, journal size, node count and head seq. Canonical case is proven on this APFS volume: `SRC/Hello.ts` edits `src/hello.ts`, the commit names `src/hello.ts`, and it stays one note. `file-locks.test.ts` covers lock.text, allow lists, `open`, watcher-created notes, lock.layout on `place`, the native default and the note-tool refusals.
- **Task 3: open_file and guards.** `reveal-note` goes from main to the preload, then to App. App refreshes the tree, expands the ancestor folders in view-only state, and sets an open request (`WorkspaceFileCard.openNonce`) that opens the card's window. Canvas.panToNote centres the frame origin + absolute position + half the size (280 × 200 before measurement). `guards.ts` is pure; `registerHandlers` takes an optional 4th `guards` argument that index.ts fills for workspace trees.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The shim tool-list test names the new tools**
- **Found during:** Task 1 (and Task 3)
- **Issue:** `shim.test.ts` asserts the exact advertised tool list, so adding tools failed it (the same thing happened in 02.7-01).
- **Fix:** Added `list_files`, `write_file` and `open_file` to the list (fifteen tools). The no-actor check is unchanged.
- **Files modified:** app/src/main/mcp/shim.test.ts
- **Commits:** ce2a5c2, 8add94d

**2. [Rule 3 - Blocking] list_files walks non-git folders synchronously**
- **Found during:** Task 1
- **Issue:** The plan says to use `walkFolder` for non-git workspaces. walkFolder is async, and every file command is synchronous and returns a CommandResult.
- **Fix:** A small synchronous lstat walk in file-tools.ts (`walkFilesSync`). It never follows links and uses the same `isIgnoredWorkspacePath` rule. Git workspaces use `listGitFiles`, as planned.
- **Commit:** ce2a5c2

**3. [Plan conflict] '' in the matrix is refused by schema validation**
- **Found during:** Task 2
- **Issue:** Task 1 fixes `path` for write_file (and Plan 01 for read/edit) at 1..4096 characters, so zod refuses `''` before the sandbox sees it. The matrix expected the sandbox's "path must name a file" text for it.
- **Fix:** Kept the schemas as specified. The matrix asserts that `''` is refused with a message naming `path` and that the fingerprint is unchanged. `'.'` gets the sandbox's "path must name a file" message as planned. list_files takes `''` as the root.
- **Commit:** 1b5d530

**4. [Rule 2 - Correctness] New-file mode applies the umask explicitly**
- **Found during:** Task 1
- **Issue:** `writeFileAtomicSync` fchmods to the exact mode, so passing 0o644 would ignore the umask. The plan says the umask still applies.
- **Fix:** commitWrite passes `0o644 & ~process.umask()` for a new file. An existing file keeps its mode, as before.
- **Commit:** ce2a5c2

**5. [Rule 2 - UX] Renderer says why before main refuses undo**
- **Found during:** Task 3
- **Issue:** With only the main-side guard, Cmd+Z would show a generic "Undo failed: Error invoking remote method..." error.
- **Fix:** handleUndo/handleRedo check the target tree's kind and show the undo notice. Main's guard stays the authority.
- **Commit:** 8add94d

**Total deviations:** 5 (2 blocking, 2 correctness/UX, 1 plan conflict). No scope change.
