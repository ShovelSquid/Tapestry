# Phase 2.7 Plan 01: Dogfood tracer Summary

**A folder opens in Tapestry as a workspace. Its git-visible files show up as cards that open into editable windows and save a second after typing stops. Claude Code reads and edits the same files through the sandboxed MCP tools `read_file` and `edit_file`. Every change is recorded in a `.tree` kept in app data, credited to `agent.claude`, `user.<name>` or, for changes Tapestry only noticed, `workspace.watcher`.**

## What Kaelen should know

- **Where the workspace tree lives (reversible).** Each workspace's history is a `.tree` file at `<userData>/workspaces/<folder name>-<hash8>.tree`. `<hash8>` is the first 8 hex digits of the sha256 of the folder's real path; on macOS the file sits under `~/Library/Application Support/<app>/workspaces/`. Adding a workspace creates nothing inside the folder, so `git status` stays clean. The tree only mirrors files that already exist, so this location can move later, for example into the folder, by re-importing.
- **Agents cannot read or write git-ignored paths.** In a git work tree the file tools reach exactly the files the window shows (`git ls-files --cached --others --exclude-standard`), plus new files at paths git would show. `.env`, `node_modules/`, `out/` and anything else `.gitignore` covers are refused with `<path> is ignored by git in <name>; file tools reach only files the window shows`. The same refusal covers `..` segments, absolute paths outside the workspace, any symbolic link along the path, `.git` in any letter case, and the workspace root itself. A refusal writes nothing.
- **Outside edits appear in windows only after a relaunch, until 02.7-06 adds live watching.** Outside edits include Claude Code's own Edit/Write tools, `git checkout`, and other editors. Until then a window updates only when Tapestry itself writes (the tapestry file tools or your typing). On relaunch the catch-up records outside edits as `observed change to <path>` by `workspace.watcher`. If you type into a window whose file changed outside in the meantime, the file wins: it keeps its bytes, your edit stays in history, and the window shows the file-wins notice.
- **Dev hot reload.** Under `npm --prefix app run dev`, electron-vite reloads the renderer whenever a file under `app/src/renderer/**` changes, even when the edit came through Tapestry's own tools. The frame and tree survive, but a window edit typed less than a second before the reload can be lost. Main-process files (such as `app/src/main/mcp/tools.ts`) do not trigger this.
- **Dogfood result (D-11): approved by Kaelen on 2026-09-24.** Kaelen opened `~/Tapestrees/windows` as a workspace and connected Claude Code through the Agents panel. Claude edited a real source file through `edit_file`, and the edit showed in `git diff` and in the card, credited to agent.claude. A line typed into the window reached the file, credited to the person. A relaunch restored the frame and caught up the outside `git checkout` as `workspace.watcher`.

## Accomplishments

- **Shared mirror core.** `app/src/main/mirror/` now owns folder walking, git listing and ignore checks, bounded `O_NOFOLLOW` reads, text decoding, atomic symlink-safe writes, and a folder/text/file/deletion planner parameterised by `MirrorShape`. `obsidian/vault-fs.ts` delegates to it with every export unchanged, and every obsidian test passes.
- **Workspace trees and the sandbox.** `resolveWorkspaceTarget` checks every agent and window path against an open workspace root. `WorkspaceService` covers adding a workspace, restoring it, a serialized catch-up over git's view, the observe-first step, agent writes and human saves.
- **MCP tools.** `read_file` and `edit_file` go over the existing socket bridge with strict, actor-free schemas; the actor comes from the agent's token. The shim test proves an edit lands in `git diff` and in the tree as `actor plugin agent.claude`, message `edit src/hello.ts (1 replacement)`.
- **Human save path with file-wins (D-04/D-05).** A person's edit is committed first. It is written only if the file still matches the base sha256 the window started from; otherwise the file's text is recorded as observed and the edit stays in history.
- **File windows.** Cards show a clipped preview and open into a 720px window that saves after a 1 s debounce, with the states Writing soon... / Writing... / Up to date, the file-wins notice and write errors. CRLF files are edited as LF and saved back as CRLF; files with mixed line endings open read-only. The window keeps keystrokes, pointer events and wheel scrolling to itself. Folder labels come from the `workspace-files` plugin, and the forest bar has Add Workspace Folder....
- **Restore.** A workspace is remembered in settings.json as `kind: 'workspace'` with its `workspaceRoot`. On launch it is reopened and caught up, so a change made while Tapestry was closed is recorded by `workspace.watcher`.
