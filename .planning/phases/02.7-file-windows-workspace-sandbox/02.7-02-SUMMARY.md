# Phase 2.7 Plan 02: In-app Claude chat, connect-on-start and Ask Claude Summary

**A workspace frame's Chat with Claude button, or Ask Claude… on the canvas, a file card or a note, opens a docked panel. The panel runs Kaelen's own `claude -p` in stream-json mode, in the workspace root, with no built-in tools and only Tapestry's sandboxed MCP tools. Replies stream in, and edits land in the file windows as `agent.claude-chat`. Agents connected over MCP now show `Connected now` as soon as their client starts the shim.**

## What Kaelen should know

- **Claude Code version and flag check.** The installed CLI is `2.1.282` (the plan was written against 2.1.281). `claude --help` lists every flag the panel uses with the planned spelling and choices: `-p`, `--input-format stream-json`, `--output-format stream-json`, `--verbose`, `--include-partial-messages`, `--mcp-config`, `--strict-mcp-config`, `--tools` (`""` disables all built-ins), `--allowedTools`, `--permission-mode` (includes `dontAsk`), `--permission-prompts none`, `--setting-sources user`, `--append-system-prompt`, `--session-id`, `--resume`. A test repeats this check against `claude --help` whenever `claude` is installed; it needs no login and spends no tokens.
- **The text fixture was captured live.** `text-turn.jsonl` comes from one real run of `claude -p … --tools '' --no-session-persistence --setting-sources user`, asked to reply "ok", which cost a few tokens once. Session ids and uuids were replaced with fixed fake UUIDs. The following were stripped: cwd, memory and socket paths, request and message ids, usage numbers, cost, rate-limit details and the output of your SessionStart hook lines. The init line's `mcp_servers` was set to `tapestry: connected` to match a run with the chat's config. The edit, crash, signed-out, slow and session-lost turns in `fake-claude.mjs` were written by hand from the same message shapes, and 02.7-03's checkpoint confirms them against the real CLI.
- **The panel signs as `agent.claude-chat`.** This agent appears in the Agents panel. Its token is re-issued on every launch, so an old config file grants nothing. The token is written only to `<userData>/chat/<16 hex of the tree id>.mcp.json` (0600, in a 0700 folder), and that file is deleted when the chat's workspace closes or Tapestry quits. The token is never in argv, the CLI's environment, a log, the renderer or the tree.
- **`--setting-sources user` means the workspace's own Claude Code settings do not apply in the panel.** A workspace's `.claude/settings.json` and `settings.local.json` (hooks, permissions, MCP servers) are not loaded, because `-p` skips the trust dialog. Your own user settings, including your user hooks, still apply. The capture run showed your SessionStart hooks firing. The workspace's CLAUDE.md still loads, because it is memory rather than settings.
- **Connect-on-start (D-20).** The shim now says hello over the agent socket when it starts, and again every 60 s. This includes `agent.claude` connected from a terminal, which you saw as "Never connected". As soon as Claude Code starts the Tapestry server, the Agents panel reads `Connected now`, and it keeps saying so while the client runs. About two minutes after the client stops, it falls back to `Last connected …`. If Tapestry starts after Claude Code, the agent shows as connected within a minute. A hello can only mark an agent as seen. It never runs a tool, and a hello with an unknown token is refused.
- **Where Ask Claude… appears (D-19).**
  - Where to find it:
    - Right-clicking the canvas background (inside or outside a frame) offers **Ask Claude…**.
    - Right-clicking a workspace file card, a native note or a vault note offers it too. Inside an open file's text, the native menu is kept for copy and paste. Inside a note being edited, clicks in its text or title also keep the native menu.
    - Every file card and note has a small speech-bubble button labelled `Ask Claude about <name>`.
  - Which workspace the chat opens in:
    1. The clicked file's own workspace.
    2. Otherwise, the workspace clicked in.
    3. Otherwise, the last chat you used, if its workspace is still open.
    4. Otherwise, the only open workspace.
    5. With several open, a chooser: "Chat in which workspace?".
    6. With none open, the panel says to add one and runs nothing.
  - The attachment shows as a chip (`Attached: <path>` or `Attached: "<title>"`) with **Remove attachment**. It is prefixed to the next message you send, followed by a blank line. Its exact formats are:
    - `Context: the file <path> in the workspace <name>.`
    - `Context: the note <id> "<title>" in the tree <tree name> (<tree id>). Read it with read_note.` In the title, `"` is escaped as `\"`, a backslash as `\\`, and newlines become spaces.
- **Close chat stops the process but keeps the conversation.** The next message resumes the same Claude Code session. **New chat** forgets the session. After a relaunch, the first message resumes the earlier session and the panel says "Continuing your earlier conversation; earlier messages aren't shown here."

## Accomplishments

- **D-20 hello.** Before its tool checks, `AgentSocketServer.handleLine` handles `{ id, token, type: 'hello' }`. A known token goes through the same `noteSeen` and `markConnected` bookkeeping as a tool call and gets the reply `{ ok: true, value: { agent: 'agent.<name>' } }`. The shim says hello at startup, then every `HELLO_INTERVAL_MS = 60_000` on an unref'd timer. Failures go only to stderr, once per failure kind. Tests can set `TAPESTRY_HELLO_INTERVAL_MS`, clamped to at least 100 ms.
- **ChatEngine seam (D-16).** `engine.ts` defines `ChatEngine`, `ChatEvent`, `ChatErrorKind` and `ChatStartOptions`. The only addition beyond the plan is an optional `killNow()`, used at quit.
- **CLI helpers.**
  - `buildClaudeArgs` returns the exact argv the plan lists, with a comment explaining each flag.
  - `parseStreamJsonLine` never throws.
  - `classifyExit` names signed-out, session-lost and crashed failures.
  - `resolveClaudeBinary` checks `TAPESTRY_CLAUDE_PATH`, then PATH, then the usual install places, and lists where it looked.
  - `childEnv` strips `ELECTRON_*` keys and any inherited `TAPESTRY_AGENT_TOKEN`.
  - `chatSystemPrompt` is constant for a chat's life.
- **ClaudeCliEngine.** The engine keeps one long-lived process per chat.
  - It spawns with an argv array, `shell: false` and `detached: true`, in the workspace's realRoot.
  - Stdout lines are capped at 8 MiB, and stderr is kept in an 8 KiB ring.
  - It enforces a 30-minute turn timeout.
  - Stop sends SIGTERM to the group, then SIGKILL after 3 s. A CLI that exits on its own takes the rest of its group with it.
- **ChatService.** One chat per open workspace. It checks that the text is a non-empty string of at most 100,000 characters. It handles bridge-off and not-installed without spawning anything. It keeps sessions in `chats.json` (0600) under `<userData>/chat`. After a lost session it resends the message once on a new session, with a notice. `killAllNow` supports quit.
- **IPC and UI.**
  - The `chat:*` handlers check tree ids against `TREE_ID_PATTERN`.
  - The preload exposes `window.tapestry.chat` and `onChatEvent`.
  - `useChat` folds events into a transcript: deltas are replaced by their complete text, and tool calls pair with their results.
  - `ChatPanel` sits 420 px wide on the right. It shows streaming text, tool rows (`edit_file src/x.ts — done` or `— refused: …`), muted notices, and error blocks with a next step for signed-out and not-installed. Enter sends, Shift+Enter adds a new line, and Stop shows while a turn runs. Keys, presses and wheel turns stay inside the panel.
- **D-19 entry points.** `ContextMenu.tsx` provides `ContextMenuProvider`, `useContextMenu` and `AskClaudeButton`. The menu is a `role="menu"` placed within the viewport. It supports arrow keys and Enter, and closes on Escape, an outside press, a wheel turn or the window losing focus, returning focus where it was.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] A synchronous spawn failure now ends its turn**
- **Found during:** Task 4
- **Issue:** If `spawn` threw outright, the engine emitted an error but no `done`. The service had already recorded the `user` event, so the panel would have stayed busy with Send disabled.
- **Fix:** `send` emits `done { ok: false }` when no process could be started.
- **Files modified:** app/src/main/chat/claude-cli-engine.ts
- **Commit:** 0c105c5

**2. [Rule 2 - Missing critical] Orphans of a CLI that exits on its own are killed**
- **Found during:** Task 4
- **Issue:** Stop killed the whole group, but after a crash, members of the group other than the CLI (the MCP shim, a tool process) could be left running.
- **Fix:** On an unexpected `close`, the engine sends SIGKILL to the group if anything in it is still alive. `killNow` covers groups still being stopped at quit.
- **Files modified:** app/src/main/chat/claude-cli-engine.ts
- **Commit:** 0c105c5

**3. [Rule 1 - Bug] Crash naming waits for stderr to drain**
- **Found during:** Task 2 Stage B
- **Issue:** Classifying a failure on `exit` can run before stderr has been read, which would drop the "Not logged in" line.
- **Fix:** The failure is named on `close`, which comes after stdio has drained. `exit` only marks the process dead.
- **Files modified:** app/src/main/chat/claude-cli-engine.ts
- **Commit:** 4634a87

**4. [Rule 3 - Blocking] Files outside the plan's list**
- **Found during:** Tasks 2 and 3
- **Issue:** The new UI needed styles. NoteCard and VaultNoteCard also had no `treeId` to build a note attachment from.
- **Fix:** Added the chat, chip, menu and chat-button styles to `App.css`, and passed `treeId` from `TreeFrame.tsx` to NoteCard and VaultNoteCard as an optional prop.
- **Files modified:** app/src/renderer/App.css, app/src/renderer/components/TreeFrame.tsx
- **Commits:** d955678, 74ad584

**5. [Judgement] Small choices within the plan's wording**
- `SocketCaller.hello()` returns `Promise<boolean>` as planned. It also takes an optional failure callback, used for the once-per-kind stderr line.
- An MCP server reported as `pending` at init is not an error, because Claude Code can report its servers before they finish connecting.
- `hasHistory` becomes true when the CLI reports its session in the init line, not just when a process spawns. A CLI that dies before starting a conversation, such as a signed-out one, is therefore retried with `--session-id`, which is correct, rather than `--resume` of a session that never existed.
- The fake CLI also takes `FAKE_CLAUDE_SCENARIO_FILE`, so one test can switch scenarios between spawns (crash then text, text then session-lost). It also logs stdin lines, so the busy-refusal test can prove nothing more was written.
- `ChatService.stopAll()` and `killAllNow()` were added for `agents:setEnabled(false)` and `will-quit`.
- Close chat also stops the chat's process, as Task 4 asks ("stopped, not deleted").
