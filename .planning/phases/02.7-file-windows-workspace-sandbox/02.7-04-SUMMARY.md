# Phase 2.7 Plan 04: Allow shell (not sandboxed) Summary

**Each chat now has an "Allow shell (not sandboxed)" switch. It is off for every new chat, for New chat and after every relaunch, and turning it on needs a confirmation. With it on, the next spawn gets `--tools Bash,Read,Edit,Write,Glob,Grep` and `--allowedTools mcp__tapestry,Bash,Read,Edit,Write,Glob,Grep`; nothing else in the argv changes. Whatever the shell or Claude Code's own file tools change is caught up at the end of the turn and recorded as `plugin workspace.watcher` "observed change to <path>", never as agent.claude-chat.**

## What Kaelen should know

- **The switch resets to off on every relaunch.** Your consent covers one session of the app. chats.json keeps `shell: { on, changedAt }` for each workspace root. When Tapestry starts, any `on: true` is rewritten to `false`. The first time that chat opens, it says: "Shell access was on in this chat before Tapestry restarted. It is off now; turn it on again if you still want it." The notice appears once.
- **Confirmed tool names.** Claude Code 2.1.282 is installed at `~/.local/share/claude/versions/2.1.282`. I read its binary with `grep -a` and did not run it. Its `--tools` help text reads: `Use "" to disable all tools, "default" to use all tools, or specify tool names (e.g. "Bash,Edit,Read")`. That confirms the comma-joined single-element form. The bundle also defines the tool-name constants `"Glob"` and `"Grep"`. `Bash`, `Read`, `Edit` and `Write` are the names the same help text and 02.7-02's `BUILTIN_TOOL_NAMES` use. I did not check them against a live `system/init` `tools` list, because this session could not run the real CLI. The fake's init now echoes the `--tools` it was given, so the shape is there for that check.
- **What the panel shows:**
  - The header has a switch labelled **Allow shell (not sandboxed)**, with the line "Lets Claude run commands outside Tapestry's workspace rules" (via aria-describedby).
  - Turning it on opens **Allow shell for this chat?** with the risk text from the plan. The buttons are **Keep shell off** (focused, and Escape does the same) and **Allow shell**.
  - Turning it off applies at once.
  - While it is on, a red banner **Shell on — not sandboxed** sits under the header.
  - Each change adds a notice to the transcript.
- **When a change applies.** It applies from the next message.
  - While idle, the live `claude` process group is ended quietly, with no `done`. The next message resumes the same session with `--resume` and the new tools.
  - During a turn, the change applies after that turn's `done`, or after Stop.
- **Honest attribution (D-06).** After every turn that ran with the shell on, including one that crashed, was stopped or timed out, the chat service awaits `WorkspaceService.catchUp(treeId)` before it shows the turn's `done`. When the panel sees the turn end, the change is already in the tree as `actor plugin workspace.watcher`. A turn with the shell off never triggers this catch-up. Until 02.7-06 adds live watching, shell edits appear at the end of the turn, not while it runs.
- **Unchanged:**
  - cwd is still the workspace root.
  - `--strict-mcp-config`, `dontAsk`, `--permission-prompts none` and `--setting-sources user` stay.
  - The system prompt is untouched.
  - There is no `--restricted`.

**4. [Rule 1 - Correctness] A shell-on turn's `done` is held until its catch-up finishes**
- **Found during:** Task 1
- **Issue:** The plan says to await `catchUp` on a shell-on `done`, but not whether the panel sees `done` before or after it. If `done` went first, the panel could start a turn whose changes land in the same catch-up, and the "commit after done" check would race.
- **Fix:**
  - `done` is recorded after the catch-up, in a `finally`.
  - `open().busy` is true while the catch-up runs.
  - `send` waits for it.
- **Commit:** `2401525`

**5. `ChatEngine.setAllowShell?` added to the engine seam**
- **Found during:** Task 1
- **Issue:** ChatService only talks to the `ChatEngine` interface (D-16), so it needs a way to pass the switch on.
- **Fix:** Added an optional method. Engines with no shell, such as 02.7-07's API-key engine, leave it out.
- **Commit:** `2401525`
