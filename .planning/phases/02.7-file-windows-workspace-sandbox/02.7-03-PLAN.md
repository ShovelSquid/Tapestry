## Phase Goal

**As** Kaelen, **I want** a workspace's folders to be subspaces with the same design as tree frames — nested, draggable as a unit, collapsible, never overlapping — **so that** a repository of ~740 files reads like a tidy space instead of one long strip of cards.

(Sourced from 02.7-CONTEXT.md D-21. The combined checkpoint also closes D-12..D-14, D-19 and D-20 from 02.7-02.)

<objective>
Folder frames (D-21), placed right after the chat panel. The phase's one hands-on checkpoint for 02.7-02 and this plan comes at the end.

Purpose: the first dogfood try showed a flat strip of 740 cards. Folders drawn as the same frames as trees, collapsed by default, make the workspace navigable. Because the design reuses the tree-frame pieces, the vault's folder groups (02.2) can adopt it later.

Output:
- `renderer/layout/subspaces.ts`, the pure geometry that main also imports, as placement.ts already is;
- `FolderFrame.tsx`;
- a folder variant of FrameHeader;
- optional size parameters on computeFrameBounds;
- the subspace layout, appends and migration in `mirror/plan.ts`;
- the migration on open;
- workspace-aware look and place;
- the combined checkpoint.

Recorded choices:
- **Folder-local coordinates.** Each workspace note's position is local to its parent folder's content origin. This is the tree-frame rule (02.2 D-15) one level down, so dragging a folder writes one folder position rather than every descendant's.
  - A folder says so with the Tapestry key `subspace` (bool true). Its collapsed state is the Tapestry key `collapsed` (bool).
  - Both are Tapestry's keys by the `file.*` rule. Neither is ever read from or written to disk.
- **The migration re-lays out rather than converting.** 02.7-01's flat layout stacked every folder as a label on one long column. Converting those coordinates would leave nested frames overlapping their parents' siblings.
  - On first open under this plan, an old workspace tree is re-laid out with the subspace layout, every folder collapsed, in one `system tapestry` commit.
  - Earlier card positions stay in history. Any hand arrangement from the first dogfood try is replaced, which is reversible from history. No real history is expected yet (see D-18).
- **Everything starts collapsed.** First import and migration both collapse every folder: the workspace shows its root files plus a compact column of folder headers, and Kaelen opens what he needs. Expanding pushes siblings aside with the existing pushApart and saves the result.
- **Folder frames are lighter.** computeFrameBounds gains an optional `options { minWidth, minHeight, headerHeight, padding }`, whose defaults are today's constants, so tree frames are untouched. `FOLDER_FRAME` = `{ minWidth: 320, minHeight: FRAME_HEADER_HEIGHT + 96, headerHeight: FRAME_HEADER_HEIGHT, padding: 24 }`. A collapsed folder is its header band only, 320 wide.
- **FrameHeader gains `variant: 'tree' | 'folder'`,** defaulting to 'tree'.
  - The folder variant shows the folder's name, the kind label "Folder", the status "<n> files", and a **Collapse folder** / **Expand folder** button.
  - It hides Tree options and the workspace's **Chat with Claude** button.
  - Name counter-scaling and styling are shared.
- **Connections into a collapsed folder are hidden** rather than rerouted. Workspace connections are rare, since `connect_notes` is the only way to make one.
- **WorkspaceFolderLabel is retired.** TreeFrame draws workspace folders itself, from the hierarchy. The workspace-files plugin still registers the folder view name; it now maps to nothing and is never reached for workspace trees. The plugin is left untouched.
- **Not in scope:** moving a file between folders (a disk write), and the vault's groups adopting this component (02.2's own later work).
</objective>

**app/src/renderer/layout/subspaces.ts** (new) is pure. It has no React and no DOM, and imports only types from kernel-bridge and the helpers in frames.ts.
- `FOLDER_FRAME` = `{ minWidth: 320, minHeight: FRAME_HEADER_HEIGHT + 96, headerHeight: FRAME_HEADER_HEIGHT, padding: 24 }`.
- `folderHierarchy(nodes)` gives, for workspace-typed nodes, `{ parentOf: Map<nodeId, folderId | null>, childrenOf: Map<folderId | null, nodeId[]> }`. The parent is derived from `file.path`'s directory, matched against folder nodes' `file.path`; `null` is the workspace root.
- `absolutePositions(nodes)` gives `Map<nodeId, {x, y}>` in workspace-frame coordinates: each node's local position plus every ancestor folder's origin.
- `toLocalPosition(nodes, nodeId, absolute)` is the inverse, relative to the node's parent folder.
- `subspaceRects(nodes, dimsOf, expandedOverride?)` gives:
  - `folderRects`: `Map<folderId, rect in the folder's parent-local coordinates>`. A collapsed folder (the `collapsed` bool is true and it is not in `expandedOverride`) is its header band only: FOLDER_FRAME.minWidth wide and headerHeight tall, above its origin. An expanded folder is `computeFrameBounds(origin, childBoxes, FOLDER_FRAME)`, where childBoxes are its cards (at `dimsOf`, defaulting to 280 × 200) and its child folders' rects, computed deepest first;
  - `rootBoxes`: the workspace root's cards plus the top-level folder rects, for the tree frame.
- `settleSubspace(nodes, dimsOf, movedFolderId, override?)` gives the `OpObject[]` of `setProperty position.x/position.y` needed after a folder moved or expanded:
  - pushApart among the moved folder's siblings (cards and folders, in the parent's local space) with the moved folder fixed;
  - then the same for the parent among its siblings, up to the root;
  - each displaced frame's origin moves by its rect's delta, as settleFrames does.
  - It never emits any other key.
- `revealExpanded(nodes, noteId)` gives the ids of the note's ancestor folders.
