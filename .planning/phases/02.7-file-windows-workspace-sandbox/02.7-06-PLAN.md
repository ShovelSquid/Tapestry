**app/src/main/chat/workspace-tools.ts** (new) exports `workspaceChatTools(files: WorkspaceFileCommands, actor: Actor, onToolEvent: (event: ChatEvent) => void)`.
- It returns five runnable tools built with `betaZodTool` from `@anthropic-ai/sdk/helpers/beta/zod`: list_files, read_file, write_file, edit_file and open_file.
- Each takes its inputSchema from the matching schemas.ts export and its description from TOOL_DEFINITIONS, and has `eager_input_streaming: true` spread on.
- Each `run(input)`:
  1. emits `tool-call`;
  2. calls the matching WorkspaceFileCommands method with `actor` for writes;
  3. emits `tool-result`;
  4. returns the value as JSON text. On `{ ok: false }` it reports the refusal to the model verbatim as a tool error, using the mechanism the skill documents for the runner.
- There is no other tool: no bash, no text editor, no server tools.

**app/src/main/chat/anthropic-api-engine.ts** (new). Exports `API_CHAT_MODEL = 'claude-opus-5'` and `class AnthropicApiEngine implements ChatEngine`, kind 'anthropic-api'. Constructor: `({ createClient: () => ClientLike, tools, systemPrompt, onError? })`. ClientLike is the minimal subset of the SDK client the engine calls, so tests can supply a fake.

- `start()` returns a new local session id (crypto.randomUUID()) with `resumed: false`.
- `send(text)`:
  1. Append `{ role: 'user', content: text }` to the in-memory history.
  2. Run the SDK's streaming tool runner with model API_CHAT_MODEL, max_tokens 64000, thinking adaptive, `system: systemPrompt`, `messages: history`, `tools`, and the refusal fallback (`betas` and `fallbacks` exactly as the skill shows).
  3. For each stream, emit `text-delta` for text deltas. After each iteration's final message:
     - append its content unchanged to history, along with the tool-result user messages the runner produced (read through the runner's documented API; if it exposes none, use the skill's manual streaming loop instead);
     - on `stop_reason === 'refusal'`, emit `error refused` ("Claude declined this request.");
     - on `max_tokens`, emit a notice.
  4. Emit `done { ok }`.
- Errors map by SDK error class, most specific first, per the skill's error table:
  - authentication or permission errors, or no credentials at all, give `error no-key`: "The Anthropic API key is missing or was refused. Add a key in this chat's engine settings, or set ANTHROPIC_API_KEY.";

  - other API and connection errors give `error crashed` with the status and message.
  - Every error text passes through a redactor that replaces the saved key, if any, with `[key]`.
- `stop()` aborts the in-flight request with the SDK's documented abort mechanism and emits `done { ok: false, reason: 'stopped' }`. Nothing from the aborted turn is appended to history.
- `dispose()` stops and clears.
