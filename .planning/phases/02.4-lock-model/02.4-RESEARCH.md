# Phase 2.4: Lock Model - Research

**Researched:** 2026-09-16
**Domain:** Permission gate in the Electron main-process command layer (TypeScript, vitest, native kernel addon)
**Confidence:** HIGH. Every claim comes from files read this session. There are no external libraries.

## Summary

This is a small refactor inside one gate. `updateNote`, `renameNote` and `deleteNote` all go through `NoteCommands.writeToOwnNote` → `assertOwnNote` (`notes.ts:570-631`). That is the only place `isAgentActor` is used for a decision. Lock resolution replaces only the authorship comparison at `notes.ts:623-629`. The live-note checks (`:615-618`, `:624`), the `prepareWrite` ordering (`:584` before `:586`) and the "refuse before any kernel call" shape all stay as they are.

The facts this phase depends on hold:
- **Every live node has a creator.** `createdBy` is set for every node from the actor of the commit that created it (`History.cpp:52-61`). The `.tree` header holds no nodes (`FORMAT.md:211-216`), and ids are never reused (`FORMAT.md:373-376`).
- **The fixture keys are legal.** `lock.text.allow` passes the kernel's key grammar (`Ops.hpp:124-139`, `FORMAT.md:267-270`).
- **Agents cannot write `lock.*`.** No agent tool can set an arbitrary property: `updateNote` writes only `body`, `renameNote` only `title`, `createFrom` a fixed prop set, and every zod schema is `.strict()`.

Three things the CONTEXT does not mention:
1. **Tool descriptions.** The agent-facing descriptions still say "You may edit only notes you created" (`mcp/schemas.ts:162-186`). No test asserts that text, but agents read it, so it should be reworded.
2. **Type mismatch.** `isAgentActor(actor: Actor)` takes `kind: ActorKind`, but `HistoryIndex.createdBy` is an `ActorRef` with `kind: string` (`kernel-bridge.ts:92-95`). Passing `createdBy` straight in will fail `tsc`.
3. **No test baseline in this worktree.** The native addon has not been built here (`app/native/build/` does not exist). All 11 kernel-backed test files fail to load, and the baseline test count could not be measured. Wave 0 must build the addon first.

**Primary recommendation:**
- Add `app/src/main/commands/locks.ts` with the two constants and a pure `checkLock(node, createdBy, actor, aspect)` function that returns a refusal string or null.
- Call it from `assertOwnNote`, renamed `assertMayWrite(tree, noteId, actor, aspect)`, in place of `notes.ts:626-629`.
- Tests first: rewrite `notes-policy.test.ts` for D-04/D-06/D-12, and add `locks.test.ts` for explicit locks.

An explicit value always overrides the D-04/D-06 default. - **D-10:** An actor may write an aspect when any of these holds: the aspect resolves open, the actor is the lock owner, or the actor is on the allow list. - **D-11:** A refusal writes nothing: the file size, node count and edge count are unchanged, which is the existing `worldFingerprint` discipline. The ownership check still runs after the tree is returned to its latest state (`prepareWrite`), as it does today.

- **D-13:** A note that doesn't exist or isn't live is refused exactly as it is today, with the `... is not a live note in ...` message.

- **Validation happens before the gate.** Text and title validation run before `writeToOwnNote`. An invalid argument is refused before any lock check, and that ordering can stay.
- **`prepareWrite` writes nothing to disk.** `discardRedo()` only replays in memory and resets `currentSeq` and `undoStack` (`kernel-bridge.ts:350-358`). A refusal after `prepareWrite` therefore still leaves `worldFingerprint` unchanged, and the existing test `:476-488` covers the rewound path.

### `HistoryIndex.createdBy` reliability

[VERIFIED: tapestry/kernel/History.cpp:21-116; kernel-bridge.ts:87-124; addon.cpp:656-690]

- **Types.**
  - `NodeHistoryEntry` = `{ createdSeq: number; createdBy: ActorRef; changedSeq: number; changedBy: ActorRef; deletedSeq: number | null; deletedBy: ActorRef | null }` (`kernel-bridge.ts:101-109`).
  - `ActorRef` = `{ kind: string; id: string }` (`:92-95`).
- **Every node is covered.** A `CreateNode` op sets `createdBy = actor` of its commit (`History.cpp:52-61`), for every `CreateNode` in every commit.
  - **Batch commits:** each node in a multi-op commit gets that commit's actor. `createFrom` makes one node per commit anyway (`notes.ts:291-310`).

- **Later writes do not change authorship.** `SetProperty`/`UnsetProperty` only touch `changedBy` (`History.cpp:36-47,62-63`), so writing `lock.*` fixtures leaves `createdBy` alone.
- **Legacy `human local`** (before 02.2 D-07): kind `human`, so not an agent. D-04 applies, and the default owner is `local`, giving the message `n1 text is locked by local`. `actor.ts:69` says `local` lines stay valid history. This is acceptable.
- **Non-agent plugins** (`plugin tapestry-notes`, `plugin obsidian.bridge`): kind `plugin` but the id doesn't start with `agent.`, so `isAgentActor` is false and D-04 locks the note. `OBSIDIAN_BRIDGE_ACTOR` **does exist in this tree** (`actor.ts:127-130`, `{kind:'plugin', id:'obsidian.bridge'}`). - **`!entry` after a live `getNode`** should be impossible. Keep returning `notLive` there, which satisfies D-13.

### Recommended `locks.ts` shape (discretion; names are suggestions)

```ts
// app/src/main/commands/locks.ts
import type { Actor } from './actor'
import type { ActorRef, NodeData } from '../kernel-bridge'

export type LockAspect = 'text' | 'delete'

// PENDING (Decision Register #1 residual): Kaelen said deletion is a lockable
// aspect but not whether it starts locked. Conservative reading: locked.
export const NON_AGENT_NOTES_DELETE_LOCKED = true

// PENDING (Decision Register): agent notes open to other agents.
export const AGENT_NOTES_OPEN_TO_AGENTS = true

/** The literal that explicitly unlocks an aspect (D-08). */
export const LOCK_OPEN = 'open'

export type LockState = { locked: false } | { locked: true; owner: string; allow: readonly string[] }

/** Agent test on a journal actor pair; ActorRef.kind is `string`, not ActorKind. */
export function isAgentRef(ref: { kind: string; id: string }): boolean {
  return ref.kind === 'plugin' && ref.id.startsWith('agent.')
}

export function resolveLock(node: NodeData, createdBy: ActorRef, aspect: LockAspect): LockState { … }

/** Refusal text, or null. Callers must already have established the actor is an agent. */
export function checkLock(noteId: string, node: NodeData, createdBy: ActorRef, actor: Actor, aspect: LockAspect): string | null { … }
```

- **Keep `locks.ts` pure.** It takes `NodeData` and `ActorRef` and never touches the bridge, so `locks.test.ts` can unit-test resolution without the addon. Integration tests still need the addon.
- **Where `isAgentActor` goes.** Either widen its parameter to `{ kind: string; id: string }` in `notes.ts`, which stays source-compatible because `Actor` satisfies it, or move it to `locks.ts` and re-export it from `notes.ts`. Either way, **do not pass `ActorRef` into the current `isAgentActor(actor: Actor)`**, because `tsc` rejects `kind: string` where `ActorKind` is expected. [VERIFIED: kernel-bridge.ts:92-95, actor.ts:27-33]
- **Circular imports.** `notes.ts` imports from `locks.ts`. If `locks.ts` needs `isAgentActor`, move the function into `locks.ts` rather than importing from `notes.ts`, to avoid a cycle.

### Resolution rules (recommended; fail closed)

1. **Explicit value.** `prop = node.props['lock.' + aspect]`. If it is present:
   - `prop.type !== 'text'` → **locked**, owner = `String(prop.value)`. This fails closed on a hand-edited `int`, `ref` and so on.
   - `prop.value === 'open'` (exact, case-sensitive, not trimmed) → **open**.
   - Otherwise → **locked**, owner = `prop.value`.
   - An empty or whitespace-only owner is still locked. Render it as something like `(no owner)` so the message stays readable.
2. **Absent → default.** Use `isAgentRef(createdBy)`:
   - Agent creator → open if `AGENT_NOTES_OPEN_TO_AGENTS`, else locked with owner = `createdBy.id`, which reproduces D-05.
   - Non-agent creator → `text` is locked with owner = `createdBy.id`. `delete` is locked with owner = `createdBy.id` if `NON_AGENT_NOTES_DELETE_LOCKED`, else open.
3. **Allow list.** `allowProp = node.props['lock.' + aspect + '.allow']`. Use it only when `type === 'text'`, as `value.trim().split(/\s+/).filter(Boolean)`. Any other type counts as an empty list (fail closed).
   - It applies to default locks as well as explicit ones. D-09 says "despite the lock" and draws no distinction.
4. **Decision.** Allow if the state is open, `owner === actor.id`, or `allow.includes(actor.id)`. Otherwise return `` `${noteId} ${aspect} is locked by ${owner}` ``.
5. **Exact matching.** An owner value that is not a valid actor id (for example `Kaelen`) matches no agent, so the aspect is effectively locked to nobody. That is the fail-closed outcome.

### Anti-Patterns to Avoid
- **Checking locks before `prepareWrite`.** Against a rewound view, a lock set in an undone commit would be invisible. Keep the order from `notes.ts:584-586` (D-11).
- **Reading `lock.*` from command args.** The rule is enforced only through `node.props` and the host-stamped actor.
- **Adding a `setLock` command, or a `lock` field to any zod schema.** Both are forbidden by D-08.
- **Writing the default locks into the file.** Defaults are derived at check time (CONTEXT; Spec §4).
- **Gating `createFrom` or `connect`.** Both stay ungated (D-01: reading and connecting unrestricted). `createFrom` from a locked parent must still succeed. Consider a regression test for this (see the test map).
- **Editing `02.3-08-PLAN.md` or `02.3-VALIDATION.md`.** The CONTEXT says to record the collision only.

## Common Pitfalls

### Pitfall 1: Tests cannot run in this worktree
**What goes wrong:** Every test that touches the kernel fails with `Failed to load native addon from …/app/native/build/Release/tapestry_addon.node`.
**Why:** `app/native/build/` is gitignored (`.gitignore`) and was never built in this worktree.
**How to avoid:** In Wave 0, run `npm --prefix app run build:native`, which is `cmake-js build --directory native -O native/build`. This is **not** `npm install`. `cmake-js` is available in the root `node_modules/.bin`, and cmake 4.4.1 is installed. It writes only to `app/native/build/` in this worktree. Record the baseline pass count straight after the build and before any test edits.
**Warning sign:** `Test Files 11 failed | 1 passed (12)` with `Tests 13 passed`. That is today's result and means "addon missing", not "logic broken".

### Pitfall 2: `ActorRef` vs `Actor` type mismatch
**What goes wrong:** `isAgentActor(entry.createdBy)` fails `tsc` because `string` is not assignable to `ActorKind`.
**How to avoid:** Add a structural helper, as in the architecture section. Run `npm --prefix app run typecheck`, which covers `tsconfig.node.json` and therefore main.

### Pitfall 3: Wrong constant name
Use `NON_AGENT_NOTES_DELETE_LOCKED`, the name locked in CONTEXT D-05, not the vault Plan's `USER_NOTES_DELETE_LOCKED`. Both constants need their exact `// PENDING (...)` markers.

### Pitfall 4: Tests that silently hard-code a constant
**What goes wrong:** The D-06 test (`:204`) and the delete-default test hard-code `ok: true` or `ok: false`, so flipping a constant breaks them for the wrong reason.
**How to avoid:** Import both constants and branch inside the test:
```ts
if (AGENT_NOTES_OPEN_TO_AGENTS) {
  expect(result.ok).toBe(true); expect(lastCommitBlock()).toContain('actor plugin agent.chatgpt')
} else {
  expect(result.ok === false && result.error).toBe(`${claudeNote} text is locked by agent.claude`)
  expect(worldFingerprint()).toEqual(before)
}
```
**Explicit-lock tests** should not depend on the constants. When a test needs a known starting state regardless of a default, write an explicit `lock.*` fixture.

### Pitfall 5: Fixture commit counted as a side effect
Take `const before = worldFingerprint()` **after** `setLockProp(...)`.

### Pitfall 6: Aspect independence proven one way only
The CONTEXT asks for both directions:
- **`lock.text open` on n1:** update succeeds, delete is still refused with `n1 delete is locked by user.kaelen`. The delete refusal only holds while `NON_AGENT_NOTES_DELETE_LOCKED` is true, so either branch on it or also set `lock.delete user.kaelen` explicitly.
- **`lock.delete` alone on an agent note:** delete is refused, but update and rename succeed.

### Pitfall 7: Delete refusal wording
Under D-12 the delete refusal says `delete is locked`. The old tests used one shared string for update, rename and delete. The new expected strings are:
- `:167` → `'n1 text is locked by user.kaelen'`
- `:181` → `'n1 text is locked by user.kaelen'` (rename checks `text`, per D-03)
- `:194` → `'n1 delete is locked by user.kaelen'`
- `:215` → becomes the constant-driven test from Pitfall 4

### Pitfall 8: A successful delete of a locked-then-opened note
Once deleted, a note's props are gone. Later calls hit D-13 (`not a live note`), not a lock message. Tests should expect that.

### Pitfall 9: Doc-comment drift
The file headers at `notes-policy.test.ts:1-15` and the `describe` titles `:111,152,245,335` cite D-05. Reword them so the suite describes the lock rule, and record in the header that 02.4 D-01 supersedes D-05.
