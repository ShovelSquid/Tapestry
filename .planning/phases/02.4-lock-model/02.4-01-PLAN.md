<objective>
In this plan, a lock decides whether an agent may change a note. Authorship no longer does. `updateNote`, `renameNote` and `deleteNote` in `app/src/main/commands/notes.ts` stop comparing the caller with the note's creator (02.2 D-05, superseded by 02.4 D-01). Instead they resolve a lock for one aspect: `text` for update and rename (D-03), `delete` for delete (D-02). The lock comes from the new pure module `app/src/main/commands/locks.ts`.

A lock is either an explicit `lock.<aspect>` text property (D-08) or a default derived from the creator. Notes not created by an agent start locked (D-04, D-05). Agent notes start open to agents (D-06). Tests come first.

Purpose: this delivers ROADMAP Phase 2.4 success criteria 1, 2 and 4, plus the explicit-lock and `open` half of criterion 3. Plan 02 adds the `.allow` list (D-09), the non-agent-plugin and bridge creator coverage, and the agent-facing wording.

Output:
- `locks.ts`, new, pure and read-only
- `locks.test.ts`, new
- `notes.ts`, rewired to one lock gate
- `notes-policy.test.ts`, rewritten expectations

Shape: tracer first. Task 1 wires the `text` aspect for `updateNote` end to end through the new resolver. `renameNote` and `deleteNote` stay on the pre-phase authorship gate for one commit, so the suite stays green. Task 2 moves them onto the same gate and deletes the old one.

Decision ids: a bare `D-NN` means `02.4-CONTEXT.md`, and `02.2 D-NN` means the Obsidian-bridge phase. The two phases both use D-05 for different things, so every D-05 you write into code must carry its phase prefix: `02.2 D-05` for the superseded authorship rule, `02.4 D-05` for the delete-default constant.

Recorded assumptions, from the orchestrator's resolutions:
- A1. The native addon is built by `npm --prefix app run build:native`, which writes only the gitignored `app/native/build/`. It is not a dependency install.
- A2. `.allow` applies to default locks as well as explicit ones. Plan 02 implements it.
- A3. Malformed values fail closed: a non-text type is locked with owner String(value), only the exact case-sensitive `open` unlocks, and an empty owner is locked and shown as `(unknown)`.
- A4. The delete constant is named `NON_AGENT_NOTES_DELETE_LOCKED`. The name in the vault plan note is not used.
- A5. ROADMAP SC-3 says an explicit lock "refuses every actor except its owner". D-10 narrows this to every agent actor, because people and non-agent plugins are not checked.

Reversibility: this plan only reads `lock.*`, and only test fixtures write it. The one-way door of D-08 (Decision Register #19) is therefore not crossed, and no decision checkpoint is needed. Replacing 02.2 D-05 (D-01) is rated costly in CONTEXT: its doc comments and tests change here, and 02.3 plan 08 is left as it is by design.
</objective>
