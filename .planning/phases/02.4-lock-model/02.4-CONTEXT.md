# Phase 2.4: Lock Model - Context

**Gathered:** 2026-09-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Agents may change any note that is not locked against them. This phase replaces the D-05 authorship gate in the agent note commands (`updateNote`, `renameNote`, `deleteNote` in `app/src/main/commands/notes.ts`) with lock resolution for two aspects, **text** and **delete**, and rewrites `notes-policy.test.ts` to match. Tests come first.

This is the first slice of the lock model, and it is deliberately small:
- **Only the note itself is checked.** There is no thread, tree or Tapestry scope yet.
- **No new command writes locks.** Tests write `lock.*` properties directly.
- **No kernel change, no `.tree` format change, and no new dependency.**
- **Human edits are not gated.** They go through the renderer's `kernel:submit`, which this phase does not touch.

</domain>

<decisions>
## Implementation Decisions

### The rule (Kaelen, 2026-09-16, verbatim in the Decision Register)
- **D-01:** Allow by default, deny if locked. Authorship is no longer the gate. This supersedes 02.2 **D-05**'s "agents may edit or delete only notes they wrote". Reading and connecting stay unrestricted, as they were under D-05. — **Reversibility:** costly — `notes-policy.test.ts` and the doc comments in `notes.ts`/`connections.ts` cite D-05 as the rule, and 02.3 plan 08 (D-22) builds a per-letter authorship gate on the old premise.
- **D-02:** Deletion is its own lockable aspect, `delete`. It is separate from `text`, so either can be locked without the other (Kaelen: "yes it should be a lockable aspect").
- **D-03:** A note's title is covered by the `text` aspect. `renameNote` checks `text`, and there is no `lock.title`. Retitling a vault note also renames its file (02.2 D-28). (Queue #10, recommended option, approved under the grant.)

### Defaults (derived at check time, never written to the file)
- **D-04:** **Every note not created by an agent starts locked for both `text` and `delete`.** That includes notes created by a person (`human user.*`), by the Obsidian bridge (`plugin obsidian.bridge`, 02.2 D-21) or by any other plugin. The default lock belongs to the note's creator. "Created by an agent" means the creating commit's actor matches `isAgentActor` (`plugin agent.*`). Authorship comes from `HistoryIndex.createdBy`, as it does today. (Queue #10, recommended option, approved under the grant.) This keeps agents off Kaelen's Obsidian notes, which the bridge signs as itself.
- **D-05:** Whether delete starts locked on those notes is a named constant, `NON_AGENT_NOTES_DELETE_LOCKED = true`, marked `// PENDING (Decision Register #1 residual)`. The value `true` was approved under the grant. Flipping it must be a one-line change.
- **D-06:** Agent-created notes start open to every agent. This is a named constant, `AGENT_NOTES_OPEN_TO_AGENTS = true`, marked `// PENDING (Decision Register)`. With `false`, an agent note is locked to its creating agent, which is today's D-05 behaviour. This constant inverts `notes-policy.test.ts:204` ("refuses one agent changing another agent's note"), and that test must be driven by the constant's value.
- **D-07:** The two constants live together in one new file, `app/src/main/commands/locks.ts`. Tests import them, so their expectations follow the values.

### Explicit locks (properties on the note)
- **D-08:** `lock.<aspect>` is a `text` property. Its value is either the owner's actor id (e.g. `user.kaelen`, `agent.claude`), which locks the aspect, or the literal `open`, which unlocks it. An explicit value always overrides the D-04/D-06 default. If the property is absent, the default applies. — **Reversibility:** one-way once written by a real command — key names and the `open` literal would sit in append-only journals. This phase only *reads* them, and only test fixtures write them. The naming is **Decision Register #19**, Kaelen's call, and it must be answered before any `setLock` slice. Planning must not add a command that writes `lock.*`.
- **D-09:** `lock.<aspect>.allow` is an optional `text` property holding whitespace-separated actor ids. Those actors may write despite the lock.
- **D-10:** An actor may write an aspect when any of these holds: the aspect resolves open, the actor is the lock owner, or the actor is on the allow list. Only agent actors are checked (`isAgentActor`). People and non-agent plugins pass, as they do today, because Tapestry has one user and Kaelen owns every lock that matters.

### Refusals
- **D-11:** A refusal writes nothing: the file size, node count and edge count are unchanged, which is the existing `worldFingerprint` discipline. The ownership check still runs after the tree is returned to its latest state (`prepareWrite`), as it does today.
- **D-12:** The refusal message names the note, the aspect and the lock owner, e.g. `n1 text is locked by user.kaelen`. Tests that match the old "may only change notes it created" string (`notes-policy.test.ts:167,181,194,215`) are updated.
- **D-13:** A note that doesn't exist or isn't live is refused exactly as it is today, with the `... is not a live note in ...` message.

### Claude's Discretion
- Exact function names and signatures in `locks.ts`, beyond the two named constants.
- Whether `writeToOwnNote` is renamed (e.g. `writeToNote`). It must take the aspect as an argument.
- Whether lock-aspect tests go in a new `locks.test.ts` or in `notes-policy.test.ts`.
- Rewording the doc comments that cite D-05 so they cite the lock rule.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `assertOwnNote(tree, noteId, actor)` already returns a refusal string or null, after the live-note check. Lock resolution replaces only its authorship comparison.
- `tree.bridge.getHistoryIndex().nodes[id].createdBy` gives the creator actor, which D-04/D-06 need.
- `tree.bridge.getNode(id).props[key]` gives `{type, value}` for reading `lock.*` properties.
- The test harness (`makeTempDir`, `TreeRegistry.create`, `tree.bridge.submitAs`, `worldFingerprint`, `lastCommitBlock`) can write `lock.*` fixtures with a raw `setProperty` op signed by any actor.

### Established Patterns
- **Main chooses the actor, never the caller** (`actor.ts` header). Lock checks must read the stamped actor only.
- **Refusal before any kernel call**, so a refused command appends nothing.
- **`CommandResult<T>`** is `{ ok: true, value } | { ok: false, error }`.
- Tests use vitest (`npm --prefix app run test`). Dependencies are symlinked, so never run `npm install`.

### Integration Points
- `app/src/main/commands/agent-tools.ts` and the MCP schemas call `NoteCommands`. Their refusal text reaches agents unchanged, so only the message string changes.
- On main, `vault-service.ts` creates vault notes as `plugin obsidian.bridge`. That tree is at `fe33d69` and has no vault service, but D-04 covers vault notes when this merges.

</code_context>

<specifics>
## Specific Ideas

- Test cases the plan names:
  - An explicit `lock.text` held by `agent.claude` refuses `agent.chatgpt` and allows `agent.claude`.
  - `lock.text.allow` admits a listed agent.
  - `lock.text open` on Kaelen's note lets an agent update it, while `delete` stays locked, which proves the aspects are independent.
  - `lock.delete` alone on an agent note refuses delete but not update.
  - A note created by a non-agent plugin actor starts locked (D-04).

</specifics>

<deferred>
## Deferred Ideas

- **Rank auto-lock** when a person sets rank. Needs a per-property last writer in `HistoryIndex`. There's no agent rank command yet.
- **`setLock` command** so only an owner (or their user) can remove or change a lock. Blocked on Decision Register #19, the `lock.*` naming, a one-way door.
- **Scope cascade**: thread and tree scopes, then the Tapestry scope once Phase 2.6 creates the Tapestry tree (shape C). Until then `agentsEnabled` stays the de facto top rung.
- **`layout` aspect and placement locks.** No agent command moves notes yet (Register #7/#8, and 2.5's `place`).
- **Gating human writes** that go through `kernel:submit`, once a second user exists.
- **Realigning 02.3 D-22** (per-letter authorship) to locks. Recorded only.

</deferred>
