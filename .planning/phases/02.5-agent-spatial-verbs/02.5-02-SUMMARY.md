# Phase 2.5 Plan 02: Following notes and relation resolving, Summary

**One pure module now decides where every note is drawn, including notes that follow their parent, and where a relation like "near n7" or "beyond n7 from n4" lands. `look` uses the same answer, so an agent sees a following note beside its parent, marked `guess: true`, while the file keeps only what someone actually did.**

## Accomplishments

- **Resolvers (D-09, D-10).** `resolveNear` starts `CHILD_GAP` right of the anchor, level with its top, which is the spot `create_note` already uses (390,20 for an anchor at 10,20 with width 300). From there it steps down one card height plus `STACK_GAP` at a time until the card overlaps nothing. `resolveBeyond` extends the line between the two centres by `CHILD_GAP` plus one card width, using a single `Math.sqrt`, then steps down the same way. Both give up after `MAX_PLACE_STEPS` and return `no-clear-spot`, `no-line` or `not-finite`.
- **`displayPositions` (D-02, D-05, D-07).**
  - Only a `pinned` value of bool `false` makes a note follow. A missing key, `true`, or the text `"false"` all leave the note at its stored spot.
  - A following note is drawn beside its parent. A live override of the parent moves the follower, and the inputs are never modified.
  - A note's own override wins for `x`/`y`, while `followSpot` stays the derived spot.
  - Knots are never obstacles. Sizes come only from stored width/height or the defaults.
  - The result is the same for any input order, and every entry's `following` equals `isFollowing`.
- **`resolveWhere` (D-01, D-06, D-08, D-12).**
  - Checks run in the planned order: not-live, self, same-note, not-placed (against the fixed view without the subject), then resolving.
  - Only "near" the subject's own lower-id grew-from parent reports `follows: true`.
  - The follow case is resolved through `displayPositions` on the simulated world. The planned case (n2 placed near n1 ahead of a higher-id follower n3) returns 360,0. Once stored, n2 is drawn at 360,0 and n3 at 360,144.
  - The create case works: the subject is absent from the world, and the caller supplies its grew-from edge.
- **`whereRefusalText` (D-14)** produces every sentence the plan lists, word for word. A test resolves each refusal case, removes the node ids from the sentence and checks that no digit remains.
- **`look`** builds its `from`, `toward` and candidate rectangles from `displayPositions(nodes, edges, new Map())`, and `guess` is the entry's `following` flag. The two not-placed refusals keep their wording. `look` still never reconciles or commits. The unused imports `isFollowing`, `isPlaced` and `storedRect` were removed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] An overflowing line in `resolveBeyond` would have placed the card on top of its anchor**
- **Found during:** Task 1
- **Issue:** When the two centres are about 1e200 apart, the squared length is `Infinity`. The scale then becomes 0, so the start spot collapses onto the beyond-note's centre. That point is finite, so the not-finite check would not catch it.
- **Fix:** If the squared length is not finite, `resolveBeyond` returns `not-finite` before scaling. A test covers this.
- **Files modified:** app/src/renderer/layout/placement.ts
- **Commit:** 8d22cb2

**2. [Rule 2 - Correctness] The follow case in `resolveWhere` could misreport, and could disagree with the drawn result for an unplaced subject**
- **Found during:** Task 2
- **Issue:** When the follow case finds no spot, `followSpot` is null for two different reasons, and the plan maps both to `no-clear-spot`. As a result, a parent too far out to add to was reported as a crowded column. Separately, if the subject has no stored spot, the notes that follow it would count as fixed in the simulation but as followers after the commit.
- **Fix:** When `followSpot` is null, a second `resolveNear` with no obstacles tells the two cases apart. An unplaced subject borrows the anchor's corner as its simulated stored spot. The follower rule never reads that value while a clear spot exists, so the returned spot is unchanged.
- **Files modified:** app/src/renderer/layout/placement.ts
- **Commit:** 692ddb7

Other choices, all within what the plan allows:
- `resolveWhere` also exports its argument type `WhereWorld`.
- Refusals for "beyond" placements carry `from` for every role, including a `from`-role refusal, where `from` equals `anchor`.
- `look` gained a test showing that `toward` uses a follower's drawn spot.
