<objective>
**As a** person looking at my tree, **I want** a note an agent attached to its parent to stay beside that parent wherever I move it, and to stop following the moment I drag it myself, **so that** the layout agents make stays tidy without ever overriding my hand.

Task 1 makes the renderer draw every note from Plan 02's `displayPositions`, computed once per tree in `Canvas`, so frame bounds, edges, knot midpoints and cards agree (D-05). Task 2 routes a person's drop — or a left/top resize — of a following note through a new takeover handler that writes position and `pinned true` in one commit (D-03, D-16).

Purpose: without this plan a `pinned false` note would be stored beside its parent but drawn at a stale spot. The renderer has no component test harness, so each task pairs typecheck, build and grep gates with an end-of-phase human check.

Output: small, additive edits to five renderer files. All geometry stays in `placement.ts` (RESEARCH Pitfall 6: keep the merge surface with 02.2 and 02.3 small).

This plan does **not** depend on Phase 2.4.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer -> main (`kernel:submit`) | The renderer asks for a commit; main stamps the human actor (the renderer never sends an actor) |
| .tree file -> renderer | Node props and edges may be hand-edited; the renderer must draw any shape without hanging |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.5-03-01 | Spoofing | `handleTakeOverPosition` commit | medium | mitigate | The handler goes through the existing `submitChange` -> `kernel:submit` path, where main signs the commit as the person's human actor (PROV-01); no actor field is added |
| T-02.5-03-02 | Tampering | Follower drag routing | medium | mitigate | Routing reads `following` from the same `displayPositions` result that drew the note, so only a note that is visibly following is pinned; a region gate proves the ordinary move handler writes no `pinned` |
| T-02.5-03-03 | Tampering | Frame containment (02.2 D-15) | medium | mitigate | Frame bounds take follower positions from the same per-tree computation as the cards, and the takeover wrapper re-settles frames |
| T-02.5-03-04 | Denial of service | `displayPositions` on every render during drags | low | accept | One call per tree per render, bounded by followers x `MAX_PLACE_STEPS` x obstacles (Plan 02); a crowded tree may render slower, which the human check observes |

No package-manager install occurs in this plan, so no package-legitimacy gate applies.
</threat_model>
