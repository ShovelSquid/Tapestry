# Phase 2.5 Plan 03: Following notes drawn and taken over in the renderer, Summary

**The renderer now draws a note with `pinned` set to bool false beside its grew-from parent. The card, its lines, the knot midpoints and the frame bounds all use the same per-tree `displayPositions` result, so they always agree on where the note is. When a person drops a following note, or resizes it from the left or top edge, one `Move note` commit records its position and `pinned bool true`, and the note stops following.**

## Accomplishments

- **One computation per tree (D-05).**
  - While building frame rects, `Canvas` turns `dragPositions` into a map of overrides keyed by node id. It then calls `displayPositions(tree.nodes, tree.edges, overrides)` once and keeps the result in `treeSpots`.
  - Frame boxes and the connection-preview line use each note's spot when it has one. Otherwise they fall back to the old logic: the drag point if the note is being dragged, else its stored position.
  - Measured sizes and `DEFAULT_NODE_WIDTH`/`HEIGHT` are unchanged.
  - `TreeFrame` gets the map, or the empty `NO_DISPLAY_SPOTS` if a tree has none.
- **TreeFrame.**
  - `getNodeCenter` reads the note's spot first, so connection lines and knot midpoints follow the note with no other change.
  - Both `NoteCard` and `FallbackNodeView` receive `displayPosition={displayPositions.get(node.id)?.followSpot ?? undefined}`.
- **Cards.**
  - `NoteCard` and `FallbackNodeView` take an optional `displayPosition` and use it for `x`/`y` (or `px`/`py`) when it is set. Notes that are not following take the same code path as before.
- **Takeover (D-03, D-16).**
  - `handleTakeOverPosition` in `App.tsx` submits three `setProperty` ops (`position.x` real, `position.y` real, `pinned` bool true) under the message `'Move note'`, then refreshes the tree.
  - Canvas wraps the handler the same way it wraps `onPositionChange`, followed by `settleFrames`.
  - `TreeFrame.writePosition` sends a note to the takeover only when `displayPositions.get(id)?.following` is true.
  - `NoteCard` reports a position only for a left or top resize (it sets `localPos` only when x or y changes). So those resizes pin the note, and right or bottom resizes do not.
- **Signing (PROV-01).** No actor field was added. The commit goes through `submitChange`, which calls `kernel:submit`, and main signs it with the person's human actor.

## Deviations from Plan

None. The plan ran as written.

Notes on the implementation, all within what the plan allows:
- In the spot-first expressions, the drag point is checked before the stored value. For a note with a spot, the spot already includes its drag override.
- `FallbackNodeView` never calls `onDragMove`, so its drag has no override. Its card still tracks its own `localPos`, as before.
- A left or top resize of a follower still writes width or height in its own `Resize note` commit, then position and `pinned` in the takeover commit. That is two commits, the same as for an ordinary note.
