# Phase 2.5 Plan 01: `look`, the read-only spatial verb, Summary

**Agents can now call `look` over MCP. It returns the notes around a note in the same tree, nearest first. Each result has exactly five fields: note, space, relation, order and guess. No coordinates are returned. The geometry lives in a new pure module, `renderer/layout/placement.ts`, which main imports with no tsconfig change.**

## Accomplishments

- `placement.ts` exports:
  - the constants `DEFAULT_NOTE_WIDTH` 280, `DEFAULT_NOTE_HEIGHT` 120, `CHILD_GAP` 80, `NEAR_GAP` 160 and `GREW_FROM_LABEL`
  - the types `PlacementProp`, `PlacementNode`, `PlacementEdge`, `PlacementRect`, `PlacementPoint`, `PlacementSize` and `Relation`
  - all 15 functions the plan lists, including `idNumber`, `compareIds`, `isFollowing`, `classifyRelation`, `liesToward` and `orderNeighbours`

  Its only import is `import type { ContentBox } from './frames'`.
- `SpatialCommands.look` follows the plan's order of checks and refusal messages:
  - It looks up `from` and `toward` only in the named tree (D-12).
  - It never calls `prepareWriteFor` or `submitAs`.
  - It sets no upper limit on `limit`, and the default is 20.
- `LookArgs` is `.strict()`, and its `limit` has no `.max()`. The `look` tool definition uses the plan's exact description, including the warning about taller cards, and is marked read-only.
- `AgentCommands.spatial` is added, `agent-tools.ts` has a `case 'look'` branch, and `index.ts` wires it with `new SpatialCommands(registry, commandHooks)`.
- The shim test now checks for exactly nine tools. A new MCP test confirms that `look` from n2 returns `n1`, `near`, order 1, guess false, and that the reply never contains `position`.
- `notes.ts` imports `CHILD_GAP`, `DEFAULT_NOTE_WIDTH` and `GREW_FROM_LABEL` from `placement.ts` and has `export { GREW_FROM_LABEL }`. Each of the three is now declared exactly once in `app/src`. The existing test that expects the new note at x 390, y 20 still passes.
