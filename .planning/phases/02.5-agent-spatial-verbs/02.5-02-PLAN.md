<objective>
**As an** agent, **I want** the host to know exactly where a note that follows its parent is drawn, and exactly where a relation like "near n7" lands, **so that** what I see through `look` matches the screen and what I later ask `place` for is resolved the same way every time.

This plan grows `app/src/renderer/layout/placement.ts` with the D-09 and D-10 resolvers, the D-05 draw-time follow derivation `displayPositions`, and the pure `resolveWhere` that Plans 04 and 05 call. Then `look` switches to drawn positions, so an agent sees a following note beside its parent with `guess: true`.

Purpose: one pure function decides where a following note is, so main (`look`, later `place`) and the renderer (Plan 03) cannot disagree (RESEARCH Pitfall 2). Building `resolveWhere` here, before Phase 2.4 arrives, means the gated wave only adds the lock check and the tool surface.

Output: the expanded module and its tests, and `look` reading drawn positions.

This plan does **not** depend on Phase 2.4.
</objective>
