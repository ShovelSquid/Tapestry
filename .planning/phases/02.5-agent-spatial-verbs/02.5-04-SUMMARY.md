# Phase 2.5 Plan 04: `place` under the layout lock, Summary

**Agents can now call `place(tree, note, { near } | { beyond, from })`. The host resolves the spot and writes `position.x`, `position.y` and `pinned` in one commit, with a message such as `Place note n2 near n1` and the actor line `plugin agent.<name>`. The only gate is Phase 2.4's `lock.layout`: a person's note, or a vault note from the Obsidian bridge, is refused by default, and the refusal names the owner. A person's `pinned true` is never removed or overwritten. Every refusal leaves the file, the world and the redo stack unchanged.**

## Accomplishments

- **Schema (D-11).** Strict `{ near }` and `{ beyond, from }` objects combine into `WhereArgs`, declared above `CreateNoteArgs` for Plan 05. Strict `PlaceArgs` has `tree`, `note` and `where`. `schemas.ts` still imports only zod. The schema refuses the space form, the orientation form, a lone `beyond`, mixed forms, extra keys and an `actor` key at either level.
- **`place` check order.**
  1. Resolve the tree.
  2. Run the checks that need no world: id shapes, self, same note.
  3. Call `prepareWriteFor`.
  4. Confirm the note is live and is not a knot.
  5. Check the layout lock with `checkLock(..., 'layout')`.
  6. Apply the takeover guard: a note a person pinned is not made to follow again.
  7. Call `resolveWhere`.
  8. Check that the spot is finite.
  9. Call `submitAs`, then `onCommitted`.
- **`placeOps` (D-08, D-17).** Always writes the two position `setProperty` ops. A note `heldByPerson` gets nothing else. Otherwise a following placement sets `pinned bool false`, and a fixed placement unsets `pinned` only when it is exactly bool false.
- **Shim.** The shim advertises ten tools. Over MCP, `place` near a note's grew-from parent writes `set n2 pinned bool false`. `place` on Kaelen's note is refused, the refusal names `user.kaelen`, and the file size is unchanged.
- **Proofs in Task 3.** Every refusal is checked with a wider fingerprint: file size, node, edge and `@commit` counts, the target's `position.x`, `position.y` and `pinned`, and the `onCommitted` count. The refusals covered are:
  - unknown tree, malformed or not-live note, a knot as the note
  - a near, beyond or from anchor that is not live, unplaced, or a knot
  - self, the same note twice, same centre (no line), and a blocked column
  - an anchor live only in another tree (D-12)
  - an explicit `lock.layout` owner, a `user.kaelen` default, and an `obsidian.bridge` default
  - a person's takeover

  Other tests show that `allow`, `open` and the owner itself succeed. Refusals decided from the arguments alone keep a rewound tree's redo, while a valid placement reconciles and announces the discarded redo once. D-05 holds after a follower placement, and no refusal sentence contains a digit once node ids are removed.
- **Mutation check (not committed).** Disabling the lock check, the takeover guard, or the pre-reconcile ordering each makes at least one test fail.

## Deviations from Plan

1. **[Checkpoint-directed] D-13 vault test adapted.** The plan assumed a vault note written by a non-human actor is open by default. Under 2.4, a note created by `plugin obsidian.bridge` is layout-locked to the bridge, and Kaelen chose to keep it that way. The test now asserts that a bridge-created vault note is refused as `<id> layout is locked by obsidian.bridge`. It then sets `lock.layout` to `open` and places the note successfully, with `md.path` byte-equal, the node count unchanged and no `md.` line. A further test places a vault-typed note that an agent created.
2. **[Rule 2] History-index guard.** When a live note has no history-index entry, `place` refuses it as not live, because the default lock owner cannot be derived. This mirrors `notes.ts` `assertMayWrite`. It cannot happen in a well-formed world.
