# Phase 2.5 Plan 05: `create_note` with an optional `where`, Summary

**`create_note` now accepts the same optional `where` as `place`: `{ near }` or `{ beyond, from }`, ids only. The host resolves it with the same `resolveWhere`. A note created near the note it grew from writes `pinned bool false` and is stored at the spot where it will be drawn. Any other relation writes a fixed spot. Without `where`, the result is the same as before, byte for byte: the note goes to the right of its parent, with no `pinned` key, no collision step, the same four `set` lines, the same message and the same four return keys.**

## What was built

- **Schema.** `CreateNoteArgs` gains `where: WhereArgs.optional()`. `schemas.ts` still imports only zod. The `create_note` description adds three sentences: where chooses the spot, a note placed near its parent follows it, and without where the note goes to the right of grewFrom.
- **Dispatch.** `runAgentTool` passes `where?: WherePlacement` through to `createFrom`, and the actor still comes from the socket.
- **`createFrom`.** Every existing check runs in its existing order. After the grewFrom id-shape check and before reconciling, a `where` must have anchor ids of node-id shape (`<role> <id> is not a live note in <tree>`), and beyond must differ from from (the `same-note` sentence). Inside the try, after the parent liveness check, the default position, ops and message are built exactly as before. When `where` is given:
  - The subject is `{ id: next.node, type: NATIVE_NOTE_TYPE, props: {} }`.
  - `resolveWhere` runs over the current nodes and the current edges plus the predicted `grew-from` edge `next.edge` from `next.node` to `grewFrom`.
  - A refusal returns `whereRefusalText(...)` and writes nothing.
  - On success, the resolved x and y replace the default spot. A following placement also adds `pinned bool false`, the message gains `, placed near <id>` or `, placed beyond <id> from <id>`, and the value gains `follows`.
  - The node and its edge stay in one commit, and the predicted-id check still runs.

## Tests added

In `notes.test.ts` (32 tests, up from 17):

- **Without where (D-02).**
  - The note has no `pinned` prop. The commit block has no `pinned` or `placed` text, holds exactly four `set n2 ` lines, and contains the exact message line.
  - The returned keys are exactly edge, note, seq and tree.
  - A note already at 390,20 is still overlapped: no collision step.
  - The original `toBe(390)` test is unedited.
- **With where.**
  - Near its own grewFrom, the note is created at 390,20 with `pinned bool false`, `follows: true`, the actor `plugin agent.claude`, the node and edge in one commit, and the message `..., placed near n1`.
  - With a note already at 390,20, the new note lands at 390,164, and `displayPositions` draws it following at exactly 390,164 (D-06).
  - Near another note gives 1360,1000, no pinned key and `follows: false`.
  - Beyond gives a fixed spot, with the message `..., placed beyond n2 from n1`.
  - Beyond its own parent is still fixed.
- **Refusals that write nothing.** Each is checked for unchanged file size, node count, edge count and `@commit` count:
  - `near n99`, `near bogus`, `from n98`, `beyond n98`
  - `beyond n1 from n1`
  - near an unplaced note
  - a fully blocked column
  - two anchors with the same centre
  - an anchor live only in a second open tree (D-12)
  - `near n2`, the id the new note would receive: `near n2 is not a live note in notes`

  A refused `where` also never reaches `onCommitted`.
- **Schema.** Accepted: where absent, `{ near }`, `{ beyond, from }`. Refused: the space form, the orientation form, a lone beyond, near combined with beyond, an extra key, and an actor key at either level.
