<objective>
Attention: levels and a user-set threshold decide what moves, a card that changes state rises in its frame, and a session that needs a look while off-screen gets an edge arrow you can click to pan there. The agent never moves the camera.

Purpose: SC5 and D-14..D-16, built on the states of 02.8-04 (reducer) and 02.8-05 (card and panel).

Output:
- pure `layout/edge-arrows.ts` with its tests;
- `EdgeArrowLayer` inside Canvas;
- `attentionOf` and `changeEffects` in the reducer module;
- the Chat alerts setting;
- the Done, Needs you and arrival motion;
- the stack raise.

Recorded choices:
- **The arrow pan uses Canvas's CameraRig** (`rig.easeTo(centerOn…)`, as `panToFrame` does), not `threads/navigation.ts`'s `flyTo`, which animates thread time and not the 2D camera (RESEARCH Pitfall 11). It also avoids `panToNote`, which ignores roll.
- **"Visible canvas area"** is the viewport minus the ChatPanel's column (420 + 16 px) when the panel is open. The off-screen test uses the screen bounding box of the card's four rotated corners, so a rolled card counts as visible whenever its box touches the area.
- **Motion fires on a change**, not on a state. It fires for a Done at level L, a Needs you (3) and a mid-turn set_status at level L, whenever `shouldAnimate(L, threshold)`. Failed never animates (`changeEffects` rules it out).
- **A new chat or fork counts as a level-2 arrival (A-08)**, acknowledged like Done when looked at.
- **The stack order** is a stable secondary sort after TreeFrame's `depthOrder`. Raised sessions draw after unraised ones at the same depth, so they are on top by DOM order, and the z-index model is unchanged.
</objective>
