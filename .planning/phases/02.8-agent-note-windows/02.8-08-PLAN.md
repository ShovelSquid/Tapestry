  <action>
**Store.**
- The snapshot gains `forkAt: number | null`, with `enterForkMode(treeId, noteId, k)` and `leaveForkMode(treeId, noteId)` (the draft is kept).
- `forkChatSession(treeId, noteId)` sends `composeFirstMessage(attachment, draft)` with `chat.fork(treeId, noteId, forkAt, text)`.
  - On success it clears the original's draft, attachment and `forkAt`, calls `markNewSession` and `raiseSession` for the fork and `requestComposerFocus` for it, and returns `{ ok: true, noteId }`.
  - On failure it returns `{ ok: false, error }` and leaves fork mode and the draft as they were.
- Test the pure parts per `<behavior>`; the IPC call is injected so the test needs no `window`.

**Transcript.**
- Each committed turn k, when k is below the total turn count (committed turns, plus one while a turn is in progress), shows **Reply from here**. It is a text button, Label, `--tap-muted`, underlined on hover, with `aria-label="Reply from turn k"`, visible on hover or `:focus-within` of the turn, and it calls `enterForkMode`.
- Show the turn label "Turn k" at the turn's top-left on hover or focus.
- In fork mode, turn k gets `.tapestry-passage-active` and later turns `opacity: 0.4`.

**Composer.** In fork mode:
- show the chip "Replying from turn k. Sending starts a new chat beside this one. This chat stays as it is." with a **Stop forking** button (`.tapestry-chat-chip-remove`);
- the placeholder is "Reply from turn k", and the primary button is **Send as new chat**, enabled even while busy;
- entering fork mode focuses the input with `preventScroll`, and Escape leaves fork mode (a second Escape blurs);
- sending calls `forkChatSession`.

**Card.** Passes its session to the transcript and composer, so fork mode works on the card.

**App.css.** Styles for `.tapestry-reply-from-here`, `.tapestry-turn-label` and `.tapestry-turn--after-fork` (opacity 0.4).
