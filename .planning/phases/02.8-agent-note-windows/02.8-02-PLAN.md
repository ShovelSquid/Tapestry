<objective>
Make the session tracer honest and safe to have many of: every way a turn can end is written truthfully as one passage, many sessions stay independent and bounded, the transcript can only be written by its chat, and sessions can be deleted and placed at a spot.

Purpose: 02.8-01 proved the happy path. This plan fixes the failure paths before any UI is built on them, and adds the two lifecycle calls (delete, create at a spot) the card needs in 02.8-03.

Output:
- ChatService: failure turns recorded, the quit-time turn commit, `MAX_LIVE_ENGINES`, `deleteSession`, create `{ at }`;
- `SessionNotes.delete`;
- the guard hardening (Pitfall 8);
- IPC `chat:delete`;
- the invariant test from 02.8-01's assumption-delta decision;
- the measured journal growth.

Recorded choices:
- **Bridge off and no `claude`** now record the person's message as a turn (`user`, then `error`, then `done { ok: false }`) instead of an error with no turn. The document and the Failed state then treat every failure alike. Reversible.
- **Quit mid-turn (resolution 4):** committing the person's message at send time would make two commits for one turn, which D-07 forbids. Instead, `closeWorkspace` and `disposeAll` commit the open turn synchronously, before their first `await`, with what arrived so far and a `Stopped` line. At quit, `will-quit` calls `disposeAll()` before `registry.closeAll()`, so the tree is still open. Reversible.
- **Live-process cap (resolution 3):** `MAX_LIVE_ENGINES = 4`. Idle sessions past the cap are ended least-recently-used first (no `done` is emitted; the conversation stays resumable). Busy sessions are never ended; the cap can be exceeded while more than four turns run at once. Reversible.
- **Spot for `{ at }`:** export the existing private `stepDown` from `placement.ts` as `firstClearSpot(start, size, obstacles)`, with no behaviour change, so the pointer case uses the same downward steps as `resolveNear`.
- **Delete keeps the session's agent** in agents.json, because its commits are attributed to it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (kernel:submit on a workspace tree) | The window may move, resize and retitle session notes, never write their conversation |
| renderer → main (chat:delete, chat:create with a spot) | The window asks main to remove a session or place one at a point |
| agent → dispatch (note and file tools) | Any connected agent could try to reach a session note |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.8-07 | Tampering | renderer kernel:submit of `body`/`chat.*` on a session | high | mitigate | `workspaceSubmitRefusal` refuses them in main with a node-type lookup, so a renderer (or FallbackNodeView) cannot rewrite a transcript or its turn count and break fork anchors (Pitfall 8) |
| T-02.8-08 | Tampering | agent note and file tools on session notes | high | mitigate | Note tools refuse workspace trees (existing `workspaceRefusal`); file tools resolve only file paths to file notes; a test asserts the body is unchanged after each refused call |
| T-02.8-09 | Denial of Service | many sessions spawning `claude` processes | medium | mitigate | `MAX_LIVE_ENGINES = 4` idle processes, LRU eviction with resume; every exit path (close, dispose, killAllNow, delete) ends process groups and deletes config files |
| T-02.8-10 | Information Disclosure | config files of deleted or closed sessions | medium | mitigate | deleteSession and closeWorkspace delete the 0600 file; tests assert it is gone |
| T-02.8-11 | Tampering | chat:create placement | low | mitigate | Only `{ at: { x, y } }` with finite coordinates of magnitude at most 1,000,000 is accepted; anything else is refused before a commit |
| T-02.8-12 | Repudiation | a turn lost at quit | low | mitigate | The open turn is committed synchronously with `Stopped` before engines are dropped, so the person's message is in history |
</threat_model>
