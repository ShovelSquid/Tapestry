## Phase Goal

**As** Kaelen, **I want** every in-app chat to be a note on the canvas whose text is the conversation, with a live status, reply-in-place and forks from any turn, **so that** my conversations with Claude live in the same readable, spatial world as everything else.

(Sourced from the ROADMAP Phase 2.8 goal. The ROADMAP `**Goal:**` line is outcome prose, not a user story; this framing restates it without adding scope.)

<objective>
The tracer for Phase 2.8: **a chat is a session note, and each turn is a passage in its text.**

After this plan, clicking New chat on a workspace frame writes a session note into the workspace tree, the docked panel opens on that session, and every completed turn is appended to the note's text in one commit signed by that session's own agent. A second New chat makes a second, independent session.

Purpose: this crosses every layer the phase touches (shared grammar, main-only commits, the re-keyed ChatService, IPC, preload types, renderer state, the panel) on one path, so a wrong turn in the architecture shows up after one plan. The card on the canvas (02.8-03), status (02.8-04, 02.8-05), levels and edge arrows (02.8-06) and forks (02.8-07, 02.8-08, 02.8-09) build out from here.

Output:
- `src/shared/chat/transcript.ts`, the session note's stored shape (type, keys and turn grammar) in one module;
- `main/chat/session-notes.ts`, the session commits and each session's identity;
- ChatService keyed per session note, with chats.json version 2;
- IPC `chat:create` and the re-keyed chat channels;
- the panel showing one session, drawn from the note's text plus the live turn.

Recorded choices (Claude's discretion or orchestrator resolutions, each reversible unless marked):
- **Agent name (D-03):** `claude-chat-<first 8 hex of the tree id>-<note id>`, built from `CHAT_AGENT_NAME`. It is at most 32 characters for note ids up to `n9999999999`, deterministic (nothing extra stored) and unique across workspaces. UI-SPEC A-01 (hex of the note id) cannot work, because note ids are `n<k>`. Reversibility: **costly**, flagged here without a checkpoint, because the id is written into every commit a session signs.
- **Who signs what:** create is signed by the person (`getHumanActor`); each turn commit by the session's agent (RESEARCH A2).
- **Session writes are main-only.** Workspace trees refuse renderer node creation (`workspaceSubmitRefusal`), and NoteCommands refuses workspace trees, so `SessionNotes` writes through `tree.bridge.submitAs` directly and calls `hooks.onCommitted`.
- **Where a new session goes (this plan):** the first clear spot right of everything in the workspace frame, stepping down: start at `CHILD_GAP` right of the union of the frame's root boxes (`subspaceRects(...).rootBoxes`, with default card sizes, plus every non-workspace node's stored rect) at that union's top, then `resolveNear`'s downward steps. An empty workspace gets (0, 0). 02.8-02 adds an explicit spot (the pointer).
- **Every accepted send ends in exactly one turn commit** when its `done` arrives, whatever the outcome; 02.8-02 hardens the failure paths.
- **Turn tagging:** every `chat-event` carries `turn`, the turn number the event belongs to (committed turns + 1 when it was recorded; `done` carries the number just committed). The renderer shows live events only while `turn > chat.turns` of the node it has, so a turn is never shown twice or missing while `tree-changed` is in flight.
- **Transcript storage (orchestrator resolution 1, known limit):** the kernel has no append or splice op, so each turn rewrites the whole `body`. The journal grows by about the body's size per turn, quadratic over a session's life. Accepted under D-07 for this phase; 02.8-02 measures it.
- **The old one-chat-per-workspace conversation (resolution 5):** chats.json v1's `chats` map is carried over unchanged and never read. Its `agent.claude-chat` stays in agents.json, because history is attributed to it.
- **`RESUMED_NOTICE` is removed.** Its words ("earlier messages aren't shown here") are false once the note shows the history.
- **chat:new is removed.** New chat now creates a session note.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (chat:create/open/send/stop/setAllowShell) | The window names a workspace tree and a note id; main decides whether that is a session |
| MCP shim → socket → dispatch | Each session's `claude` reaches Tapestry's tools with its own token; the actor comes from the token |
| main → workspace `.tree` | Session commits are written by main, as the person (create) or the session agent (turns) |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02.8-01 | Elevation of Privilege | ChatService.sessionFor | high | mitigate | A crafted note id (a file note, another tree's note, a malformed id) is refused by `SESSION_NOTE_ID_RE` in index.ts and by the live `isSessionNode` check in that open workspace before any engine, token or config file is made |
| T-02.8-02 | Spoofing | per-session agent identity | high | mitigate | Each session's token is issued by AgentRegistry and lives only in its 0600 config file; the socket derives the actor from the token (`agentActor(name)`), never from tool arguments; tests assert the edit_file commit is signed by that session's agent |
| T-02.8-03 | Information Disclosure | per-session MCP config files | medium | mitigate | Files are 0600 under a 0700 dir, one per session, deleted on workspace close, disposeAll and killAllNow; tokens never reach argv, env, logs, the renderer or the tree (unchanged 02.7 rule, extended to every session) |
