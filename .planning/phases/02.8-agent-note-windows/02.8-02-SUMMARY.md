# Phase 02.8 Plan 02: Honest failure turns, many sessions, delete and place Summary

**Every way a chat turn can end, including quitting Tapestry mid-reply, is now one committed passage that says what happened. Up to four idle session processes stay alive (least recently used ended and resumed with `--resume`). Only the chat can write its transcript. Sessions can be deleted and created at a point.**

## Accomplishments

- **One turn path.** `send` records `user` as soon as the message is accepted. Agents off, no `claude` and a failed engine start (a new `crashed` error, "Claude Code couldn't be started: …") go through `failTurn`, which records the error, then commits the turn with `done { ok: false }`. The engine's `done` and the close path both use `commitOpenTurn(session, extra)`.
- **Quit and close.** `closeWorkspace` calls `commitOnClose` for every session before it forgets them or drops an engine, and before its first `await`. `disposeAll` calls `closeWorkspace` synchronously for every tree. So at `will-quit` the turn is on disk before `registry.closeAll()`. If a shell turn's catch-up is still running, its real `done` (held as `pendingDone`) is used instead of `Stopped`.
- **Session lost.** The resend is not recorded again. The notice is a `Note:` line in the same passage, and the failed attempt's error and `done` are swallowed. If the resend itself cannot start (no `claude`, or a start that throws), the turn is now committed as failed. Before, it stayed open.
- **Cap.** `MAX_LIVE_ENGINES = 4`, with `lastUsed` bumped on each send. `makeRoomForEngine` runs before an engine is created and drops the least recently used idle session. A session that is busy, settling, recovering or has an open turn is never dropped.
- **Guard.** `workspaceSubmitRefusal(ops, nodeTypeOf?)` refuses `setProperty` or `unsetProperty` of `body` or `chat.*` on a `tapestry.chat/session@1` node with `CHAT_BODY_REFUSAL`. When a lookup is given, a body or chat op whose target is not a string is refused with the workspace message. index.ts passes `(id) => registry.get(treeId)?.bridge.getNode(id)?.type`.
- **Delete.** `SessionNotes.delete` makes one `deleteNode` commit, signed by the person, with the message `delete chat <nK> "<title>"`. The kernel removes both edges that touch the note (tested). `ChatService.deleteSession` checks the person's actor first, then drops the engine without committing the open turn, and removes the config file and the chats.json entry. It deletes the note last. The session's key is refused while the delete runs.
- **Create at a spot.** `checkSessionPlacement` accepts `undefined`/`null`, or exactly `{ at: { x, y } }` with finite numbers of magnitude at most 1,000,000. `sessionSpotAt` uses `firstClearSpot` (the old private `stepDown`, now exported with no behaviour change) with the same obstacles as `nextSessionSpot`, through a shared `sessionObstacles`.
- **IPC.** `chat:delete(treeId, noteId)` added. `chat:create` passes `placement` through to ChatService. preload has `chat.delete` and a typed `chat.create(treeId, placement?)`, and `global.d.ts` matches both.

## Measured journal growth (orchestrator resolution 1)

Five turns in one session. Each turn is a question, one tool line and a reply of about 600 characters (session-notes.test.ts, "journal growth per turn"):

```
[02.8-02 journal growth] turn 1: body 686 B, commit 1027 B; turn 2: body 1374 B, commit 1716 B; turn 3: body 2062 B, commit 2404 B; turn 4: body 2750 B, commit 3092 B; turn 5: body 3438 B, commit 3780 B; total 12019 B for 5 turns
```

Each turn commit is the note's whole current body plus about 342 bytes of commit header and ops. The journal grows quadratically over a session's life. With 700-byte turns, a session of n turns writes about 350·n² bytes: roughly 3.5 MB at 100 turns and 14 MB at 200. This is the accepted limit under D-07 until the kernel has an append op. The test asserts `commit ≤ body + 512` for every turn.

## Decisions Made

- The five recorded choices in the plan were taken as written: failure turns, the quit-time commit, the cap of 4, `firstClearSpot`, and keeping the agent on delete.
- While a shell turn's catch-up is running at close, the turn is committed with the engine's real `done` rather than `Stopped`, because that turn did finish.
- `send` now also refuses with "still answering" while a turn is open but the engine is not busy, for example between a lost session's failure and its resend.
- Each session has one agent. The Agents panel therefore gets one row per session and does not group them. This is the planner's assumption for UI-SPEC A-11 and an accepted limit for this phase.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A lost session whose resend could not start left its turn open forever**
- **Found during:** Task 1
- **Issue:** `resendAfterLoss` recorded a bare `not-installed` error and returned, and a throwing `ensureEngine` rejected an unawaited promise. Either way the turn never ended and `send` stayed blocked.
- **Fix:** both paths now go through `failTurn`, so the turn ends as one failed passage.
- **Files modified:** app/src/main/chat/chat-service.ts
- **Commit:** 9c0e01f

**2. [Rule 2 - Correctness] A failed engine start is recorded as a turn instead of throwing after the message was accepted**
- **Found during:** Task 1
- **Issue:** `send` now records the person's message before it starts the engine. If `ensureEngine` or `engine.send` then threw, the turn would have been left open.
- **Fix:** the turn is recorded as `Error (crashed): Claude Code couldn't be started: <reason>` and committed. Before this plan, such a send threw to the IPC caller.
- **Files modified:** app/src/main/chat/chat-service.ts
- **Commit:** 9c0e01f

**3. [Rule 2 - Correctness] deleteSession refuses its note id while the delete is in progress**
- **Found during:** Task 3
- **Issue:** `deleteSession` awaits `dropEngine`. During that wait, a send could re-create the session from the still-live note and spawn a new process.
- **Fix:** a `deleting` set makes `sessionFor` refuse that key until the delete finishes.
- **Files modified:** app/src/main/chat/chat-service.ts
- **Commit:** 5ea9299
