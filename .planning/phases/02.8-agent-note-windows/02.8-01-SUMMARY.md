# Phase 02.8 Plan 01: Session notes and turn passages Summary

**Every in-app chat is now a `tapestry.chat/session@1` note in its workspace tree, and each completed turn is appended to that note's plain-text body as a `Turn k` block in one commit signed by the session's own agent, `agent.claude-chat-<8 hex>-<note id>`.**

## Accomplishments

- `src/shared/chat/transcript.ts` holds the whole on-disk contract in one pure module: the node type and keys, `isSessionNode`, `committedTurns`, `sessionBody`, and the turn grammar (`toolSummary`, `turnItemsFromEvents`, `encodeTurn`, `appendTurnText`, `parseTranscript`). The parser never throws.
- `main/chat/session-notes.ts` is the only writer of session notes. It also defines a session's identity: `sessionAgentName`, `sessionKey`, `persistKey`, `SESSION_NOTE_ID_RE`, and `CHAT_AGENT_NAME` (moved here from chat-service.ts).
- A new session goes at the first clear spot right of everything in the workspace frame (`nextSessionSpot`). An empty workspace puts it at (0, 0).
- ChatService is keyed by (tree id, note id). Each session has its own agent, token, `<16 hex>-<nK>.mcp.json` config file, Claude Code session id and chats.json v2 entry (`<realRoot>#<nK>`). A session's token is issued when it is created, so the agent is listed before any turn.
- IPC: `chat:create` is new. `chat:open/send/stop/setAllowShell` take the note id, which is checked against `SESSION_NOTE_ID_RE` in index.ts and against the live node in ChatService. `chat:new` is removed.
- The panel shows one session. Committed turns come from `parseTranscript(body)` and the turn in progress from `liveAfter(live, chat.turns)`. The title is the session's title, and the subtitle names `agent.<session agent>`. New chat (in the frame header and the panel header) makes another session.

## Decisions Made

- **Task 1: option a (Recommended), taken by the unattended driver, queued as autonomy/REVIEW.md item 6.** This means a plain-text line grammar with `Turn k` headers, node type `tapestry.chat/session@1`, and keys `chat.turns`, `width` and `height`. "Passage" in D-07 is the `Turn k` block of a plain-text body, and "passage anchor (2.1)" in D-18 is the turn number k. Neither is a 2.1 ProseMirror passage mark.
- **Agent name format:** `claude-chat-<first 8 hex of the tree id>-<note id>`, for example `claude-chat-3c31b6e5-n13`. This is costly to reverse because every turn commit carries it.
- **Journal growth limit:** each turn commit rewrites the whole `body`, so a session's journal grows by about the body's size per turn (quadratic over its life). This is accepted for this phase, and 02.8-02 measures it.
- **chat:new and the resumed notice are gone.** After a relaunch, the first message resumes with `--resume <id>` and adds no notice.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] NUL and unpaired surrogates in transcript content become U+FFFD**
- **Found during:** Task 2
- **Issue:** FORMAT.md forbids NUL anywhere in a `.tree` file, and a lone surrogate has no UTF-8 form. A reply containing either would make the turn commit fail. The plan names line-breaking as the only lossy rule.
- **Fix:** `cleanText` replaces both with U+FFFD. The grammar header documents this as a second lossy rule, and a test covers it.
- **Files modified:** app/src/shared/chat/transcript.ts
- **Commit:** 67ffce6

**2. [Rule 2 - Correctness] Tool lines are capped at 1,000 characters**
- **Found during:** Task 2
- **Issue:** A refusal's first line (or a path) has no length bound, and each tool line is a single `.tree` line.
- **Fix:** `MAX_TOOL_SUMMARY_CHARS = 1000`, ending in `…`. The UI-SPEC says tool lines are "never truncated", but real summaries are far below this cap, and the cap only guards against pathological input.
- **Files modified:** app/src/shared/chat/transcript.ts
- **Commit:** 67ffce6

**3. [Rule 1 - Bug] A committed turn's `done` is sent but not kept live**
- **Found during:** Task 2 (the tracer test caught it)
- **Issue:** Recording `done` tagged k after dropping turns ≤ k left a stale entry in `live`, so `open()` returned it after the note already held the turn.
- **Fix:** `emitEvent` sends the committed `done` without keeping it.
- **Files modified:** app/src/main/chat/chat-service.ts
- **Commit:** 67ffce6

**4. [Rule 3 - Blocking] App.css gains `.tapestry-chat-turn`, `.tapestry-chat-empty-*` and `.tapestry-chat-other`**
- **Found during:** Task 3
- **Issue:** Wrapping each turn in a `role="group"` element takes its items out of `.tapestry-chat-transcript`'s flex column, which would break the right-aligned "You" bubble. App.css was not in the plan's file list.
- **Fix:** each turn is its own flex column with the same 8px gap. The rules use existing tokens only (`--tap-muted`, no new colour).
- **Files modified:** app/src/renderer/App.css
- **Commit:** edb7802
