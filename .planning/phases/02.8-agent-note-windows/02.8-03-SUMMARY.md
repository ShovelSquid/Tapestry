# Phase 02.8 Plan 03: The session card Summary

**Every chat session note is now a note-sized card on the canvas with its conversation scrolling inside and a composer you can reply from. The docked panel is the enlarged view of the same session, and both read one store (`state/chat-sessions.ts`) with a single `onChatEvent` subscription.**

## Performance

- **Duration:** about 12 min
- **Started:** 2026-09-26T01:37:37Z
- **Completed:** 2026-09-26T01:49:32Z
- **Tasks:** 3
- **Files:** 6 created, 7 modified

## Accomplishments

- **One store.** `state/chat-sessions.ts` follows `workspace-status.ts`. It holds a module Map keyed `<treeId>:<noteId>` and one lazy `window.tapestry.onChatEvent` subscription, and `useChatSession` reads it through `useSyncExternalStore`. Snapshots are replaced, never mutated. They hold `{ loaded, workspace, agent, entries, busy, sending, allowShell, draft, attachment, error, focusNonce, focusPlace }`. Events heard before `chat.open` answers are dropped, because open's `live` already holds them. `useChat` is gone.
- **Composer** (`ChatSessionComposer`): "Message Claude", grows from 1 to 5 lines and then scrolls. **Send message** is disabled while the draft is empty, a turn is running or a send is in flight. **Stop reply** shows only while a turn runs. Enter sends, Shift+Enter makes a new line, and IME composition is respected. The attachment chip has **Remove attachment**. A focus request is taken once per (nonce, place), with `preventScroll: true`.
- **Transcript** (`ChatSessionTranscript`) now owns its scroller. It follows new text only within 48px of the bottom. Otherwise it stays put, and **Jump to latest** (sticky, centred, 8px above the composer rule) shows until the reader is back at the bottom. It opens at the bottom, or where the reader left it. A wheel turn over it scrolls it and never pans (pinch passes through). Every item wraps with `pre-wrap` and `overflow-wrap: anywhere`. The live reply keeps its static trailing "…".
- **Card** (`ChatSessionCard`, memoised with forwarded handlers like WorkspaceFileCard):
  - It has a drag strip, drags in the camera's axes, and supports the D-05 follow spot.
  - The title input commits a `title` change on blur or Enter; Escape reverts it.
  - **Close/Open** ("Close chat card" / "Open chat card") and **Enlarge** ("Open beside the canvas", `aria-pressed` while enlarged) sit in the header.
  - The transcript and composer sit in a body that stops keydown, pointerdown, dblclick and contextmenu.
  - NoteControls give connect and delete. Resize handles sit on the right edge, the bottom edge and the bottom-right corner.
  - `role="article"`, `aria-label="Chat: <title>"`.
  - TreeFrame draws every `isSessionNode(node)` as this card, before the plugin-view branches.
- **Enlarged view.** `ChatPanel`'s chat kind renders one session from `useChatSession`. It has a title, **New chat** (creates a session and enlarges it) and **Back to card**, then the subtitle "Edits go through Tapestry's workspace tools as agent.<agent>". The shell switch and banner work per session. The transcript and composer are the same components the card uses.
- **Entry points.** `openChat(target)` runs `chatWorkspaceFor`, then `createChatSession(treeId, at, attachment)`. That calls `chat.create`, puts the attachment into the new session's draft and asks the card's composer to take focus. It then refreshes the tree and returns `{ treeId, noteId }`, or null for the chooser, no workspace or a refusal. It never opens the panel or moves the camera. The canvas menu's Ask Claude… inside a workspace passes the frame-local pointer as `at`. `openChat` now reads the trees through refs, so the context value no longer changes on every commit.
- **Delete.** For a session note, `handleDeleteNote` checks the store:
  - While Working, it shows "Delete this chat?": **Keep chat** has initial focus and is the Escape answer, and **Delete chat** is destructive.
  - Otherwise, or after Delete chat, it calls `chat.delete`, then `forgetChatSession`, closes the panel if it showed that session, and refreshes the tree. A failure shows as a TransientNotice.
- **View state** (`layout/session-card.ts`): size, closed and scroll are kept in localStorage under `tapestry.chat.cardViews`, keyed tree:note. Writes are clamped and never throw, and the transcript's scroll is saved at most once per animation frame. The card has no width or height handler, so none of this can commit or write `width`/`height`.
- **Typography:** transcript text, the empty state and the input moved to 16px. Tool rows, the chip, its remove button, the shell-risk line and the frame chat button moved to 13px. Turns are now 16px apart in the panel as well as the card.

## Decisions Made

- **A-10 changed:** Ask Claude… on a note or file creates the session at the workspace's next free spot, not `beyond` the card. This is reversible.
- **A-12:** Back to card closes the panel only. Nothing in the renderer calls `chat.stop` except Stop reply.
- **Backstop "enlarged view with no session selected":** the panel never opens without a session. It closes when its session's node is gone (the existing effect), when the session is deleted, or when the tree leaves the space. The chooser and no-workspace panels close with Close.
- **Delete and undo:** a session delete is one `chat:delete` commit. Undo is unavailable in a workspace window, so the conversation stays in history only (orchestrator resolution 7).
- **Opening the enlarged view focuses its composer** (focus place `panel`), as the 02.7 panel did on open.
- **Live-entry pruning:** when turn k's `user` event arrives, entries older than turn k−1 are dropped. The previous turn's entries are kept one turn longer, so the card never shows neither the live nor the committed turn.
- **retainChatSessions:** when a tree leaves the space, its sessions leave the store, so a reopened workspace loads them afresh from main.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] A `sending` flag disables Send message while a send is on its way**
- **Found during:** Task 1
- **Issue:** Between the click and main's `user` event, busy is still false, so a quick second Enter would send twice and hit "still answering".
- **Fix:** `sending` in the snapshot. Text typed while a send is in flight is kept.
- **Files modified:** app/src/renderer/state/chat-sessions.ts, app/src/renderer/components/ChatSessionComposer.tsx
- **Commit:** 34e32c9

**2. [Rule 1 - Bug] The store never pruned live entries**
- **Found during:** Task 1
- **Issue:** Main sends every turn's events, including the committed `done`. A long session would hold every past event.
- **Fix:** pruning on each new turn's `user` event, as described under Decisions.
- **Files modified:** app/src/renderer/state/chat-sessions.ts
- **Commit:** 34e32c9

**3. [Rule 1 - Bug] A session forgotten while its card stays drawn would never reload**
- **Found during:** Task 2
- **Issue:** `useChatSession`'s load effect ran only when the key changed.
- **Fix:** it also re-checks when the snapshot changes. `loadChatSession` is a no-op for a key already requested.
- **Files modified:** app/src/renderer/state/chat-sessions.ts
- **Commit:** 232d2e1

**4. [Rule 2 - Performance] openChat no longer changes on every commit**
- **Found during:** Task 2
- **Issue:** `openChat` depended on `trees`, so the ChatContext value, which every card consumes, changed with each commit.
- **Fix:** it reads `trees` and `lastChatTreeId` through refs.
- **Files modified:** app/src/renderer/App.tsx
- **Commit:** 232d2e1

### Other notes (current code vs the plan and UI-SPEC)

- **NoteControls vs CornerCluster:** ws/ui replaced NoteControls on NoteCard with the Line Lab `CornerCluster`, which puts the delete dot on the top-left. The session card keeps NoteControls (connect on the right edge, delete bubble top-right), as the plan and the UI-SPEC say, because the top-left corner is where 02.8-04's "!" badge goes. The session card is also not an ink note: it keeps the plain NoteCard surface (1px `--tap-border`, 8px radius, `--tap-surface`). All colours are existing tokens and no new ones were added.
- **Provenance footer:** the card takes no `provenance` prop and shows no footer. The session's author is its agent, and the header's status line comes in 02.8-04.
- **Title placeholder** is "New chat" (A-05). An empty title reverts on blur instead of committing an empty string.
- **Resize handles:** only the right edge, the bottom edge and the bottom-right corner, as the plan says. The UI-SPEC's "existing eight" would include left and top handles, which need a position write, and a resize must never commit. A closed card keeps only the right handle.
- **`ChatSessionTranscript` gained** `className`, `ariaLive`, `initialScroll` and `onScrollChange` props, and owns its scroller. The panel keeps its `aria-live="polite"` region; the card has none (UI-SPEC: announcements go through LiveAnnouncer in 02.8-04).
- **Extra exports beyond the plan's list:** `ChatSessionSnapshot`, `EMPTY_CHAT_SESSION`, `ComposerPlace`, `chatSessionKey`, `chatSessionFor`, `recordChatPayload`, `retainChatSessions` (chat-sessions.ts); `CardViewStorage`, `browserCardViewStorage` (session-card.ts); `attachmentLabel` (ChatSessionComposer); `TranscriptScroll` (ChatSessionTranscript); `sameSessionCardData` (ChatSessionCard).
