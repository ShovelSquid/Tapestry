# Phase 02.8 — UI Design Contract

> Visual and interaction contract for agent note windows: the session card on the canvas, its status line and five states, levels and the motion threshold, edge arrows, the transcript as one document, the docked ChatPanel as the enlarged view, and reply-at-any-turn forks with their `forked-from` line. Generated by gsd-ui-researcher in `--auto` mode (nobody was asked anything), verified by gsd-ui-checker.

This phase inherits the approved 02.1, 02.2 and 02.3 UI-SPECs and the existing `app/src/renderer/App.css`. **No new hue, no new type size, no new weight and no new spacing token.** It adds three CSS custom properties that name values the app already uses (§ Color → Tokens this phase adds). Every product decision comes from `02.8-CONTEXT.md` (D-01 … D-21, Kaelen 2026-09-25). Everything the context left open is derived from existing code and listed as an assumption (`A-nn`) in § Assumptions, each shipping as written unless Kaelen says otherwise.

Locked decisions this contract binds (restated, not re-opened):

| # | Locked | Where it binds here |
|---|--------|---------------------|
| D-02 | A session is a note in its workspace tree with a real placement | § Session card anatomy |
| D-04 | The docked ChatPanel is the enlarged view of a session note, not a second UI or store | § Enlarged view |
| D-05 | The card keeps its note size; the conversation scrolls inside it. Scroll, size and open/closed are view state | § Session card anatomy |
| D-06 | The dialogue box is in the window | § Composer |
| D-07, D-08 | One document; each turn one passage, one commit; tool calls as one-line summaries | § Transcript rendering |

| D-12 | After relaunch every session shows Idle with its last status text | § Relaunch |
| D-13 | `set_status({ text, needs?, level? })`, fallback status text, level 2 on done | § Status line |
| D-14, D-15 | Levels 0–3, ceiling 3; a visibility threshold setting | § Levels and the motion threshold |

| D-17 … D-19 | Reply at an earlier completed turn forks a new note beside the original; one commit with a `forked-from` edge to turn k's passage; the line clamps to the card edge; the in-progress turn is not a fork point | § Reply at any turn |

Exceptions, each with its reason:

- **Session card default size 360 × 440px** (view state, A-02). 360 − 2 × 16 padding = 328px of Body text ≈ 40 characters a line; 440 holds the header (≈ 70px), about eight Body lines of transcript and the one-line composer with its button row.
- **Session card size limits: min 280 × 240, max 720 × 960.** 280 is `DEFAULT_NOTE_WIDTH` (`layout/placement.ts`), so a session never draws narrower than a default note; 240 is `MIN_WINDOW_HEIGHT` (`surface-windows.ts`). 720 × 960 keeps a card inside one 1080p screen at 100% zoom. The note card's own 400px `max-width` does not apply to the session card.
- **Closed card: header only** (drag strip + title row + status line + 16px bottom padding ≈ 88px). Width unchanged.
- **Composer textarea: 1 line (40px tall: 24px line + 2 × 8px padding) at rest, grows to 5 lines (136px) while typing, then scrolls.**
- **User message bubble padding 8px × 12px** — carried from `.tapestry-chat-user` unchanged.
- **"!" badge: 24px circle, centred on the card's top-left corner (offset −12px, −12px).** Mirrors the delete bubble on the top-right corner; 24px is the app's minimum hit size (`.tapestry-ask-claude-button`).
- **Edge arrow: 32px circle, 16px from the side and bottom edges, 64px from the top edge**; when the ChatPanel is open the right inset is `420 + 16 + 16 = 452px` so arrows never sit under the panel. Arrows on one edge keep centre-to-centre ≥ 40px (32 + 8).
- **Forked-from anchor dot 8px diameter; clamp inset 8px** from the original card's top or bottom edge when turn k is scrolled out.
- **Forked-from line 1.5px** — carried from `ConnectionLine` (non-temporary stroke width).
- Carried unchanged: 8px card radius, 1px border, 2px selected border, 32px buttons, 24px icon buttons, 420px ChatPanel width, 440px dialog width, 6s transient notice.

### Author colour for sessions

Each session is its own agent (D-03), so `ChatService`'s `agents.issueToken(<session agent>)` puts every session in `agents.json`, and `orderAgentsByConnection` gives it a palette slot in creation order, cycling past the fifth (existing `author-palette.ts` rule). The colour is used for exactly four things:

1. The Done flash ring and the settled Done border (§ States).
2. The Needs you border and the "!" badge fill.
3. The Done and Needs you state glyphs.
4. The edge arrow's border and glyph.

Every author colour clears 4.5:1 on `--tap-paper` and on `--tap-surface` (02.3 table), so white "!" on an author-colour disc and author-colour glyphs on white both pass. Colour is never the only cue: each use also carries a glyph shape and a state word (§ States).

## Session card anatomy

A session card is drawn by `SessionCard` wherever `TreeFrame` meets a session note. Its position is the note's real placement (D-02: `place` and `lock.layout` apply); its size, open/closed state and transcript scroll are view state, kept in the renderer (localStorage, keyed by tree id + note id) and never in a commit (D-05).

```
┌──────────────────────────────────────────┐  ← 1px --tap-border, 8px radius, --tap-surface
│ (20px drag strip, invisible, existing)   │
│ [glyph] Session title…          [▾] [⤢] │  row 1: 16px glyph · Note Title · Close/Open · Enlarge
│ Working · write_file notes/plan.md       │  row 2: status line, Label, --tap-muted, 1 line
├──────────────────────────────────────────┤  1px --tap-border, 8px above and below
│                    ┌───────────────────┐ │
│                    │ your message      │ │  --tap-surface-sunk bubble, right, max 85%
│                    └───────────────────┘ │
│ Claude's reply, Body, left, pre-wrap     │
│ · read_file notes.md — done              │  tool summary: Label, mono, --tap-muted
│                          Reply from here │  on hover/focus of a completed, non-last turn
│  … (scrolls inside the card)             │
├──────────────────────────────────────────┤
│ [ Message Claude                       ] │  composer: 1 line at rest, Body
│            [Stop reply] [Send message]   │  Stop reply only while working
└──────────────────────────────────────────┘
```

- **Surface**: the NoteCard surface unchanged (`--tap-surface`, 1px `--tap-border`, 8px radius, `0 2px 4px rgba(0,0,0,0.06)` shadow, 16px padding, 24px top padding over the drag strip). Selection, editing and connect-target borders are NoteCard's.
- **Row 1**: state glyph (16px, § States), then the title input (existing `.tapestry-note-title-input`, Note Title role, editable like any note title), then two 24px icon buttons in the `.tapestry-ask-claude-button` style: **Close/Open** (chevron; closes the card to its header) and **Enlarge** (opens this session in the docked panel; `aria-pressed="true"` while it is the enlarged session).
- **Row 2 — status line**: Label, `--tap-muted`, one line with ellipsis, full text in its `title`. Format `<State word> · <status text>`; Idle shows the status text alone (§ Status line).
- **Transcript**: `flex: 1`, `overflow-y: auto`, 8px top padding under a 1px `--tap-border` rule. Turns 16px apart; items inside a turn 8px apart.
- **Composer**: under a 1px `--tap-border` rule with 8px top padding; the existing `.tapestry-chat-input` and `.tapestry-chat-actions`, moved to Body (§ Typography).
- **Controls**: NoteControls' connect bubble (right edge) and delete bubble (top-right) unchanged. The "!" badge sits on the top-left corner (§ States).
- **Resize**: the existing eight resize handles. A resize writes the card's view-state size, not the note's `width`/`height` props (D-05).
- **Closed card**: rows 1 and 2 only, the same width. The "!" badge, the state glyph, the Done border and the Working treatment all still show on a closed card.
- **Input isolation** (as `ChatPanel`'s `PanelShell` and file windows): key presses inside the composer and transcript stop propagation, so typing never deletes a note. A wheel turn over the transcript scrolls it and does not pan the canvas (pinch-zoom with `ctrlKey` passes through); a wheel turn anywhere else on the card pans the canvas like any note.

### Stack order (D-16)

Within its tree frame, a session card that changes state at level ≥ 1 moves to the top of that frame's note stacking order — the same "last is on top" rule as `raiseWindow` in `surface-windows.ts`. The order is renderer state per tree, never written. Clicking or focusing a card also raises it. A card never rises above the ChatPanel, dialogs, menus or edge arrows.

## States

All of this is renderer state (D-10). Nothing in this section enters `.tree`, a commit, or a hash.

| State | Source (observed, never guessed) | Glyph (16px, row 1) | State word | Card treatment | Motion |
|-------|------------------------------------|---------------------|------------|----------------|--------|
| Idle | no turn running, nothing unread | Spark (the Agents-panel glyph), `--tap-muted` | none | NoteCard at rest: sharp, 1px `--tap-border` | none |
| Working | `engine.busy` | Spark, `--tap-muted` | "Working" | Transcript: `filter: saturate(0.2) blur(2px)`. Composer: `saturate(0.2)` only. Header row stays sharp and full colour, so the status line and Stop reply stay readable. Hover or focus inside the card sets blur to 0 (desaturation stays). Border stays `--tap-border`, never the gray `--tap-author-unknown` | 200ms ease filter transition in and out |
| Needs you | `set_status` with `needs: true` (or level 3, § Levels) | "!" in a circle, `--tap-session-author` | "Needs you" | 2px `--tap-session-author` border + "!" badge on the top-left corner: 24px disc filled `--tap-session-author`, white "!" glyph, `0 1px 4px rgba(0,0,0,0.15)` shadow (the control-bubble shadow) | badge appears with one 240ms scale 0.6 → 1; then still. No pulsing, no loop |
| Done | `done { ok: true }` | check in a circle, `--tap-session-author` | "Done" | On arrival: jiggle + flash ring (§ Motion). Settled: 2px `--tap-session-author` border. **Decays**: after 30s the border fades over 2s back to 1px `--tap-border`; the glyph and "Done" word stay until you look (acknowledgement below) | jiggle + flash once, if level ≥ threshold |
| Failed | `error` event, or `done { ok: false }` | × in a circle, `--tap-destructive-text` | "Failed" | State word and status text in `--tap-destructive-text`. The failed turn ends with the error box (existing `.tapestry-chat-error`: 1px `--tap-destructive` border, `--tap-destructive-wash` fill, `--tap-destructive-text` text, plus the fix hint where one exists). Border stays 1px `--tap-border`, no author colour | **none, ever** — Failed never jiggles or flashes, so it can never read as Done |

Selection wins the border: a selected card keeps its 2px accent border in every state; the glyph, state word and "!" badge still show.

### Leaving a state

- **Working → Done / Failed / Idle**: by the next engine event. Stop reply ends the turn as Idle, with status text "Stopped".
- **Done → Idle**: when you look at it: the pointer rests on the card for 1000ms, you click or focus anything in it, you open it in the enlarged view, or you send in it. The status text stays; only the word, glyph colour and border go.
- **Failed → Idle**: the same acknowledgement as Done. The status text keeps the short failure phrase, now in `--tap-muted`; the error box stays in the transcript.
- **Needs you → Idle/Working**: **only** when you send a reply at the last turn of that session. Hovering, opening or scrolling does not clear it. Forking from an earlier turn does not clear it on the original (D-19: the original never knows).

### Status line (D-13)

`<State word> · <status text>`; Idle shows `<status text>` alone. The text is, in order of preference:

1. The `text` of the agent's latest `set_status` call in this turn (a few words; truncated with ellipsis to one line).
2. Otherwise the latest tool call's one-line summary, the same string the transcript records (e.g. `write_file notes/plan.md`).
3. Otherwise the first non-empty line of the latest reply.
4. Otherwise, before anything has happened in a turn: "Reading your message".
5. A session with no turns: "New chat".

The line never says "needs you" unless `needs: true` (or level 3) arrived. Nothing is inferred from reply text.

### Relaunch (D-12)

After a relaunch every session card shows **Idle**: spark glyph, no state word, 1px border, no "!", no blur, no arrow, with its last status text in `--tap-muted`. The last status text is remembered outside the tree (chrome, D-10). A session that was mid-turn when the app quit shows its last status text followed by nothing else; the engine resumes by `resumeSessionId` when you next send.

## Levels and the motion threshold (D-14, D-15)

`level` comes from `set_status` (clamped to 0–3, ceiling 3). Defaults: Done → 2 (or the level of the turn's last `set_status`, A-04); `needs: true` → 3. Working and Failed are observed engine states, not levelled announcements: they always show.

| Level | Card status text | Rises in stack | Jiggle + flash | "!" badge (persistent) | Edge arrow when off-screen | Announced |
|-------|------------------|----------------|----------------|------------------------|----------------------------|-----------|
| 0 | not updated on the card (the enlarged view still shows it) | no | no | no | no | no |
| 1 | updated | yes | only if threshold is 1 | no | no | polite |
| 2 | updated | yes | if threshold ≤ 2 (default: yes) | no | yes | polite |
| 3 | updated | yes | if threshold ≤ 3 (always) | **yes**, until you reply | yes, with "!" | polite |

The **visibility threshold** is the lowest level that animates (jiggle + flash, and the badge's one arrival scale). Below it a change only updates text. It never hides the "!" badge, the state word, the glyph or an edge arrow — the threshold turns off motion, not information. Default: 2.

Setting (A-06): a row in the Agents panel, below "Let agents connect", using `.tapestry-field-label` + a native `<select class="tapestry-field-input">`, stored in renderer localStorage (view state, never in a tree).

## Edge arrows (D-16)

`EdgeArrowLayer` is a fixed, screen-space layer over the canvas (outside the canvas transform, below the ChatPanel and dialogs).

- **When**: a session card is entirely outside the visible canvas area and holds an unacknowledged state at level ≥ 2: Done (level ≥ 2), Needs you, Failed (A-07), or a just-created fork (A-08). One arrow per session.
- **Where**: on the visible-area edge where the line from the viewport centre to the card centre leaves it, inset per § Spacing (16px sides and bottom, 64px top, and left of the ChatPanel when it is open). Arrows on one edge are spread along it, sorted by their angle, keeping ≥ 40px centre-to-centre.
- **Look**: 32px circle, `--tap-surface` fill, 2px `--tap-session-author` border, the control-bubble shadow. Inside, a 16px chevron pointing toward the card in `--tap-session-author`. Needs you: the chevron is replaced by the "!" glyph and the disc is filled `--tap-session-author` with a white "!", the same look as the card's badge. Failed: a × glyph in `--tap-session-author` (the arrow says which session; the card says what went wrong).
- **Hover**: a Label tooltip on the `.passage-chooser` surface, `<title> — <State word>`.
- **Click / Enter / Space**: pans the camera so the card is centred in the visible area, zoom unchanged (the person's own action, so D-16 holds). It does not acknowledge the state; looking at the card does.
- **Gone when**: the card is at least partly visible, or its state is acknowledged or cleared.
- **Keyboard**: arrows are `<button>`s in DOM order after the canvas and before the ChatPanel; `:focus-visible` ring 2px accent, 2px offset.

## Transcript rendering (D-07, D-08, D-09)

The transcript is the session note's own text: one passage per completed turn (your message, then Claude's reply with its tool summaries), appended one commit per turn. The card and the enlarged view render it **read-only** from the note's text (A-09); the turn in progress renders live from `foldChatEvents` until its commit lands, then is replaced by the committed passage with no visible jump.

| Item | Look |
|------|------|
| Your message | `--tap-surface-sunk` bubble, right-aligned, max 85% width, 8px × 12px padding, 8px radius, Body, `white-space: pre-wrap`, `overflow-wrap: anywhere` (existing `.tapestry-chat-user`) |
| Claude's reply | Left-aligned Body, pre-wrap, no bubble (existing `.tapestry-chat-assistant`) |
| Tool summary | One line per call: `· <tool> <path> — done` or `· <tool> <path> — refused: <first line>`. Label size, mono, `--tap-muted`; refused in `--tap-destructive-text`. Wraps, never truncated. Never a payload (D-08) |
| Notice | Label, `--tap-muted` (existing `.tapestry-chat-notice`) |
| Failed turn | The turn's items, then the error box (§ States → Failed) |
| Turn in progress | Rendered live; no "Reply from here"; a static "…" after the streaming text. No spinner |
| Turn label | "Turn k", Label, `--tap-muted`, shown at the turn's top-left only on hover or keyboard focus of that turn |
| Screen reader | Each turn is `role="group"` with `aria-label="Turn k"`; each message starts with visually hidden "You said:" or "Claude said:" (`.tapestry-visually-hidden`) |

Suggested stored encoding (CONTEXT leaves the exact form to Claude's discretion; this is a recommendation, not a lock): each turn passage starts `You: `, the reply starts on its own line with `Claude: `, and each tool summary is its own line starting `· `. Whatever the planner picks, the renderer must find turn boundaries, speakers and tool lines from the text alone, so the card and a plain `.tree` read the same conversation.

**Scroll** (view state): while you are within 48px of the bottom, the transcript follows new text. If you have scrolled further up, it stays put and a **Jump to latest** button (`.tapestry-button--secondary`, 32px, centred 8px above the composer rule) appears until you are back at the bottom. Opening a card for the first time scrolls it to the bottom.

## Reply at any turn: forks (D-17 … D-21)

### Choosing a turn

- Every **completed** turn except the last shows **Reply from here** at its bottom-right on hover or keyboard focus of the turn: a text button, Label, `--tap-muted`, underline on hover, `aria-label="Reply from turn k"`. The last turn has none (replying there is the ordinary composer). The turn in progress has none (D-19).
- Choosing it enters **fork mode** in that composer:
  - Turn k takes the `.tapestry-passage-active` treatment; turns after k drop to `opacity: 0.4` (they will not be in the new chat).
  - A chip above the input (`.tapestry-chat-chip`): "Replying from turn k. Sending starts a new chat beside this one. This chat stays as it is." with a **Stop forking** button (`.tapestry-chat-chip-remove`).
  - Placeholder becomes "Reply from turn k". Send message's label becomes **Send as new chat**, enabled even while this session is Working (D-19).
  - Focus moves to the input.
- **Escape** or **Stop forking** leaves fork mode with the draft kept.

### What sending does

- One commit creates the fork note (turns 1..k copied into its text, titled `<original title>, from turn k`, placed with 2.5's resolver `beyond` the original from its parent) and its `forked-from` edge to turn k's passage anchor. Your reply then runs as the fork's first turn in its own engine session (D-20).
- The original card does not change in any way: no state, no border, no scroll change, its composer leaves fork mode.
- The camera does not move. The fork card appears in the Working state and at the top of the frame's stack. If it lands off-screen it gets an edge arrow (A-08).
- If the fork was made from the enlarged view, the panel switches to the fork; the original stays on the canvas. Keyboard focus moves to the fork's composer (card or panel, whichever you forked from).
- Polite announcement: "New chat started from turn k of <original title>."
- Refused (e.g. a lock refuses the placement): a TransientNotice, "Couldn't start a new chat from turn k: <reason>. Nothing was changed." Your draft stays in fork mode.

### Forked-from line (D-18)

- Drawn in the tree's connection SVG (`TreeFrame`), from an anchor on the **original** card to the nearest edge midpoint of the **fork** card.
- **Anchor**: on the original card's side edge facing the fork, at the vertical middle of turn k's passage as currently drawn. When turn k is scrolled above or below the transcript's visible part, the anchor clamps to 8px inside the card's top or bottom edge. When the original card is closed, it sits at the card's bottom edge.
- **Line**: 1.5px, `--tap-thread-line` (#8E8A80, 3.16:1 on paper, passes the 3:1 graphics floor), solid, round caps. Not accent, not author colour: it is structure.
- **Anchor dot**: 8px circle in `--tap-thread-line`. Filled while turn k is visible; a 1.5px ring (hollow) while it is clamped, so you can tell the turn is out of view. The dot is a button: clicking it scrolls the original's transcript to turn k and flashes nothing. `aria-label="Show turn k in <original title>"`.
- Forks of forks draw the same way; a family reads as a small tree.
- The line and dot are view geometry from the edge; only the edge itself is in the tree.

## Deleting a session

Deleting a session card uses the existing delete bubble and Delete key path, with one addition:

- **Idle, Done, Needs you or Failed**: deleted like any note, no dialog (existing behaviour; history keeps it). Its engine process is ended.
- **Working**: a Dialog first, because a turn is running. Title "Delete this chat?", body "Claude is still answering. Deleting stops it now. The conversation stays in history, and chats started from it stay on the canvas." Buttons **Keep chat** (secondary, initial focus, also Escape) and **Delete chat** (destructive).
- Forks of a deleted session stay; their `forked-from` edge is cascaded with the node, as every edge is.

## Accessibility

- Card: `role="article"`, `aria-label="Chat: <title>"`. Status line: plain text (no per-card live region; announcements go through `LiveAnnouncer`).
- Announcements (level ≥ 1, not level 0): polite "<title>: done. <status text>"; polite "<title> needs you: <status text>"; assertive "<title> failed: <short phrase>". Working is not announced (it is continuous).
- Every state is carried by glyph shape + state word, never colour alone; Needs you is carried by the "!" badge + word + border, never motion alone.
- Keyboard: Tab reaches the card's title, Close/Open, Enlarge, each turn (to reveal Reply from here), Jump to latest, the composer, Stop reply and Send message. Enter/Space activate buttons. Escape in the composer leaves fork mode, then blurs the composer. Edge arrows and anchor dots are buttons.
- Focus rings: 2px `--tap-accent`, 2px offset on every new control.
