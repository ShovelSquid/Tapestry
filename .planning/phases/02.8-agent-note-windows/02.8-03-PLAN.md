<objective>
The session card: every session note is drawn on the canvas as a card at the note's size. It shows the conversation scrolling inside and a composer you can reply from, and the docked panel becomes the enlarged view of the same session, on the same store.

Purpose: SC3 and D-04..D-06. After 02.8-01 and 02.8-02 the conversation is in the note and main is safe; this plan puts it on the canvas. Status (02.8-04, 02.8-05), motion and arrows (02.8-06) and forks (02.8-07, 02.8-08, 02.8-09) are drawn onto this card.

Output:
- `state/chat-sessions.ts`, which replaces the per-hook `useChat`;
- `ChatSessionCard`, `ChatSessionComposer`, with `ChatSessionTranscript` extended;
- the panel as the enlarged view;
- the entry points and delete;
- card view state in `layout/session-card.ts`.

Recorded choices:
- **One store.** It follows the `state/workspace-status.ts` pattern (a module Map, listeners, a lazy single `window.tapestry.onChatEvent` subscription, `useSyncExternalStore`, immutable snapshots). `useChat` is removed.
- **The attachment lives in the session's draft**, not in the panel state, so a chip set by Ask Claude… shows in the card and the panel alike.
- **Focus without camera moves.** Focusing a new card's composer uses `focus({ preventScroll: true })`, so the canvas never scrolls to it (D-16, A-08). A card that lands off-screen gets its edge arrow in 02.8-06.
- **Ask Claude… on a note or file** creates the session at the workspace's next free spot, not `beyond` the card (UI-SPEC A-10 changed). A session is a top-level note, and the resolver does not see folder frames, so a spot beside a file inside a folder can land on top of that folder's frame. Reversible.
- **The card title** is an ordinary editable note title (A-05). An edit is a `title` kernel:submit, which the workspace guard allows.
- **Typography consolidation (UI-SPEC):** chat transcript and input move from 14px to Body 16px, and tool rows, chip, shell-risk line and frame chat button from 12px to Label 13px.
</objective>
