# Requirements: Data Drawing

**Defined:** 2026-09-22
**Core Value:** The same file, seed, and pinned versions reproduce the same node state at every tick of every branch, so every mark is an object that can be revisited and edited later rather than a pixel that is gone.

## v1 Requirements

Requirements for the first milestone: deterministic core plus painting frontend. Each maps to roadmap phases.

### Simulation Core

- [x] **SIM-01**: The sim's authoritative state is fixed-point integer only (Q32.32 on int64), advanced by a fixed timestep with strictly ordered updates and a seeded PRNG, with no wall clock, floats, threads, or unordered containers in the sim target; a CI check fails the build if any leak in.
- [x] **SIM-02**: The sim can serialize, restore, and hash its state through one canonical byte walk, so two runs of the same actions produce the same SHA-256 hash and a restored state hashes identically to the original.
- [ ] **SIM-03**: The same C++20 sim source builds to WebAssembly and runs live in a renderer Web Worker, reached only through a flat C ABI, so the painting surface sees state without ever mutating it.
- [ ] **SIM-04**: One versioned, data-driven material rule (weight settling: mass-dependent drift on the plane with damping) makes the canvas visibly behave over time, and quiet nodes sleep so idle ticks replay cheaply.

### Strokes and Brushes

- [ ] **STRK-01**: A stroke action records raw pen samples (position on the plane, pressure, tilt) quantized once to integers and stamped with the sim tick and sample index at record time; no smoothed or predicted positions are ever recorded.
- [ ] **STRK-02**: The brush is a spring-damper body integrated inside the sim from the recorded samples, with stiffness and damping derived from the brush's mass, so heavy brushes lag and carry momentum and the feel replays exactly.
- [x] **STRK-03**: Nodes are emitted along the brush body's path at the brush's spacing, with ids derived from the stroke ordinal and emission index (branch-tag bits reserved), never from a counter.
- [ ] **STRK-04**: Brushes are versioned and immutable: a brush version holds a free-text description, mass, radius, spacing, and pressure curve; editing creates a new version and old strokes keep theirs; three or four presets ship differing in description and mass.
- [ ] **STRK-05**: A pulled-string dead zone and finish-line-on-pen-up are brush-version parameters, so light brushes feel direct and a stroke completes to the pen's final position.
- [x] **STRK-06**: Tilt and twist are captured and recorded when the pen reports them; no sim rule depends on them in v1.

### Journal and Readability

- [ ] **JRNL-01**: The plugin registers `.tree` node types for stroke, brush version, and canvas (seed, tick rate, sim and fixed-point and PRNG version pins as properties), with each stroke's samples in a readable one-sample-per-line text block of integer fields.
- [ ] **JRNL-02**: Ticks enter the journal through coalesced advance commits, one before each stroke and one on pause or close, never one commit per tick.
- [ ] **JRNL-03**: A person can open a saved Data Drawing `.tree` in a text editor and identify each stroke, its brush description, its tick, and its branch without the plugin, and with the plugin disabled Tapestry still opens the world and shows readable fallback values.
- [ ] **JRNL-04**: A golden Data Drawing example `.tree` lives in Tapestry's readability suite and is regenerated byte for byte by the tests.

### Painting Surface

- [ ] **CANV-01**: The user paints on one plane facing a fixed camera; node positions are stored as 3D with z taken from the plane, and the plane frame is recorded per stroke so replay never depends on the camera.
- [ ] **CANV-02**: Pen input is captured at the device's full sample rate through pointer capture and coalesced events, recorded only when the pointer is a pen with the tip down (a setting allows the mouse), and predicted events drive the preview only.
- [ ] **CANV-03**: A deterministic placeholder renderer shows the node field live, with each node colored from a hash of its brush description, and a cursor overlay draws the pen position, the brush body position, and the spring between them.
- [ ] **CANV-04**: A plugin can own a WebGL or WebGPU canvas surface inside the Tapestry renderer through a public host extension point, so the painting surface ships without a private hook or an app fork.

### Timeline

- [ ] **TIME-01**: The user can play, pause, single-step, and change speed as ticks per rendered frame, with a tick readout; speed never changes the frame rate or input handling.
- [ ] **TIME-02**: Reopening a saved world replays the recorded actions in the Wasm sim and verifies the resulting state hash against the hash recorded at save, reporting any divergence with the first differing tick.
- [ ] **TIME-03**: The user can scrub to any tick on a scrubber with stroke markers and play in reverse as a decreasing scrub target, computed by replay from zero with an in-memory keyframe ring that is verified against from-zero hashes and never written to disk.

### Marks

- [ ] **MARK-01**: The user can erase by recording a remove-nodes action (radius on the plane at the current tick); erased nodes stay in history and never leave the journal.
- [ ] **MARK-02**: The user can undo the last stroke as a new recorded retract action; history is never truncated and the hash chain stays intact.
- [ ] **MARK-03**: The user can select a stroke and read its description, tick, brush version, weight, and velocity in a read-only inspector.

## v2 Requirements

Deferred to a later release. Tracked but not in the current roadmap.

### Simulation Core

- **SIM-05**: A CI test proves the native and Wasm builds produce identical hashes on golden fixtures (addon preset).
- **SIM-06**: A headless replay oracle CLI opens a `.tree`, verifies checkpoint hashes, and bisects to the first divergent tick.

### Journal and Readability

- **JRNL-05**: Stroke commits carry the sim hash and tick as readable properties so a person can verify with `shasum` and Tapestry Phase 3 can consume them as snapshot keys.

### Painting Surface

- **CANV-05**: Orbit camera and a movable painting plane.
- **CANV-06**: Tilt-driven brush parameters.

### Timeline

- **TIME-04**: Painting while scrubbed into the past is blocked with a visible cue until branching exists.
- **TIME-05**: Snapshot-accelerated scrubbing, branch-at-tick undo, and fork-on-edit (from Tapestry Phase 3).

### Marks

- **MARK-04**: Edit actions on existing marks and rebinding strokes to a newer brush version.
- **MARK-05**: Time-lapse export rendered from replay.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Raster layers and pixel compositing | Pixels are not the source of truth; layer semantics cannot replay from a node field |
| Video time-lapse recording | A lossy cache of the action log; render from replay later instead |
| Frontend-side smoothing using wall-clock timestamps | Nondeterministic; replay on a slower machine yields a different stroke |
| Speed control by capping frame rate | Ties sim time to render time and slows input |
| Floating-point or GPU-parallel simulation | Drift and reordering; cannot be retrofitted |
| Committing per-node state or snapshots into `.tree` | Explodes the readable journal and duplicates Tapestry Phase 3 |
| Destructive undo that truncates the log | Destroys the future branching must preserve; breaks the hash chain |
| Brush edits that mutate existing strokes | Violates the versioned-brush invariant |
| Model-based rendering | Brief milestone 5; cross-hardware nondeterminism; would mask whether the node model and feel are right |
| Raster brush engine features (grain, wet mix, blend modes) | Pixel-space concepts; they become renderer prompts in milestone 5 |
| A menu of stabilizer algorithms | Each is another deterministic code path to version forever; one spring-damper model |
| Recording predicted pointer samples | Browser-implementation-defined; breaks replay across Chromium versions |
| Live collaboration | Ordering and identity are Phase 3 concerns; adds network nondeterminism |
| Infinite canvas, tile tree, procedural spawning | Requires the render tier; scale band is recorded now, tree built in milestone 6 |
| Groups, instancing, weighted bindings | Brief milestone 3 |
| Math brushes, SDF regions, generator brushes | Brief milestone 7 |
| Branching and snapshots inside this project | Owned by Tapestry Phase 3 |
