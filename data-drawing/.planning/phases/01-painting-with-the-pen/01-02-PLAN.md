RESEARCH § CANV-04 proposes the shape below; two points differ from the research proposal and need a human eye:
    (1) kernel access: RESEARCH's SurfaceHost carries `kernel`, but the renderer's only kernel route (`window.tapestry.kernel.*`) signs commits as the HUMAN actor, which would let a plugin write as a person — exactly what D-06 and plugin-facade.test.ts forbid. Phase 1 writes nothing to a `.tree`, so the recommendation is to OMIT `kernel` from SurfaceHost now and add it in Phase 2 through a plugin-signed IPC route (an additive change).
    (2) URL shape: standard-scheme hosts are lowercased by the URL parser, so plugin ids in surface URLs are lowercase-only.
    Undo cost if wrong: every plugin surface module and the renderer layer would need a coordinated change plus an SDK version bump.
  </context>
  <options>
    <option id="A-same-realm">
      <name>SurfaceContribution + same-realm import() over tapestry-plugin://<plugin-id>/<path> (recommended)</name>

      <cons>The module runs in the host renderer's JS realm (can reach window.tapestry — accepted as policy); plugin ids in URLs must be lowercase</cons>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer → `tapestry-plugin://` handler (main process) | Any URL the renderer (or a plugin surface) constructs reaches the file-serving handler; path and plugin id arrive untrusted |
| Plugin manifest / `registerSurface` → host registry | A plugin's `entry` string is joined into a filesystem path |
| Plugins directory → renderer realm | Whatever the handler serves is executed as an ES module in the host renderer |

| T-02-01 | Information disclosure | `resolvePluginFile` (plugin-scheme.ts) — path traversal via `..`, encoded dots, absolute paths, symlinks | high | mitigate | Lowercase host regex; per-segment `..`/`.`/empty rejection after decoding; `relative()` containment; `realpathSync` prefix check against the realpath'd plugin dir; regular-file check; unit-tested with traversal, encoded and symlink fixtures |
