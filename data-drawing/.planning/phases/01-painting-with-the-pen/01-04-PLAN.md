<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Registry data → `import()` URL | `pluginName` and `entry` from the main process become a module URL executed in the renderer realm |
| Plugin surface module → host renderer realm | Same-realm code; can reach `window.tapestry` (policy, not sandbox) |
| Scheme → Worker/WASM | Module Worker and `.wasm` bytes fetched from the scheme origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Spoofing | `PluginSurfaceLayer` import URL | high | mitigate | URL assembled only from `getContributions().surfaces` (main-process validated `entry`, directory-derived `pluginName`); no free-string prop; `grep -c "tapestry-plugin://"` is exactly 1 in the file |
| T-04-02 | Elevation of privilege | Surface module in the host realm | medium | accept | Same trust level as `require()`d plugin mains today (documented in the SDK doc comment, 01-02); `SurfaceHost` exposes no kernel route in API 1; future iframe isolation recorded |
| T-04-03 | Denial of service | Leaked WebGL contexts / workers across open-close cycles | medium | mitigate | `dispose()` contract is idempotent and is called from the effect cleanup; the checkpoint counts mounts vs disposes over four cycles; the data-drawing surface (01-08) runs a 20-cycle test |
| T-04-04 | Information disclosure | Error text rendered in the layer includes the module URL | low | accept | Local single-user app; the URL names only a plugin directory |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this plan (plain JS example, hoisted React) |
</threat_model>
