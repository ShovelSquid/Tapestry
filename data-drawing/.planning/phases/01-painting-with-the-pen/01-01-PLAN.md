## Phase Goal

**As a** painter holding a pressure pen (Kaelen), **I want to** paint inside Tapestry and watch nodes land on a plane facing a fixed camera, placed by a deterministic fixed-point sim running live in a Worker, **so that** the brush body's mass can be felt and seen.

(Transcribed from the ROADMAP `**Goal:**` line for Phase 1; nothing invented. Phase mode is `mvp` and `WALKING_SKELETON=true`; this plan is the skeleton described in `01-SKELETON.md`.)

<objective>
Build the walking skeleton: a dependency-free C++20 `ddsim` library whose only numeric type is a Q32.32 `fx64`, whose state is hashed through one canonical byte walk, compiled both natively (doctest under CTest, committed golden hashes) and to WebAssembly (Emscripten 6.0.10), and run live at 60 Hz inside a module Web Worker behind an async `SimHost`, so that the plugin's own Vite dev page can submit one `DefineBrush` action and show a hash that equals the native build's golden for the same tick.

Purpose: SIM-01/SIM-02 cannot be retrofitted, and the roadmap locks "harness first, on a no-op step()" and "establish the wasm preset and pin Emscripten on this skeleton so toolchain failures surface with no behaviour to blame". Proving action → sim → hash → Wasm → Worker → page on the agent's best early-context tokens catches an architectural dead-end after one commit instead of after ten layers.

Output: `data-drawing/sim/` (library, tests, goldens, fixture generator, wasm target), `plugins/data-drawing/` (manifest, CommonJS entry, Vite/Vitest config, worker, SimHost, dev page, Wasm golden test), emsdk 6.0.10 installed at `~/emsdk`.
</objective>
